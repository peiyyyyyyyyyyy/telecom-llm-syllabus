# 5.1.6 基地台工程參數（組態資料、NRM）

所屬：[5.1 資料的種類](5-1.md)

## 內文

#### 是什麼、什麼時候會用到

基地台工程參數是基地台「被設定成什麼樣子」的資料，例如每個小區的實體小區識別碼（PCI）、頻點、頻寬、追蹤區碼與管理狀態。在 3GPP 的管理架構裡，這些組態資料用網路資源模型（Network Resource Model，NRM）描述：每一類可管理的東西是一個資訊物件類別（Information Object Class，IOC），每個 IOC 有一組屬性。NR 與 NG-RAN 的 NRM 定義在 TS 28.541。維運人員在這些情況會讀組態資料：告警或 KPI 異常時確認小區設定有沒有被改過、路測（5.1.5）發現干擾時檢查 PCI 與頻點、新站開通的參數核對，以及判斷某小區沒有話務是故障還是被人為鎖住。

#### 怎麼讀

**1. 物件的層級。** gNB 在 NRM 裡拆成幾個功能物件。GNBDUFunction 在 2-split、3-split 架構中代表 gNB-DU（TS 28.541 V18.15.0 clause 4.3.1.1）；GNBCUCPFunction 在 3-split 架構中代表 gNB-CU-CP，在 2-split 架構中與 GNBCUUPFunction 一起代表 gNB-CU（clause 4.3.2.1）。小區也拆成兩半：

| IOC | 原文定義重點 | 主要屬性（TS 28.541 V18.15.0） |
|---|---|---|
| NRCellCU | 負責小區間移動性與經由 ANR 的鄰區關係（clause 4.3.4.1） | `cellLocalId`、`pLMNInfoList`、`nRFrequencyRef`（clause 4.3.4.2） |
| NRCellDU | 描述小區實際使用的資源（clause 4.3.5.1） | `cellLocalId`、`operationalState`、`administrativeState`、`cellState`、`pLMNInfoList`、`nRPCI`、`nRTAC`、`arfcnDL`、`arfcnUL`、`bSChannelBwDL`、`bSChannelBwUL`、`ssbFrequency`、`ssbPeriodicity`、`ssbSubCarrierSpacing`、`ssbOffset`、`ssbDuration`、`nRSectorCarrierRef`、`bWPRef`（clause 4.3.5.2） |
| GNBDUFunction | gNB-DU 的管理表示 | `gNBDUId`、`gNBDUName`、`gNBId`、`gNBIdLength`（clause 4.3.1.2） |
| GNBCUCPFunction | gNB-CU-CP（或與 GNBCUUPFunction 合起來代表 gNB-CU）的管理表示 | `gNBId`、`gNBIdLength`、`gNBCUName`、`pLMNId` 等（clause 4.3.2.2） |

鄰區關係則另有 NRCellRelation、NRFreqRelation 等 IOC（clause 4.3.32、4.3.33）。

**2. NRCellDU 常看的屬性。** 下表的意義與允許值都取自屬性定義表（TS 28.541 V18.15.0 clause 4.4.1）：

| 屬性 | 意義 | 型別與允許值 |
|---|---|---|
| `nRPCI` | 小區的 PCI | Integer；原文指向 TS 36.211 clause 6.11 的合法值（NR 的 PhysCellId 在 TS 38.331 為 0..1007） |
| `nRTAC` | 各 PLMN 共用的追蹤區碼，可為 TAC 或 Extended-TAC | String |
| `arfcnDL`／`arfcnUL` | 下行／上行的 NR-ARFCN | Integer；合法值見 TS 38.104 clause 5.4.2 |
| `bSChannelBwDL` | 下行基地台通道頻寬 | Integer，單位 MHz；見 TS 38.104 clause 5.3 |
| `ssbSubCarrierSpacing` | SSB 子載波間隔 | 單位 kHz；{15, 30, 120, 240} |
| `ssbPeriodicity` | SSB 週期 | 單位 ms；5、10、20、40、80、160 |
| `ssbOffset`／`ssbDuration` | 量測窗的偏移與長度 | 單位 ms；偏移範圍依週期而定，長度 1～5 |
| `administrativeState` | 經由 OAM 允許或禁止使用小區 | LOCKED、SHUTTING DOWN、UNLOCKED；預設 LOCKED |
| `operationalState` | 資源是否已安裝且可運作 | ENABLED、DISABLED |
| `cellState` | 使用狀態 | IDLE、INACTIVE、ACTIVE |

**3. 怎麼從屬性推出常用的值。**
- **NR Cell Identity（NCI）**：`cellLocalId` 和上層功能物件的 `gNBId` 合起來就是 NCI，`gNBId` 佔的位元數由 `gNBIdLength` 決定（允許值 22～32）（TS 28.541 V18.15.0 clause 4.4.1）。NCI 在 TS 38.331 是 36 位元的 CellIdentity，所以 `cellLocalId` 可用的位元數是 36 減去 `gNBIdLength`。
- **頻率**：`arfcnDL` 換成 MHz 要用 TS 38.104 的公式 F_REF = F_REF-Offs + ΔF_Global × (N_REF − N_REF-Offs)。在 3000～24250 MHz 範圍內，ΔF_Global = 15 kHz、F_REF-Offs = 3000 MHz、N_REF-Offs = 600000（TS 38.104 V18.15.0 clause 5.4.2.1）。
- **TDD 小區**：`arfcnUL`、`bSChannelBwUL` 必須和下行的值相同（TS 28.541 V18.15.0 clause 4.3.5.1）。

**4. 物件怎麼定位。** 每個物件實例以 DN（Distinguished Name）表示，由上到下列出各層的「類別名=識別值」（DN 規則見 5.2.2）。引用屬性（例如 `nRSectorCarrierRef`）的值也是 DN，指向另一個物件。

#### 實際例子

下面是從組態資料匯出的三個小區屬性。屬性名稱與列舉值照 TS 28.541；DN、識別碼與數值都是虛構的。為了方便比較，排成表格，不代表某一種特定的匯出編碼格式。

| 屬性 | 小區 A | 小區 B | 小區 C |
|---|---|---|---|
| DN | `SubNetwork=AreaN,ManagedElement=gNB-70001,GNBDUFunction=1,NRCellDU=1` | `SubNetwork=AreaN,ManagedElement=gNB-70001,GNBDUFunction=1,NRCellDU=2` | `SubNetwork=AreaN,ManagedElement=gNB-70002,GNBDUFunction=1,NRCellDU=1` |
| 上層 `gNBId`／`gNBIdLength` | 70001／24 | 70001／24 | 70002／24 |
| `cellLocalId` | 1 | 2 | 1 |
| `nRPCI` | 301 | 302 | 301 |
| `nRTAC` | "001F4A" | "001F4A" | "001F4A" |
| `arfcnDL`／`arfcnUL` | 640000／640000 | 640000／640000 | 640000／640000 |
| `bSChannelBwDL` | 100 | 100 | 100 |
| `ssbSubCarrierSpacing` | 30 | 30 | 30 |
| `ssbPeriodicity`／`ssbOffset`／`ssbDuration` | 20／0／1 | 20／0／1 | 20／0／1 |
| `administrativeState` | UNLOCKED | LOCKED | UNLOCKED |
| `operationalState` | ENABLED | ENABLED | ENABLED |
| `cellState` | ACTIVE | IDLE | ACTIVE |

逐欄讀法：
- **NCI**：`gNBIdLength` 是 24，`cellLocalId` 有 36 − 24 = 12 位元可用（0～4095）。小區 A 的 NCI = 70001 × 4096 + 1 = 286724097（十六進位 011171001）；小區 C 的 NCI = 70002 × 4096 + 1 = 286728193。兩者 `cellLocalId` 都是 1，但屬於不同 gNB，所以 NCI 不同，不是重複設定。
- **頻率與頻寬**：`arfcnDL` = 640000，換算為 3000 + 0.015 × (640000 − 600000) = 3600 MHz，在 n78 的 NR-ARFCN 範圍 620000～653333 內（TS 38.104 V18.15.0 Table 5.4.2.3-1）；`bSChannelBwDL` 是 100 MHz。三個小區同頻，`arfcnUL` 等於 `arfcnDL`，符合 TDD 的規則。
- **小區 B**：`administrativeState` 是 LOCKED，`operationalState` 是 ENABLED。也就是設備可運作，但被 OAM 鎖住，所以沒有話務是人為設定的結果，不是故障。這種情況應查變更紀錄，不應當成設備異常派修。
- **小區 A 與小區 C**：同頻（640000）且 `nRPCI` 都是 301。如果兩者在地理上相鄰或有共同鄰區，終端只靠 PCI 就分不出兩者，可能造成切換到錯的小區。下一步應查兩者的鄰區關係（NRCellRelation）與路測資料（5.1.5），確認是否真的會互相看到。

#### 容易搞混的地方

1. **NRCellCU 和 NRCellDU 是同一個小區的兩個物件。** PCI、頻點、頻寬、SSB 設定在 NRCellDU；移動性與鄰區關係歸 NRCellCU。查 PCI 時要找 NRCellDU 的 `nRPCI`，不是 NRCellCU。
2. **三種狀態各自獨立。** `administrativeState` 是管理上允不允許使用，`operationalState` 是設備能不能運作，`cellState` 是目前是否在使用、是否承載話務。LOCKED 加上 ENABLED 代表「能用但被鎖住」，不等於故障。
3. **`cellLocalId` 不是 NCI，也不是 PCI。** `cellLocalId` 要和 `gNBId` 合起來才是 NCI（小區全域識別的一部分）；PCI（`nRPCI`）是實體層的識別碼，範圍小、會在不同地點重複使用。
4. **`arfcnDL` 不是 MHz。** 它是頻道編號，要用 TS 38.104 的公式換算，而且不同頻率範圍的參數不同。

#### 和其他小節的關係

DN 的組成與 gNB ID、Cell ID、NCI 的關係見 5.2.2；路測或 MDT（5.1.5）看到的 PCI 要回到本節的 `nRPCI` 對應實際小區；告警（5.1.1）中的物件實例也以 DN 指向這些物件。組態被改動的時間點應排入 5.5.1 的事件時間軸，並在 6.1 判斷根因是否屬於參數設定類。
