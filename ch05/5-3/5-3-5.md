# 5.3.5 告警的清除與確認

所屬：[5.3 告警](../5-3.md)

## 正文

In a live telecom network, alarms are generated whenever a fault is detected. An alarm remains *active* until the underlying fault is repaired and the network element (NE) confirms that the condition no longer exists. Clearing alarms prevents the alarm list from being flooded with stale entries, allows operators to focus on current problems, and ensures that downstream management systems (e.g., fault‑management (FM) or performance‑management (PM) modules) work with an accurate view of the system state.  

### Definition of a Cleared Alarm

A *cleared alarm* is defined as an alarm whose severity is set to **cleared**. The clear alarm carries either the same identifying parameters as the original active alarm or an explicit reference to that alarm, and its generation triggers the removal of the active alarm from the NE’s active‑alarm list [TS 32.111-1 §4.1.3].  

### Mechanisms that Lead to Alarm Clearance

1. **Repair of the Underlying Fault** – The primary condition for clearing an alarm is the successful repair of the fault that caused it. Repair actions are specified in the alarm maintenance manual and must be recorded in the alarm’s repair‑action field [TS 32.111-1 §4.1.3].  

2. **Automatic Detection of Fault Resolution** – The NE may autonomously detect that a fault has been repaired using the same detection mechanisms that originally raised the alarm. For example, when a threshold‑crossed condition falls back within limits, the NE clears the alarm without operator interaction [TS 32.111-1 §4.1.3].  

3. **Operator‑initiated Clearance** – An operator can request clearance explicitly (e.g., via a management console) or implicitly (e.g., by installing a replacement device). In both cases the NE must clear the associated fault and all related alarms [TS 32.111-1 §4.1.3].  

4. **ADMC vs. ADAC Faults** – Faults classified as *Alarm‑Driven Management – Manual Clearance* (ADMC) must always be cleared by an operator; the NE never clears them autonomously. Conversely, *Alarm‑Driven Management – Automatic Clearance* (ADAC) faults may be cleared automatically when the NE detects that the condition no longer holds [TS 32.111-1 §4.1.3].  

### Typical Repair Actions by Fault Category

| Fault Category | Typical Repair Action (as per specification) |
|----------------|---------------------------------------------|
| Equipment      | Replace the faulty unit with a working one |
| Software       | Apply patches, reload software, or perform a partial/global initialization |
| Communication | Replace faulty transmission equipment or eliminate excessive noise |
| QoS            | Remove the cause of degradation or enhance system reaction capability |
| Environmental  | Remedy high temperature, humidity, etc. |
| ADAC (threshold‑crossed) | No operator action; NE clears when measurement returns within limits |

These actions are illustrative; the exact procedure is implementation‑dependent and therefore outside the scope of this subsection [TS 32.111-1 §4.1.3].  

### Acknowledgement of Alarms

Before an alarm can be removed from the alarm list, many operators require that it be *acknowledged* – i.e., an operator or an automated management‑system (MnS) consumer signals that the alarm has been seen. The alarm record contains an **acknowledgement state** attribute, which can be **acknowledged** or **unacknowledged** [TS 28.111 §6.7].  

* When the alarm is first created, its acknowledgement state is set to **unacknowledged**.  
* An MnS consumer (human operator or software) can set the attribute to **acknowledged**, optionally providing its identity (user ID, system ID). The producer stores this information in the alarm record.  
* The system automatically timestamps the change in a dedicated **acknowledgement time** attribute.  

Acknowledgement is optional; a system may allow alarms to be cleared without prior acknowledgment, but best practice in operational networks is to require acknowledgment to avoid accidental loss of fault information [TS 28.111 §6.7].  

### Worked Example

Assume a base‑station NE detects a temperature alarm (severity **major**) because the measured temperature exceeds the critical threshold of 75 °C.  

| Step | Action | Result |
|------|--------|--------|
| 1 | NE generates active alarm **A1** with severity *major*, acknowledgment state *unacknowledged*, and records the repair‑action “Replace cooling fan”. | Alarm list now contains A1. |
| 2 | Operator logs into the FM console, sees A1, and acknowledges it. The MnS consumer sets the acknowledgment state to **acknowledged** and the system records the acknowledgement time. | A1 is now acknowledged; still active. |
| 3 | Technician replaces the cooling fan. The NE detects that temperature has fallen to 60 °C (within limits). | NE automatically clears the fault. |
| 4 | NE creates clear alarm **C1** with severity *cleared*, re‑using the identifier of A1, and removes A1 from the active‑alarm list. | Alarm list no longer shows A1; C1 is logged for historical analysis. |

In this scenario the alarm was both *acknowledged* (step 2) and *cleared* (step 4) in compliance with the specifications.  

### Common Pitfalls and Practical Notes

* **Clearing without Repair** – Removing an alarm without fixing the underlying fault violates the principle that “alarms originated in consequence of faults need to be cleared … by repairing the corresponding fault” [TS 32.111-1 §4.1.3]. This leads to hidden failures and service degradation.  

* **Missing Acknowledgement** – Some operators clear alarms directly, bypassing acknowledgment. While technically allowed if the feature is optional, it defeats the purpose of the acknowledgement attribute, which provides auditability and operator accountability [TS 28.111 §6.7].  

* **Confusing ADMC and ADAC** – Attempting to let the NE automatically clear an ADMC fault will not succeed, because “ADMC faults/alarms can, by definition, not be cleared by the NE autonomously” [TS 32.111-1 §4.1.3]. Ensure fault classification is correct in the alarm maintenance manual.  

* **Incomplete Clear‑Alarm Correlation** – If the clear alarm does not reuse the original identifiers or reference the active alarm, downstream systems may treat the clear event as unrelated, causing duplicate entries in historical logs. Always follow the two prescribed methods for establishing the relationship [TS 32.111-1 §4.1.3].  

* **Threshold‑Crossed Alarms** – For ADAC threshold alarms, the NE must clear the alarm automatically when the measurement returns within limits; however, the exact condition is implementation‑specific [TS 32.111-1 §4.1.3]. Verify the vendor’s threshold management policy to avoid premature clearance.  

By adhering to the defined clearing mechanisms and acknowledgment procedures, engineers can maintain a reliable and auditable alarm management process, which is essential for rapid fault isolation and service restoration.

## 練習題

**1.** Which statement best describes when a Network Element (NE) may automatically clear an alarm?

- A. Only after an operator manually confirms the fault is repaired.
- B. When the NE detects that a threshold‑crossed condition is no longer valid.
- C. Whenever the alarm severity is set to "major".
- D. Only for equipment‑fault alarms that require hardware replacement.

<details><summary>看答案</summary>

正解：B。Automatic clearance is allowed for threshold‑crossed alarms when the NE determines the condition is no longer valid.

</details>

**2.** In the alarm record, the attribute that indicates whether an alarm has been seen by an operator or system is called:

- A. severity
- B. acknowledgement state
- C. clear‑alarm flag
- D. fault‑type

<details><summary>看答案</summary>

正解：B。The specification defines an acknowledgement state attribute with values acknowledged and unacknowledged.

</details>

**3.** Which fault category typically requires a “partial or global system initialization” as a repair action?

- A. Communication faults
- B. Software faults
- C. Environmental faults
- D. QoS faults

<details><summary>看答案</summary>

正解：B。The reference lists software faults being repaired by partial or global system initializations.

</details>

**4.** When a clear alarm is generated, what happens to the corresponding active alarm in the NE’s alarm list?

- A. It remains in the list with a “cleared” flag.
- B. It is moved to a separate “historical” list.
- C. It is removed from the active alarm list.
- D. It is duplicated with a new identifier.

<details><summary>看答案</summary>

正解：C。The specification states that the active alarm is removed when a clear alarm is generated.

</details>
