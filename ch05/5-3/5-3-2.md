# 5.3.2 告警之間的關聯

所屬：[5.3 告警](../5-3.md)

## 正文

In a live telecom network a single physical fault (e.g., a fiber cut, a power supply failure, or a software bug) often triggers **many** alarms and events that appear on different network elements, at different times, and sometimes across a wide geographical area. If operators treat each alarm in isolation, they may waste valuable time chasing symptoms rather than the underlying cause. Therefore, the Operations Support (OS) system is expected to **indicate which alarms and events are correlated to each other** so that the fault‑root can be identified more quickly and efficiently【TS 32.111-1 §4.1.8】.

### Key definitions

| Symbol | Meaning | Reference |
|--------|---------|-----------|
| $F$ | A single network fault (physical or logical) | 【TS 32.111-1 §4.1.8】 |
| $A_{i}$ | An individual alarm generated as a consequence of $F$ | 【TS 32.111-1 §4.1.8】 |
| $E_{k}$ | An event (e.g., a configuration change) that may be related to $F$ | 【TS 32.111-1 §4.1.8】 |
| $S_{c}$ | A **correlated set** – a collection of alarms (and possibly events) that have a high probability of being caused by the same fault $F$ | 【TS 32.111-1 §4.1.8】 |
| **correlatedNotifications** | Attribute that records that a notification belongs to a correlated set | 【TS 28.111 §6.10】 |
| **rootCauseIndicator** | Attribute that points to the alarm or event identified as the most likely root cause within a correlated set | 【TS 28.111 §6.10】 |

A correlated set $S_{c}$ is formed according to **correlation rules** such as:

* **Alarm propagation path** – alarms that travel along the same logical or physical chain.  
* **Specific geographical area** – alarms that originate from equipment located in the same region.  
* **Specific equipment** – alarms that are raised by the same hardware or software module.  
* **Repeated alarms from the same source** – identical alarm types that recur on the same element.  

These rules are listed in the specification and are the only basis we may cite for correlation【TS 32.111-1 §4.1.8】.

### How correlation is represented

When the OS groups alarms, it assigns the **correlatedNotifications** attribute to each member of the set. If the system can identify which member most likely reflects the original fault, it also sets the **rootCauseIndicator** for that member. Any change to these attributes is reported through a *notify correlated notification changed* notification【TS 28.111 §6.10】.

### Worked example

Consider a regional back‑haul link that suffers a fiber cut (fault $F$). The following notifications are generated:

| Time (s) | Source | Type | Notification |
|----------|--------|------|--------------|
| 10 | Router‑A (interface) | Alarm $A_{1}$ – loss of signal | correlatedNotifications = $S_{c1}$ |
| 12 | Router‑B (interface) | Alarm $A_{2}$ – loss of signal | correlatedNotifications = $S_{c1}$ |
| 15 | Network Management System | Event $E_{1}$ – link status change to *down* | correlatedNotifications = $S_{c1}$ |
| 30 | Router‑A (CPU) | Alarm $A_{3}$ – high CPU load | correlatedNotifications = $S_{c2}$ |

Using the **alarm propagation path** rule, the OS groups $A_{1}$, $A_{2}$ and $E_{1}$ into a single correlated set $S_{c1}$ because they all stem from the same physical link. The later alarm $A_{3}$ is placed in a different set $S_{c2}$ because its cause (CPU overload) is unrelated to the fiber cut. The OS also marks $A_{1}$ as the **rootCauseIndicator** for $S_{c1}$ because the loss of signal on the first router is the earliest observable symptom of the cut【TS 32.111-1 §4.1.8】【TS 28.111 §6.10】.

### Practical notes and common pitfalls

1. **Geography alone is insufficient** – Two alarms in the same city may belong to different faults; correlation must also consider propagation paths and equipment identity【TS 32.111-1 §4.1.8】.  
2. **Events belong to correlated sets** – Ignoring events (e.g., configuration changes) can hide the true relationship between alarms【TS 32.111-1 §4.1.8】.  
3. **Root‑cause indication is optional** – Not every correlated set will have a clear root‑cause indicator; operators should still investigate when the attribute is absent【TS 28.111 §6.10】.  
4. **Dynamic updates** – As new alarms appear, the OS may modify the **correlatedNotifications** attribute; these changes must be tracked via the *notify correlated notification changed* notification【TS 28.111 §6.10】.  
5. **Over‑correlation** – Applying too many rules (e.g., grouping all alarms from a region) creates overly large sets that dilute the usefulness of correlation. Stick to the rules explicitly mentioned in the specifications.

By adhering to the defined correlation concepts and attributes, network operators can reduce alarm storms, focus on the true fault, and accelerate restoration activities.

## 練習題

**1.** According to TS 32.111‑1, what is the primary purpose of alarm correlation in an OS?

- A. To reduce the number of alarms displayed to the operator.
- B. To indicate which alarms and events are correlated to each other.
- C. To assign a severity level to each alarm.
- D. To archive historical alarms for later analysis.

<details><summary>看答案</summary>

正解：B。The specification states the OS should indicate which alarms and events are correlated.

</details>

**2.** Which attribute is defined in TS 28.111 to capture the relationship between notifications that belong to the same fault?

- A. alarmPropagationPath
- B. correlatedNotifications
- C. alarmSeverityLevel
- D. notificationTimestamp

<details><summary>看答案</summary>

正解：B。The standard introduces the *correlatedNotifications* attribute for this purpose.

</details>

**3.** TS 28.111 mentions that a single fault may cause multiple ______.

- A. alarms only
- B. errors and failures
- C. configuration changes
- D. user sessions

<details><summary>看答案</summary>

正解：B。The text explicitly says a single fault can cause multiple errors and failures.

</details>

**4.** How does TS 32.111‑1 define a *correlated set*?

- A. A group of alarms that share the same severity.
- B. A collection of alarms and possibly events that have a high probability of being caused by the same network fault.
- C. All alarms generated within a 5‑minute window.
- D. Alarms that originate from the same vendor equipment.

<details><summary>看答案</summary>

正解：B。The definition ties the set to a high probability of common fault origin.

</details>

**5.** Which of the following is NOT listed as a rule for alarm correlation in TS 32.111‑1?

- A. Alarm propagation path
- B. Specific geographical area
- C. Specific equipment
- D. Time of day

<details><summary>看答案</summary>

正解：D。The specification lists the first three rules; time of day is not mentioned.

</details>
