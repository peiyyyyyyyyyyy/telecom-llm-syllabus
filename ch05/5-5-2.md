# 5.5.2 影響範圍

所屬：[5.5 寫摘要](5-5.md)

## 內文

#### 是什麼、什麼時候會用到

影響範圍（impact scope）是說明一個事件「影響了哪些小區、大約多少用戶、哪些服務、持續多久」。告警只告訴我們哪一個物件出問題，例如一個 gNB-DU；影響範圍則要從這個物件出發，沿著網路資源模型（Network Resource Model，NRM）的拓撲關係找出底下或依賴它的小區，再用績效量測估計用戶數。維運人員在事件進行中要用它決定處理優先順序與是否通報，在事後報告裡要用它說明事件的嚴重程度。本節以方法論為主，拓撲關係與屬性名稱依 TS 28.541，用戶數的量測名稱依 TS 28.552。

#### 怎麼讀

**1. 從告警物件沿拓撲往下找**

告警的 `objectInstance` 是發生告警的物件 DN（TS 28.111 V18.8.0 clause 6.3）。TS 28.541 的 NRM 用「名稱包含」（name-containment，圖上標為 `<<names>>`）表示上下層關係，Figure 4.2.1.1-1 畫出的關係如下（TS 28.541 V18.15.0 clause 4.2.1.1）：

| 上層 | 包含的下層 |
|---|---|
| ManagedElement | GNBDUFunction、GNBCUCPFunction、GNBCUUPFunction |
| GNBDUFunction | NRCellDU |
| GNBCUCPFunction | NRCellCU |

所以告警落在 `GNBDUFunction=1` 時，第一步是列出它底下所有 `NRCellDU`。**告警落在 ManagedElement 時，其下所有功能與小區是要檢查的候選範圍，實際影響仍需用狀態或量測確認。**

**2. 再找「參照」關係**

有些依賴不是包含，而是用 DN 參照：`NRCellDU` 的 `nRSectorCarrierRef` 存放所參照的 `NRSectorCarrier` 的 DN，`NRSectorCarrier` 的 `sectorEquipmentFunctionRef` 存放所參照的 `SectorEquipmentFunction` 的 DN（TS 28.541 V18.15.0 clause 4.4.1）。告警若落在 `SectorEquipmentFunction` 或 `NRSectorCarrier`，就要反過來找「哪些小區參照到它」，不能只看包含樹。

**3. DU 側小區對到 CU 側小區**

用戶數量測不在 `NRCellDU` 上：TS 28.552 的 `RRC.ConnMean`（RRC 連線態用戶的平均數）與 `RRC.ConnMax`（最大數）量測物件是 `NRCellCU`（TS 28.552 V18.12.0 clause 5.1.1.4.1、5.1.1.4.2）。兩邊靠 `cellLocalId` 對應：`cellLocalId` 加上上層的 gNB Identifier 組成 NR Cell Identity（NCI）（TS 28.541 V18.15.0 clause 4.4.1）。

**4. 排除事前就不在服務的小區**

| 屬性 | 允許值（照原文） | 用途 |
|---|---|---|
| `administrativeState` | LOCKED、SHUTTING DOWN、UNLOCKED | 事前已被鎖定的小區不算本事件造成的影響 |
| `operationalState` | ENABLED、DISABLED | 是否可運作 |
| `cellState` | IDLE、INACTIVE、ACTIVE | INACTIVE 表示不服務 UE；ACTIVE 表示應可服務 UE |

以上皆為 `NRCellDU` 的屬性（TS 28.541 V18.15.0 clause 4.3.5.2、4.4.1）。

**5. 服務**：`pLMNInfoList` 列出小區可服務的 PLMN，以及支援網路切片時每個 PLMN 下的 S-NSSAI（TS 28.541 V18.15.0 clause 4.4.1、4.3.41）。影響了哪些 PLMN 或切片，從受影響小區的這個屬性彙整。

**6. 用戶數的估法與假設**

`RRC.ConnMean` 是取樣後的算術平均（TS 28.552 V18.12.0 clause 5.1.1.4.1），它算的是「同時處於 RRC 連線態的用戶」，不是「不同用戶的人數」，也不含閒置態的用戶。故障期間的量測已經被故障拉低，所以要用基線（例如過去 4 個同星期、同時段的平均）來估「本來會有多少人在線」。報告裡一定要寫明用了哪個量測、哪段基線、做了哪些假設。

#### 實際例子

組態快照（虛構，事件前一天匯出）：

```
ManagedElement=gNB-HC012
├─ GNBDUFunction=1
│   ├─ NRCellDU=1  cellLocalId=1  administrativeState=UNLOCKED  cellState=ACTIVE
│   ├─ NRCellDU=2  cellLocalId=2  administrativeState=UNLOCKED  cellState=ACTIVE
│   └─ NRCellDU=3  cellLocalId=3  administrativeState=LOCKED    cellState=IDLE
├─ GNBDUFunction=2
│   ├─ NRCellDU=4  cellLocalId=4  administrativeState=UNLOCKED  cellState=ACTIVE
│   └─ NRCellDU=5  cellLocalId=5  administrativeState=UNLOCKED  cellState=ACTIVE
└─ GNBCUCPFunction=1
    └─ NRCellCU=1 ~ NRCellCU=5（cellLocalId 1～5）
```

告警：`GNBDUFunction=1` 的 Link failure，14:41:07 產生、15:12:40 清除（UTC+08:00，見 5.5.1）。

`RRC.ConnMean`（NRCellCU，15 分鐘週期）：

| 小區 | 基線（過去 4 週同星期 14:30～15:15 平均） | 事件期間（14:45～15:00） |
|---|---|---|
| NRCellCU=1 | 410 | 0 |
| NRCellCU=2 | 181 | 0 |
| NRCellCU=4 | 150 | 205 |
| NRCellCU=5 | 120 | 158 |

推估步驟：

1. **受影響小區**：`GNBDUFunction=1` 包含 NRCellDU=1、2、3。NRCellDU=3 事前已 LOCKED，不算本事件影響。結論是 2 個小區（NRCellDU=1、2），占本站 4 個服務中小區的 50%。
2. **對到 CU 側**：cellLocalId 1、2 對應 NRCellCU=1、2。
3. **平均同時連線數**：410 + 181 = 591。假設：當天流量與過去 4 週同時段相近。
4. **持續時間**：15:12:40 − 14:41:07 = 31 分 33 秒，即 31.55 分鐘。
5. **連線分鐘數**：591 × 31.55 ≈ 18,646（連線·分鐘）。這是「平均在線連線數乘以時間」，不是人數。
6. **鄰區吸收**：NRCellCU=4、5 比基線多了 (205 − 150) + (158 − 120) = 55 + 38 = 93，約占 591 的 15.7%。這只表示同時段鄰區連線變多，是否就是原本 NRCellCU=1、2 的用戶，需要切換或追蹤資料才能確認。

報告寫法：「受影響小區 2 個；以基線估計平均約 591 個 RRC 連線受影響，持續 31.55 分鐘；同時段鄰區連線增加 93，可能有部分用戶轉到鄰區（待確認）。」

#### 容易搞混的地方

- **用 NRCellDU 找用戶數**：`RRC.ConnMean`、`RRC.ConnMax` 的量測物件是 `NRCellCU`，要先用 `cellLocalId` 對到 CU 側再查。
- **把 RRC 連線數當成用戶人數**：它是同時在線的平均值，不含閒置態用戶，也不等於期間內不同用戶的總數；要估人數需要其他資料（例如核心網路的資料），並寫明假設。
- **用故障期間的量測估影響**：故障期間值已經被拉低（例子中是 0），要用基線估「原本會有多少」。
- **把事前已鎖定或非 ACTIVE 的小區算進來**：會高估影響；`administrativeState`、`cellState` 要用事件前的快照判斷。

#### 和其他小節的關係

DN 寫法見 5.2.2，NRM 屬性見 5.1.6，`RRC.ConnMean` 等量測與單位見 5.1.2、5.2.3，基線的做法見 5.4.1，時間範圍來自 5.5.1 的時間軸。本節的推估在 5.5.3 要標成「推導」或「推測」，並作為 6.3 決定處置優先順序、6.5 報告影響範圍的依據。

**2407.** What makes an observation a verified data point within the impact scope of an incident?

<details><summary>看答案</summary>
