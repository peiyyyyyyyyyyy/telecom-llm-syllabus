# 5.2.2 設備代碼與命名

所屬：[5.2 對齊資料](5-2.md)

## 內文

#### 是什麼、什麼時候會用到

同一個小區，在不同資料裡會用不同的代碼出現：告警紀錄與量測檔用 Distinguished Name（DN）指出物件；信令追蹤、鄰區關係、UE 回報用 NR 小區識別碼（NR Cell Identity, NCI）或全球小區識別碼（NCGI）；路測資料常只有實體層小區識別碼（physical-layer cell identity, PCI）；工程人員口頭說的則是站名或 `userLabel`。要把告警、績效與追蹤資料接在一起，就得知道這些代碼怎麼組成、怎麼互相換算。維運人員在比對「這筆告警的物件」與「那份量測檔的哪一列」，或把追蹤紀錄裡的 NCI 對回網管上的小區時，都會用到本節。

#### 怎麼讀

**一、DN 的寫法（TS 32.300）**

1. DN 用來在一個名稱空間（name space）中唯一識別一個受管物件（managed object, MO），由一串相對識別名（Relative Distinguished Name, RDN）組成（TS 32.300 V18.1.0 clause 3.1.7）。3GPP 只支援單值 RDN（clause 5）。
2. 每個 RDN 寫成「類別名＝值」，例如 `ManagedElement=gNB-TPE-0412`（clause 7.1.1.3）。RDN 之間用逗號分隔，逗號旁的空白要忽略（clause 7.1.1.1）。順序從上層容器寫到下層物件。
3. 若 AttributeValue 中的值含有逗號、等號、`+`、`<`、`>`、`#`、`;`、反斜線、雙引號、CR、LF，允許使用跳脫機制，例如以反斜線加兩位十六進位方式跳脫；這些字元在 7.2 中被列為不允許的字元，且 AttributeType 不允許跳脫。
4. DN 字串最長 400 位元組，這是 IRP 方案的限制，SBMA 方案不受此限（clause 7.4）。
5. DN 只表達「包含」關係，不帶其他關係（clause 3.1.7）。所以從 DN 看得出小區屬於哪個 ManagedElement，看不出它接哪一台傳輸設備。
6. DN prefix 加上本地識別名（Local Distinguished Name, LDN）就是完整 DN（TS 32.300 V18.1.0 Annex C）。

**二、量測檔裡的 DN 拆成三段**

TS 32.435 的 XML 把 DN 拆開放：`fileHeader@dnPrefix`、`managedElement@localDn`、`measValue@measObjLdn`；`dnPrefix` 在發送端沒設定時可以不出現（TS 32.435 V18.0.0 clause 4.1 Table 4.1）。`measObjLdn`（TS 32.432 稱 `measObjInstId`）是在 NE 的 DN 範圍內的 LDN，兩者串接才是被量測物件的 DN；NE 層級的量測，這一段是空的（TS 32.432 V18.0.0 clause 4.1 Table 4.1）。

**三、NR 的識別碼**

| 識別碼 | 長度／範圍 | 依據 |
|---|---|---|
| gNB ID | 22～32 位元 | TS 38.413 V18.11.0 clause 9.3.1.6；TS 28.541 `gNBIdLength` allowedValues 22..32 |
| NCI | 固定 36 位元，以完整十六進位表示 | TS 23.003 V18.8.0 clause 19.6A |
| NCGI | PLMN ID 串接 NCI | TS 23.003 V18.8.0 clause 19.6A；TS 38.300 V18.11.0 clause 8.2 |
| PCI | 1008 個值（0～1007） | TS 38.211 V18.10.0 clause 7.4.2.1 |

規則：NCI 最左邊的位元就是 gNB ID（TS 38.413 V18.11.0 clause 9.3.1.7）；gNB ID 包含在其所屬小區的 NCI 中（TS 38.300 V18.11.0 clause 8.2）。在網管模型裡，`gNBId`、`gNBIdLength` 是 `GNBDUFunction` 的屬性，`cellLocalId` 是 `NRCellDU` 的屬性；NCI 由長度為 `gNBIdLength` 的 gNB ID 與 `cellLocalId` 組成（TS 28.541 V18.15.0 clause 4.3.1.2、4.3.5.2、4.4.1）。由此推得：`cellLocalId` 佔 36 減 `gNBIdLength` 個位元。NCI 的實際編碼由各業者自訂（TS 23.003 V18.8.0 clause 19.6A），所以 gNB ID 長度要查組態，不能假設。

**四、給人看的名稱**

量測檔的 `managedElement@userLabel` 對應 TS 32.432 的 `neUserName`，是使用者自訂的名稱，沒設定時可以是空字串；相對地，NE 的 DN 在業者網路內是唯一的（TS 32.432 V18.0.0 clause 4.1 Table 4.1）。站名、`userLabel` 方便人閱讀，但可能改名、重複或留空，程式對齊資料時應以 DN 為主鍵，`userLabel` 只當輔助欄位。同理，NCGI 是在 NCI 前面加上 PLMN ID（TS 23.003 V18.8.0 clause 19.6A），跨業者或網路共享的情境下，只比對 NCI 可能撞號，要連同 PLMN ID 一起比。

#### 實際例子

同一個小區在三份資料中的樣子（名稱與數值虛構；DN 寫法依 TS 32.300，類別名依 TS 28.541）：

```
[告警] objectInstance:
  DC=op.example,SubNetwork=TW-North,ManagedElement=gNB-TPE-0412,GNBDUFunction=1,NRCellDU=2

[量測檔]
  <fileHeader ... dnPrefix="DC=op.example,SubNetwork=TW-North">
  <managedElement localDn="ManagedElement=gNB-TPE-0412" userLabel="TPE-0412"/>
  <measValue measObjLdn="GNBDUFunction=1,NRCellDU=2">

[組態]
  GNBDUFunction=1 : gNBId = 1715005, gNBIdLength = 24
  NRCellDU=2      : cellLocalId = 18
```

**DN 對齊**：把 `dnPrefix`、`localDn`、`measObjLdn` 依序用逗號串起來，得到 `DC=op.example,SubNetwork=TW-North,ManagedElement=gNB-TPE-0412,GNBDUFunction=1,NRCellDU=2`，和告警的 `objectInstance` 完全相同，可以確定兩筆資料講的是同一個小區（TS 32.432 V18.0.0 clause 4.1）。

**NCI 換算**：`gNBIdLength`＝24，所以 `cellLocalId` 佔 36－24＝12 位元。  
NCI＝1715005 × 2¹²＋18＝7,024,660,480＋18＝7,024,660,498，十六進位為 `1A2B3D012`（9 個十六進位字元＝36 位元）。  
反過來，在信令追蹤看到 NCI `1A2B3D012` 時：24 與 12 都是 4 的倍數，可以直接切開，前 6 個字元 `1A2B3D`＝1715005 是 gNB ID，後 3 個字元 `012`＝18 是 `cellLocalId`。

**拆錯長度的後果**：若誤以為 gNB ID 是 22 位元，`cellLocalId` 就變成 14 位元：gNB ID＝⌊7,024,660,498 ÷ 2¹⁴⌋＝428,751（`68ACF`），`cellLocalId`＝4,114。驗算 428,751 × 16,384＋4,114＝7,024,660,498，數字自洽，但指向一個不存在的 gNB。長度不是 4 的倍數時，也不能用切十六進位字元的方式拆。

能得出的結論：告警、量測檔、組態三份資料指向同一個小區；追蹤紀錄裡出現 `1A2B3D012` 時，應對回 `gNB-TPE-0412` 底下 `cellLocalId`＝18 的 `NRCellDU=2`，而不是另找一台 gNB ID 為 428,751 的設備。

#### 容易搞混的地方

1. **`NRCellDU=2` 不是 `cellLocalId`**：DN 裡的 2 是物件的命名值，例子中的 `cellLocalId` 是 18，PCI 又是另一個數字。口語的「Cell ID」可能指其中任何一個，報告裡要寫明是哪一種。
2. **只看 `measObjLdn` 不夠**：`GNBDUFunction=1,NRCellDU=2` 在每一台 gNB 底下都可能出現，一定要加上 `localDn` 與 `dnPrefix` 才唯一。
3. **DN 不是拓撲**：DN 只有包含關係，傳輸路徑、上下游設備要另外查組態或拓撲資料。
4. **gNB ID 長度因業者、因站而異**：同一網路裡可能混用不同長度，換算前要先讀 `gNBIdLength`。

#### 和其他小節的關係

本節的 DN 寫法用於讀 5.1.1 告警與 5.1.6 組態資料；NCI 對照用於 5.1.4 信令追蹤與 5.1.5 路測資料。物件對齊後，5.3.2 才能判斷上下游關聯，5.5.2 才能推估影響範圍，再接到 6.2 推理。
