# 5.4.3 尖峰與忙時

所屬：[5.4 指標趨勢](../5-4.md)

## 正文

In a live network a **peak** is observed when a performance measurement of a network function (NF) exceeds a value that has been accepted as a threshold for that metric.  The 3GPP Management Service for NF performance threshold monitoring (TS 28.550 §5.2.14) provides the mechanism to define those thresholds, to watch the measurements, and to generate a notification as soon as the threshold is crossed.  Detecting peaks is essential because it signals that a resource (CPU, memory, bandwidth, etc.) is being stressed and that immediate corrective action may be required to maintain service quality.

### Definition of a “Busy Hour” in the context of threshold monitoring
A **busy hour** is a time interval during which the number of threshold‑crossing events is high enough to indicate sustained heavy load on the NF.  The management service does not prescribe a fixed duration for a busy hour; rather, it enables the consumer to create a monitoring instance that continuously checks the NF’s performance measurements and reports each crossing.  By analysing the sequence of notifications, operators can infer when a busy hour occurs.

### Formal description of threshold crossing
For a given performance metric $M(t)$ measured at time $t$ (unit depends on the metric, e.g. % CPU, Mbps), and a pre‑configured threshold value $T$ (same unit as $M$), a **threshold crossing** is defined as  

$$
\text{Crossing event at } t \iff M(t) > T .
$$

When the condition becomes true, the management service producer sends a **threshold crossing notification** to the designated notification target.

*Symbols*  
- $M(t)$: instantaneous measurement of the NF performance metric, unit varies.  
- $T$: threshold value agreed between consumer and producer, same unit as $M(t)$.  
- $t$: time instant, typically expressed in seconds or as a timestamp.

### Creating and terminating a monitoring instance
Before any peak can be detected, the consumer must request the creation of a performance threshold monitoring instance.  The management service producer is required to fulfil that request, establishing the threshold $T$ and the notification destination.  When the monitoring is no longer needed—e.g., after a maintenance window—the consumer may request termination, and the producer must comply.  Both operations are explicitly mandated by the specification.  

[TS 28.550 §5.2.14]

### Notification delivery
The specification obliges the producer to allow the **threshold monitoring notification target** to receive each crossing notification.  The target may be a fault‑management system, an alarm collector, or any authorized consumer that has subscribed to the service.  Successful delivery is a prerequisite for any downstream automation (e.g., scaling actions) that reacts to peaks.  

[TS 28.550 §5.2.14]

### Worked example
Assume an NF that reports CPU utilisation every 5 seconds.  The consumer defines a threshold $T = 80\%$ for “CPU overload”.  

| Time (s) | $M(t)$ (CPU %) |
|----------|-----------------|
| 0        | 55 |
| 5        | 62 |
| 10       | 78 |
| 15       | 81 |
| 20       | 85 |
| 25       | 77 |

1. The consumer creates a monitoring instance (REQ‑THMS_NF‑FUN‑1).  
2. At $t = 15$ s, $M(15)=81\% > T$; a crossing event is generated.  
3. The producer sends a notification to the target (REQ‑THMS_NF‑FUN‑3).  
4. At $t = 20$ s, another crossing occurs (85 % > 80 %).  
5. After the incident, the consumer terminates the monitoring (REQ‑THMS_NF‑FUN‑2).

The two consecutive notifications within a short interval would be interpreted by the operator as the beginning of a busy hour.

### Practical notes and common mistakes

| Mistake | Why it matters |
|---------|----------------|
| **Omitting the notification target** | Without a target, the crossing event cannot be delivered, defeating the purpose of the monitoring. |
| **Failing to terminate an unused monitoring instance** | Unnecessary monitoring consumes resources and may generate spurious alarms. |
| **Choosing an inappropriate threshold** | A threshold that is too low generates frequent false positives; too high may miss true peaks. |
| **Assuming the service automatically aggregates notifications** | The specification only guarantees delivery of individual crossing notifications; aggregation must be implemented by the consumer. |

All three capabilities—creation, termination, and notification delivery—are required by the management service producer for NF performance threshold monitoring.  Ensuring each step is correctly configured enables reliable detection of peaks and accurate identification of busy hours.  

[TS 28.550 §5.2.14]

## 練習題

**1.** Which capability must the management service producer provide to allow a consumer to start monitoring NF performance thresholds?

- A. Ability to modify existing thresholds
- B. Ability to create a performance threshold monitoring
- C. Ability to generate synthetic traffic
- D. Ability to encrypt notification messages

<details><summary>看答案</summary>

正解：B。The specification states that the producer shall have the capability to fulfill the consumer's request to create a performance threshold monitoring.

</details>

**2.** According to TS 28.550 §5.2.14, what must the producer do when a threshold crossing occurs?

- A. Store the event locally without notifying anyone
- B. Forward the crossing event to a third‑party analytics platform only if requested
- C. Allow the threshold monitoring notification target to receive the notification
- D. Reset the threshold automatically

<details><summary>看答案</summary>

正解：C。The requirement explicitly mentions allowing the notification target to receive threshold crossing notifications.

</details>

**3.** If an authorized consumer no longer needs a performance threshold monitoring instance, which action is the producer required to support?

- A. Archive the monitoring data for 30 days
- B. Terminate the performance threshold monitoring
- C. Convert the monitoring into a reporting service
- D. Change the threshold value automatically

<details><summary>看答案</summary>

正解：B。The specification requires the producer to fulfill a request to terminate a performance threshold monitoring.

</details>

**4.** In the context of peak detection, which of the following statements is true?

- A. Peaks are detected only when the measurement stays above the threshold for a predefined duration.
- B. A peak is reported as a threshold crossing notification when the measurement exceeds the configured threshold.
- C. Peaks are identified solely by the frequency of notifications, not by individual measurement values.
- D. The management service can generate peaks without any consumer‑defined threshold.

<details><summary>看答案</summary>

正解：B。A peak corresponds to a measurement exceeding the threshold, which triggers a crossing notification.

</details>

**5.** Which entity is responsible for fulfilling the consumer's request to create a performance threshold monitoring?

- A. The network element itself
- B. The management service producer responsible for NF performance threshold monitoring
- C. The end‑user device
- D. An external third‑party vendor

<details><summary>看答案</summary>

正解：B。The specification assigns that responsibility to the management service producer.

</details>
