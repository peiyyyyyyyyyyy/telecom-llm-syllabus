# 5.5.1 事件時間軸

所屬：[5.5 寫摘要](../5-5.md)

## 正文

In a 3GPP‑based network, every fault must be **detected immediately** and reported with a precise timestamp so that operators can reconstruct the **event timeline** – the ordered series of moments from fault occurrence, through detection, to clearing (if applicable). A clear timeline enables root‑cause analysis, SLA verification, and coordinated recovery actions across multiple network entities. Without accurate timing, alarms may be mis‑correlated, leading to delayed mitigation or unnecessary manual interventions.

### Core Definitions
| Term | Definition (as per TS 32.111‑1 §4.1.1) |
|------|--------------------------------------|
| **Fault occurrence** | The moment a fault condition first becomes true in the network element (NE). |
| **Detection time** | “The time at which the fault was detected in the faulty network entity” [TS 32.111‑1 §4.1.1]. |
| **Clearing time** | The moment the NE recognises that an **ADAC** fault is no longer present, using the same self‑check mechanisms that detected it [TS 32.111‑1 §4.1.1]. |
| **ADAC fault** | A fault with both **occurrence** and **clearing** conditions; it can be cleared autonomously by the NE [TS 32.111‑1 §4.1.1]. |
| **ADMC fault** | A fault that **cannot be cleared** by the NE; manual operator action is required [TS 32.111‑1 §4.1.1]. |
| **Transient fault** | A fault that disappears within a single sampling interval and therefore needs no short‑term action [TS 32.111‑1 §4.1.1]. |

### Timestamp Representation
For each alarm the NE supplies a **UTC timestamp** $t_{\text{det}}$ (detection time). If the fault is ADAC, a second timestamp $t_{\text{clr}}$ (clearing time) is also provided. The **fault duration** $\Delta t$ is:

$$
\Delta t = t_{\text{clr}} - t_{\text{det}}
$$

If $t_{\text{clr}}$ is absent, the fault is either ADMC or still active.

### Building the Timeline
1. **Occurrence detection** – The NE’s autonomous self‑check circuits (measurements, counters, thresholds) trigger an alarm **immediately** when a fault condition is met [TS 32.111‑1 §4.1.1].  
2. **Timestamp insertion** – The detection time $t_{\text{det}}$ is logged together with fault type, severity, probable cause, and nature (ADAC/ADMC).  
3. **Clearing evaluation** – For ADAC faults, the NE continuously monitors the same parameters; when the clearing condition is satisfied, $t_{\text{clr}}$ is recorded [TS 32.111‑1 §4.1.1].  
4. **Operator correlation** – Operators align timestamps from multiple NEs to form a network‑wide chronology, identifying propagation paths or common root causes.

### Worked Example
A base‑station controller (BSC) monitors CPU load. The threshold for **overload** is 85 % sampled every 30 s.

| Event | Description | Timestamp (UTC) |
|------|-------------|-----------------|
| 1 | CPU load crosses 85 % → overload condition begins | 2026‑11‑23 10:15:00 |
| 2 | NE detects overload and raises an ADAC alarm | $t_{\text{det}} = $ 2026‑11‑23 10:15:00 |
| 3 | Load falls below 85 % in next sampling interval | 2026‑11‑23 10:15:30 |
| 4 | NE recognises clearing condition, logs $t_{\text{clr}}$ | $t_{\text{clr}} = $ 2026‑11‑23 10:15:30 |
| 5 | Calculated fault duration | $\Delta t = 30\ \text{s}$ |

Because the overload cleared within one sampling interval, the fault is **transient** and required no manual action [TS 32.111‑1 §4.1.1].

### Common Mistakes & Practical Notes
- **Assuming occurrence time equals detection time.** The specification only guarantees the **detection time**; the actual occurrence may be earlier, especially for transient faults [TS 32.111‑1 §4.1.1].  
- **Treating all faults as ADAC.** Some faults are ADMC and must be cleared manually; neglecting this leads to stale alarms [TS 32.111‑1 §4.1.1].  
- **Ignoring standby components.** The fault detection mechanism applies to both active and standby parts of an NE [TS 32.111‑1 §4.1.1]; missing a standby alarm can hide redundancy failures.  
- **Overlooking the “no short‑term action” case.** A fault that disappears in the next sampling interval should not trigger escalation procedures [TS 32.111‑1 §4.1.1].  
- **Mismatched time zones.** Always store timestamps in UTC to avoid correlation errors across geographically dispersed NEs.

By consistently recording $t_{\text{det}}$, $t_{\text{clr}}$, and the fault nature, engineers can produce reliable event timelines that support rapid fault isolation and effective network management.  
[TS 32.111‑1 §4.1.1]

## 練習題

**1.** Which timestamp is explicitly required by the fault detection process for every reported fault?

- A. The time the fault was cleared.
- B. The time the fault was detected in the faulty network entity.
- C. The time the fault first occurred.
- D. The time the operator acknowledged the alarm.

<details><summary>看答案</summary>

正解：B。The specification states that the detection time must be supplied for each fault.

</details>

**2.** An ADMC fault differs from an ADAC fault because:

- A. It can be cleared automatically by the network entity.
- B. It never requires operator intervention.
- C. It lacks a defined clearing condition and needs manual intervention.
- D. It only affects standby components.

<details><summary>看答案</summary>

正解：C。ADMC faults have no clearing condition and must be cleared manually.

</details>

**3.** Which of the following statements about transient faults is correct?

- A. They always require immediate operator action.
- B. They are a type of ADMC fault.
- C. They disappear within a single sampling interval and need no short‑term action.
- D. Their detection time is recorded after the fault clears.

<details><summary>看答案</summary>

正解：C。The reference defines transient faults as lasting only one sampling interval with no short‑term action needed.

</details>

**4.** The fault detection mechanism must monitor which components of a network entity?

- A. Only active components.
- B. Only hardware components.
- C. Both active and standby components.
- D. Only software processes.

<details><summary>看答案</summary>

正解：C。The specification explicitly includes both active and standby components in fault detection.

</details>

**5.** When constructing an event timeline, the duration of an ADAC fault is calculated as:

- A. $t_{\text{det}} - t_{\text{occ}}$
- B. $t_{\text{clr}} - t_{\text{det}}$
- C. $t_{\text{det}} + t_{\text{clr}}$
- D. $t_{\text{occ}} / t_{\text{clr}}$

<details><summary>看答案</summary>

正解：B。For ADAC faults, the duration is the interval between detection and clearing timestamps.

</details>
