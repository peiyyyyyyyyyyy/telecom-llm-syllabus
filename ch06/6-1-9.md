# 6.1.9 軟體問題：版本、升級失敗

所屬：[6.1 根因的類型](6-1.md)

## 內文

#### 是什麼、什麼時候會用到

軟體問題（software problem）指軟體錯誤、資料庫不一致這一類非硬體造成的故障，TS 32.111-1 把它列為與硬體故障並列的一類（TS 32.111-1 V18.0.0 clause 4.1.0）。維運上最常見的情境是**升級前後**：軟體下載、安裝或啟用失敗；同一批網元升級後版本不一致；升級完成卻出現新告警或 KPI 下滑，需要決定是否回退（fallback）。客服端的徵兆則是升級維護窗口之後，特定站點或特定功能（例如某種業務）開始出現抱怨。判斷這類障礙的第一步，是確認「現在每台網元實際跑的是哪個版本」，以及「升級流程停在哪一步」。規格頁：[TS 32.532 FTP 目錄](https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)。

#### 怎麼做／怎麼判斷

1. **確認升級走到哪一步。** TS 32.532 把非自動化軟體管理拆成下載（downloadNESw，clause 5.7.1）、安裝（installNESw，選用，clause 5.8.1）、啟用（activateNESw，clause 5.7.2）。每個操作的 result 為 requestAccepted、requestFailed 或 notAllowedBecauseOfOngoingSwmActivity；規格特別註明啟用「may be service affecting」（clause 5.7.2.1）。
2. **讀狀態通知的列舉值，不要自己編。**
   - notifyDownloadNESwStatusChanged 的 downloadOperationStatus：NE_SWDOWNLOAD_SUCCESSFUL、NE_SWDOWNLOAD_FAILED、NE_SWDOWNLOAD_PARTIALLY_SUCCESSFUL，失敗項目可放在 failedSwInfo（clause 5.9.1.2）。
   - notifyInstallNESwStatusChanged 的 installOperationStatus：NE_SWINSTALLATION_SUCCESSFUL／FAILED／PARTIALLY_SUCCESSFUL（clause 5.10.1.2）。
   - notifyActivateNESwStatusChanged 帶 activateOperationStatus（NE_SWACTIVATION_SUCCESSFUL／FAILED／PARTIALLY_SUCCESSFUL）、swVersion（嘗試啟用的版本，不論成敗都填），以及在非成功時才出現的 failureReason（clause 5.9.2.2）。
3. **查實際版本。** ManagedElement 的 swVersion 為必備屬性（M），其支援資格為 isReadable T、isWritable F、isNotifyable T（TS 28.622 V18.14.0 clause 4.3.3.2、4.4.1）。效能資料檔的 measObjRootSwVersion 記錄量測根物件的軟體版本（TS 28.532 V18.8.0 clause 11.3.2.1.2），XML 格式中對應 measEntity 的 swVersion 屬性（clause 12.3.2.2）。比對升級前後的效能檔，就能看出版本在哪個量測週期改變。
4. **看告警裡的軟體線索。** 軟體類告警的 alarmType 為 PROCESSING_ERROR_ALARM，定義是主要與軟體或處理故障相關的告警（TS 28.111 V18.8.0 clause 6.3）。TS 28.111 Annex B 中與升級相關的 probableCause 有 Software Download Failure（156）、Version Mismatch（357）、Software Error（346）、Software Program Abnormally Terminated（347）、Corrupt Data（153）、Reinitialized（158）、Configuration or Customizing Error（307）。軟體故障的偵測資訊應包含受影響的軟體元件，例如損壞的檔案、資料庫或程式碼（TS 32.111-1 clause 4.1.1）。
5. **回退的兩條路。** NE 遇到軟體故障時，可自行採取的復原包括不同層級的系統初始化、啟用備份或回退軟體載入（TS 32.111-1 clause 4.1.6）。另一條是管理端主動發起：swFallback 操作由 IRPManager 啟動，輸出每個 NE 的 swFallbackStatus（fallbackSuccessful／fallbackUnsuccessful）與整體 result（Success、Partly successful、Failure）（TS 32.532 clause 5.3.7）。
6. **自癒的軟體錯誤看日誌。** 被 NE 以軟體重啟等方式自行修復的內部錯誤（如堆疊溢位、記憶體不足）不需要告警，但「should be recorded into the related logs」（TS 32.111-1 Annex A）。所以沒有告警不代表沒發生過軟體異常。

原文：[TS 32.532 V18.0.0](https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/32532-i00.zip)、[TS 28.532 V18.8.0](https://www.3gpp.org/ftp/Specs/archive/28_series/28.532/28532-i80.zip)。

#### 實際例子

虛構業者「乙電信」夜間升級三站，由 NR-24.2.1 升到 NR-24.3.0（站名、版本字串、數值均為虛構；通知欄位依 TS 32.532 clause 5.9）：

```
01:05  notifyDownloadNESwStatusChanged  GNB-M201/M202/M203
       downloadOperationStatus: NE_SWDOWNLOAD_SUCCESSFUL（三站）
01:18:44 notificationType: notifyActivateNESwStatusChanged
       objectInstance: SubNetwork=SouthX,ManagedElement=GNB-M202
       activateProcessId: 5512
       activateOperationStatus: NE_SWACTIVATION_FAILED
       swVersion: NR-24.3.0
       failureReason: post-activation health check timeout   # 廠商自訂字串
01:19:02 GNB-M201、GNB-M203  activateOperationStatus: NE_SWACTIVATION_SUCCESSFUL
01:25:10 告警  objectInstance: SubNetwork=SouthX,ManagedElement=GNB-M203
       alarmType: PROCESSING_ERROR_ALARM  probableCause: Version Mismatch
       specificProblem: RU firmware incompatible with baseband load   # 廠商自訂字串
02:00  讀取 swVersion：M201=NR-24.3.0、M202=NR-24.2.1、M203=NR-24.3.0
效能檔 01:30 週期 measEntity swVersion：M202=NR-24.2.1
```

判讀：第一，M202 的啟用通知明確為 FAILED，現行 swVersion 與 01:30 效能檔都仍是 NR-24.2.1，表示它停在舊版本運作，升級失敗但不一定有服務影響，需看 KPI 才知道。第二，M203 啟用通知是 SUCCESSFUL，但約 6 分鐘（6 分 8 秒）後出現 Version Mismatch，說明「啟用成功」不等於「整站版本相容」；三站版本也因此不一致（兩站新版、一站舊版）。第三，若 M203 的 KPI 同時下滑，可考慮對 M203 發起 swFallback，這是會影響服務的動作，要照 6.3.2 與第 9 章送批准。

不能下的結論：failureReason 是廠商自訂字串，不能據此判定是軟體包本身有缺陷；Version Mismatch 只說明有元件版本不相容，**哪個元件該升或降**要查廠商的相容性清單。參考：[TS 32.532 V18.0.0](https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/32532-i00.zip)。

#### 容易搞混的地方

- **通知成功 ≠ 服務正常**：activateOperationStatus 只回報啟用操作本身的結果，升級後仍要看告警與 KPI（[TS 28.111 FTP 目錄](https://www.3gpp.org/ftp/Specs/archive/28_series/28.111/)）。
- **requestAccepted 不是完成**：它只表示請求被接受，最後結果要等對應的 StatusChanged 通知（TS 32.532 clause 5.7.1.5）。
- **回退不一定都要人工**：NE 對軟體故障可自主啟用回退載入（TS 32.111-1 clause 4.1.6）；管理端發起的 swFallback 才是人為處置，要走批准流程。
- **不要自創欄位**：TS 32.532 與 TS 28.111 都沒有「升級批次號」「回退原因碼」這類欄位；廠商的額外資訊只會出現在 failureReason、specificProblem 或 additionalText 等欄位的內容裡。

#### 和其他小節的關係

版本變更是時間軸上最重要的「同時發生的變更」，排法見 5.5.1、6.2.1；升級、回退本身屬第 9 章異動流程，回退需 6.3.2 的批准。若升級後是單一板卡失效，改看 6.1.7；升級後參數被覆蓋則對照 6.1.6。過去升級案例的比對見 6.3.3。規格：[TS 32.111-1 FTP 目錄](https://www.3gpp.org/ftp/Specs/archive/32_series/32.111-1/)。

#### Locating the step where a non-automated upgrade stopped

**情境 001**　Overnight NASWM run on four gNBs

Fictional operator NorthLink Mobile upgrades four gNB managed elements from GX-7.2.4 to GX-7.3.0 using non-automated software management (NASWM). The IRPManager log below is complete up to 02:00:00.

00:10:04  downloadNESw                            KH-0421         downloadProcessId=8804     requestAccepted

**001.** At which point did the upgrade of KH-0418 stop?

1. The download was never started: the IRPAgent failed to initiate the download operation.
2. The download started but ended with NE_SWDOWNLOAD_FAILED.
3. The download was partially successful and the remaining entities were skipped.
4. The download was rejected because another software management activity was ongoing on KH-0418.

<details><summary>看答案</summary>

**答案**　1

**詳解**　For downloadNESw, result "requestFailed" means the IRPAgent has failed to initiate the NE software download operation, with the specific error in the reason field; no notifyDownloadNESwStatusChanged follows for 8803 in the log. Option 2 would require a status notification with NE_SWDOWNLOAD_FAILED, which does not exist for 8803. Option 3 is a notification status, not an operation result, and also needs a notification. Option 4 corresponds to the separate result value notAllowedBecauseOfOngoingSwmActivity, not requestFailed.

**出處**　3GPP TS 32.532 V18.0.0 clause 5.7.1.3 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**002.** For KH-0421, activateNESw was requested after a successful download but without any installNESw step. How should this be judged against TS 32.532?

1. It is a procedural error: activateNESw requires a preceding NE_SWINSTALLATION_SUCCESSFUL.
2. It is allowed only for automatic software management, not for NASWM.
3. Allowed: activation permits swAvailable or swInstalled; install is optional.
4. It is allowed only if the IRPAgent supports cancellation of NASWM operations.

<details><summary>看答案</summary>

**答案**　3

**詳解**　The pre-condition of activateNESw is "swAvailable or swInstalled", where swAvailable means the NE software has been successfully downloaded; installNESw is in SwMIRPOperations_4, which is optional for NASWM. Option 1 ignores the "or swAvailable" branch. Option 2 is wrong because downloadNESw/activateNESw are the NASWM operations themselves. Option 4 mixes in the condition for SwmOperations_6 (cancellation), which has nothing to do with the activation pre-condition.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.1, 5.7.2.4, 5.8 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**003.** What was the final result of the activation of GX-7.3.0 on KH-0421?

<details><summary>看答案</summary>

**答案**　Cannot be determined: the log only shows requestAccepted for activateProcessId 6602 and no notifyActivateNESwStatusChanged for 6602; that notification (or a progress query / a read of the current swVersion of KH-0421) is needed.

**詳解**　requestAccepted only means the IRPAgent would perform the activation (post-condition swActivationInProgress); the final state swActivated is reached only when the operation is complete and notifyActivateNESwStatusChanged has been generated. Nothing after 01:05:01 refers to 6602, so the outcome (successful, failed, partially successful, or still running) is unknown.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.7.2.3, 5.7.2.5, 5.9.2 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**004.** What does the status reported for KH-0415 at 00:58:02 mean according to the specification?

1. At least one of several software entities was not installed.
2. The software has not been installed.
3. Installation succeeded but activation is still pending.
4. The previously downloaded software was deleted from the NE.

<details><summary>看答案</summary>

**答案**　2

**詳解**　NE_SWINSTALLATION_FAILED leads to the state neSwInstallationFailed, defined as "Software has not been installed". Option 1 is the definition of neSwInstallationPartiallySuccessful. Option 3 would correspond to NE_SWINSTALLATION_SUCCESSFUL. Option 4 is the post-condition downloadedSWIsDeleted of cancelling a download with cancelNaswmProcesses, which is not in the log.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.10.1.2, 5.10.1.3.2, 5.12.1.5 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**005.** Why must an operator not record a NASWM step as "done" when the operation returns requestAccepted?

<details><summary>看答案</summary>

**答案**　Because requestAccepted only means the IRPAgent has accepted the request and will perform the operation; the step is complete only when the corresponding StatusChanged notification has been generated (for download, the final state swAvailable).

**詳解**　The post-conditions of downloadNESw distinguish swDownloadInProgress ("the SwMIRP has accepted the download request") from swAvailable ("the final state when downloadNESw operation is complete and notifyDownloadNESwStatusChanged has been generated"). activateNESw and installNESw are defined the same way with their own notifications.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.7.1.5, 5.7.2.5, 5.8.1.5 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**情境 003**　Activation attempted after a failed download

Change ticket CHG-55120 of fictional operator Telco-X, site PT-0307, single software package GX-8.0.1.

```
CHG-55120  ManagedElement=PT-0307  target GX-8.0.1
21:02  downloadNESw
         swToBeDownloaded: swLocation=sftp://swrepo.telco-x.example/gnb/GX-8.0.1.pkg
                           swFileSize=812345600
         -> downloadProcessId=4410  result=requestAccepted
21:29  notifyDownloadNESwStatusChanged  downloadProcessId=4410
         downloadOperationStatus=NE_SWDOWNLOAD_FAILED
         failedSwInfo: [GX-8.0.1.pkg, "checksum mismatch"]
21:35  activateNESw  swVersionToBeActivated=GX-8.0.1
         -> exception operationFailed (exit state: entry state)
21:40  installNESw  swTobeInstalled=GX-8.0.1
         -> exception swNotAvailable
21:44  engineer note: "PT-0307 still carrying traffic, no new alarms"
22:05  read ManagedElement=PT-0307 swVersion -> GX-7.9.3
```

**011.** Why did the activateNESw request at 21:35 raise operationFailed?

1. Activation may be service affecting, so the IRPAgent blocks it while the NE carries traffic.
2. Its pre-condition was false: GX-8.0.1 was neither successfully downloaded (swAvailable) nor installed (swInstalled).
3. Another SWM activity was still ongoing for PT-0307.
4. swVersionToBeActivated did not exactly match the swLocation string.

<details><summary>看答案</summary>

**答案**　2

**詳解**　operationFailed is raised when the pre-condition or post-condition is false; the pre-condition of activateNESw is swAvailable or swInstalled, and the 21:29 notification shows the download failed. Option 1 is wrong: "may be service affecting" is a note in the definition, not a blocking rule. Option 3 would give the result notAllowedBecauseOfOngoingSwmActivity, and the download had already ended at 21:29. Option 4 is invented: the spec defines no such string-matching rule.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.7.2.1, 5.7.2.4, 5.7.2.6 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**012.** When only one software entity has to be downloaded, which downloadOperationStatus values can the notification carry?

1. NE_SWDOWNLOAD_SUCCESSFUL, NE_SWDOWNLOAD_FAILED or NE_SWDOWNLOAD_PARTIALLY_SUCCESSFUL
2. NE_SWDOWNLOAD_SUCCESSFUL or NE_SWDOWNLOAD_PARTIALLY_SUCCESSFUL
3. requestAccepted or requestFailed
4. NE_SWDOWNLOAD_SUCCESSFUL or NE_SWDOWNLOAD_FAILED

<details><summary>看答案</summary>

**答案**　4

**詳解**　The note under downloadOperationStatus says that when only one software entity has to be downloaded, the status can be either NE_SWDOWNLOAD_SUCCESSFUL or NE_SWDOWNLOAD_FAILED; partial success "can be used only when multiple software need to be downloaded". Options 1 and 2 include partial success, which is not possible for one entity. Option 3 lists operation result values, not notification status values.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.9.1.2, 5.9.1.3.2 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**013.** What does "exit state: entry state" in the operationFailed exception tell the operator about the NE?

<details><summary>看答案</summary>

**答案**　The failed operation leaves the NE in the same state it was in before the request, i.e. nothing was activated or installed by that request.

**詳解**　All exceptions of activateNESw and installNESw (operationFailed, resourceLimitation, swNotAvailable) are specified with "Exit state: Entry state". In this ticket, that matches the 22:05 reading of the old version GX-7.9.3.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.7.2.6, 5.8.1.6 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**014.** Can the ticket conclude that the file GX-8.0.1.pkg in the repository is corrupt?

1. Yes: "checksum mismatch" in failedSwInfo proves that the repository file is corrupt.
2. Yes: NE_SWDOWNLOAD_FAILED is only reported when the source file is invalid.
3. No: the failure text points to the NE storage, so the NE should be replaced.
4. No; free text does not locate the fault. Verify checksum and retry.

<details><summary>看答案</summary>

**答案**　4

**詳解**　failedSwInfo carries the failed software and "the corresponding failure reason" without any standardized cause list, and the file transfer details are vendor specific and outside the scope of TS 32.532. Option 1 over-reads a vendor string. Option 2 is wrong: neSwDownloadFailed only means the software has not been downloaded, for any reason. Option 3 draws a hardware conclusion that nothing in the data supports.

**出處**　3GPP TS 32.532 V18.0.0 clauses 5.7.1.1, 5.9.1.2, 5.9.1.3.2 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

**015.** Which software version is PT-0307 running, and is that consistent with the ticket?

<details><summary>看答案</summary>

**答案**　GX-7.9.3; this is consistent, because the download of GX-8.0.1 failed and the later activation and installation requests were rejected with no change of state.

**詳解**　The 22:05 swVersion read gives GX-7.9.3. The chain 21:29 NE_SWDOWNLOAD_FAILED → 21:35 operationFailed → 21:40 swNotAvailable means GX-8.0.1 never became available on the NE, so the old load is still running, matching the note that the site still carries traffic.

**出處**　3GPP TS 28.622 V18.14.0 clauses 4.3.3.2, 4.4.1 (https://www.3gpp.org/ftp/Specs/archive/28_series/28.622/); 3GPP TS 32.532 V18.0.0 clauses 5.7.2.6, 5.8.1.6 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>

#### Reading download and install status notifications

**105.** Besides normal process deletion, in which case shall the IRPAgent send notifySwMProcessDeletion?

<details><summary>看答案</summary>

**答案**　When the process is terminated because of an exception, for example when the IRPAgent terminates it because it had to wait too long after a suspend.

**詳解**　Clause 5.5.5.1: "IRPAgent shall also send out this notification in case of a process termination caused by an exception, for example IRP Agent terminates the process because it had to wait too long after a suspend operation." This is what lets the IRPManager see the RG-1201 timeout.

**出處**　3GPP TS 32.532 V18.0.0 clause 5.5.5.1 (https://www.3gpp.org/ftp/Specs/archive/32_series/32.532/)

</details>
