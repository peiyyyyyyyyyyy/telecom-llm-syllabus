# 6.3.3 對照過去案例

所屬：[6.3 處置](../6-3.md)

## 正文

When a set of correlated alarms appears, the network operator must quickly pinpoint the underlying fault that triggers the cascade. 3GPP TS 32.111‑1 §4.1.9 defines **Root Cause Analysis (RCA)** as the process that “can determine and identify the network condition (e.g., fault, mis‑configuration) causing the alarms” [TS 32.111‑1 §4.1.9].  One of the most reliable sources of information for RCA is the collection of **past cases** that have been solved previously. By matching the current alarm pattern to historical patterns, engineers can leverage “Operators' network management experience” to accelerate identification of the **Root Cause Alarm** [TS 32.111‑1 §4.1.9].

### Key inputs for case‑based RCA
The specification lists five example inputs that may be used in RCA:

* **Alarm information** – identifiers, severity, timestamps, and textual description carried in each alarm.  
* **Correlated alarm sets** – groups of alarms that have been linked by the OSS as belonging to the same incident.  
* **Network notifications** – asynchronous messages from network elements (e.g., fault‑induced resets).  
* **Network configuration information** – current parameter values that may explain abnormal behavior.  
* **Operators' network management experience** – knowledge accumulated from previous fault‑handling cases [TS 32.111‑1 §4.1.9].

When an engineer performs a **case‑based comparison**, the historical inputs are treated as a reference set $H$ that is searched for similarity with the current inputs $I$. A simple abstract representation is  

$$
R = f(I, H) \quad\text{where}\quad
\begin{cases}
I = \{A, C, N, Conf\}\\
H = \{ \text{past alarm patterns},\ \text{recorded root causes} \}
\end{cases}
$$

* $A$ – information carried in alarm(s)  
* $C$ – information carried in correlated alarm sets  
* $N$ – information carried in network notifications  
* $Conf$ – network configuration information  

The function $f(\cdot)$ embodies the analyst’s reasoning, which is guided by the five inputs above and by the “Operators' network management experience” [TS 32.111‑1 §4.1.9].

### Worked example
Consider a LTE eNodeB that reports three alarms within a 30‑second window:

| Alarm ID | Severity | Timestamp (s) | Description |
|----------|----------|---------------|-------------|
| 101      | Major    | 10            | “RRC connection failure” |
| 102      | Major    | 22            | “UL interference detected” |
| 103      | Minor    | 28            | “PDCP discard count high” |

The OSS correlates these into a set $C = \{101,102,103\}$. The engineer queries the case‑history database and finds a past incident (Case #57) with the same three‑alarm pattern, recorded root cause: **faulty RF front‑end module**. The historical case also contains configuration data showing that the RF module version $v_{3.2}$ had a known firmware bug.

Using the inputs:

* $A$ = alarm descriptions above  
* $C$ = correlated set $\{101,102,103\}$  
* $N$ = no additional network notifications in this interval  
* $Conf$ = current RF module version $v_{3.2}$  

The similarity function $f$ matches $I$ to $H_{57}$ and returns the root cause alarm “RF front‑end fault”. The engineer therefore recommends replacing the RF module, which is a **pre‑approved** action (outside the scope of this subsection). The comparison with the past case reduced diagnostic time from an estimated 2 hours to 15 minutes.

### Practical notes and common mistakes

| Mistake | Why it matters |
|---------|----------------|
| Ignoring correlated alarm sets | The specification stresses that “information carried in correlated alarm sets” is a core input; overlooking it discards valuable context [TS 32.111‑1 §4.1.9]. |
| Relying on a single past case without checking configuration differences | Network configuration may have changed; the same alarm pattern can have a different root cause if $Conf$ differs. |
| Assuming the most recent case is always the best match | Operators’ experience includes older cases that may be more relevant; a blind “most recent” rule can mislead. |
| Not documenting the comparison outcome | Future engineers lose the benefit of the experience; the reference text highlights the importance of “Operators' network management experience”. |
| Over‑generalizing a root cause to unrelated alarms | RCA is specific to the current set $I$; applying a root cause from a dissimilar alarm set violates the principle that RCA “identifies the network condition causing the alarms”. |

When performing case‑based RCA, always verify that the historical pattern aligns on **all five** inputs listed in the specification. This disciplined approach ensures that the identified Root Cause Alarm is truly representative of the present fault condition.

## 練習題

**1.** Which of the following is *explicitly* listed in TS 32.111‑1 §4.1.9 as an input that may be used for Root Cause Analysis?

- A. Vendor warranty records
- B. Information carried in alarm(s)
- C. Customer satisfaction surveys
- D. Power consumption logs

<details><summary>看答案</summary>

正解：B。The specification enumerates alarm information as one of the example inputs for RCA.

</details>

**2.** In the worked example, which element of the current inputs was *not* present?

- A. Network notifications
- B. Alarm severity
- C. Correlated alarm set
- D. RF module version

<details><summary>看答案</summary>

正解：A。The example states “no additional network notifications in this interval.”

</details>

**3.** Which of the following best describes the role of “Operators' network management experience” in case‑based RCA?

- A. It provides a formal algorithm for alarm correlation.
- B. It supplies historical patterns that can be matched to current alarms.
- C. It defines the physical layer modulation scheme.
- D. It determines the licensing fees for network equipment.

<details><summary>看答案</summary>

正解：B。The specification lists operator experience as a source of knowledge for identifying root causes.

</details>

**4.** According to the reference, what is the ultimate output of a Root Cause Analysis?

- A. A list of all alarms generated in the last hour.
- B. The identification and indication of the Root Cause Alarm.
- C. A new network configuration file.
- D. A performance benchmark report.

<details><summary>看答案</summary>

正解：B。The definition states that RCA “identify and indicate the Root Cause Alarm.”

</details>

**5.** When comparing a current alarm set to past cases, which of the following must *also* be verified to avoid mis‑diagnosis?

- A. That the vendor’s warranty is still valid.
- B. That the network configuration information matches.
- C. That the customer’s billing cycle is unchanged.
- D. That the physical location of the base station is the same.

<details><summary>看答案</summary>

正解：B。The specification includes network configuration information as a key input; mismatched configuration can invalidate a case match.

</details>
