# 6.1.6 參數設定錯誤：下傾角、功率、鄰區、PCI、換手參數

所屬：[6.1 根因的類型](../6-1.md)

## 正文

In a live 4G/5G network the radio access node (RAN) is configured with a set of physical and logical parameters that directly shape the radio environment. Errors in these parameters—such as an inappropriate antenna down‑tilt, transmit power that is too low or too high, mismatched neighbour‑cell lists, wrong Physical Cell Identity (PCI) allocation, or hand‑over thresholds that do not reflect the actual radio conditions—can manifest as coverage holes, excessive interference, or frequent hand‑over failures. Because the user‑experience (QoE) is tightly coupled to the received signal quality (RSRP, SINR) and to the success of mobility procedures, even a modest deviation from the optimal setting can degrade throughput, increase call drops, or cause UE‑initiated re‑tries.  

The 3GPP specifications explicitly tie the analysis of such problems to the *coverage* capability of the MDA (Measurement Data Analysis) functions. A Radio Environment Map (REM) may be built from observed UE measurements **and** from the radio configuration parameters of the cells, *including transmit powers, antenna gains, antenna tilts, etc.* [TS 28.104 §7.2.1.1.3]. When a coverage problem is identified, the MDA is also expected to suggest remedial actions such as “reconfigure … antennas, …” [TS 28.104 §7.2.1.1.3].

### Key parameters that are often mis‑set

| Parameter | Typical impact on coverage / mobility | Reference |
|-----------|----------------------------------------|-----------|
| **Antenna down‑tilt** | Controls the vertical beam direction; excessive downtilt reduces far‑field coverage, insufficient downtilt may increase inter‑cell interference. | [TS 28.104 §7.2.1.1.3] |
| **Transmit power** | Directly influences RSRP; too low power creates weak coverage, too high power can cause pilot pollution and hand‑over ping‑pong. | [TS 28.104 §7.2.1.1.3] |
| **Neighbour‑cell list** | Determines which cells are considered for hand‑over; an incomplete list can cause “no suitable target” failures, an over‑inclusive list can trigger unnecessary hand‑overs. | [TS 28.627 §5.4.1] |
| **PCI (Physical Cell Identity)** | Must be unique within a certain modulo‑30 range to avoid confusion at the UE; collisions lead to “PCI mod‑30 conflict” (outside the scope of the supplied references). | *outside scope* |
| **Handover thresholds (e.g., A3 offset, time‑to‑trigger)** | Define when a UE should consider a neighbour cell; wrong values cause early or late hand‑overs, increasing RRC failures (outside the scope of the supplied references). | *outside scope* |

### How the MDA uses these parameters

The MDA correlates performance measurements (e.g., RSRP, SINR, hand‑over success rate) with the *configuration data* of the affected cells. By overlaying the measurements on a REM, it can pinpoint that a particular sector shows RSRP values below the acceptable threshold only in the far‑field region. The underlying cause is often traced to an **excessive down‑tilt** or **insufficient transmit power**.  

If the analysis confirms a parameter‑setting error, the MDA may generate a **remedy recommendation** such as “reduce antenna tilt by 2°” or “increase transmit power by 2 dB” [TS 28.104 §7.2.1.1.3]. In NR, the NG‑RAN node can also be pre‑configured with **alternative coverage configurations** that define permissible ranges for each parameter, allowing the node to autonomously adjust within those bounds [TS 38.300 §15.5.5.2]. When such a change is performed, the node notifies its neighbours via the **NG‑RAN NODE CONFIGURATION UPDATE** message, including a *coverage state indicator* that the receiving node can use to adapt its own mobility robustness optimisation [TS 38.300 §15.5.5.3].

### Worked example (illustrative)

Consider a macro cell “Cell‑A” that serves an urban district. The operator has provisioned the following initial settings:

* Transmit power (P<sub>tx</sub>) = 46 dBm  
* Antenna down‑tilt = 6° (mechanical + electrical)  

After launch, the REM shows a **coverage hole** on the western edge of the cell, where the measured RSRP is –92 dBm, well below the –85 dBm target. The MDA correlates the hole with the high down‑tilt and suggests reducing the tilt by 2°.  

The operator applies the new tilt (4°) and re‑runs the measurement campaign. The REM now displays RSRP ≈ –84 dBm in the previously weak area, satisfying the target. The MDA also records the change as a **remedial action** that could be stored as an *alternative coverage configuration* for future autonomous adjustments [TS 28.104 §7.2.1.1.3; TS 38.300 §15.5.5.2].

### Practical notes and common mistakes

1. **Changing only one parameter** – Adjusting transmit power without revisiting the neighbour‑cell list may introduce pilot pollution in the overlapping area, triggering unnecessary hand‑overs (see load‑balancing scenarios).  
2. **Neglecting the neighbour‑cell relationship** – The load‑balancing concepts of *overlapping*, *hierarchical*, and *neighbouring* coverage describe when UE‑centric balancing is applicable; ignoring these can lead to sub‑optimal hand‑over decisions [TS 28.627 §5.4.1].  
3. **Relying on static configurations** – Modern NR nodes can switch between *alternative coverage configurations* autonomously; static settings lock the network into a possibly sub‑optimal state [TS 38.300 §15.5.5.2].  
4. **Assuming PCI is always correct** – PCI conflicts are a known source of hand‑over failures, but the current reference set does not detail them; a separate analysis is required.  
5. **Forgetting the coverage state indicator** – When a node changes its coverage configuration, it must include the indicator in the NG‑RAN NODE CONFIGURATION UPDATE; otherwise neighbour nodes may continue to trigger hand‑overs toward a cell that has become inactive, leading to connection failures [TS 38.300 §15.5.5.3].

By systematically analysing the REM, cross‑checking the configuration parameters, and employing the automated optimisation loops defined in the 3GPP specifications, engineers can quickly detect and correct parameter‑setting errors, thereby restoring the intended coverage and mobility performance.

## 練習題

**1.** Which radio configuration parameters are explicitly mentioned as inputs for constructing a Radio Environment Map?

- A. Sub‑carrier spacing and numerology
- B. Transmit powers, antenna gains, antenna tilts
- C. Scheduling algorithms and buffer sizes
- D. Core network latency

<details><summary>看答案</summary>

正解：B。The reference states that the REM may be built from parameters including transmit powers, antenna gains, and antenna tilts.

</details>

**2.** What is the purpose of the coverage state indicator sent in an NG‑RAN NODE CONFIGURATION UPDATE message?

- A. To request additional spectrum from the regulator
- B. To adjust the functions of Mobility Robustness Optimisation in the receiving node
- C. To reset the UE's security context
- D. To trigger a network‑wide reboot

<details><summary>看答案</summary>

正解：B。The coverage state indicator allows the neighbour node to adapt its mobility robustness optimisation based on the new coverage configuration.

</details>

**3.** In the load‑balancing scenarios defined by 3GPP, which description matches the “Overlapping Coverage” case?

- A. Two cells of different sizes where the smaller is fully contained in the larger
- B. Two same‑size cells covering the same area
- C. Two cells with no common area but sharing the same PCI
- D. Two cells where only one serves UE traffic at a time

<details><summary>看答案</summary>

正解：B。Overlapping Coverage is defined as two same‑size cells that both cover the same area.

</details>
