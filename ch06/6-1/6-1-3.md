# 6.1.3 換手與鄰區問題：鄰區較強、頻繁換手、過早／過晚換手

所屬：[6.1 根因的類型](../6-1.md)

## 正文

In a mobile network a UE constantly moves between the radio coverage of different cells. The handover (or “handoff”) procedure transfers the radio connection from a serving cell to a neighbour cell without interrupting user data. When handover decisions are sub‑optimal, the network experiences **frequent handovers**, **premature (early) handovers**, or **delayed (late) handovers**. These symptoms manifest as RRC connection failures, random‑access problems, or degraded QoE, and are explicitly listed among the RAN coverage‑related problems that can cause handover failures [TS 28.104 §7.2.1.1].  

### Key definitions

- **Neighbour cell** – a cell that appears in the UE’s measurement list and is a candidate for handover.  
- **Strong neighbour** – a neighbour whose received signal power (e.g., RSRP) is higher than that of the serving cell in the UE’s current location.  
- **Frequent handover** – a succession of handovers occurring in a short time interval, often caused by oscillating measurements between a serving cell and a strong neighbour.  
- **Early handover** – a handover triggered before the serving cell’s signal has degraded below a safe margin, leading to unnecessary radio link changes.  
- **Late handover** – a handover that is delayed until the serving cell’s signal is already poor, increasing the risk of radio link failure.  

The 3GPP specifications do not prescribe a single numeric threshold for these events; instead they define **coverage and capacity optimisation (CCO)** functions that monitor measurement trends and adjust radio parameters to avoid the above situations [TS 28.627 §5.1.5] and **Mobility Robustness Optimisation (MRO)** that can use a *coverage state indicator* to influence handover timing [TS 38.300 §15.5.5.3].

### How neighbour‑cell interactions lead to handover problems

1. **Neighbour stronger than serving cell** – When the UE enters an area where a neighbour’s RSRP exceeds that of the serving cell, the handover algorithm may decide to switch. If the coverage overlap is narrow, the UE may quickly re‑enter the original cell’s area, causing *ping‑pong* handovers (a typical form of frequent handover).  

2. **Frequent handover** – Repeated toggling between two cells is often observed in **overlapping coverage** scenarios (identical‑size cells) or **hierarchical coverage** (small cell fully inside a larger cell) [TS 28.627 §5.4.1]. Load‑balancing mechanisms can deliberately trigger handovers in such overlaps, but if the algorithm is too aggressive, the UE experiences unnecessary handovers.  

3. **Early handover** – If the handover criteria (e.g., RSRP difference) are set with a very small margin, the UE may be handed over while the serving cell still provides adequate quality. This wastes signalling resources and can increase the probability of a subsequent handover when the UE moves further.  

4. **Late handover** – Conversely, a large margin postpones the handover until the serving cell’s signal is already weak, raising the likelihood of a Radio Link Failure (RLF) before the target cell can be reached.  

### Role of dynamic coverage configuration

NR nodes can store **alternative coverage configurations** that include permissible ranges for radio parameters [TS 38.300 §15.5.5.2]. An NG‑RAN node may autonomously switch between these configurations and **notify neighbour nodes** using the **NG‑RAN NODE CONFIGURATION UPDATE** message, which carries a *coverage state indicator* [TS 38.300 §15.5.5.3]. Receiving nodes can then adapt their MRO logic, for example by suppressing handovers toward cells that are currently marked inactive, thereby mitigating premature handovers.  

### Worked example (qualitative)

Consider a macro cell **A** and a small‑cell **B** that overlap in a suburban area. UE X measures:

- **Cell A** RSRP = –85 dBm  
- **Cell B** RSRP = –78 dBm  

Because **Cell B** is stronger, the handover algorithm decides to switch UE X to **B**. Shortly after, UE X moves back into the region where **A** regains dominance (RSRP = –80 dBm, **B** = –88 dBm). If the handover margin is set too low, the UE will immediately hand back to **A**, creating a *ping‑pong* situation (frequent handover). By adjusting the handover margin (or by applying a coverage state indicator that temporarily suppresses handovers to **B** while **A** is still adequate), the network can avoid the unnecessary handover cycle.  

### Common mistakes and practical notes

| Mistake | Why it hurts | Remedy (per spec) |
|---|---|---|
| **Ignoring neighbour‑cell strength** | Leads to early handovers when a neighbour is only marginally stronger. | Use CCO functions to analyse neighbour RSRP trends and set appropriate margins [TS 28.627 §5.1.5]. |
| **Over‑aggressive load balancing** in overlapping coverage | Triggers frequent handovers even when traffic load is acceptable. | Apply load‑balancing policies only when UE is in the *overlapping* or *neighbouring* area, as defined in load‑balancing scenarios [TS 28.627 §5.4.1]. |
| **Not signalling coverage changes** | Neighboring nodes keep stale handover parameters, causing late handovers after a cell reduces power. | Send NG‑RAN NODE CONFIGURATION UPDATE with coverage state indicator [TS 38.300 §15.5.5.3]. |
| **Static handover thresholds** | Cannot adapt to dynamic environment (e.g., temporary interference). | Deploy dynamic coverage configuration that can be autonomously adjusted [TS 38.300 §15.5.5.2]. |
| **Assuming a single “best” neighbour** | In hierarchical coverage, the smaller cell may be unsuitable for certain UEs (e.g., high‑speed). | Consider UE speed and service type in handover decision logic (outside the strict scope of the cited references). |

By continuously correlating measurement data, MDT reports, and radio environment maps [TS 28.104 §7.2.1.1], operators can detect the patterns that indicate strong neighbours, frequent handovers, or mistimed handovers, and then apply the optimisation mechanisms prescribed in the standards to restore stable mobility.

## 練習題

**1.** Which of the following is listed as a possible RAN coverage problem that can cause handover failures?

- A. Weak coverage only
- B. Coverage holes only
- C. Pilot pollution only
- D. All of the above

<details><summary>看答案</summary>

正解：D。The specification lists weak coverage, coverage holes, pilot pollution, overshoot coverage, and DL/UL mismatch as coverage problems that may affect handover.

</details>

**2.** In the load‑balancing taxonomy, which scenario describes the usual neighbour‑cell situation where two cells share some overlapped area?

- A. Overlapping Coverage
- B. Hierarchical Coverage
- C. Neighbouring Coverage
- D. Isolated Coverage

<details><summary>看答案</summary>

正解：C。The neighbour‑cell scenario is defined as “Neighbouring Coverage” where two neighbour cells have overlapped area.

</details>

**3.** Which NG‑RAN message is used to inform neighbour nodes about a change in coverage configuration that may affect mobility robustness optimisation?

- A. HANDOVER REQUEST
- B. NG‑RAN NODE CONFIGURATION UPDATE
- C. RADIO RESOURCE CONTROL SETUP
- D. X2 HANDOVER NOTIFICATION

<details><summary>看答案</summary>

正解：B。The specification states that an NG‑RAN node notifies neighbours with the NG‑RAN NODE CONFIGURATION UPDATE message when coverage changes occur.

</details>

**4.** The coverage state indicator sent in the NG‑RAN NODE CONFIGURATION UPDATE can be used by the receiving node to adjust which function?

- A. Radio Resource Management
- B. Mobility Robustness Optimisation
- C. Scheduling Policy
- D. Core Network Authentication

<details><summary>看答案</summary>

正解：B。The coverage state indicator is explicitly mentioned as a means to adjust the Mobility Robustness Optimisation function.

</details>

**5.** According to TS 28.627, which of the following is **not** one of the scenarios considered in coverage and capacity optimisation?

- A. E‑UTRAN cells with too large coverage
- B. E‑UTRAN coverage holes with 2G/3G coverage
- C. E‑UTRAN coverage holes without any other radio coverage
- D. LTE downlink overload due to excessive traffic

<details><summary>看答案</summary>

正解：D。The listed scenarios in the specification do not include “LTE downlink overload due to excessive traffic”.

</details>
