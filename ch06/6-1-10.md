# 6.1.10 上下行涵蓋不平衡

所屬：[6.1 根因的類型](6-1.md)

## 內文

#### 是什麼、什麼時候會用到

上下行涵蓋不平衡是指同一個小區的下行（基地台到終端）與上行（終端到基地台）能到達的範圍不一樣。最常見的是**上行受限**：基地台發射功率遠大於手機，手機在小區邊緣仍收得到可用的下行訊號，但手機已用到最大發射功率，上行到達基地台時 SINR 仍不足。TS 37.320 V18.5.0 Annex A 把 UL coverage 列為涵蓋問題的一種，指出上行涵蓋差會造成建立通話失敗、掉話、上行語音品質差，上下行涵蓋應該取得平衡（[TS 37.320](https://www.3gpp.org/ftp/Specs/archive/37_series/37.320/37320-i50.zip)）。常見情境：客訴「下載正常、上傳很慢」「我聽得到對方，對方聽不到我」；郊區小區邊緣掉話；下行 RSRP 還可以，上行速率卻很差。

#### 怎麼做／怎麼判斷

**1. 終端最大功率有上限（TS 38.101-1 V18.15.0，[TS 38.101-1](https://www.3gpp.org/ftp/Specs/archive/38_series/38.101-1/38101-1-if0.zip)）。** Table 6.2.1-1 定義 UE 功率等級：Class 3 是 23 dBm，原文註明 power class 3 是預設功率等級（NOTE 2）；部分頻段另有 Class 2（26 dBm）、Class 1.5（29 dBm）、Class 1（31 dBm，例如 n77、n78），並註明 PC1 一般不以智慧型手機為目標。實際上限是組態最大輸出功率 PCMAX,f,c，其上界 PCMAX_H,f,c＝MIN{PEMAX,c, PPowerClass − ΔPPowerClass + ΔPPowerBoost}，PEMAX,c 來自 p-Max（clause 6.2.4）。同一條款也規定：power class 2 的 UE 在網路指示 P-max 為 23 dBm 以下，或上行符號比例超過 50%（且未回報相關 duty cycle 能力）等條件下，ΔPPowerClass＝3 dB，也就是退回 23 dBm。

**2. 上行功率控制（TS 38.213 V18.9.0 clause 7.1.1，[TS 38.213](https://www.3gpp.org/ftp/Specs/archive/38_series/38.213/38213-i90.zip)）。** PUSCH 發射功率為

```
PPUSCH = min{ PCMAX ,  PO_PUSCH(j) + 10·log10(2^μ · MRB) + α(j)·PL + ΔTF + f(i,l) }   [dBm]
```

PL 是終端估算的下行路徑損耗，PL＝referenceSignalPower − higher layer filtered RSRP，referenceSignalPower 由 ss-PBCH-BlockPower 等參數提供（clause 7.1.1）。這個式子說明三件事：路徑損耗越大，需要的功率越高；分到的 RB 數 MRB 越多，需要的功率也越高；一旦需求超過 PCMAX，終端只能送 PCMAX，路徑損耗再增加，基地台收到的上行 SINR 就直接下降。

**3. 功率餘裕（power headroom）是最直接的證據。** Type 1 PH＝PCMAX −（上式大括號內的需求功率）（TS 38.213 V18.9.0 clause 7.7.1）；PH 為負，代表終端需要的功率已超過上限。TS 28.552 V18.12.0 clause 5.1.1.26.1 的 Type 1 power headroom distribution（`L1M.PHR1.BinX`，範圍 −32～+38 dB）可看整個小區的分布；Immediate MDT 的 M2 也是 UE 的 Power Headroom 量測（TS 37.320 V18.5.0 clause 5.4.1.1）。

**4. 判斷步驟。**

1. 下行先看：SS-RSRP、SS-SINR 分布正常或只是偏弱。
2. 上行再看：PH 分布負值比例偏高、`CARR.PUSCHMCSDist` 偏向低 MCS（TS 28.552 clause 5.1.1.12.2）、上行速率 `DRB.UEThpUl`（clause 5.1.1.3.3）偏低。
3. 排除上行干擾：上行雜訊底（多為設備商自訂計數器，名稱以設備文件為準）正常，而且近處 UE 的 PH 為正、上行正常 → 上行受限；若連近處 UE 都受影響、雜訊底升高 → 轉 6.1.2。
4. 影響評估：上行受限除了上傳慢，也會讓上行控制資訊（HARQ 回覆、CSI 回報）不可靠，進而拖累下行與通話建立。

#### 實際例子

甲電信（虛構）郊區 n78 小區，SCS 30 kHz，終端多為 power class 3。組態與數值全為虛構；「PH<0 比例」「MCS≤4 比例」是業者報表欄位（虛構）：

```
組態摘錄：p-Max 23；p0-NominalWithGrant -90；alpha alpha08；ss-PBCH-BlockPower 18
統計：2026-11-20 19:00-23:00
量測                         NRC-R710-1      NRC-R712-1（對照）
SS-RSRP<-110dBm 比例         8%              7%
SS-SINR<0dB 比例             10%             9%
L1M.PHR1 PH<0dB 樣本比例     34%             6%
CARR.PUSCHMCSDist MCS<=4     41%             9%
DRB.UEThpUl (kbit/s)         1800            9500
DRB.UEThpDl (kbit/s)         48000           51000
上行雜訊底（設備商計數器）   -113 dBm/PRB    -114 dBm/PRB
客訴：視訊通話對方畫面卡住、上傳照片失敗；下載正常
```

逐步判斷：

1. 下行兩個小區差不多，R710-1 的下行速率也正常，下行沒有明顯問題。
2. R710-1 有 34% 的 PH 樣本為負、41% 的 PUSCH 排在低 MCS，上行速率只有對照小區的約 1/5，符合上行受限。
3. 雜訊底和對照小區相近，約等於熱雜訊每 PRB 約 −118.4 dBm（360 kHz）加上數 dB 接收機雜訊指數的正常水準，沒有上行干擾的跡象。
4. 算例（套 TS 38.213 V18.9.0 clause 7.1.1 的式子，[TS 38.213](https://www.3gpp.org/ftp/Specs/archive/38_series/38.213/38213-i90.zip)；假設 PCMAX＝23 dBm、ΔTF＝0、f＝0，PO_PUSCH 只計 nominal 值）：下行 RSRP −107 dBm 時，PL＝18 −（−107）＝125 dB。排 10 個 RB：−90 + 10·log10(20) + 0.8×125 ≈ 23.0 dBm，剛好用滿，PH ≈ 0 dB。排 50 個 RB：−90 + 20 + 100＝30 dBm，PH ≈ −7 dB，終端只能送 23 dBm。也就是說，RSRP −107 dBm 在下行還能用，上行已經沒有餘裕，只能減少 RB，上行速率因此受限。
5. **不能下的結論**：這些數據無法區分「站距太大」與「天線或接收路徑劣化」，要再查接收通道告警與組態（6.1.6、6.1.7）；PH 分布也不能指出受影響 UE 的位置，需要 MDT 補收。

#### 容易搞混的地方

1. **只看下行指標會漏掉上行受限。** SS-RSRP、SS-SINR 都是 UE 量的下行量（TS 38.215 V18.4.0 clause 5.1.1、5.1.5，[TS 38.215](https://www.3gpp.org/ftp/Specs/archive/38_series/38.215/38215-i40.zip)），下行正常不代表上行正常。
2. **上行受限不等於上行干擾。** 受限是 UE 功率不夠，PH 負、雜訊底正常；干擾是雜訊底升高，連 PH 充足的近處 UE 也受影響。
3. **功率等級高不保證一直用得到。** Power class 2 終端在 P-max 指示 23 dBm 以下或上行比例高時會退回 23 dBm（TS 38.101-1 clause 6.2.4）。
4. **PH 是 UE 依公式回報的計算值，不是基地台量到的功率。** 它反映的是「還差多少」，要搭配上行 MCS 與速率一起看。

#### 和其他小節的關係

上下行鏈路預算比較見第 3 章 3.3.6。下行涵蓋不足見 6.1.1，上行干擾見 6.1.2，上行慢也可能是容量（6.1.4）。功率與天線設定錯誤見 6.1.6，接收通道故障見 6.1.7。MDT 補收見 6.2.3，量測讀法見 5.1.5、5.1.7；調整功率控制參數屬於 6.3.2 需要批准的處置，走第 9 章異動流程。功率控制依據見 [TS 38.213](https://www.3gpp.org/ftp/Specs/archive/38_series/38.213/38213-i90.zip)。
