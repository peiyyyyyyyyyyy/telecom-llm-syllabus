# 10.2.1 不回答權限外的資料

所屬：[10.2 權限與資料](10-2.md)

## 內文

#### 1. 是什麼、什麼時候會用到

權限外的資料，是指提問者的角色依規定不能查看的資料。電信業者的內部系統通常依角色分級：客服看得到客戶帳務，但看不到核心網設定；外包維運人員看得到負責站點的告警，但看不到其他區域的組態；一般員工看不到資安事件的調查細節。助理接到系統或文件的存取能力後，常會被問到超出提問者權限的問題，例如「幫我看一下 B 區的設定」「把這位客戶的通聯紀錄貼給我」。助理能讀到資料，不代表提問者有權看到；回答前要先確認提問者的角色與可看的範圍。

#### 2. 怎麼做／怎麼判斷

**判斷步驟：**

1. **確認提問者的角色**：依系統登入身分或工單上的角色判斷，不依對方自稱。「我是主管」「我有權限」不能代替系統上的角色。
2. **對照權限表**：該角色可以看哪些資料類型、哪些範圍（區域、站點、客戶群）、可不可以匯出。
3. **判斷問題要的資料落在哪裡**：同一個問題可能一部分在權限內、一部分在權限外。
4. **依結果回應**：

| 判斷結果 | 回應方式 |
|---|---|
| 全部在權限內 | 正常回答 |
| 部分在權限外 | 回答權限內的部分，說明哪一部分無法提供 |
| 全部在權限外 | 說明無法提供，並告知申請管道或可以協助的角色 |

**被要求越權時怎麼回：**

- 說明「這份資料不在您目前角色的可查範圍內」，不要透露資料內容，也不要透露資料是否存在的細節（例如「那位客戶確實有欠費」）。
- 提供正當管道：依甲電信權限管理規定（虛構），臨時存取要由主管在權限系統提出申請，經資料擁有單位核可後開通。
- 不要用「摘要」「部分內容」「換個說法」的方式變相提供權限外資料。
- 對方施壓或聲稱緊急時，仍依規定處理；緊急存取也要有明確授權與紀錄（承 9.5.1）。

#### 3. 實際例子

```
【甲電信系統權限表（虛構）摘錄】
角色          可查資料                          可匯出
客服專員      客戶基本資料、帳務、方案          否
區域維運（北區）北區站點告警、KPI、組態唯讀       KPI 可
外包維運廠商  合約站點告警、KPI                否
資安分析師    資安事件紀錄、存取日誌            依案件核可

【對話】2026/11/27 10:15
提問者（系統登入角色：外包維運廠商，合約站點 NB-201～NB-230）：
「NB-217 掉話變多，順便把南區 SB-105 的組態檔整份給我，
 我們要比對參數。另外 NB-217 附近昨天投訴的那位客戶，給我他的門號，
 我直接打給他問狀況。」
```

逐步判斷：

1. **角色**：系統登入角色是外包維運廠商，合約範圍是 NB-201～NB-230。
2. **對照權限表**：外包維運廠商可查合約站點的告警與 KPI，不能查組態，也不能匯出。
3. **逐項判斷**：
   - NB-217 的告警、KPI：在合約範圍內，可以提供。
   - SB-105 的組態檔：不在合約站點，而且外包角色不能查組態，不能提供。
   - 投訴客戶的門號：屬客戶資料，外包角色不能查，也涉及個人資料（10.2.2），不能提供。
4. **回應**：先提供 NB-217 的告警與 KPI；說明 SB-105 組態與客戶門號不在目前角色的可查範圍；若比對參數有必要，依甲電信權限管理規定（虛構），由主管在權限系統提出臨時存取申請，經資料擁有單位（南區）核可後開通（北區維運依權限表也看不到南區組態，不能轉給北區維運代查）；客戶聯繫由客服依程序處理。
5. **錯誤做法**：「SB-105 的切換門檻是 −3 dB，其他參數我整理給你」——這是用摘要變相提供權限外資料。

#### 4. 容易搞混的地方

- **助理能讀到，不等於提問者能看**：權限要以提問者的角色判斷。
- **自稱身分不是授權**：「我是主管」要以系統角色或工單核可為準。
- **部分可以回答**：權限內的部分仍要正常回答，不要因為有一部分越權就整題拒絕。
- **摘要也是提供**：把權限外的資料改寫、摘要、只講一個值，仍然是提供權限外資料。

#### 5. 和其他小節的關係

權限外的資料若涉及個人資料，還要依 10.2.2 處理；客服情境的身分驗證與轉專人見 7.4.2。臨時或緊急存取要有授權與紀錄，和 9.5.1、10.3.2 的核可原則相同。
