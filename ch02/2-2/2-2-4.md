# 2.2.4 程序與訊息的描述方式

所屬：[2.2 規格文件的結構](../2-2.md)

## 正文

In 3GPP specifications, a *procedure* defines the ordered exchange of signalling messages that a network function must follow to achieve a specific task, such as setting up a PDU session. The *message description* details each Information Element (IE) that can appear in those messages, indicating whether the IE is mandatory, optional, or conditional, and specifies the node’s required reaction when the message violates the rules. Accurate procedure and message descriptions are essential because they guarantee interoperable behaviour across equipment from different vendors and prevent undefined error conditions in live networks.

### Conditional Behaviour and the “shall” Modality

The specifications use the normative keyword **shall** to impose mandatory actions on the receiving node. When a received message does not satisfy the stated conditions, the node must generate a failure response with an *appropriate cause value*. This deterministic error handling allows the UE and the network to recover gracefully and to log the exact reason for the failure.

### Typical Validation Checks

The reference text (TS 38.413 §8.2.1.4) lists several validation checks that the NG‑RAN node performs on a **PDU SESSION RESOURCE SETUP REQUEST** message:

1. **Duplicate PDU Session IDs** – If the request contains several *PDU Session ID* IEs set to the same value, the NG‑RAN node shall report the establishment of the corresponding PDU sessions as failed.  

2. **Collision with an Active Session** – If a *PDU Session ID* IE identifies a session that is already active, the NG‑RAN node shall report the establishment of the new session as failed.  

3. **Missing Aggregate Bit Rate for Non‑GBR Flows** – If a *QoS Flow Setup Request List* IE includes at least one Non‑GBR QoS flow but the *PDU Session Aggregate Maximum Bit Rate* IE is absent, the NG‑RAN node shall report the establishment of the corresponding PDU session as failed.  

4. **Missing GBR Information** – If a *QoS Flow Level QoS Parameters* IE for a GBR QoS flow is present but the *GBR QoS Flow Information* IE is missing, the NG‑RAN node shall report the establishment of the corresponding QoS flow as failed.  

5. **Delay‑Critical without Burst Volume** – If the *Delay Critical* IE is set to “delay critical” but the *Maximum Data Burst Volume* IE is absent, the NG‑RAN node shall report the establishment of the corresponding QoS flow as failed.  

Each of these checks is performed independently; the node may return multiple failure indications in a single **PDU SESSION RESOURCE SETUP RESPONSE** message.  

### Worked Example

Consider a NG‑RAN node that receives the following **PDU SESSION RESOURCE SETUP REQUEST** (simplified for illustration):

| List entry | PDU Session ID | QoS Flow Type | Presence of IEs |
|------------|----------------|----------------|-----------------|
| 1          | 5              | Non‑GBR        | *QoS Flow Setup Request List* present, *PDU Session Aggregate Maximum Bit Rate* **absent** |
| 2          | 5              | GBR            | *QoS Flow Level QoS Parameters* present, *GBR QoS Flow Information* **absent** |
| 3          | 7              | GBR (delay‑critical) | *Delay Critical* = “delay critical”, *Maximum Data Burst Volume* **absent** |

The node evaluates the three entries:

* **Entry 1** triggers check 3 because a Non‑GBR flow is requested without the aggregate maximum bit rate IE. According to the specification, the node must report the establishment of the corresponding PDU session as failed.  

* **Entry 2** triggers check 1 (duplicate PDU Session ID) **and** check 4 (missing GBR information). Both conditions require a failure report for the session ID 5.  

* **Entry 3** triggers check 5 (delay‑critical without burst volume). The node must report the QoS flow as failed.  

The resulting **PDU SESSION RESOURCE SETUP RESPONSE** contains three failure entries, each with an appropriate cause value (e.g., *invalid mandatory information*).  

### Common Mistakes and Practical Tips

| Mistake | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| Ignoring duplicate *PDU Session ID* values | Assumes later entries override earlier ones | Implement a check for equality across the entire *PDU Session Resource Setup Request List* and generate a failure for each duplicate. |
| Omitting mandatory IEs for GBR flows | Confusing optional vs. conditional IEs | Verify that *GBR QoS Flow Information* is present whenever a GBR flow is described. |
| Forgetting to include *PDU Session Aggregate Maximum Bit Rate* when any Non‑GBR flow is present | Misreading the wording “including at least one Non‑GBR QoS flow” | Perform a presence test for the aggregate bitrate IE whenever the *QoS Flow Setup Request List* contains a Non‑GBR entry. |
| Not handling the “delay critical” case | Assuming *Delay Critical* is only advisory | When *Delay Critical* = “delay critical”, ensure *Maximum Data Burst Volume* is supplied; otherwise, trigger a failure. |
| Returning a generic error instead of the “appropriate cause value” | Lack of mapping to cause enumeration | Use the cause values defined in TS 38.413 (e.g., *invalid mandatory information*) to allow the UE to interpret the failure correctly. |

By systematically applying the validation rules defined in the specification, engineers can avoid these pitfalls and ensure that their implementations behave predictably under abnormal conditions.

## 練習題

**1.** What must the NG‑RAN node do when a PDU SESSION RESOURCE SETUP REQUEST contains several PDU Session ID IEs set to the same value?

- A. Accept the first ID and ignore the rest.
- B. Report the establishment of the corresponding PDU sessions as failed.
- C. Merge the duplicate entries into a single session.
- D. Forward the request to the core network for disambiguation.

<details><summary>看答案</summary>

正解：B。The specification mandates a failure response for duplicate session IDs.

</details>

**2.** For a GBR QoS flow, the NG‑RAN node requires which IE to avoid a failure response?

- A. Dynamic 5QI Descriptor
- B. GBR QoS Flow Information
- C. Delay Critical
- D. Maximum Data Burst Volume

<details><summary>看答案</summary>

正解：B。The presence of GBR QoS Flow Information is mandatory for GBR flows.

</details>

**3.** When the *Delay Critical* IE is set to “delay critical” but the *Maximum Data Burst Volume* IE is missing, the NG‑RAN node shall:

- A. Accept the QoS flow and use a default burst volume.
- B. Report the establishment of the corresponding QoS flow as failed.
- C. Request the UE to resend the missing IE.
- D. Ignore the *Delay Critical* setting and proceed.

<details><summary>看答案</summary>

正解：B。The specification requires a failure response for this condition.

</details>
