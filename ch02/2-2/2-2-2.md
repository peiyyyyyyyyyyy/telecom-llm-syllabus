# 2.2.2 規格編號與系列

所屬：[2.2 規格文件的結構](../2-2.md)

## 正文

In large‑scale mobile networks dozens of documents define everything from high‑level requirements to low‑level bit‑exact signalling. Engineers must be able to locate the correct document quickly, and automated tools (e.g., version‑control systems, parsers, and domain‑specific language models) rely on a predictable identifier. 3GPP therefore mandates a **two‑part numbering scheme** “aa.bbb” that conveys both the *type* of document (Technical Specification TS or Technical Report TR) and the *functional series* to which the document belongs [TS 21.900 §4.0].

### Structure of the identifier

*Prefix*:  
- **3GPP TS** aa.bbb → Technical Specification  
- **3GPP TR** aa.bbb → Technical Report  

*First part* (**aa**) selects a **series**; the second part (**bbb**) is a three‑digit serial within that series.  The series ranges are defined in Table 1 of the reference and are **strictly enforced** [TS 21.900 §4.0].

| Series (aa) | Functional area (as defined in Table 1) | Typical content |
|-------------|------------------------------------------|-----------------|
| 0 – 41      | Requirements                            | Transient requirements that may later be replaced by reports |
| 0 – 42      | Service aspects                         | Service features, building blocks, platforms |
| 0 – 43      | Technical realization                   | Stage‑2 specifications, interworking behaviour |
| 0 – 44      | Signalling protocols (UE ↔ CN)          | Detailed, bit‑exact protocol definitions |
| 0 – 45      | Radio access aspects                    | UTRAN/UTRA performance, layer specifications, interfaces |
| 0 – 46      | Codecs                                   | Speech, video and other codec descriptions |

The **bbb** field is free‑form but usually follows a pattern such as “0.xx”, “1.bb”, “2.bb”, etc., where the leading digit may indicate a sub‑category (e.g., “25.1bb” for UTRAN radio performance) [TS 21.900 §4.0].

### Worked example

Suppose an engineer is asked to locate the specification that defines the NAS signalling between the UE and the Core Network for LTE. The known document number is **3GPP TS 24.301**.

1. The prefix “TS” tells us it is a Technical Specification.  
2. The first part “24” falls into the **0 – 44** range, which the table labels *Signalling protocols* [TS 21.900 §4.0].  
3. Consequently, TS 24.301 belongs to the signalling‑protocol series and can be expected to contain detailed, bit‑exact protocol definitions for NAS.  

If the same functional area were expressed as a performance report, the identifier would be **3GPP TR 24.301**, preserving the series while changing the document type.

### Practical notes and common pitfalls

| Pitfall | Why it occurs | How to avoid it |
|---------|---------------|-----------------|
| **Confusing the series range with the version number** | The “aa” part is *not* a release version; it is a functional series. | Always refer to Table 1 for the intended functional area before assuming a release. |
| **Assuming any number in the range is valid** | Table 1 defines allowed ranges, but Table 2 (not reproduced here) provides guidance; deviations are only allowed for backwards compatibility. | Verify that a given “aa” value appears in Table 1; treat out‑of‑range numbers as non‑standard. |
| **Omitting the prefix (TS/TR)** | Tools that parse specifications may mis‑classify a document without the correct prefix. | Include “3GPP TS” or “3GPP TR” consistently in all references. |
| **Using the same “bbb” across different series** | Identical three‑digit identifiers can exist in multiple series (e.g., 25.1bb in radio‑access vs 44.1bb in signalling). | Disambiguate by always stating the full “aa.bbb” number together with its series purpose. |

Finally, remember that **Table 1’s provisions are mandatory**, whereas **Table 2 is advisory**; deviations are only permissible for reasons such as backwards compatibility [TS 21.900 §4.0].

## 練習題

**1.** Which series range in the 3GPP numbering scheme is designated for signalling protocols (UE ↔ CN)?

- A. 0 – 41
- B. 0 – 42
- C. 0 – 44
- D. 0 – 46

<details><summary>看答案</summary>

正解：C。The table lists “0 – 44” as the range for Signalling protocols.

</details>

**2.** What prefix is used for a Technical Specification in the 3GPP numbering scheme?

- A. 3GPP TS
- B. 3GPP TR
- C. 3GPP TSR
- D. 3GPP SP

<details><summary>看答案</summary>

正解：A。The reference explicitly defines “3GPP TS aa.bbb” for Technical Specifications.

</details>

**3.** According to the reference, which series is described as “Requirements” and often transient?

- A. 0 – 41
- B. 0 – 42
- C. 0 – 43
- D. 0 – 45

<details><summary>看答案</summary>

正解：A。The row for 0 – 41 is labelled “Requirements” with the remark “Often transient”.

</details>

**4.** Is it permissible to deviate from the provisions of Table 2 for backwards compatibility?

- A. Yes
- B. No
- C. Only with 3GPP approval
- D. Only for Technical Reports

<details><summary>看答案</summary>

正解：A。The reference states that deviation from Table 2 is acceptable for backwards compatibility.

</details>

**5.** The document 3GPP TS 25.331 belongs to which functional series?

- A. Requirements (0 – 41)
- B. Service aspects (0 – 42)
- C. Radio access aspects (0 – 45)
- D. Codecs (0 – 46)

<details><summary>看答案</summary>

正解：C。The first part “25” falls within the 0 – 45 range, which is the Radio access aspects series.

</details>
