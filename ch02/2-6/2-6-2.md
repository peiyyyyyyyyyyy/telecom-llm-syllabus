# 2.6.2 新舊版衝突時用哪一版

所屬：[2.6 引用規則](../2-6.md)

## 正文

In a large‑scale mobile network the documentation that drives implementation is organized into *Releases*. Each Release may contain several versions of a given Technical Specification (TS) or Technical Report (TR). Engineers often encounter a situation where two different versions of the same document appear to be relevant – for example, an older version that was used during initial deployment and a newer version that contains bug fixes or additional features. Selecting the correct version is crucial because using an incompatible version can lead to mis‑aligned protocol behaviour, failed conformance tests, or even network outages.

The 3GPP standard‑referencing rules provide a deterministic way to resolve such conflicts: **when a reference is non‑specific, it is implicitly understood to point to the latest version of the referenced TS/TR that belongs to the same Release as the referring document**. This rule ensures that all documents within a Release evolve together, preserving interoperability while still allowing future updates within that Release to be adopted without changing the referencing text.

### Key definitions

- **Release** – a logical collection of TSs and TRs that are intended to be used together. Releases are identified by a sequential number (e.g., Release 17).  
- **Version** – the concrete iteration of a TS/TR within a Release, identified by a version number (e.g., 16.5.0).  
- **Non‑specific reference** – a citation that does *not* point to a particular clause, figure, or table, but only to the document as a whole. According to the rule, it refers to “the TS or TR *in the same Release* as that of the referring TS or TR” and “implicitly to the latest version of the referenced TS or TR in the Release in question” [TS 21.801 §6.6.6.5.3].

Because non‑specific references cannot guarantee stable numbering, the standard forbids citing clause numbers, figures, or tables when the reference may later change.

### How to determine the applicable version

1. **Identify the Release of the referring document** – this is usually indicated in the document header (e.g., “3GPP TS 38.331 Release 17”).  
2. **Locate all versions of the referenced document that belong to the same Release** – versions that are part of earlier or later Releases are *not* eligible.  
3. **Select the newest version among those** – the rule states that the reference is “implicitly to the latest version of the referenced TS or TR in the Release in question” [TS 21.801 §6.6.6.5.3].

If no version of the referenced document exists in the same Release, the reference is considered invalid and must be replaced by a specific reference or an explicit statement that the document cannot be found (handled in Section 2.6.3).

### Worked example

Assume you are drafting **TS 38.331 Release 17** and need to refer to **TS 23.401**. Two versions of TS 23.401 are available:

| Version | Release |
|---------|---------|
| v16.5.0 | Release 16 |
| v17.2.0 | Release 17 |

Because the referring document is in Release 17, the rule tells us to use the *latest* version of TS 23.401 that also belongs to Release 17. In this case, that is **v17.2.0**. The citation in the text would be written simply as “see TS 23.401” without a clause number, because the reference is non‑specific. If later a newer version v17.3.1 is published within Release 17, the same non‑specific reference will automatically resolve to that newer version, preserving forward compatibility.

### Practical notes and common pitfalls

- **Do not cite clause numbers** when using a non‑specific reference. The standard explicitly prohibits “citing particular clauses, figures or tables” because their numbering may change in later versions [TS 21.801 §6.6.6.5.3].  
- **Do not mix Releases**. Referring to a document from a different Release breaks the implicit “same Release” rule and creates ambiguity.  
- **When only an older Release version exists**, the reference is invalid under the non‑specific rule; the author must either locate a suitable version in the same Release or change the reference to a specific one that explicitly states the version.  
- **Version tracking tools** (e.g., a document management system that extracts Release and version from the filename) are very helpful to avoid manual errors.  

By consistently applying the “same Release, latest version” rule, engineers ensure that all parts of the specification suite evolve coherently, reducing the risk of incompatibilities in real‑world deployments.

**1.** When a non‑specific reference is used, to which version does it implicitly refer?

- A. The earliest version of the referenced document across all Releases.
- B. The latest version of the referenced document *in the same Release* as the referring document.
- C. The version explicitly mentioned in the reference clause.
- D. Any version that the author prefers.

<details><summary>看答案</summary>

正解：B。The rule states the reference points to the latest version within the same Release.

</details>

**2.** Which statement best describes the purpose of the “same Release” requirement for non‑specific references?

- A. To ensure that all referenced documents are from the earliest possible Release.
- B. To guarantee that the referenced document’s clause numbers remain constant.
- C. To keep the set of specifications within a Release mutually compatible.
- D. To allow authors to reference any document regardless of its version.

<details><summary>看答案</summary>

正解：C。The rule keeps documents within a Release aligned, preserving compatibility.

</details>

**3.** When updating a specification that contains a non‑specific reference, what happens to the reference if a newer version of the referenced TS is released within the same Release?

- A. The reference must be edited to point to the new version explicitly.
- B. The reference automatically resolves to the newer version.
- C. The reference becomes invalid and must be removed.
- D. The reference continues to point to the original version forever.

<details><summary>看答案</summary>

正解：B。Because the reference is to the latest version in the same Release, it automatically picks up newer versions.

</details>
