# 2.6.4 由檔名讀出版本與 Release

所屬：[2.6 引用規則](../2-6.md)

## 正文

In the 3GPP document repository every specification is stored as a computer file whose name encodes the specification number, the part (if any), and the version (release) of the document.  The generic pattern is  

$$
\texttt{aabbb-xyz.eee}
$$

where **aa** and **bbb** together represent the specification number (the same significance as in the official TS number) and **x y z** represent the three version elements – major (release), technical and editorial – using the single‑character base‑36 coding defined in Table 6 of TS 21.900 §5A.  The extension **eee** is the de‑facto tool‑specific suffix (normally “doc”).  For a multi‑part specification the pattern becomes  

$$
\texttt{aabbb-n-xyz.eee}
$$

with **n** the part number (decimal, one‑ or two‑digit) as described in Tables 6 and 6A [TS 21.900 §5A].

If a specification is distributed as a compressed archive, the same base name is kept and the extension is changed to “.zip”.  The archive therefore looks like  

$$
\texttt{aabbb-xyz.zip}
$$

or, for multi‑part specifications,  

$$
\texttt{aabbb-n-xyz.zip}
$$

as shown in EXAMPLE 1 and EXAMPLE 6 of the reference [TS 21.900 §5A].

### Mapping characters to numeric version

Each character in the **xyz** block maps to a numeric value according to Table 6:

| Value | Character |
|------|-----------|
| 0‑9  | 0‑9 |
| 10   | a |
| …    | … |
| 35   | z |

Thus the three characters encode the three version fields *major*, *technical* and *editorial* in base‑36.  For example, the character “g” corresponds to the decimal value 16, so a version field “g” means **16**.  When any version element exceeds 35, the filename must switch to a six‑character decimal representation (two decimal digits per element) as mandated in the standard [TS 21.900 §5A].

### Determining the Release (major version)

The **Release** in 3GPP terminology is the first element of the version triple (the *major* component).  To obtain it from a filename:

1. Identify the **xyz** block (or the six‑digit block if the “> 35” rule applies).  
2. Take the first character **x** (or the first two digits).  
3. Convert **x** using Table 6 (or decimal) to obtain the major version number.  

The resulting integer is the Release number, e.g. Release 4 for the filename *29341‑420.zip* [TS 21.900 §5A].

### Draft versions

Drafts are distinguished by inserting the letter “d” **before** the hyphen that precedes the version block, yielding the pattern  

$$
\texttt{aabbbdxyz.eee}
$$

Such files never appear in the official specification directories [TS 21.900 §5A].  For instance, a draft of TS 28.033 version 4.1.0 is named *28033d410.zip* [TS 21.900 §5A].

### Worked example

Suppose you encounter the file **31811‑m‑6g2.doc**.  

*Step 1 – Specification number*: “31.811” is obtained from **aa = 31** and **bbb = 811** (the same significance as the TS number) [TS 21.900 §5A].  

*Step 2 – Part number*: The character **m** follows the first hyphen.  Table 6 maps **m → 22**, therefore this is **part 22** [TS 21.900 §5A].  

*Step 3 – Version block*: The three characters **6 g 2** correspond to:  

- **6** → 6 (major)  
- **g** → 16 (technical)  
- **2** → 2 (editorial)  

Hence the version is **6.16.2**, i.e. Release 6 [TS 21.900 §5A].

*Step 4 – File type*: The “.doc” suffix indicates a source document created with Microsoft Word [TS 21.900 §5A].

Thus the complete identification reads: *Specification 31.811, part 22, version 6.16.2 (Release 6), source document* [TS 21.900 §5A].

### Practical notes and common pitfalls

| Pitfall | Why it happens | How to avoid |
|---------|----------------|--------------|
| **Using alphabetic characters for part numbers** | Table 6A allows only decimal values for part/sub‑part numbers; letters are reserved for version fields. | Verify that the part field **n** consists solely of digits (0‑9) or two‑digit decimal strings [TS 21.900 §5A]. |
| **Confusing draft and official files** | Drafts replace the hyphen with “d” before the version block. | Look for the “d” character; if present, treat the file as non‑official [TS 21.900 §5A]. |
| **Misreading base‑36 values** | Characters a‑z represent values 10‑35; forgetting this leads to incorrect version numbers. | Keep Table 6 handy; translate each character systematically [TS 21.900 §5A]. |
| **Ignoring the six‑digit rule** | When any version element > 35, the filename must switch to two‑digit decimal per element. | Check each version element; if any exceeds 35, expect a six‑character block (e.g., “153600”) [TS 21.900 §5A]. |
| **Overlooking the zip extension** | Compressed archives keep the base name but change the suffix to “.zip”. | Treat “.zip” as a container; the underlying source file name follows the same rules [TS 21.900 §5A]. |

By consistently applying the naming conventions, engineers can reliably locate the correct specification, determine its release, and avoid version mismatches that could otherwise lead to incompatible implementations in live networks.

## 練習題

**1.** Which of the following filenames represents the official (non‑draft) source document for specification 29.341 version 4.2.0?

- A. 29341-420.doc
- B. 29341d420.doc
- C. 29341-0420.doc
- D. 29341-420.zip

<details><summary>看答案</summary>

正解：A。The filename follows the pattern aabbb-xyz.eee with xyz = 420, which maps to version 4.2.0; it is a source document (".doc") and lacks the draft marker “d”.

</details>

**2.** In the filename **31811‑m‑6g2.doc**, what numeric part number does the character “m” correspond to?

- A. 12
- B. 22
- C. 16
- D. 13

<details><summary>看答案</summary>

正解：B。Table 6 maps “m” to the decimal value 22, which is the part number.

</details>

**3.** If a specification’s technical version element exceeds 35, how must the filename be formed?

- A. Keep using a single base‑36 character for each element.
- B. Use two decimal characters (00‑99) for each of the three elements, yielding six characters total.
- C. Switch to hexadecimal representation for the exceeding element only.
- D. Append an extra hyphen and the decimal value after the original block.

<details><summary>看答案</summary>

正解：B。The standard mandates a six‑character decimal representation when any version element is greater than 35.

</details>

**4.** Which of the following filenames would be invalid for a multi‑part specification according to the naming rules?

- A. 29341-1-5.doc
- B. 29342-2-15.doc
- C. 29343-13-21.doc
- D. 29345-az-6.doc

<details><summary>看答案</summary>

正解：D。Part numbers must be decimal digits only; the string “az” uses alphabetic characters, which are prohibited for part numbers.

</details>
