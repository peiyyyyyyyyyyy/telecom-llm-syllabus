# 2.3.3 條件與註腳

所屬：[2.3 表格與參數](../2-3.md)

## 正文

In telecom specifications, tables are the primary vehicle for conveying numerical parameters, limits, and configuration options. However, a table alone cannot capture every nuance; **conditions** (requirements that apply only under certain circumstances) and **notes** provide the necessary contextual information. Properly formatted notes ensure that engineers interpreting the table understand constraints such as optional features, implementation dependencies, or clarification of ambiguous entries. Misinterpretation can lead to non‑conformant equipment, interoperability failures, or costly redesigns in live networks.

### Definitions

| Term | Definition (as per 3GPP TS 21.801) |
|------|-----------------------------------|
| **Note to a table** | Text that is part of a table, located within the table’s frame, and may contain requirements. It is distinguished from textual notes that appear in the prose. |
| **Footnote to a table** | A reference marker placed outside the table body; **not permitted** in 3GPP TS/ TR documents. |
| **NOTE:** | Prefix for a single note in a table. |
| **NOTE 1:, NOTE 2:, …** | Prefixes used when a table contains multiple notes; each note is numbered sequentially **per table**. |
| **TAN style** | The prescribed layout style for tables in 3GPP specifications (Table, Annotation, Note). |
| **Merged cell** | A single cell that spans the full width of the table, used to contain the note(s) at the bottom of the table. |

### Placement and Formatting Rules

1. **Independence from Textual Notes** – Notes to tables are **treated independently** from notes integrated in the surrounding text. They must be placed **inside the table frame** and not in the surrounding narrative [TS 21.801 §6.6.5.6].  

2. **Prefix and Numbering**  
   - A solitary note is introduced with the literal string **`NOTE:`**.  
   - When a table contains more than one note, each note receives a unique sequential identifier **`NOTE 1:`**, **`NOTE 2:`**, … and the sequence restarts for every new table [TS 21.801 §6.6.5.6].  

3. **Cell Merging** – All notes belonging to a table must be placed **in a single merged cell** that occupies the full width of the table and is located at the **bottom** of the table body. The merged cell is the only place where note text may appear [TS 21.801 §6.6.5.6].  

4. **Style Requirement** – The **TAN style** must be used for the entire table, which includes the merged‑cell note area. This ensures a uniform visual presentation across all 3GPP documents.  

5. **Prohibition of Footnotes** – **Footnotes shall not be used** in any 3GPP Technical Specification (TS) or Technical Report (TR) [TS 21.801 §6.6.5.7].  

### Worked Example

Consider a simplified table that lists the maximum transmit power for three LTE carrier aggregation (CA) component carriers. The table must indicate that the power limit applies only when the device operates in **FDD** mode.

| Component Carrier | Frequency (MHz) | Max Tx Power (dBm) |
|-------------------|-----------------|--------------------|
| CC‑1              | 1800            | 23                 |
| CC‑2              | 2600            | 20                 |
| CC‑3              | 3500            | 18                 |
| **NOTE 1:** | **The above power limits are valid **only** for FDD operation.** |   |

Implementation steps (per the specification):

1. **Create the three data rows** as usual.  
2. **Add a fourth row** that spans all three columns. Merge the three cells into a single cell.  
3. Insert the prefix **`NOTE 1:`** followed by the condition text.  
4. Ensure the merged cell is the **bottommost** row of the table.  

The final visual representation follows the example given in the spec, where the note cell “is a merged cell” placed under the data rows.

### Common Mistakes and Practical Tips

| Mistake | Why It Is Wrong | Correct Approach |
|---------|-----------------|------------------|
| Using a footnote marker (e.g., superscript numbers) inside the table. | Footnotes are explicitly forbidden in 3GPP TS/TR documents. | Place the explanatory text as a **NOTE** inside a merged cell at the bottom of the table. |
| Numbering notes continuously across multiple tables. | Each table must have its **own** numbering sequence. | Restart numbering with **NOTE 1:** for every new table. |
| Placing notes outside the table borders. | Notes must be **within** the table frame to be treated independently. | Merge cells at the bottom of the table and insert the note there. |
| Forgetting the **TAN** style header. | Non‑conformant tables may be rejected during standard review. | Follow the prescribed **TAN** layout, including merged‑cell notes. |
| Using “NOTE:” for multiple notes without numbering. | Ambiguity arises; readers cannot reference a specific note. | Use **NOTE 1:**, **NOTE 2:**, etc., when more than one note is needed. |

**Practical tip:** When authoring a table, draft the note text first, then construct the merged cell. This prevents overflow or line‑break issues that could otherwise force the note outside the table boundary.

## 練習題

**1.** According to TS 21.801 §6.6.5.6, how should multiple notes in the same table be designated?

- A. NOTE:
- B. NOTE 1:, NOTE 2:, NOTE 3:, etc.
- C. Footnote 1, Footnote 2
- D. NOTE A, NOTE B

<details><summary>看答案</summary>

正解：B。The specification requires sequential numbering (NOTE 1:, NOTE 2:, …) for multiple notes within a single table.

</details>

**2.** What is the required location for a note to a table?

- A. Outside the table, in the surrounding paragraph.
- B. In a separate appendix.
- C. Within the frame of the relevant table, in a merged bottom cell.
- D. As a footnote at the bottom of the page.

<details><summary>看答案</summary>

正解：C。Notes must be placed inside the table borders, merged into a single cell at the bottom.

</details>

**3.** Which of the following statements is true regarding footnotes in 3GPP TS documents?

- A. Footnotes may be used for optional parameters.
- B. Footnotes are allowed only in TRs, not TSs.
- C. Footnotes shall not be used in 3GPP TSs or 3GPP TRs.
- D. Footnotes replace notes when the table is too wide.

<details><summary>看答案</summary>

正解：C。The specification explicitly forbids the use of footnotes in both TS and TR documents.

</details>

**4.** How should a single note in a table be introduced?

- A. With the prefix "NOTE:".
- B. With the prefix "NOTE 1:".
- C. With a superscript number.
- D. With the word "Condition:".

<details><summary>看答案</summary>

正解：A。A single note uses the literal string "NOTE:" as its prefix.

</details>

**5.** When numbering notes, what is the scope of the numbering sequence?

- A. Global across the entire document.
- B. Per table; a separate sequence for each table.
- C. Per chapter.
- D. Per section.

<details><summary>看答案</summary>

正解：B。Each table restarts its own numbering sequence for notes.

</details>
