# 2.1.3 Release 與版本演進

所屬：[2.1 標準體系](../2-1.md)

## 正文

In the 3GPP world a **Release** is the primary unit of evolution for the whole mobile‑communication system.  All specifications that share the same Release together define a complete, self‑consistent set of radio, core‑network and service features that can be deployed in a commercial network.  Because operators plan upgrades, equipment vendors ship software, and test labs certify devices against a specific Release, understanding the Release concept is essential for any real‑world deployment or for a language model that must reason about version‑dependent behaviour.  

The reference definition states that *“Specifications are grouped into ‘Releases’”* and that *“A mobile system can be constructed based on the set of all specifications which comprise a given Release”* [TS 21.900 §4.0B].  Moreover, a Release is not a mere renaming of existing documents – it *“differs from the previous Release by having added functionality introduced as a result of ongoing standardization work within the Groups”* [TS 21.900 §4.0B].  

### Version Number Structure

Every specification that belongs to a Release carries a version number written as  

$$
v = x.y.z
$$

where  

* $x$ – **major field** (identifies the Release)  
* $y$ – **minor field** (indicates incremental changes within the same Release)  
* $z$ – **patch field** (tiny corrections, editorial updates)  

The reference explicitly says that *“Specifications pertaining to a given Release shall be distinguished by the first field of the version number (‘x’ in x.y.z) according to table 4”* [TS 21.900 §4.0B].  Thus, the major field $x$ is the only part that maps a document to a particular Release.  

### Mapping Between GSM Phases, 3GPP Releases and Version Formats

Table 4 (reproduced in the reference) links historic GSM phases, the early 3GPP “Phase 2+” releases, and the later unified “GERAN‑ & UTRAN‑based” releases to concrete version‑number patterns.  A few representative rows are shown below (the full table is in the specification):

| System description | Version number pattern |
|--------------------|------------------------|
| **GSM Phase 2+ Release 1998** | `aa.bb v7.y.z` |
| **pure UTRAN‑based system and common UTRAN‑& GERAN‑based systems Release 1999** | `aa.bbb v3.y.z` |
| **GERAN‑ & UTRAN‑based systems Release 4** | `aa.bbb v4.y.z` |
| **GERAN‑ & UTRAN‑based systems Release 5** | `aa.bbb v5.y.z` |
| **…** | **…** |

The note attached to the table adds that *“From Release 4 onwards the 3GPP format for specification numbers and versions applies to all specifications (including those only relevant for implementation of a stand‑alone GSM system)”* [TS 21.900 §4.0B].  Consequently, from Release 4 the pattern `aa.bbb vX.y.z` is universal, whereas earlier releases used the `aa.bb vX.y.z` format for GSM‑only specifications.  

### Worked Example

Suppose a 3GPP specification for the Radio Resource Control (RRC) protocol is identified as **TS 36.331 v5.2.0**.  

1. Identify the major field: $x = 5$.  
2. Consult Table 4: the pattern `aa.bbb v5.y.z` corresponds to **GERAN‑ & UTRAN‑based systems Release 5**.  

Hence, **TS 36.331 v5.2.0 belongs to Release 5**, which means the feature set defined in this document is available only to equipment that implements at least Release 5.  

If the same document were labelled **TS 06.12 v7.0.1**, the major field $x = 7$ would map, via the GSM rows, to **GSM Phase 2+ Release 1998** (pattern `aa.bb v7.y.z`).  This illustrates how the same numeric major field can refer to different historical releases depending on the version‑format family.  

### Common Mistakes and Practical Tips

| Mistake | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| **Treating the minor field $y$ as the Release identifier** | The three‑digit version looks similar to software versioning (e.g., 1.2.3). | Always read the *first* field $x$ to determine the Release. |
| **Assuming the same version pattern applies to all releases** | Early releases used `aa.bb` while later releases use `aa.bbb`. | Remember that *“From Release 4 onwards the 3GPP format … applies to all specifications”* [TS 21.900 §4.0B]. |
| **Mixing GSM Phase numbers with 3GPP Release numbers** | Both use numbers (e.g., “Release 1999”), but they refer to different naming conventions. | Use Table 4 to translate between GSM Phase/Release labels and the version pattern. |
| **Ignoring the “added functionality” clause** | Believing a new Release is just a bug‑fix roll‑up. | Recognize that each Release *adds* functionality, which may affect radio parameters, protocol messages, or service capabilities. |

**Practical tip:** When planning a network upgrade, verify that *all* required specifications share the same major field $x$.  Mixing documents from different major fields (e.g., a v4.x.x core‑network spec with a v5.x.x radio spec) would lead to incompatibilities because the two belong to different Releases.

## 練習題

**1.** Which part of a 3GPP version number identifies the Release to which a specification belongs?

- A. The second field $y$
- B. The third field $z$
- C. The first field $x$
- D. The combination of $y$ and $z$

<details><summary>看答案</summary>

正解：C。The reference states that the first field (x) distinguishes the Release.

</details>

**2.** According to Table 4, which version‑number pattern corresponds to GSM Phase 2+ Release 1998?

- A. aa.bb v7.y.z
- B. aa.bb v8.y.z
- C. aa.bbb v7.y.z
- D. aa.bbb v8.y.z

<details><summary>看答案</summary>

正解：A。The row for GSM Phase 2+ Release 1998 lists the pattern aa.bb v7.y.z.

</details>

**3.** A specification has version number v5.3.1 and follows the “aa.bbb” format. To which Release does it belong for GERAN‑ & UTRAN‑based systems?

- A. Release 4
- B. Release 5
- C. Release 6
- D. Release 7

<details><summary>看答案</summary>

正解：B。The major field 5 maps to Release 5 in the “aa.bbb” family.

</details>

**4.** Which of the following statements about 3GPP Releases is **false**?

- A. A Release adds functionality compared with the previous Release.
- B. Releases are distinguished by the first field of the version number.
- C. The version format v3.y.z can correspond to a pure UTRAN‑based system Release 1999.
- D. A Release is a static snapshot that never changes after publication.

<details><summary>看答案</summary>

正解：D。The reference says a Release differs by added functionality, implying it evolves; it is not static.

</details>
