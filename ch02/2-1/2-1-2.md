# 2.1.2 工作組分工與 Stage 1／2／3

所屬：[2.1 標準體系](../2-1.md)

## 練習題

**1.** Which sub‑group is responsible for producing the Stage 1 descriptions (requirements) for new features?

- A. SA2
- B. SA3
- C. SA1
- D. The Working Groups

<details><summary>看答案</summary>

正解：C。SA1 is explicitly tasked with creating Stage 1 requirement documents before passing them to SA2.

</details>

**2.** What is the primary output of a work task performed by a TSG Working Group in Stage 3?

- A. Architectural diagrams only
- B. New or updated specifications and technical reports
- C. Security certificates
- D. Release schedule tables

<details><summary>看答案</summary>

正解：B。The reference lists new specifications, updated specifications, technical reports, or confirmation of existing support as typical outputs.

</details>

**3.** Which entity defines the system architecture and splits features into building blocks?

- A. SA1
- B. SA2
- C. SA3
- D. The Working Groups

<details><summary>看答案</summary>

正解：B。SA2’s role includes defining architecture and creating building blocks for later detailed work.

</details>

**4.** During detailed work in Stage 3, who must be kept informed about progress?

- A. Only SA1
- B. Only SA3
- C. SA2
- D. The Release Management Board

<details><summary>看答案</summary>

正解：C。The reference states that SA2 must be kept informed while TSGs and WGs perform detailed work.

</details>

**5.** Why does SA2 invite TSG CT and TSG RAN to evaluate a new feature?

- A. To allocate budget for the feature
- B. To assess impact on conformance testing and mobile‑station capabilities
- C. To write the final release notes
- D. To approve the security policy

<details><summary>看答案</summary>

正解：B。SA2’s invitation is intended to let CT and RAN evaluate the impact on horizontal tasks such as testing and capability definition.

</details>
