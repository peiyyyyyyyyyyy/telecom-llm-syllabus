# 2.1.7 研究項目（SI）與工作項目（WI）

所屬：[2.1 標準體系](../2-1.md)

## 正文

In 3GPP, any change that introduces new services, features, functions, or performance improvements must be organised as a **Work Item (WI)**.  A WI provides the formal mechanism by which the community agrees on the scope, responsibilities, and schedule of the development effort.  Without a WI, work could start in a Working Group (WG) without coordination, leading to duplicated effort, incompatibilities, or specifications that do not meet the needs of operators and equipment vendors.  The creation process is triggered when “new or enhanced functionality of the 3GPP system is considered desirable” and an individual member (or a group of members) submits a **Work Item Description (WID) sheet** to the relevant Technical Specification Group (TSG) or its WG [TS 21.900 §6.1].

### Key Definitions

| Symbol / Term | Definition | Source |
|---|---|---|
| **WID** | Work Item Description sheet that contains the proposal, scope, and initial justification. | [TS 21.900 §6.1] |
| **TSG** | Technical Specification Group that has the authority to adopt a WI. | [TS 21.900 §6.1] |
| **prime TSG** | The TSG primarily responsible for the WI. | [TS 21.900 §6.1] |
| **secondary TSG** | Additional TSG(s) that may be required for cross‑cutting aspects. | [TS 21.900 §6.1] |
| **Support Team** | Entity that maintains the WI database and distributes guidance. | [TS 21.900 §6.1] |
| **TEI\<x\>** | Pseudo‑Work Item code for *Technical Enhancements and Improvements* applicable to Release *x* (e.g., TEI16 for Release 16). | [TS 21.900 §6.2] |
| **Category B/C/F/A CR** | Classification of Change Requests (CRs) defined by 3GPP; used when linking CRs to WIs or TEI codes. | [TS 21.900 §6.2] |

### Types of Work Items

3GPP distinguishes two broad categories of modifications [TS 21.900 §6.2]:

1. **New services / features / functions** – usually affect several specifications and multiple TSGs/WGs.  
2. **Technical enhancements / improvements** – typically impact a single or a small number of specifications and can be handled by one or a few groups.

For the second category, a WI may be omitted; instead, the modification can be submitted directly as a **Change Request (CR)** that references the pseudo‑WI **Technical Enhancements and Improvements** and is tagged with a **TEI\<x\>** code [TS 21.900 §6.2].

### When to Use a TEI Code

A TEI code is appropriate only if **both** conditions are satisfied [TS 21.900 §6.2]:

* The modification can be completed **within one TSG cycle**.  
* The normal Stage 1‑2‑3 CR sequence does **not** require an additional meeting cycle in each affected TSG.

If either condition fails, a dedicated WI with its own code must be created.  The TEI code **must not** be used for new services/features/functions (Category B CRs) nor for pure functional modifications (Category C CRs) [TS 21.900 §6.2].

### Worked Example

An operator notices that the latency of the uplink scheduling algorithm in Release 16 can be reduced by 5 ms with a software tweak. The enhancement is confined to the RAN specification and does not require interaction with other TSGs.

1. **Assess eligibility** – The change can be finished in the current Release 16 TSG cycle and does not need extra meetings → eligible for TEI.  
2. **Select TEI code** – Use **TEI16** (Release 16) [TS 21.900 §6.2].  
3. **Create CR** – Draft a Category C CR (functional modification) and tag it with **TEI16**. Since the feature was originally introduced by WI **ABCD** in Release 13, the CR cover sheet lists both codes: “ABCD, TEI16”. The order “ABCD, TEI16” or “TEI16, ABCD” is irrelevant [TS 21.900 §6.2].  
4. **Submit** – The CR is submitted to the responsible TSG (e.g., RAN). No separate WI is created because the TEI code suffices.

### Practical Notes & Common Mistakes

| Mistake | Why It Is Wrong | Reference |
|---|---|---|
| Starting work in a WG before the TSG has formally adopted the WI. | “No substantial work shall commence … prior to a decision of the responsible TSG.” | [TS 21.900 §6.1] |
| Using a TEI\<x\> code for a new service or feature. | “TEI Work Item codes should not be used for the definition of new services/features/functions (i.e. Category B CRs).” | [TS 21.900 §6.2] |
| Applying a TEI code alone when a dedicated WI already exists. | “The use of a TEI Work Item code alone should be avoided whenever possible.” | [TS 21.900 §6.2] |
| Assuming the order of multiple WI codes on a CR matters. | “The order in which multiple Work Item codes appear on a CR cover sheet is not significant.” | [TS 21.900 §6.2] |
| Forgetting to update the Support Team’s WI database. | “The Support Team shall maintain a database of Work Items, and make it available on the 3GPP file server and portal.” | [TS 21.900 §6.1] |

> **Note:** The term **研究項目（SI）** (Study Item) is used in other 3GPP processes, but the official 3GPP TS 21.900 does not define SI.  Consequently, this subsection focuses exclusively on **Work Items (WI)** as described in the referenced clauses.

## 練習題

**1.** Who may initiate the creation of a new Work Item in 3GPP?

- A. The 3GPP Management Board
- B. An Individual Member of 3GPP (or a group thereof)
- C. Any equipment vendor
- D. The ITU‑R

<details><summary>看答案</summary>

正解：B。The reference states that an Individual Member (or group) may make a proposal by submitting a WID sheet.

</details>

**2.** Which Technical Specification Group is responsible for a Work Item that introduces a new service?

- A. The TSG responsible for Services and System Aspects
- B. The TSG responsible for Radio Access Network
- C. The TSG responsible for Core Network
- D. Any TSG can be assigned arbitrarily

<details><summary>看答案</summary>

正解：A。For new services, the Services and System Aspects TSG is the relevant one and assigns prime and secondary TSGs.

</details>

**3.** A TEI\<x\> code may be used for a modification only if:

- A. The modification affects at least three specifications.
- B. The modification can be completed within one TSG cycle and does not need extra meeting cycles in each affected TSG.
- C. The modification is a brand‑new feature not present in any previous Release.
- D. The modification is a Category B Change Request.

<details><summary>看答案</summary>

正解：B。The TEI code is allowed when both conditions about a single TSG cycle and meeting cycles are met.

</details>

**4.** Regarding the order of multiple Work Item codes on a Change Request cover sheet, which statement is correct?

- A. The primary WI code must be listed first.
- B. The TEI code must always be listed last.
- C. The order is not significant.
- D. Codes must be ordered alphabetically.

<details><summary>看答案</summary>

正解：C。The specification explicitly says that order does not matter.

</details>

**5.** Which of the following is prohibited when using a TEI\<x\> code?

- A. Tagging a Category C CR that merely corrects a typo.
- B. Tagging a Category B CR that defines a new service.
- C. Tagging a Category F CR that amends an existing specification.
- D. Tagging a Category A mirror CR for a later Release.

<details><summary>看答案</summary>

正解：B。TEI codes must not be used for new services/features/functions (Category B CRs).

</details>
