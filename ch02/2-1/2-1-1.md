# 2.1.1 3GPP 組織：TSG RAN、SA、CT

所屬：[2.1 標準體系](../2-1.md)

## 正文

In the 3GPP ecosystem, the **Technical Specification Group (TSG)** is the top‑level decision‑making body that owns the specification portfolio. 3GPP’s three TSGs – **RAN**, **SA**, and **CT** – together cover the entire mobile system, from the radio interface to the core network and terminal specifications. Understanding which TSG is responsible for a given document is essential for engineers who need to locate the authoritative source of a feature, trace change requests, or participate in standardisation meetings. Each TSG is a **group** as defined in the reference text, and it may contain one or more **Working Groups (WG)** that perform the detailed drafting work [TS 21.900 §2].

### Definitions Relevant to the Three TSGs

| Term | Definition (as per 3GPP) |
|------|--------------------------|
| **Group** | “TSG or TSG sub‑group.” [TS 21.900 §2] |
| **Technical Specification Group (TSG)** | “Technical Specification Group.” [TS 21.900 §2] |
| **Working Group (WG)** | “Official subgroup of a TSG reporting to that TSG.” [TS 21.900 §2] |
| **Work Item (WI)** | “Description of an enhancement to a technical area, which may be categorized as Study Item, Feature, Building Block or Work Task.” [TS 21.900 §2] |
| **Change Request (CR)** | “Formal proposal presented on a standard form to modify a specification which is under change control.” [TS 21.900 §2] |
| **Version** | “Unique identifier in the form x.y.z for a specification at a given point in time.” [TS 21.900 §2] |
| **Major version** | “For version x.y.z of a specification, x is called the major version.” [TS 21.900 §2] |

These definitions apply uniformly across the three TSGs.  For example, a **Change Request** submitted to the **RAN** TSG follows the same procedural rules as one submitted to **SA** or **CT**.

### Hierarchical Structure

The hierarchy can be summarised as  

$$
\text{TSG} \;\rightarrow\; \text{WG} \;\rightarrow\; \text{WI (Feature / Building Block)} \;\rightarrow\; \text{Specification (version)}.
$$

- **TSG** – owns the overall scope (e.g., RAN, SA, CT).  
- **WG** – drafts the normative text, resolves CRs, and moves the document through the status flow (draft → change control → frozen → closed).  
- **WI** – defines the concrete enhancement that will become a **feature** or **building block**.  
- **Specification** – the final technical document, identified by a version number $x.y.z$.

### Version Numbering – A Practical Formula

When a specification is released, its version number follows the pattern $x.y.z$ where:

* $x$ = **major version** (significant architectural change)  
* $y$ = **minor version** (new features or extensions)  
* $z$ = **patch version** (bug fixes or essential corrections)

To extract the major version programmatically, one may use  

$$
\text{major}(x.y.z) = \left\lfloor \frac{x.y.z}{100} \right\rfloor,
$$

or simply read the first integer before the first dot, as defined in the reference [TS 21.900 §2].

### Worked Example

Suppose a 3GPP document has the version **3.12.3**.  

1. Identify the three components: $x = 3$, $y = 12$, $z = 3$.  
2. The **major version** is $x = 3$ (the integer before the first dot).  
3. According to the definition, “For version 3.2.0 of a specification, the major version is 3.” [TS 21.900 §2]; the same rule applies here, so the major version is **3**.

If a new **Change Request** is submitted to add a feature that will be part of the next minor release, the version will evolve to **3.13.0** after the change control process is completed.

### Common Mistakes and Practical Tips

| Mistake | Why it Happens | Correct Approach |
|---------|----------------|------------------|
| **Confusing TSG with WG** – treating a WG as the ultimate authority. | Both are called “group” in the standard, but only the TSG can approve CRs. | Remember that **TSG change control** is the level where CRs are approved; **WG change control** only agrees on CRs before forwarding them. |
| **Misreading version numbers** – assuming the third digit is a “major” revision. | The reference defines the **major version** as the first digit only. | Use the definition of **major version**: the integer $x$ in $x.y.z$. |
| **Submitting a CR to a draft document** – thinking a CR is needed before the document enters change control. | A **draft** status allows changes without formal CRs. | Only submit a **Change Request** once the specification is under **change control**. |
| **Overlooking the “building block” concept** – treating a feature as a monolithic item. | A **building block** is a coherent set of functionality that may be split into **work tasks**. | Decompose complex features into building blocks and work tasks for clearer WI descriptions. |

By keeping these definitions and procedural nuances in mind, engineers can navigate 3GPP’s organisational landscape efficiently, locate the correct source of a specification, and participate correctly in the change‑control workflow.

## 練習題

**1.** Which of the following statements correctly describes the relationship between a TSG and a WG in 3GPP?

- A. A WG can approve Change Requests without involving the TSG.
- B. A WG reports to a TSG and drafts specifications under its scope.
- C. A TSG is a sub‑group of a WG.
- D. Both TSG and WG have the same authority over version numbers.

<details><summary>看答案</summary>

正解：B。A Working Group reports to its Technical Specification Group and drafts the normative text, while the TSG holds the ultimate approval authority.

</details>

**2.** In a version identifier of the form $x.y.z$, which component represents the major version according to 3GPP terminology?

- A. $y$
- B. $z$
- C. $x$
- D. The concatenation of $x$ and $y$

<details><summary>看答案</summary>

正解：C。The major version is defined as the first integer before the first dot.

</details>

**3.** What is the definition of a Change Request (CR) in the 3GPP process?

- A. An informal suggestion that does not require a formal number.
- B. A formal proposal presented on a standard form to modify a specification under change control.
- C. The final version of a specification after all corrections.
- D. A work task that belongs to a building block.

<details><summary>看答案</summary>

正解：B。A CR is a formal proposal on a standard form to modify a specification that is under change control.

</details>

**4.** Which term refers to a sub‑division of a feature that is expected to reside in a single system element?

- A. Work Item
- B. Building block
- C. Study Item
- D. Change Request

<details><summary>看答案</summary>

正解：B。A building block is defined as a sub‑division of a feature representing a coherent set of technical functionality.

</details>

**5.** When a specification status is described as “frozen,” which of the following is true?

- A. No further changes of any kind are permitted.
- B. Only essential corrections are permitted.
- C. The specification is being drafted and can be freely edited.
- D. The specification has been withdrawn from the valid set.

<details><summary>看答案</summary>

正解：B。In the frozen status, only essential corrections are allowed.

</details>
