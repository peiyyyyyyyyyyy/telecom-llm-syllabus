# 1.4.5 加密與完整性保護

## 正文

In modern telecom networks every user plane packet that traverses the radio access network (RAN) or the core must be shielded from eavesdropping and tampering. Encryption guarantees *confidentiality*—only parties that possess the correct secret can recover the original payload—while integrity protection assures that any modification of the transmitted data can be detected. Together they form the cornerstone of secure signalling (e.g., NAS, RRC) and user data (e.g., IP‑PDN traffic) in 4G/5G systems.

---

### 1.4.5.1 Fundamental definitions  

| Symbol | Meaning | Unit / Size |
|--------|---------|-------------|
| $P$ | Plaintext (or message) | bits |
| $C$ | Ciphertext | bits |
| $K$ | Secret key (symmetric) | bits (e.g., 128, 256) |
| $IV$ | Initialization vector (for block modes) | bits (commonly 96–128) |
| $N$ | Nonce (for AEAD) | bits |
| $A$ | Associated data (authenticated but not encrypted) | bits |
| $T$ | Authentication tag (MAC) | bits (e.g., 128) |
| $\mathsf{Enc}_K(\cdot)$ | Symmetric encryption algorithm with key $K$ | – |
| $\mathsf{Dec}_K(\cdot)$ | Symmetric decryption algorithm with key $K$ | – |
| $\mathsf{MAC}_K(\cdot)$ | Message Authentication Code with key $K$ | – |
| $\mathsf{AEADEnc}_K(N, P, A)$ | Authenticated Encryption with Associated Data | $(C,T)$ |
| $\mathsf{AEADDec}_K(N, C, A, T)$ | Authenticated decryption, returns $P$ if $T$ verifies | $P$ or error |

**Confidentiality** is achieved when an adversary, given only $C$, cannot recover any information about $P$ beyond what is feasible by brute‑force search of $K$. Formally, for a probabilistic polynomial‑time adversary $\mathcal{A}$, the advantage

$$
\text{Adv}^{\text{IND-CPA}}_{\mathsf{Enc}}(\mathcal{A}) = \big| \Pr[\mathcal{A}\text{ guesses correctly}] - \tfrac{1}{2} \big|
$$

must be negligible.

**Integrity** (or authenticity) is expressed via unforgeability of the MAC:

$$
\text{Adv}^{\text{EUF-CMA}}_{\mathsf{MAC}}(\mathcal{F}) = \Pr[\mathcal{F}\text{ outputs a new valid tag}]
$$

which also must be negligible.

---

### 1.4.5.2 Symmetric encryption primitives  

1. **Block ciphers** (e.g., AES) operate on fixed‑size blocks (128 bits). Modes of operation turn a block cipher into a stream‑like primitive:

   * **ECB (Electronic Code Book)** – insecure; identical plaintext blocks produce identical ciphertext blocks.
   * **CBC (Cipher Block Chaining)** – $C_i = \mathsf{Enc}_K(P_i \oplus C_{i-1})$, requires a random $IV$ for the first block.
   * **CTR (Counter)** – $C_i = P_i \oplus \mathsf{Enc}_K(\text{CTR}_i)$, where $\text{CTR}_i = IV + i$; provides parallelism and random access.

2. **Stream ciphers** (e.g., ZUC, Snow‑3G) generate a keystream $Z$ and compute $C = P \oplus Z$; the keystream is seeded by a secret key and a *nonce*.

Both families require **unique** IV/nonce per key; reuse leads to catastrophic loss of confidentiality.

---

### 1.4.5.3 Integrity primitives  

* **MAC** – deterministic function of the message and a secret key, e.g., HMAC‑SHA‑256:  

  $$ T = \text{HMAC}_{K}(M) $$  

* **CMAC** – block‑cipher based MAC (e.g., CMAC‑AES).

The tag length $|T|$ determines the probability of a successful forgery; 128 bits is standard in 3GPP.

---

### 1.4.5.4 Authenticated Encryption (AE)  

AE schemes combine confidentiality and integrity in a single primitive, eliminating the “encrypt‑then‑MAC” pitfalls. The most widely deployed in telecom is **AES‑GCM** (Galois/Counter Mode). Its operation can be summarised as:

$$
(C,T) = \mathsf{AEADEnc}_K(N, P, A)
$$

where  

* $N$ (nonce) is 96 bits and **must never repeat** under the same $K$;  
* $A$ is optional associated data (e.g., packet headers) that is authenticated but not encrypted;  
* $C = P \oplus \mathsf{Enc}_K(\text{CTR}_i)$ (CTR mode);  
* $T$ is a 128‑bit tag derived from a GHASH multiplication in the Galois field $GF(2^{128})$.

Decryption verifies $T$ before releasing $P$:

$$
P = \mathsf{AEADDec}_K(N, C, A, T) \quad \text{(returns error if verification fails)}.
$$

### 1.4.5.5 Worked example (AES‑GCM, 128‑bit key)

Assume a simplified environment where all intermediate values are expressed in hexadecimal.

| Parameter | Value (hex) |
|-----------|-------------|
| $K$ (AES‑128 key) | $00112233445566778899AABBCCDDEEFF$ |
| $N$ (nonce, 96 bits) | $CAFEBABE01234567$ |
| $P$ (plaintext, 64 bits) | $1122334455667788$ |
| $A$ (associated data, 32 bits) | $DEADBEEF$ |

**Step 1 – Counter block generation**  
The initial counter block $CB_0 = N || 0x00000001$ → $CB_0 = \text{CAFEBABE0123456700000001}$.  

Encrypt $CB_0$ with AES‑128:

$$
S_0 = \mathsf{Enc}_K(CB_0) = 0x8E1A0B9F4A1C2D3E4F5A6B7C8D9E0F1A.
$$

**Step 2 – Encryption of plaintext**  
Counter for the first plaintext block: $CB_1 = N || 0x00000002$.  

$$
S_1 = \mathsf{Enc}_K(CB_1) = 0x3B4C5D6E7F8091A2B3C4D5E6F7080910.
$$  

Ciphertext $C = P \oplus S_1$  

$$
C = 1122334455667788 \oplus 3B4C5D6E7F8091A2B3C4D5E6F7080910 = 2A6F6E2A2AE6E6EA.
$$

**Step 3 – GHASH (authentication tag)**  
Compute $X = \text{GHASH}_H(A \| C \| \text{len}(A) \| \text{len}(C))$, where $H = \mathsf{Enc}_K(0^{128})$.  
Assume $H = 0x66E94BD4EF8A2C3B884CFA59CA342B2E$ (pre‑computed).  
After performing the finite‑field multiplication (omitted for brevity), we obtain $X = 0x5F8D9C3B4A6E1F2D3C4B5A6978876655$.

**Step 4 – Tag generation**  

$$
T = S_0 \oplus X = 0x8E1A0B9F4A1C2D3E4F5A6B7C8D9E0F1A \oplus 5F8D9C3B4A6E1F2D3C4B5A6978876655 = D19797809072461313F1D1E5B5B79D74F.
$$

The final transmitted payload is $(C,T) = (\text{2A6F6E2A2AE6E6EA},\ \text{D19797809072461313F1D1E5B5B79D74F})$.

A receiver that knows $K$ and $N$ repeats steps 1–4, verifies $T$, and recovers $P$ only if the tag matches.

### 1.4.5.6 Practical notes & common pitfalls  

| Pitfall | Why it is dangerous | Remedy |
|---------|---------------------|--------|
| Re‑using $IV$/nonce with the same $K$ (e.g., CBC with static IV, GCM with repeated nonce) | Leads to keystream reuse → linear equations that reveal $P$; in GCM it also collapses the authentication guarantee. | Enforce a per‑session counter or random generator with a statistically negligible collision probability. |
| Employing ECB mode for user data | Patterns in $P$ survive unchanged in $C$, enabling traffic analysis. | Use CBC, CTR, or AEAD modes; ECB is only acceptable for small, randomised tokens. |
| Separate keys for encryption and MAC but derived from the same master key without a proper KDF | Correlation may be exploitable; key‑reuse attacks exist. | Apply a well‑defined Key Derivation Function (e.g., HKDF) to produce independent $K_{\text{enc}}$ and $K_{\text{mac}}$. |
| Truncating the authentication tag to less than 64 bits in a high‑throughput radio link | Increases forgery probability to $2^{-t}$ where $t$ is tag length; 64 bits may be acceptable, but shorter values are not. | Follow 3GPP TS 33.401 which mandates at least 128‑bit tags for NAS and RRC. |
| Forgetting to authenticate associated data (e.g., packet headers) | An attacker can modify routing or QoS fields without detection. | Use AEAD modes that include $A$ in the GHASH computation, or explicitly MAC the header. |

**Standard reference** – 3GPP TS 33.401 “Security Architecture and Procedures for 5G System” defines the use of AES‑GCM (128‑bit key, 96‑bit nonce, 128‑bit tag) for user‑plane confidentiality and integrity in the 5G NR. Adhering to the prescribed key hierarchy and nonce construction eliminates the above pitfalls.

---

In summary, encryption protects the *privacy* of telecom traffic, while integrity protection guards against *undetected manipulation*. Proper selection of algorithms (AES‑GCM or ChaCha20‑Poly1305), disciplined nonce management, and rigorous key derivation are the engineering foundations that keep modern networks trustworthy.
