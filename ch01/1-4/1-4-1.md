# 1.4.1 網管架構：FCAPS、OSS／BSS

所屬：[1.4 網管、計費、安全與密碼學](../1-4.md)

## 正文

Modern telecommunication networks are no longer monolithic boxes but collections of software‑defined functions that can be instantiated, scaled, and upgraded independently. To keep such a distributed system operable, a *service‑based management architecture* (SBMA) is defined in 3GPP TS 28.533 §4. SBMA replaces the older “FCAPS” (Fault, Configuration, Accounting, Performance, Security) view and the classic OSS/BSS split with a more granular, API‑driven model. The SBMA concepts are the foundation for any network‑management system that must expose, consume, or orchestrate management capabilities across vendors and domains.

---

### 1.1 Core Concepts of SBMA

| Term | Definition (per TS 28.533 §4) |
|------|------------------------------|
| **Management Service (MnS)** | A *set of offered capabilities* for management and orchestration of network and services. The entity producing an MnS is the *MnS producer*; the entity consuming it is the *MnS consumer*【[TS 28.533 §4.1]】. |
| **MnS component type A** | A group of *network‑agnostic* management operations/notifications (e.g., generic CRUD operations)【[TS 28.533 §4.2.2]】. |
| **MnS component type B** | A *Network Resource Model* (NRM) that represents managed entities (e.g., models defined in TS 28.622, TS 28.541)【[TS 28.533 §4.2.3.1]】. |
| **MnS component type C** | *Performance* and *fault* information of the managed entity (e.g., alarm or performance data)【[TS 28.533 §4.2.3.2]】. |
| **MnS producer profile** | Metadata describing which components (A, B, C) and which *version numbers* are supported, optionally indicating extra features such as filtering【[TS 28.533 §4.2.4]】. |
| **Management Function (MnF)** | A logical entity that can act as both MnS producer and consumer【[TS 28.533 §4.5]】. |

An MnS **must contain at least two** of the component types (A+B, or B+C)【[TS 28.533 §4.2.1]】. The combination determines whether the service focuses on generic operations, resource modelling, or performance/fault data.

---

### 1.2 Service Exposure and Governance

When an MnS is exposed without any control, any consumer (including third parties) can invoke *all* offered capabilities【[TS 28.533 §4.4]】. SBMA therefore introduces **Management Capability Exposure Governance**, which allows the producer to restrict access to selected components (A, B, C) based on policy or contractual agreements. The governance process is illustrated in Figure 4.4.1 of the specification: a producer first offers an MnS, a privileged consumer (often an operator) requests a specific governance policy, and a *derived* MnS′ is generated that enforces the policy【[TS 28.533 §4.4]】.

Key practical points:

* The **association** between component metadata and MnS instances is required for governance, but its concrete implementation is left to the vendor【[TS 28.533 §4.4]】.
* A single MnF can embody the roles of producer, consumer, and governance manager simultaneously【[TS 28.533 §4.4]】.

---

### 1.3 Worked Example – Exposing a Configuration‑Performance Service

Consider a virtualised LTE Core Network function (e.g., the AMF) that wants to expose a management service to an OSS/BSS orchestration platform.

| Step | Action | Details |
|------|--------|---------|
| 1 | **Define components** | • **A** – CRUD operations for AMF instances (create, read, update, delete).<br>• **B** – NRM defined in TS 28.622 describing AMF parameters.<br>• **C** – Performance counters (e.g., session setup latency) defined in TS 28.552. |
| 2 | **Assemble MnS** | The MN‑service includes components **A** and **B** (A+B) – satisfies the “at least two components” rule【[TS 28.533 §4.2.1]】. |
| 3 | **Publish producer profile** | Version 1.0 for component A, version 2.1 for component B, optional filtering *supported* (recorded in the profile)【[TS 28.533 §4.2.4]】. |
| 4 | **Apply exposure governance** | The operator requests that performance data (component C) be hidden from third‑party OSS. Governance creates MnS′ that only contains A+B. |
| 5 | **Consume MnS′** | The OSS registers as an MnS consumer, invokes a *read* operation on the NRM (component B) to obtain current AMF configuration, and uses the generic *update* operation (component A) to modify a threshold. |

In this example the **service interface** is a set of API endpoints defined by the MnS producer; the consumer interacts only with the allowed subset, ensuring security and compliance.

---

### 1.4 Relation to FCAPS and OSS/BSS

*FCAPS* and the traditional *OSS/BSS* architecture are **outside the scope of the TS 28.533 reference**; they are not described in the cited clauses. However, SBMA can be viewed as a modern, service‑oriented reinterpretation of the same management dimensions: *fault* and *performance* map to component C, *configuration* maps to component A, and *accounting* is typically handled by separate billing services (covered in another subsection). OSS/BSS systems become **consumers** of MnS instances, while network functions act as **producers**.

---

### 1.5 Common Pitfalls and Practical Notes

| Pitfall | Why it happens | Correct practice |
|---------|----------------|------------------|
| **Omitting component B** | Assuming generic CRUD (A) is sufficient. | Remember that an MnS must contain **at least two** components; include either B or C【[TS 28.533 §4.2.1]】. |
| **Exposing all capabilities without governance** | Belief that “open APIs” are always safe. | Apply *Management Capability Exposure Governance* to restrict access to sensitive performance/fault data【[TS 28.533 §4.4]】. |
| **Confusing producer profile with runtime data** | Treating version numbers as dynamic metrics. | The producer profile is *static metadata* describing supported components and optional features, not live performance counters【[TS 28.533 §4.2.4]】. |
| **Implementing governance logic inside the consumer** | Assuming the consumer will self‑filter. | Governance is enforced **by the producer** when creating MnS′; the consumer receives only the allowed API surface【[TS 28.533 §4.4]】. |
| **Assuming a single MnF cannot be both producer and consumer** | Misreading the MnF definition. | A MnF may play *both* roles simultaneously【[TS 28.533 §4.5]】. |

By adhering strictly to the component composition rules, publishing accurate producer profiles, and applying exposure governance, engineers can build interoperable, secure management interfaces that align with the SBMA model defined by 3GPP.

## 練習題

**1.** Which statement correctly describes a requirement for a concrete Management Service (MnS) according to TS 28.533 §4?

- A. It must contain exactly one component of type A, B, or C.
- B. It must be composed of at least two components, selected from types A, B, and C.
- C. It may consist solely of component type C if performance data is needed.
- D. It must include all three component types A, B, and C.

<details><summary>看答案</summary>

正解：B。The specification mandates that a concrete MnS is composed of at least two components.

</details>

**2.** In SBMA, which component type carries alarm and performance information?

- A. Component type A
- B. Component type B
- C. Component type C
- D. Component type D

<details><summary>看答案</summary>

正解：C。Component type C is defined for performance and fault (alarm) information.

</details>

**3.** What is the role of a Management Capability Exposure Governance when an MnS is exposed?

- A. It automatically upgrades the MnS version.
- B. It filters the MnS to a subset of components according to policy.
- C. It converts component type B into type A.
- D. It removes the need for an MnS producer profile.

<details><summary>看答案</summary>

正解：B。Governance applies a policy that limits which components are accessible, producing a derived MnS′.

</details>

**4.** Which of the following best describes a Management Function (MnF)?

- A. A physical network element that only consumes MnS.
- B. A logical entity that can act as MnS producer, consumer, or both.
- C. A database that stores component type B models.
- D. An optional feature listed in the MnS producer profile.

<details><summary>看答案</summary>

正解：B。The MnF is defined as a logical entity playing the roles of MnS consumer and/or producer.

</details>

**5.** When a producer publishes its MnS, what information is included in the MnS producer profile?

- A. Real‑time performance counters.
- B. Supported component types and their version numbers, possibly optional features.
- C. The full list of authorized MnS consumers.
- D. The encryption keys for secure transport.

<details><summary>看答案</summary>

正解：B。The producer profile holds metadata about supported components, versions, and optional features.

</details>
