## 正文

Modern telecom networks rely on cryptography to protect subscriber data, ensure the integrity of signalling, and authenticate devices. Whether a mobile core is encrypting user‑plane payload, a 5G base station is establishing a secure key with a UE, or a billing system is hashing a customer identifier, the four primitive concepts—**symmetric encryption**, **public‑key encryption**, **cryptographic hash functions**, and **random number generation**—form the mathematical backbone of every security service.

---

### 1. Symmetric Encryption  

A symmetric algorithm uses a **single secret key** $K$ for both encryption and decryption:

$$
C = E_K(P) \qquad\text{(encryption)}
$$
$$
P = D_K(C) \qquad\text{(decryption)}
$$

* $P$ – plaintext (bits, typically measured in bytes)  
* $C$ – ciphertext (same length as $P$)  
* $E_K$, $D_K$ – algorithmic transformations parameterised by $K$  

Common families: **block ciphers** (AES, 128‑bit block size) and **stream ciphers** (ChaCha20). Security is expressed by the **key length** $|K|$ (bits); a 128‑bit key provides $2^{128}$ possible keys, far beyond exhaustive search capabilities of current hardware.

**Modes of operation** (e.g., CBC, GCM) turn a block cipher into a probabilistic encryptor by adding an **initialisation vector** (IV) $V$:

$$
C = E_K^{\text{GCM}}(P, V)
$$

GCM also yields an authentication tag $T$, providing confidentiality *and* integrity.

---

### 2. Public‑Key (Asymmetric) Encryption  

Public‑key cryptography employs a **key pair** $(K_{\text{pub}}, K_{\text{priv}})$. The public key can be distributed openly; the private key remains secret.

A classic example is **RSA**. Let $p$ and $q$ be distinct large primes, $n = p q$, and $\phi(n) = (p-1)(q-1)$. Choose a public exponent $e$ such that $\gcd(e,\phi(n)) = 1$, then compute the private exponent $d$ satisfying

$$
e d \equiv 1 \pmod{\phi(n)} .
$$

Encryption of a message $m$ (interpreted as an integer $0 \le m < n$) is

$$
c = m^{e} \bmod n ,
$$

and decryption is

$$
m = c^{d} \bmod n .
$$

Security rests on the difficulty of factoring $n$; key sizes of at least 2048 bits are recommended for long‑term protection.

Elliptic‑curve cryptography (ECC) offers comparable security with much shorter keys (e.g., 256‑bit curves for ~128‑bit security) by operating on points $P = (x,y)$ over a finite field $\mathbb{F}_p$ and using scalar multiplication $kP$ as the one‑way function.

---

### 3. Cryptographic Hash Functions  

A hash function $H$ maps an arbitrary‑length message $M$ to a fixed‑length **digest** $h$:

$$
h = H(M), \qquad h \in \{0,1\}^{\ell}
$$

where $\ell$ is the output length (e.g., 256 bits for SHA‑256). Desired properties:

* **Pre‑image resistance**: given $h$, finding any $M$ with $H(M)=h$ is infeasible.  
* **Second pre‑image resistance**: given $M_1$, finding $M_2 \neq M_1$ with $H(M_2)=H(M_1)$ is infeasible.  
* **Collision resistance**: finding any pair $(M_1,M_2)$ with $M_1\neq M_2$ and $H(M_1)=H(M_2)$ is infeasible.  

Hash functions are used for **integrity checks**, **digital signatures**, and as building blocks in key‑derivation functions.

---

### 4. Random Number Generation  

Cryptographic operations require unpredictable numbers: session keys, IVs, nonces, and salts. Two classes are defined:

| Class | Source | Example | Typical Use |
|------|--------|---------|-------------|
| **True Random Number Generator (TRNG)** | Physical entropy (thermal noise, quantum effects) | Hardware RNG chip | Seed for PRNG, high‑value keys |
| **Pseudo‑Random Number Generator (PRNG)** | Deterministic algorithm seeded with entropy | NIST‑approved DRBG (e.g., Hash‑DRBG) | Bulk key material, IVs, nonces |

A **cryptographically secure PRNG (CSPRNG)** must satisfy forward and backward secrecy: knowing the current state must not reveal past outputs, nor allow prediction of future outputs without the seed.

**Entropy estimate** $H_{\text{bits}}$ quantifies randomness; a minimum of 128 bits of entropy is recommended for a master secret in TLS‑like protocols.

---

### Worked Example: RSA Encryption & Decryption (small numbers)

> **Goal:** Encrypt the integer $m = 65$ using RSA with small primes for illustration.

1. Choose primes: $p = 61$, $q = 53$.  
   Compute modulus $n = p q = 61 \times 53 = 3233$.  
   Compute $\phi(n) = (p-1)(q-1) = 60 \times 52 = 3120$.
2. Choose public exponent $e = 17$ (common small exponent, $\gcd(17,3120)=1$).  
3. Compute private exponent $d$ such that $e d \equiv 1 \pmod{3120}$.
   Using the extended Euclidean algorithm, $d = 2753$ because $17 \times 2753 = 46801 = 1 + 15 \times 3120$.
4. **Encryption:**  
   $$
   c = m^{e} \bmod n = 65^{17} \bmod 3233 = 2790 .
   $$
5. **Decryption:**  
   $$
   m' = c^{d} \bmod n = 2790^{2753} \bmod 3233 = 65 .
   $$
   The recovered plaintext $m'$ matches the original $m$, confirming correctness.

*Note:* Real deployments use $p$, $q$ of at least 1024 bits each; the tiny numbers above are only pedagogical.*

---

### Common Pitfalls & Practical Tips  

1. **Key reuse across domains** – Using the same symmetric key for encrypting user data *and* generating MACs breaks the proven security of authenticated encryption modes (e.g., GCM). Allocate distinct keys or employ a key‑derivation function (KDF) to separate purposes.
2. **Insufficient key length** – 56‑bit DES or 1024‑bit RSA are considered broken; always follow current recommendations (AES‑128/256, RSA‑2048+, ECC‑P‑256).
3. **Deterministic encryption** – Omitting a fresh IV/nonce (e.g., encrypting two identical payloads with the same key and IV) reveals patterns and enables replay attacks. Generate nonces with a CSPRNG and never repeat them with the same key.
4. **Weak random sources** – Seeding a PRNG with low‑entropy data (e.g., timestamps) leads to predictable keys. Combine multiple entropy sources and, when possible, use hardware TRNGs.
5. **Ignoring hash collisions** – Although collisions in SHA‑256 are currently infeasible, protocols that rely solely on hashes for authentication (e.g., HMAC without a secret) are vulnerable. Always pair hashes with a secret key (HMAC) or use digital signatures for non‑repudiation.

By mastering these primitives and observing the operational cautions, telecom engineers can design robust security mechanisms that scale from 2G signalling to 5G core network functions.
