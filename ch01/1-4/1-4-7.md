# 1.4.7 網路安全威脅與防護

所屬：[1.4 網管、計費、安全與密碼學](../1-4.md)

## 正文

In any telecommunications network, the functions that manage, bill, and secure subscribers run on *generic network products* (GNPs) such as management servers, databases, and virtualised network functions. If an attacker compromises a GNP, the impact can range from service outage to loss of personal data. Consequently, identifying **critical assets** and the **generic threats** that target them is a prerequisite for any security‑by‑design effort.

### Critical assets defined in TS 33.926

TS 33.926 §5.2 enumerates the assets that must be protected:

* **User account data and credentials** – passwords, usernames, and other authentication material.  
* **Log data** – audit trails that record system events.  
* **Configuration data** – IP addresses, ports, VPN identifiers, management objects, etc.  
* **Operating System (OS)** – both the files that constitute the OS and its running processes.  
* **GNP Application** – the functional software that provides network‑management services.  
* **Sufficient processing capacity** – the ability of the system to operate without exhausting CPU, memory, or storage.  
* **Hardware** – physical components such as boards, power supplies, and chassis.  
* **Interfaces** – e.g., the **Console interface** for local access and the **OAM interface** for remote management.  
* **GNP Software** – any binary or executable code owned by any user, including the items above.

These assets constitute the *attack surface*; protecting them requires a systematic threat analysis. [TS 33.926 §5.2]

### The STRIDE taxonomy of generic threats

TS 33.926 §5.3 adopts the six STRIDE categories originally defined by Microsoft:

| Category | Typical exploit (as described in the specification) |
|----------|------------------------------------------------------|
| **Spoofing identity** | Illegally accessing and using another user’s authentication information (e.g., username and password). |
| **Tampering with data** | Unauthorized changes to persistent data (e.g., a database) or alteration of data in transit. |
| **Repudiation** | Users deny having performed an action, and the system lacks evidence to prove otherwise. |
| **Information disclosure** | Exposure of data to parties that should not have access, such as reading files without permission or intercepting data in transit. |
| **Denial of service** | Making a service unavailable to legitimate users (e.g., overwhelming a web server). |
| **Elevation of privilege** | An unprivileged user gains privileged access, allowing full system compromise. |

Each threat is described in the reference with a short narrative that ties the *action* (e.g., “reading a file”) to the *impacted asset* (e.g., “User account data”). [TS 33.926 §5.3]

### Mapping threats to assets

A concise way to organise protection measures is to create a **threat‑asset matrix**. For illustration, consider three assets from the list above:

| Asset | Relevant STRIDE threats | Example from the specification |
|-------|--------------------------|---------------------------------|
| **User account data** | Spoofing identity, Information disclosure, Elevation of privilege | “Illegally accessing and then using another user’s authentication information” (spoofing) and “Information disclosure threats involve the exposure of information to individuals who are not supposed to have access to it.” |
| **Configuration data** | Tampering with data, Information disclosure | “Data tampering involves the malicious modification of data… unauthorized changes made to persistent data, such as that held in a database.” |
| **Console interface** | Spoofing identity, Elevation of privilege, Denial of service | The interface itself is listed among the “interfaces of GNP to be protected.” An attacker who gains local console access could spoof identity or elevate privilege. |

By explicitly linking each asset to the relevant STRIDE categories, engineers can derive security requirements (e.g., authentication for console access, integrity protection for configuration files, logging to detect repudiation).

### Worked example: Identifying a threat for a log‑file leak

*Scenario*: A log file stored on the GNP’s filesystem contains timestamps of user authentication attempts, including usernames.

1. **Asset** – *Log data* (listed as a critical asset). [TS 33.926 §5.2]  
2. **Potential threat** – *Information disclosure* because an attacker who reads the file learns usernames that may be used in subsequent attacks. [TS 33.926 §5.3]  
3. **Mitigation** – Apply file‑system permissions (restrict read access to privileged accounts) and encrypt the log at rest. While the reference does not prescribe a specific mitigation, the mapping shows that protecting the asset against the identified STRIDE category is required.

### Practical notes and common mistakes

1. **Assuming 3GPP interface coverage is sufficient** – The specification explicitly states that threats related to 3GPP‑defined interfaces “may have been sufficiently covered” and are therefore *not* considered separately here. However, many attacks target local interfaces or internal processes that are *outside* the scope of those interface specifications. [TS 33.926 §5.3.2]  
2. **Over‑looking the “Processing capacity” asset** – DoS attacks are often thought of only as network‑layer floods, but exhausting CPU or memory on a management node also constitutes a denial‑of‑service threat to the *sufficient processing capacity* asset.  
3. **Treating “GNP Software” as a single monolithic item** – The reference clarifies that any executable code, regardless of ownership, is part of the asset list. Ignoring user‑installed scripts or third‑party binaries can leave a hidden attack vector. [TS 33.926 §5.2]  
4. **Confusing “Repudiation” with “Non‑repudiation”** – The specification distinguishes the two: repudiation is the threat, whereas non‑repudiation is the protective property (e.g., signed receipts). Designing audit logs without cryptographic integrity checks fails to counter repudiation. [TS 33.926 §5.3]  

By systematically enumerating assets, applying the STRIDE taxonomy, and recognising the limits of existing 3GPP interface security, telecom engineers can construct a robust threat model that guides the selection of authentication, integrity, confidentiality, and availability controls across the entire management plane.

## 練習題

**1.** Which of the following is **not** listed among the generic critical assets in TS 33.926 §5.2?

- A. User account data and credentials
- B. Encryption keys
- C. Log data
- D. Configuration data

<details><summary>看答案</summary>

正解：B。The asset list includes user account data, log data, and configuration data, but does not mention encryption keys.

</details>

**2.** Which STRIDE category specifically describes attacks that make a service unavailable to legitimate users?

- A. Spoofing identity
- B. Denial of service
- C. Elevation of privilege
- D. Repudiation

<details><summary>看答案</summary>

正解：B。The definition of denial‑of‑service attacks in the reference matches this description.

</details>

**3.** According to TS 33.926, why might some threats not be addressed by existing 3GPP security specifications?

- A. They are considered irrelevant to telecom networks.
- B. They relate to actions local to the NP and/or do not affect interoperability.
- C. They are already mitigated by hardware firewalls.
- D. They are covered by other international standards.

<details><summary>看答案</summary>

正解：B。The reference notes that locally‑scoped threats may be omitted from 3GPP work.

</details>

**4.** Which of the following is given as an example of a GNP interface that must be protected?

- A. Console interface
- B. User data interface
- C. Encryption key interface
- D. Billing API

<details><summary>看答案</summary>

正解：A。The specification lists the console interface as a protected interface.

</details>

**5.** An attacker who modifies entries in a database without authorization is exploiting which STRIDE threat category?

- A. Tampering with data
- B. Information disclosure
- C. Repudiation
- D. Elevation of privilege

<details><summary>看答案</summary>

正解：A。The reference defines tampering as unauthorized changes to persistent data such as databases.

</details>
