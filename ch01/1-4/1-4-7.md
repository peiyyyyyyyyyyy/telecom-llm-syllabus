# 1.4.7 網路安全威脅與防護

## 正文

In any operational telecom network, the confidentiality, integrity, and availability (CIA) of user data and control plane signalling are continuously challenged by a wide spectrum of attacks.  A breach can lead to revenue loss, regulatory penalties, service outage, or even end‑user safety issues (e.g., malicious control of vehicular communication).  Consequently, network engineers must understand **what** the threats are, **how** they are quantified, and **which** technical controls mitigate them.

---

### 1.4.1 Threat taxonomy

| Category | Typical attacks | Primary impact |
|----------|----------------|----------------|
| **Passive eavesdropping** | Traffic sniffing, IMSI catchers, passive radar | Loss of confidentiality |
| **Active tampering** | Message modification, replay, man‑in‑the‑middle (MitM) | Loss of integrity, authentication bypass |
| **Denial‑of‑service (DoS) / Distributed DoS (DDoS)** | SYN flood, UDP amplification, signaling storm | Loss of availability |
| **Authentication attacks** | Credential stuffing, offline password cracking, AKA replay | Unauthorized access |
| **Infrastructure compromise** | Rogue base stations, compromised OSS/BSS, supply‑chain malware | Systemic control loss |
| **Side‑channel & cryptanalytic attacks** | Power analysis, timing attacks, quantum‑size reductions | Reduced effective key strength |

The **3GPP TS 33.501** security architecture explicitly lists these vectors for 5G, but the classification is applicable to LTE, GSM, and even fixed‑line back‑haul.

---

### 1.4.2 Quantifying attack feasibility

A common first‑order metric is the **probability of a successful brute‑force guess** for a symmetric key of length $k$ bits:

$$
P_{\text{succ}} = \frac{1}{2^{k}}.
$$

If an attacker can test $R$ candidate keys per second, the **expected time** to recover the key is

$$
T_{\text{exp}} = \frac{2^{k-1}}{R}\quad\text{seconds}.
$$

*Symbols*:  
- $k$: key length (bits)  
- $R$: trial rate (keys · s$^{-1}$)  
- $P_{\text{succ}}$: single‑try success probability (dimensionless)  
- $T_{\text{exp}}$: expected time to success (s)

For a **cryptographic integrity check**, the probability that a random packet passes a $n$‑bit Message Authentication Code (MAC) is

$$
P_{\text{MAC\_pass}} = \frac{1}{2^{n}}.
$$

Thus a 64‑bit MAC yields a forgery probability of $5.4\times10^{-20}$ per attempt.

---

### 1.4.3 Worked example – brute‑forcing AES‑128

Assume an attacker possesses a high‑performance GPU farm capable of $R = 10^{12}$ AES‑128 key trials per second (a realistic upper bound for modern ASICs).  

- Key length $k = 128$ bits.  

The expected time to recover the key is

$$
T_{\text{exp}} = \frac{2^{127}}{10^{12}} \approx \frac{1.7\times10^{38}}{10^{12}} = 1.7\times10^{26}\ \text{s}.
$$

Convert to years:

$$
\frac{1.7\times10^{26}\ \text{s}}{60\cdot60\cdot24\cdot365}\approx 5.4\times10^{18}\ \text{years},
$$

far exceeding the age of the universe.  This demonstrates why **key length selection** is the primary lever for resisting exhaustive search, provided the key is generated with sufficient entropy (see §1.4.6).

---

### 1.4.4 Counter‑measure toolbox

| Threat | Primary counter‑measure(s) | Relevant parameter / formula |
|--------|---------------------------|------------------------------|
| Passive eavesdropping | End‑to‑end encryption (e.g., IPsec, EPS security), SUPI concealment (SUCI) | Encryption throughput $T_{\text{eff}} = T_{\text{raw}}\bigl(1-\frac{H}{L}\bigr)$ |
| Active tampering / replay | Integrity protection (MAC), sequence numbers, nonce‐based AKA | MAC forgery probability $P_{\text{MAC\_pass}}$ |
| DoS / DDoS | Rate limiting, traffic shaping, SYN cookies, network‑level scrubbing centers | Maximum sustained rate $R_{\max}$ after mitigation |
| Authentication attacks | Strong mutual authentication (e.g., 5G‑AKA), credential rotation, password hashing with salt (bcrypt, scrypt) | Salted hash work factor $W$ (iterations) |
| Rogue infrastructure | Certificate‑based base‑station authentication, secure boot, TPM attestation | Certificate revocation checking (CRL/OCSP) |
| Side‑channel | Constant‑time implementations, masking, hardware random number generators (TRNG) | Entropy per bit $E\ge 1$ (ideal) |

**Key management** is the glue that ties these mechanisms together.  The 3GPP **Key Derivation Function (KDF)** defined in TS 33.501 produces fresh session keys ($K_{\text{encr}}$, $K_{\text{int}}$, $K_{\text{up}}$) from a master secret $K_{\text{ausf}}$ using a hash‑based HMAC:

$$
K_i = \text{HMAC}_{\text{SHA‑256}}\bigl(K_{\text{ausf}},\; \text{Info}_i\bigr),
$$

where $\text{Info}_i$ includes context such as serving network name, UE identity, and a counter.  The HMAC construction guarantees that **key isolation** holds: compromise of $K_i$ does not reveal $K_{\text{ausf}}$.

---

### 1.4.5 Practical notes & common pitfalls

1. **Static or short‑lived keys** – Re‑using the same $K_{\text{encr}}$ for months (e.g., in legacy LTE) dramatically reduces $T_{\text{exp}}$ because the attacker can accumulate ciphertext‑only samples and launch statistical attacks.  Rotate keys at least every 24 h for high‑value traffic.

2. **Insufficient entropy** – Generating a 128‑bit key from a pseudo‑random number generator seeded only with system time can yield effective entropy far below $k$, inflating $P_{\text{succ}}$.  Always employ a hardware TRNG or a vetted CSPRNG (e.g., NIST SP 800‑90A).

3. **Disabling integrity protection for performance** – Some operators disable EPS integrity on the user plane to reduce latency.  This removes the $P_{\text{MAC\_pass}}$ barrier, enabling undetectable packet injection.  Modern ASICs can compute 64‑bit MACs at line rate, so the performance penalty is negligible.

4. **Mis‑configured firewalls / ACLs** – Overly permissive rules (e.g., “allow all traffic from any IP to the S1‑MME interface”) open the signaling plane to DoS and MitM.  Apply the principle of least privilege and enforce stateful inspection.

5. **Neglecting side‑channel hardening** – Even with mathematically strong algorithms, a poorly implemented AES core can leak key bits via power analysis.  Use constant‑time libraries and, where possible, hardware modules that meet FIPS 140‑2 Level 3.

By systematically mapping each identified threat to a concrete control, and by validating the control with the quantitative formulas above, telecom engineers can build networks that meet both commercial SLAs and regulatory security requirements.
