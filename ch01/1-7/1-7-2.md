# 1.7.2 干擾管理：遠端干擾（RIM）與交叉鏈路干擾（CLI）

所屬：[1.7 網路優化與終端](../1-7.md)

## 正文

In a live NR (New Radio) deployment, interference is one of the dominant factors that limit both coverage quality and usable capacity.  When a cell‑edge user experiences high interference, the signal‑to‑interference‑plus‑noise ratio (SINR) degrades, leading to lower throughput, higher block error rate, and possibly a failed hand‑over.  **Remote Interference Management (RIM)** and **Cross‑Link Interference (CLI)** are two concepts that appear in many operator‑level optimisation discussions:  

* **Remote Interference (RIM)** – interference that originates from a neighbouring NG‑RAN node (or a distant cell) whose radio parameters are not coordinated with the victim cell.  
* **Cross‑Link Interference (CLI)** – interference that occurs between two links that share the same frequency resources, for example when a down‑link transmission of one cell collides with the uplink transmission of a neighbouring cell on the same carrier.  

The official 3GPP specification that we are allowed to quote in this textbook, **TS 38.300 §15.5.5**, primarily defines the *Coverage and Capacity Optimisation (CCO)* function.  It states that CCO “detects and resolves or mitigates … coverage and cell‑edge interference issues” [TS 38.300 §15.5.5.1] and describes how an NG‑RAN node can change its coverage configuration and inform neighbours.  The detailed mechanisms that are labelled RIM or CLI in operator practice are **outside the scope of the reference text**; therefore this subsection can only summarise the high‑level relationship between the generic CCO procedures and the management of remote or cross‑link interference.

---

### 1.7.2.1 How CCO Supports Interference Mitigation  

The CCO function provides two key levers that can be employed to reduce both RIM and CLI:

| Lever | Description | Relevance to Interference |
|------|-------------|---------------------------|
| **Alternative Coverage Configurations** | OAM may configure a node with several sets of radio parameters (e.g., transmission power, antenna tilt, SSB periodicity) together with allowed adjustment ranges. | By selecting a less aggressive configuration for a cell that is identified as a strong interferer, the node can lower its emitted power and thus mitigate RIM on neighbours. |
| **Dynamic Coverage Configuration Changes** | An NG‑RAN node may autonomously switch between coverage configurations and notify neighbours via the *NG‑RAN NODE CONFIGURATION UPDATE* message, which carries a list of modified cells and SSBs together with a *coverage state indicator*. | The neighbour can use the received indicator to adapt its own mobility‑robustness optimisation, for example by avoiding hand‑overs to a cell that has just been set to an inactive state, thereby preventing hand‑over failures caused by sudden interference spikes. |

Both levers are defined in the reference text and can be interpreted as generic tools for interference control, even though the specification does not explicitly name RIM or CLI.

---

### 1.7.2.2 Key Definitions  

* **Coverage State Indicator (CSI)** – a binary or enumerated value transmitted in the *NG‑RAN NODE CONFIGURATION UPDATE* that describes the current coverage status of a cell or SSB (e.g., *active*, *reduced*, *inactive*).  The exact encoding is implementation‑specific, but the presence of the indicator enables neighbours to react appropriately [TS 38.300 §15.5.5.3].  

* **NG‑RAN NODE CONFIGURATION UPDATE** – the Xn‑based message that carries the list of cells/SSBs whose coverage parameters have been modified, together with their CSI [TS 38.300 §15.5.5.3].  

* **Neighbour NG‑RAN Node** – any NG‑RAN node that shares an Xn interface with the transmitting node and therefore receives the configuration update [TS 38.300 §15.5.5.3].

---

### 1.7.2.3 Worked Example  

Assume two neighbouring gNBs, **gNB‑A** and **gNB‑B**, are connected over the Xn interface.  gNB‑A detects that its down‑link transmission is causing excessive RIM on the cell‑edge users of gNB‑B.  Using its pre‑configured alternative coverage configurations, gNB‑A decides to switch Cell C1 to a *reduced* coverage state.

1. **Select configuration** – gNB‑A chooses the alternative configuration where the transmission power of Cell C1 is reduced by 3 dB.  
2. **Generate update** – gNB‑A sends an *NG‑RAN NODE CONFIGURATION UPDATE* to gNB‑B containing:  

   * CGI = 001‑02‑C1 (unique identifier of Cell C1)  
   * Coverage State Indicator = 0 (meaning *reduced*).  

3. **Neighbour reaction** – Upon receipt, gNB‑B reads the CSI and, according to its locally stored Mobility Robustness Optimisation (MRO) state, refrains from triggering hand‑overs toward Cell C1 while the reduced state persists [TS 38.300 §15.5.5.3].

| Symbol | Meaning | Example Value |
|--------|---------|---------------|
| $P_{\text{orig}}$ | Original down‑link power (dBm) | 30 dBm |
| $\Delta P$ | Power reduction (dB) | –3 dB |
| $P_{\text{new}} = P_{\text{orig}} + \Delta P$ | New down‑link power | 27 dBm |
| CSI | Coverage State Indicator (0 = reduced) | 0 |

By lowering $P_{\text{new}}$, the interference power received by the victim UE in gNB‑B is reduced by a factor of $10^{\Delta P/10}=10^{-0.3}\approx0.5$, i.e., roughly a 50 % reduction in linear scale.  This simple adjustment directly mitigates the remote interference without requiring a full re‑planning of the network.

---

### 1.7.2.4 Common Mistakes and Practical Notes  

| Mistake | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| **Ignoring the CSI** – Operators sometimes trigger hand‑overs to a cell that has just been set to *inactive* because the neighbour node did not process the update in time. | The update may be delayed or the receiving node may not map the CSI to its MRO logic. | Ensure that the *NG‑RAN NODE CONFIGURATION UPDATE* is processed promptly and that the CSI is used to suppress hand‑overs toward inactive cells [TS 38.300 §15.5.5.3]. |
| **Applying a static configuration** – Using a single coverage configuration for all traffic conditions, which can cause persistent CLI when uplink and downlink resources overlap. | No dynamic adaptation; the node cannot react to changing interference patterns. | Deploy alternative coverage configurations and enable autonomous switching, allowing the node to react to measured interference levels [TS 38.300 §15.5.5.2]. |
| **Not informing neighbours of planned re‑configuration** – Changing a cell’s state without sending the list of *replacing cells* or *inactive cells* can lead to connection failures. | The neighbour may attempt a hand‑over to a cell that is about to become unavailable. | Include planned re‑configuration details in the update message so that neighbours can avoid triggering problematic hand‑overs [TS 38.300 §15.5.5.3]. |

**Practical tip:** When configuring alternative coverage sets, include a realistic adjustment range for transmission power (e.g., ±3 dB).  This range is sufficient to alleviate many RIM situations while preserving enough link budget for the served UEs.  Always verify, via drive‑test or KPI monitoring, that the CSI‑based neighbour reactions are effective; otherwise, the intended interference mitigation may not materialise.

---

*Note:* The specific terminology “Remote Interference Management (RIM)” and “Cross‑Link Interference (CLI)” is commonly used in operator documentation and research papers, but the 3GPP TS 38.300 §15.5.5 reference does not define these terms explicitly.  Consequently, this subsection limits itself to the mechanisms that are explicitly described in the reference and explains how they can be leveraged to address the broader interference challenges that RIM and CLI represent.

- D. TS 36.331 §7.3.2

正解：A。The reference explicitly mentions the *NG‑RAN NODE CONFIGURATION UPDATE* message in §15.5.5.3.

</details>

**2.** What is the primary purpose of the Coverage State Indicator (CSI) sent in the configuration update?

- A. To indicate the exact transmit power value of a cell.
- B. To allow the receiving node to adjust its Mobility Robustness Optimisation.
- C. To request additional spectrum from the regulator.
- D. To trigger an immediate hand‑over to the indicated cell.

<details><summary>看答案</summary>

正解：B。The CSI is used by the neighbour to adjust MRO functions, as stated in the reference.

</details>

**3.** According to the reference, what may a sending NG‑RAN node include in the update to help the receiver avoid connection failures?

- A. The UE’s GPS coordinates.
- B. A list of replacing cells and indication of planned re‑configuration.
- C. The full MAC scheduling table.
- D. The hardware serial number of the gNB.

<details><summary>看答案</summary>

正解：B。The reference mentions that the list may contain planned re‑configuration and replacing cells.

</details>

**4.** Which of the following actions is recommended to prevent hand‑overs toward a cell that has become inactive?

- A. Increase the UE’s transmission power.
- B. Disable the Xn interface temporarily.
- C. The receiving NG‑RAN node should avoid triggering hand‑overs towards cell(s) that are indicated to be inactive.
- D. Force the UE to stay on the current cell indefinitely.

<details><summary>看答案</summary>

正解：C。The reference explicitly advises avoiding hand‑overs to inactive cells.

</details>

**5.** What does the specification allow an NG‑RAN node to do with alternative coverage configurations?

- A. Permanently lock them after initial deployment.
- B. Adjust parameters only manually via OAM.
- C. Autonomously adjust within and switch between them.
- D. Broadcast them to all UEs in the network.

正解：C。The reference states that a node may autonomously adjust and switch between coverage configurations.

</details>
