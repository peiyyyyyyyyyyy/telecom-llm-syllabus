# 1.7.6 終端一致性測試（Conformance testing）

## 正文

Conformance testing (also called *compliance* or *type‑approval* testing) verifies that a user equipment (UE) or network terminal behaves exactly as specified in the relevant radio access standard (e.g., 3GPP TS 36.521 for LTE, 3GPP TS 38.521 for NR). In a live operator network, only devices that have passed conformance testing are allowed to connect because the tests guarantee that the terminal will not cause harmful interference, will respect timing and power limits, and will interoperate with all network functions. Without a rigorous conformance regime, a single non‑compliant UE could degrade coverage, increase hand‑over failures, or violate regulatory emission limits.

---

### 1. Key Definitions  

| Symbol | Meaning | Unit |
|--------|---------|------|
| $P_{\text{tx}}$ | Transmit power of the UE (average over the measurement interval) | dBm |
| $P_{\text{max}}$ | Maximum allowed transmit power defined by the standard for the given band | dBm |
| $E_{\text{meas}}$ | Measured emission level (e.g., spurious emission) | dBm |
| $E_{\text{limit}}$ | Emission limit (spectral mask) | dBm |
| $T_{\text{meas}}$ | Measured timing offset (e.g., RACH pre‑amble timing) | µs |
| $T_{\text{max}}$ | Maximum permissible timing offset | µs |
| $L_{\text{meas}}$ | Measured latency for a given procedure (e.g., RRC connection setup) | ms |
| $L_{\text{max}}$ | Specified latency ceiling | ms |
| $P_{\text{pass}}$ | Pass‑criteria indicator (binary, 1 = pass, 0 = fail) | – |
| $N_{\text{TC}}$ | Number of test cases executed for a given feature | – |
| $N_{\text{fail}}$ | Number of test cases that failed | – |

A UE is considered **conformant** if for every mandatory test case $i$ ($i = 1,\dots,N_{\text{TC}}$)

$$
P_{\text{pass}}^{(i)} = 
\begin{cases}
1, & \text{if } P_{\text{tx}}^{(i)} \le P_{\text{max}}^{(i)} \\
   & \text{and } E_{\text{meas}}^{(i)} \le E_{\text{limit}}^{(i)} \\
   & \text{and } T_{\text{meas}}^{(i)} \le T_{\text{max}}^{(i)} \\
   & \text{and } L_{\text{meas}}^{(i)} \le L_{\text{max}}^{(i)}\\[4pt]
0, & \text{otherwise}
\end{cases}
$$

The overall conformance result is often expressed as a *pass rate*:

$$
\text{Pass Rate} = \frac{N_{\text{TC}} - N_{\text{fail}}}{N_{\text{TC}}}\times 100\%
$$

A pass rate of 100 % is required for type‑approval; any failure must be corrected and the test repeated.

---

### 2. Test Architecture  

Conformance testing is performed in a **test laboratory** that provides:

1. **Test Equipment** – RF signal generators, spectrum analyzers, vector signal analyzers (VSA), and timing measurement tools that are calibrated to traceable standards.  
2. **Test Harness** – A software framework that drives the UE through standardized procedures (e.g., attach, hand‑over, carrier aggregation) and records the measured parameters.  
3. **Reference Network** – A simulated eNodeB/gNodeB (often called *test network* or *emulated base station*) that implements the exact protocol stack defined in the standard, allowing deterministic control of radio resources.

The test flow typically follows the *Test Specification* (e.g., 3GPP TS 36.521), which lists mandatory test cases, required equipment settings, and acceptance tolerances.

---

### 3. Typical Test Cases  

| Category | Example Test Case | Measured Parameter | Acceptance Criterion |
|----------|-------------------|--------------------|----------------------|
| **Power** | Verify maximum Tx power on Band 3 | $P_{\text{tx}}$ | $P_{\text{tx}} \le P_{\text{max}} = 23\ \text{dBm}$ |
| **Spectral Mask** | Measure out‑of‑band emissions | $E_{\text{meas}}$ | $E_{\text{meas}} \le E_{\text{limit}} = -45\ \text{dBm/MHz}$ |
| **Timing** | RACH pre‑amble timing alignment | $T_{\text{meas}}$ | $|T_{\text{meas}}| \le T_{\text{max}} = 2\ \mu\text{s}$ |
| **Latency** | RRC connection setup delay | $L_{\text{meas}}$ | $L_{\text{meas}} \le L_{\text{max}} = 100\ \text{ms}$ |
| **Procedural** | Correct handling of MME‑initiated detach | N/A | UE must send Detach Accept within 200 ms |

Each test case is executed under defined **environmental conditions** (temperature, supply voltage) because performance can vary across the operational range.

---

### 4. Worked Example: Transmit Power Conformance  

A UE is to be tested on LTE Band 1 (2100 MHz). The standard specifies a maximum UE transmit power $P_{\text{max}} = 23\ \text{dBm}$ with a tolerance of $\pm 1\ \text{dB}$.  

**Test steps**

1. Connect the UE to the test harness and command it to transmit a continuous reference signal at the highest allowed power level.  
2. Use a calibrated power meter placed at a distance that ensures far‑field conditions (≥ 2 m for 2100 MHz).  
3. Record the average measured power $P_{\text{meas}}$ over a 10 s interval.

**Measured result**: $P_{\text{meas}} = 22.8\ \text{dBm}$  

**Pass‑fail evaluation**

The acceptance interval is $[P_{\text{max}}-1,\; P_{\text{max}}+1] = [22,\; 24]\ \text{dBm}$. Since $22.8\ \text{dBm} \in [22,\;24]$, the test case passes:

$$
P_{\text{pass}} = 1.
$$

If the measurement had been $24.5\ \text{dBm}$, the UE would have failed the power test, requiring firmware or RF chain adjustment before re‑testing.

---

### 5. Common Mistakes and Practical Notes  

| Mistake | Why it Happens | Remedy |
|---------|----------------|--------|
| **Ignoring temperature drift** | Power amplifiers can vary > 2 dB across the -40 °C ÷ +85 °C range. | Perform the test at the worst‑case temperature or repeat across the full range. |
| **Using near‑field probe for far‑field power** | Near‑field measurements over‑estimate radiated power, leading to false failures. | Ensure the probe distance satisfies $d \ge \frac{2D^{2}}{\lambda}$, where $D$ is the largest antenna dimension and $\lambda$ the wavelength. |
| **Mismatched reference signal bandwidth** | Spectral mask limits are defined per 100 kHz or 1 MHz sub‑band; using a different bandwidth yields incorrect $E_{\text{meas}}$. | Align the measurement bandwidth to the specification (e.g., 100 kHz resolution bandwidth for spurious emission). |
| **Skipping calibration traceability** | Uncalibrated equipment introduces unknown systematic error, compromising pass/fail decisions. | Keep a calibration certificate within the last 12 months and apply the documented uncertainty budget. |
| **Treating “optional” test cases as “mandatory”** | Some features (e.g., carrier aggregation in a specific band) are optional; failing them may be misinterpreted as a full‑device failure. | Consult the test specification’s *mandatory/optional* matrix before interpreting results. |

Finally, remember that conformance testing is **not** a performance benchmark. A device may pass all conformance tests yet exhibit sub‑optimal throughput under heavy load; performance testing is a separate activity (e.g., 3GPP TS 36.522 for LTE performance). Conformance guarantees that the UE will *behave safely* and *interoperate* within the defined limits, which is the foundation for any subsequent optimization work.
