# 1.7.3 換手與移動性管理

所屬：[1.7 網路優化與終端](../1-7.md)

## 正文

Mobility management in 5G NR is the set of network‑controlled procedures that keep a User Equipment (UE) attached to the radio access network while it moves. In the RRC_CONNECTED state the UE can experience two distinct kinds of mobility: **cell‑level mobility** (handovers) and **beam‑level mobility** (intra‑cell or inter‑cell beam switches). Proper handling of both is essential for maintaining service continuity, minimizing latency, and avoiding unnecessary radio resource consumption in real deployments【TS 38.300 §9.2.3】.

---

### 1.2.1 Cell‑Level Mobility (Handover)

A handover is an explicit RRC signalling sequence that transfers the UE’s connection from a *source* gNB to a *target* gNB. The minimum elemental steps for an inter‑gNB handover are:

1. **HANDOVER REQUEST** – source gNB initiates the procedure and sends a request to the target gNB over the Xn interface.  
2. **HANDOVER REQUEST ACKNOWLEDGE** – target gNB performs admission control and returns the new RRC configuration.  
3. **RRCReconfiguration** – source gNB forwards the configuration (including cell ID, access‑information, and optionally beam‑specific data) to the UE.  
4. **RRCReconfigurationComplete** – UE moves the RRC connection to the target gNB and acknowledges the command.  

User data may be piggy‑backed on step 4 if the grant permits【TS 38.300 §9.2.3】.

#### 1.2.1.1 Discontinuous Reception (DAPS) Handover

In a *DAPS* handover the UE continues to receive downlink data from the source gNB and to transmit uplink data to the source until the random‑access (RA) procedure to the target gNB succeeds. Only the source and target **PCell** are kept; all secondary cells (CA, DC, SUL, multi‑TRP, etc.) are released before the handover command is sent【TS 38.300 §9.2.3】.  

During DAPS the UE:

* creates a MAC entity for the target,
* establishes an RLC entity and a DTCH logical channel for each DRB configured with DAPS,
* re‑configures the PDCP entity with separate security/ROHC functions for source and target,
* retains the remaining source configurations until the source cell is released【TS 38.300 §9.2.3】.

---

### 1.2.2 Beam‑Level Mobility

Beam‑level mobility does **not** require explicit RRC signalling. It can be intra‑cell (the UE switches to a different beam of the same cell) or inter‑cell (inter‑cell beam management, ICBM). In ICBM the UE may use a Transmission‑Reception Point (TRP) belonging to a PCI different from the serving cell for UE‑dedicated channels, while non‑dedicated channels remain bound to the serving cell’s PCI【TS 38.300 §9.2.3】.  

The gNB supplies the UE with a measurement configuration that lists SSB/CSI resources, measurement sets, and trigger states. The UE then performs beam switching based on physical‑layer and MAC‑layer control signalling; the RRC layer does not need to know which beam is active at any moment【TS 38.300 §9.2.3】.

---

### 1.2.3 Radio Link Failure (RLF) and Recovery

While in RRC_CONNECTED the UE monitors the radio link using reference signals (SSB or CSI‑RS) and thresholds configured by the network. An RLF is declared when **any** of the following occurs【TS 38.300 §9.2.7】:

* Expiry of a radio‑problem timer after a PHY‑layer problem indication,
* Expiry of a measurement‑report timer while another radio‑problem timer is running,
* Random‑access procedure failure,
* RLC failure,
* Consistent uplink LBT failures (shared spectrum),
* IAB‑MT reception of a backhaul‑RLF indication.

After declaring RLF the UE **remains** in RRC_CONNECTED. The subsequent actions depend on the mobility context:

| Scenario | UE Action |
|----------|-----------|
| **DAPS handover – RLF in source cell** | Stop data on source link, release source link, keep source RRC configuration【TS 38.300 §9.2.7】 |
| **DAPS handover – RLF in target cell before source release** | Select a suitable cell and initiate RRC re‑establishment; if none found, enter RRC_IDLE【TS 38.300 §9.2.7】 |
| **CHO (Conditional Handover) – RLF in source cell** | If network permits, attempt CHO once; otherwise perform re‑establishment【TS 38.300 §9.2.7】 |
| **General RLF (no handover)** | Select a suitable cell and re‑establish; otherwise go to RRC_IDLE【TS 38.300 §9.2.7】 |

---

### 1.2.4 Mobility Robustness Optimisation (MRO)

MRO is a set of network‑side analytics that distinguishes mobility‑related connection failures from coverage‑related problems. It specifically detects three intra‑system handover pathologies【TS 15.5.2】:

* **Too Late Handover** – RLF occurs after the UE has stayed a long time in the cell; the UE re‑establishes in a *different* cell.
* **Too Early Handover** – RLF occurs shortly after a successful handover (or a handover failure); the UE re‑establishes in the *source* cell.
* **Handover to Wrong Cell** – RLF occurs shortly after a handover and the UE re‑establishes in a cell that is neither the source nor the target.

The detection relies on the **UE‑reported timer** (often denoted $T_{\text{store\_UE\_cntxt}}$). If this timer is **absent** or **larger** than the configured threshold, the failure is classified as *Too Late*; if it is **smaller** than the threshold, the failure is *Too Early* or *Wrong Cell* depending on which cell the UE attempts to reconnect to【TS 15.5.2】.

---

### 1.2.5 Worked Example – Timing a Standard Handover

Assume a UE moving from Cell A (source) to Cell B (target). The network configures the following timer thresholds:

* $T_{\text{store\_UE\_cntxt}} = 200\ \text{ms}$ (used by MRO),
* Hand‑over signalling latency ≈ 5 ms per Xn hop (typical for fiber‑backhauled gNBs).

| Step | Event | Time (ms) |
|------|-------|-----------|
| 0 | UE reports measurement event triggering handover. | 0 |
| 1 | Source gNB sends **HANDOVER REQUEST** to target gNB. | 0 |
| 2 | Target gNB replies **HANDOVER REQUEST ACKNOWLEDGE** (5 ms). | 5 |
| 3 | Source forwards **RRCReconfiguration** to UE (additional 5 ms). | 10 |
| 4 | UE executes handover, creates MAC/RLC/PDCP for target, sends **RRCReconfigurationComplete** (5 ms). | 15 |
| 5 | UE resumes data transmission on target cell. | 15 |

The UE‑reported timer $T_{\text{store\_UE\_cntxt}}$ is set to 12 ms (time since last handover). Since 12 ms < 200 ms, if an RLF were to occur immediately after step 4, MRO would classify it as a **Too Early Handover**【TS 15.5.2】.

---

### 1.2.6 Common Pitfalls and Practical Notes

| Pitfall | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| **Assuming beam‑level mobility needs RRC signalling** | Beam switches are handled at PHY/MAC; RRC is unaware of the active beam. | Configure measurement sets correctly and let the UE’s lower layers manage beam tracking【TS 38.300 §9.2.3】. |
| **Releasing secondary cells too early in DAPS handover** | All CA/DC/etc. must be released **before** the handover command; otherwise the UE may retain stale configurations. | Follow the DAPS procedure: release secondary cells prior to sending the handover command【TS 38.300 §9.2.3】. |
| **Ignoring PDCP re‑establishment options** | Some DRBs can keep PDCP state (no key change) while others must re‑establish; wrong choice leads to data loss or security issues. | Choose PDCP handling based on DRB mode (AM vs UM) and security requirements as described in the handover spec【TS 38.300 §9.2.3】. |
| **Mis‑classifying RLF as coverage problem** | MRO distinguishes mobility‑induced failures (Too Early/Late/Wrong Cell) from pure coverage loss. | Use the UE‑reported timer and cell IDs during failure indication to let the NG‑RAN node apply MRO logic【TS 15.5.2】. |
| **Neglecting backhaul RLF for IAB nodes** | IAB‑MTs propagate backhaul RLF to child nodes; failure to forward this can block recovery. | Forward BH RLF indications as BAP Control PDUs per the specification【TS 38.300 §9.2.7】. |

Understanding these nuances helps engineers design robust handover parameters, minimise service interruption, and correctly interpret failure reports for optimisation loops.

## 練習題

**1.** Which of the following is NOT one of the minimum elemental steps for an inter‑gNB handover as defined in the specification?

- A. HANDOVER REQUEST sent over the Xn interface
- B. HANDOVER REQUEST ACKNOWLEDGE containing the new RRC configuration
- C. RRCReconfiguration message forwarded to the UE
- D. RRCConnectionSetup message exchanged with the target gNB

<details><summary>看答案</summary>

正解：D。The handover procedure consists of the four steps listed in options A‑C; an RRCConnectionSetup is not part of the described handover sequence.

</details>

**2.** During a DAPS handover, which set of configurations is released by the source gNB before the handover command is sent?

- A. Only the source PCell is released
- B. All secondary cells such as CA, DC, SUL, multi‑TRP, etc. are released
- C. Beam‑specific information is released but secondary cells remain active
- D. No configurations are released until after the handover completes

<details><summary>看答案</summary>

正解：B。The specification states that secondary cells are released prior to the handover command, leaving only the source and target PCell.

</details>

**3.** Which statement correctly describes beam‑level mobility in NR?

- A. It requires explicit RRC signalling to be triggered.
- B. It does not require explicit RRC signalling to be triggered.
- C. It can only occur within a single cell.
- D. It requires the UE to read system information before each beam switch.

<details><summary>看答案</summary>

正解：B。Beam‑level mobility is handled by lower‑layer control signalling and the RRC layer is not involved.

</details>

**4.** According to the Radio Link Failure criteria, which single event can cause the UE to declare an RLF?

- A. Expiry of a radio‑problem timer after a PHY indication
- B. Successful completion of a handover
- C. Measurement‑report timer expiry while another radio‑problem timer is running
- D. Random access procedure failure

<details><summary>看答案</summary>

正解：D。The list of RLF trigger conditions explicitly includes a failure of the random access procedure.

</details>

**5.** In Mobility Robustness Optimisation, a handover is classified as “Too Early” when the UE‑reported timer satisfies which condition?

- A. The timer is absent or larger than the configured threshold.
- B. The timer is smaller than the configured threshold.
- C. The timer is exactly equal to the configured threshold.
- D. The timer value is not reported to the network.

<details><summary>看答案</summary>

正解：B。“Too Early” handovers are identified by a recent handover indication, i.e., the UE‑reported timer being smaller than the threshold.

</details>
