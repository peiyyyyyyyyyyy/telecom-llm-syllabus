# 1.7.1 涵蓋與涵蓋容量優化（CCO）

所屬：[1.7 網路優化與終端](../1-7.md)

## 正文

*Why CCO matters* – In a live 5G NR deployment the radio environment is never static. Buildings, foliage, traffic load and even seasonal changes can create “coverage holes” or increase interference at the cell edge. If a user equipment (UE) experiences poor signal quality, the network may see higher retransmission rates, reduced throughput, and an increased number of hand‑over failures. The **Coverage and Capacity Optimisation (CCO)** function exists to detect such problems and to adjust radio parameters so that the intended service area is covered with the required quality while keeping capacity sufficient for the traffic demand.

---

### Key definitions  

| Symbol / term | Meaning (as defined in 3GPP TS 38.300 §15.5.5) | Unit / type |
|----------------|----------------------------------------------|--------------|
| **NG‑RAN node** | Any gNB or gNB‑DU that participates in NR radio access. | – |
| **Alternative coverage configuration** | A set of radio parameters (e.g., power, antenna tilt) that can be applied to a cell; it is provisioned by OAM and may include allowed adjustment ranges. | – |
| **Coverage state indicator (CSI)** | An identifier transmitted in the NG‑RAN NODE CONFIGURATION UPDATE that describes the current coverage configuration of a cell or SSB. | – |
| **CGI** | Cell Global Identifier – uniquely identifies a cell in the network. | – |
| **SSB index** | Index of a Synchronisation Signal / Physical Broadcast Channel block that may have its own CSI. | – |
| **Mobility Robustness Optimisation (MRO)** | Functions that control hand‑over thresholds, timers, and related parameters to keep UE mobility reliable. | – |

No explicit formulas are prescribed for CCO in the specification; the optimisation is driven by the *objective* to “detect and resolve or mitigate CCO issues, e.g. coverage and cell‑edge interference issues” [TS 38.300 §15.5.5.1].

---

### How CCO works  

1. **Provisioning (OAM)** – The operator’s Operations, Administration and Management (OAM) system defines one or more *alternative coverage configurations* for each NG‑RAN node. These configurations contain the radio parameters that may be changed and optionally a permitted range for each parameter [TS 38.300 §15.5.5.2].

2. **Autonomous adjustment** – An NG‑RAN node may *autonomously* decide, based on measurements (e.g., RSRP, interference) or higher‑layer directives, to *adjust within* a configuration or to *switch between* configurations [TS 38.300 §15.5.5.3].

3. **Neighbour notification** – When a change is applied, the node sends an **NG‑RAN NODE CONFIGURATION UPDATE** message to its neighbour nodes. The message carries a list that includes for each affected cell:  
   * the **CGI**,  
   * the **coverage state indicator** for the cell, and optionally  
   * the **SSB index** together with its CSI [TS 38.300 §15.5.5.3].

4. **Use of CSI at the receiver** – The neighbour node can use the received CSI to:  
   * retrieve a previously stored **MRO** state,  
   * adopt a matching coverage configuration, and  
   * avoid hand‑overs toward cells that are announced as *inactive* [TS 38.300 §15.5.5.3].

---

### Worked example (illustrative numbers)  

Assume **gNB‑A** serves Cell C1 (CGI = `001-01-001`) and has two alternative coverage configurations:

| Config | Tx Power (dBm) | Antenna tilt (°) |
|--------|----------------|------------------|
| Cfg‑1  |  46            | 0                |
| Cfg‑2  |  44            | 2                |

During a busy evening the UE at the cell edge reports an average RSRP of –95 dBm, which is below the target –90 dBm. The CCO algorithm decides to switch to **Cfg‑2**, which reduces interference to neighbouring cells.

1. **Local change** – gNB‑A changes its parameters to Tx = 44 dBm, tilt = 2°. The internal **coverage state indicator** for C1 becomes `2` (meaning “Cfg‑2 active”).

2. **Neighbour update** – gNB‑A sends an NG‑RAN NODE CONFIGURATION UPDATE to the neighbouring gNB‑B, including the list:  

   ```
   CGI: 001-01-001, CSI: 2
   ```

3. **Neighbour reaction** – gNB‑B receives the CSI `2`. It uses the value to retrieve the stored MRO state that corresponds to a neighbour operating under Cfg‑2, and it *avoids* triggering hand‑overs toward C1 while the new configuration is stabilising [TS 38.300 §15.5.5.3].

The result is a smoother UE experience at the cell edge and reduced inter‑cell interference.

---

### Practical notes and common pitfalls  

| Pitfall | Why it occurs | Correct practice |
|---------|---------------|------------------|
| **Omitting the NG‑RAN NODE CONFIGURATION UPDATE** | Engineers may assume the neighbour will infer the change from measurement reports. | Always transmit the update with the CGI and CSI as prescribed [TS 38.300 §15.5.5.3]. |
| **Misinterpreting CSI** | Treating the CSI as a binary “on/off” flag rather than an identifier of a specific configuration. | Map each CSI value to the corresponding alternative coverage configuration defined by OAM. |
| **Ignoring inactive‑cell indications** | Hand‑overs may be attempted toward cells that are temporarily switched off, causing connection failures. | The receiving node *should avoid triggering handovers* toward cells indicated as inactive [TS 38.300 §15.5.5.3]. |
| **Changing parameters outside the allowed range** | The alternative configuration may include a permitted adjustment range; exceeding it can breach OAM policies. | Respect the range limits supplied with the alternative coverage configuration [TS 38.300 §15.5.5.2]. |
| **Not coordinating planned re‑configurations** | When a set of cells is to be replaced, missing the “planned reconfiguration” flag can lead to UE re‑establishment failures. | Include the planned re‑configuration indication and any list of replacing cells in the update message [TS 38.300 §15.5.5.3]. |

By adhering to the defined CCO workflow—proper provisioning, autonomous but controlled adjustments, and explicit neighbour notifications—operators can maintain the delicate balance between coverage reliability and capacity utilisation across the NR network.
