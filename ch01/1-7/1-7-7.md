# 1.7.7 自我組態與自我優化（SON）

所屬：[1.7 網路優化與終端](../1-7.md)

## 正文

Self‑Configuration and Self‑Optimisation (often grouped under the term SON – Self‑Organising Networks) refer to the ability of an NG‑RAN node (gNB) to set up and adapt its interfaces and neighbour relations without manual operator intervention. In a live 5G deployment, rapid addition of new cells, changes in back‑haul topology, or failures of signalling links must be handled automatically to keep the network operational and to maintain service quality. The specifications in **3GPP TS 38.300 §15** describe the mechanisms that enable a gNB to configure the NG‑C and Xn interfaces dynamically and to manage Neighbour Cell Relations (NCRs) through the Automatic Neighbour Relation (ANR) function.

### Connectivity Rules – NG‑C Interface

The NG‑C interface connects a gNB to the Access and Mobility Management Function (AMF). Its dynamic configuration proceeds in three steps:

1. **Prerequisites** – The gNB must already have an initial remote IP endpoint for SCTP initialisation supplied for each AMF it will contact.  
   *“An initial remote IP end point to be used for SCTP initialisation is provided to the NG‑RAN node for each AMF the NG‑RAN node is supposed to connect to.”*【TS 38.300 §15.3.1.1】  

2. **SCTP initialisation** – Using a configured IP address, the gNB establishes the first SCTP association (IETF RFC 4960). If the association fails, the gNB may try alternative source or destination IP endpoints.  
   *“NG‑RAN establishes the first SCTP (IETF RFC 4960 [23]) using a configured IP address.”*【TS 38.300 §15.3.1.2】  

3. **Application‑layer initialisation** – Over the established SCTP link the gNB and AMF exchange NGAP messages in the NG Setup procedure. The gNB sends its supported Tracking Areas (TAs) and the AMF returns PLMN identity and other configuration data. Successful completion renders the NG‑C interface operational and permits later addition, update or removal of SCTP endpoints as defined in TS 23.501.  
   *“Once SCTP connectivity has been established, the NG‑RAN node and the AMF shall exchange application level configuration data over NGAP with the NG Setup procedure … When the application layer initialization is successfully concluded, the dynamic configuration procedure is completed and the NG‑C interface is operational.”*【TS 38.300 §15.3.1.3】

### Connectivity Rules – Xn Interface

The Xn interface interconnects neighbouring gNBs for hand‑over and load‑balancing. Its dynamic configuration mirrors that of NG‑C:

*Prerequisite* – an initial remote IP endpoint for SCTP.  
*“An initial remote IP end point to be used for SCTP initialisation is provided to the NG‑RAN node.”*【TS 38.300 §15.3.2.1】

* SCTP initialisation follows the same rule as NG‑C.  
* “NG‑RAN establishes the first SCTP (IETF RFC 4960 [23]) using a configured IP address.”*【TS 38.300 §15.3.2.2】

*Application‑layer exchange* – XnAP messages convey served‑cell information in both directions; after successful exchange the Xn link becomes operational and the gNB must keep its peers updated with the complete (or limited, upon request) list of served cells.  
*“When the application layer initialization is successfully concluded, the dynamic configuration procedure is completed and the Xn interface is operational; the NG‑RAN node shall keep neighbouring NG‑RAN nodes updated with the complete list of served cells … while the Xn interface is operational.”*【TS 38.300 §15.3.2.3】

### Automatic Neighbour Relation (ANR) Function

ANR automates the management of the Neighbour Cell Relation Table (NCRT) stored in the gNB. It consists of two implementation‑specific sub‑functions:

* **Neighbour Detection** – discovers new neighbour cells from UE measurement reports and adds entries to the NCRT.  
* **Neighbour Removal** – deletes stale entries that are no longer valid.

The ANR function resides in the gNB and may be instructed by the Operations & Maintenance (OAM) system to add, delete or modify NCR attributes.  
*“The ANR function resides in the gNB and manages the Neighbour Cell Relation Table (NCRT).”*【TS 38.300 §15.3.3.1】

An **existing NCR** from a source cell to a target cell implies three conditions:

1. The source gNB knows the global and physical identifiers (e.g., NR CGI/PCI, ECGI/PCI) of the target cell.  
2. An entry for the target cell exists in the source cell’s NCRT.  
3. The attributes of that entry are defined, either by OAM or set to default values.  
*“An existing NCR from a source cell to a target cell means that gNB controlling the source cell: a) Knows the global and physical IDs …; b) Has an entry in the NCRT …; c) Has the attributes … defined, either by OAM or set to default values.”*【TS 38.300 §15.3.3.1】

It is important to note that NCRs are **unidirectional** relations, whereas an Xn link is **bidirectional**.  
*“NCRs are cell‑to‑cell relations, while an Xn link is set up between two gNBs. Neighbour Cell Relations are unidirectional, while an Xn link is bidirectional.”*【TS 38.300 §15.3.3.1】

### Intra‑system ANR Procedure

When a UE is in RRC_CONNECTED, the gNB commands it to measure neighbour cells. The UE reports the PCI of a discovered cell (e.g., Cell B) without the NCGI/ECGI. Upon receipt, the gNB may request the UE to read the broadcast NCGI/ECGI, TAC, RANAC, PLMN ID and other identifiers from the neighbour cell’s broadcast channel, possibly scheduling idle periods for the UE to perform this read. This measurement‑report loop enables the gNB to populate the NCRT automatically.  
*“In RRC_CONNECTED, the NG‑RAN node instructs each UE to perform measurements on neighbour cells … The UE sends a measurement report regarding cell B. This report contains Cell B's PCI, but not its NCGI/ECGI … the NG‑RAN node instructs the UE … to read all the broadcast NCGI(s) /ECGI(s) …”*【TS 38.300 §15.3.3.2】

### Worked Example – Dynamic NG‑C Setup

Consider a new gNB that must connect to two AMFs (AMF‑1 and AMF‑2) for redundancy.

| Step | Action | Data |
|------|--------|------|
| 1 | Prerequisite | Remote IPs: 192.0.2.10 (AMF‑1) and 192.0.2.20 (AMF‑2) |
| 2 | SCTP init (first attempt) | Source IP 10.1.1.5 → Destination 192.0.2.10 (success) |
| 3 | NG Setup with AMF‑1 | gNB sends supported TA list; AMF‑1 returns PLMN ID = 00101 |
| 4 | SCTP init for secondary link | Source IP 10.1.1.5 → Destination 192.0.2.20 (fails) → retry with source IP 10.1.1.6 (success) |
| 5 | NG Setup with AMF‑2 | Same exchange; both NG‑C links become operational |

The example follows the three‑step procedure defined in §§15.3.1.1‑15.3.1.3. Note that the gNB is allowed to change source IP when the first attempt fails, as permitted by the specification.

### Common Mistakes and Practical Notes

| Mistake | Why it Happens | Remedy |
|---------|----------------|--------|
| Assuming a single static SCTP endpoint | The spec allows the gNB to switch source/destination IPs on failure. | Implement fallback logic that retries with alternative IPs as per §15.3.1.2 and §15.3.2.2. |
| Treating NCRs as bidirectional | NCRs are defined as unidirectional, unlike Xn links. | Update the NCRT for each direction separately; verify with §15.3.3.1. |
| Forgetting to inform OAM of NCRT changes | OAM may need to synchronise configuration; ANR reports updates. | Ensure the gNB sends NCRT change notifications as described in §15.3.3.1. |
| Relying solely on PCI for neighbour identification | PCI alone does not provide global identifiers; the gNB must request NCGI/ECGI. | Follow the measurement‑report sequence in §15.3.3.2 to obtain full identifiers. |

By adhering to the dynamic configuration steps and leveraging ANR, operators can achieve rapid, reliable deployment and ongoing optimisation of 5G cells with minimal manual configuration.

## 練習題

**1.** 在 NG‑C 介面的動態組態過程中，必須先提供什麼資訊給 NG‑RAN 節點？

- A. AMF 的遠端 IP 終端點
- B. 本地 MAC 位址
- C. UE 的 IMSI
- D. Xn 介面的頻段

<details><summary>看答案</summary>

正解：A。動態組態需要先知道要連接的 AMF 的遠端 IP 端點，以便建立 SCTP 連線。

</details>

**2.** SCTP 連線建立後，NG‑RAN 與 AMF 透過哪個程序交換應用層設定資料？

- A. Xn Setup
- B. NG Setup
- C. RRC Connection Setup
- D. NAS Attach

<details><summary>看答案</summary>

正解：B。NG‑RAN 與 AMF 使用 NG Setup 程序交換 NGAP 層的組態資訊。

</details>

**3.** 當 Xn 介面的應用層初始化成功結束時，系統狀態為何？

- A. 動態組態失敗
- B. Xn 介面仍未啟用
- C. 動態組態程序完成且 Xn 介面可運作
- D. 需要重新啟動 SCTP

<details><summary>看答案</summary>

正解：C。成功的應用層初始化標誌著動態組態完成，Xn 介面即可投入使用。

</details>

**4.** ANR 功能的主要目的為何？

- A. 提高頻譜效率
- B. 減少 UE 功耗
- C. 免除營運商手動管理 NCR
- D. 增加下行速率

<details><summary>看答案</summary>

正解：C。ANR 旨在自動管理鄰近小區關係，減少人工介入的需求。

</details>

**5.** 在同系統 ANR 中，UE 首次回報相鄰小區時會包含哪項資訊？

- A. NCGI/ECGI
- B. PCI 但不含 NCGI/ECGI
- C. PLMN ID
- D. RANAC

<details><summary>看答案</summary>

正解：B。UE 最初只回報相鄰小區的 PCI，並未提供其 NCGI/ECGI。

</details>
