# 1.7.5 終端能力與類別

所屬：[1.7 網路優化與終端](../1-7.md)

## 正文

In a live cellular system the network must know how fast a user equipment (UE) can receive and transmit data, how much buffering it can hold, and which radio features it supports. This information drives **carrier aggregation decisions**, **handover criteria**, and **QoS scheduling**. If the UE’s advertised capability is over‑estimated, the gNB may allocate more resources than the device can handle, leading to dropped packets or excessive latency. Conversely, under‑estimating the capability wastes spectrum that could have been used for higher throughput. Therefore, a precise description of UE radio access capability parameters is a cornerstone of network optimisation and terminal testing [TS 38.306 §4.1.1].

### Supported maximum data rate

For New Radio (NR) the **approximate** maximum data rate is derived per band or band‑combination. The generic expression is  

$$
R_{\text{max}} = \frac{948}{1024}\;
\sum_{j=1}^{J}
\underbrace{v^{(j)}_{\text{Layers}}}_{\text{MIMO layers}}
\;
\underbrace{Q_{m}^{(j)}}_{\text{modulation order}}
\;
\underbrace{f^{(j)}}_{\text{scaling factor}}
\;
\frac{1}{T^{(j)}_{\text{symb}}}
\;
N^{(j)}_{\text{RB}}
\;
\bigl(1-\text{OH}^{(j)}\bigr)
$$

where  

* $J$ – number of aggregated **component carriers** (CCs) in the band or band‑combination [TS 38.306 §4.1.2];  
* $v^{(j)}_{\text{Layers}}$ – maximum number of supported layers for the $j^{\text{th}}$ CC (downlink: *maxNumberMIMO‑LayersPDSCH*) [TS 38.306 §4.1.2];  
* $Q_{m}^{(j)}$ – maximum supported modulation order (e.g. 2, 4, 6, 8 for QPSK, 16‑QAM, 64‑QAM, 256‑QAM) given by *supportedModulationOrderDL* [TS 38.306 §4.1.2];  
* $f^{(j)}$ – **scaling factor**; possible values are 1, 0.8, 0.75, 0.4 [TS 38.306 §4.1.2];  
* $T^{(j)}_{\text{symb}}$ – average OFDM symbol duration for the numerology $\mu$ of the $j^{\text{th}}$ CC (normal cyclic prefix assumed) [TS 38.306 §4.1.2];  
* $N^{(j)}_{\text{RB}}$ – maximum number of resource blocks that can be allocated in the UE‑supported bandwidth for that CC [TS 38.306 §4.1.2];  
* $\text{OH}^{(j)}$ – **overhead**; for FR1 downlink it is 0.14, for FR2 downlink 0.18, for FR1 uplink 0.08, for FR2 uplink 0.10 [TS 38.306 §4.1.2].

The factor $948/1024$ accounts for useful symbols after control and reference signals [TS 38.306 §4.1.2].

**Uplink** uses the same structure, but the layer count is the maximum of *maxNumberMIMO‑LayersCB‑PUSCH* and *maxNumberMIMO‑LayersNonCB‑PUSCH*, and the overhead value changes to the UL‑specific numbers [TS 38.306 §4.1.2].

**Special notes**

* **SUL (supplementary uplink)** – when a cell operates SUL, only the carrier (UL or SUL) that yields the higher data rate is counted [TS 38.306 §4.1.2 NOTE 1].  
* **Carrier‑switching** – for UL Tx switching, the UE may select the MIMO‑layer combination across carriers that gives the highest combined rate [TS 38.306 §4.1.2 NOTE 2].

### Worked example

Assume a UE that supports a single NR carrier (so $J=1$) in FR1 downlink with the following capabilities:

* $v_{\text{Layers}} = 2$ (2‑layer MIMO);  
* $Q_{m} = 8$ (256‑QAM, modulation order 8);  
* $f = 1$ (no scaling);  
* Numerology $\mu = 0$ (15 kHz SCS) → $T_{\text{symb}} = 71.4\,\mu\text{s}$ (average normal‑CP symbol);  
* $N_{\text{RB}} = 100$ (UE can use 100 RBs);  
* Overhead $\text{OH}=0.14$ (FR1 DL).

Plugging into the formula:

$$
\begin{aligned}
R_{\text{max}} &=
\frac{948}{1024}\;
\bigl(2 \times 8 \times 1\bigr)\;
\frac{1}{71.4\times10^{-6}}\;
100\;
(1-0.14)\\
&\approx 0.9258 \times 16 \times 14\,000 \times 100 \times 0.86\\
&\approx 0.9258 \times 16 \times 1.204\times10^{6}\\
&\approx 1.78\times10^{7}\;\text{bps}\\
&\approx 17.8\;\text{Mbps}.
\end{aligned}
$$

Thus the UE must be able to sustain at least **17.8 Mbps** on that carrier, satisfying the requirement that the computed rate be **no smaller** than the UE‑supported rate [TS 38.306 §4.1.2].

### Layer‑2 buffer dimensioning

The UE also advertises the **total layer‑2 buffer size**, defined as the sum of bytes that can be stored in:

* RLC transmission windows,  
* RLC reception and reassembly windows, and  
* PDCP reordering windows for **all** radio bearers [TS 38.306 §4.1.4].

For multi‑RAT (MR‑DC) configurations the required buffer is the maximum of the expressions  

$$
\begin{aligned}
&\text{MaxULDataRate}_{\text{MN}}\!\times\! \text{RLCRTT}_{\text{MN}} \;+\; \text{MaxULDataRate}_{\text{SN}}\!\times\! \text{RLCRTT}_{\text{SN}} \\
&\quad +\; \text{MaxDLDataRate}_{\text{SN}}\!\times\! \text{RLCRTT}_{\text{SN}} \;+\; \text{MaxDLDataRate}_{\text{MN}}\!\times\! (\text{RLCRTT}_{\text{SN}} + \text{X2/Xn delay} + \text{Queuing in SN}) ,
\end{aligned}
$$

and a symmetric formula where MN and SN are swapped [TS 38.306 §4.1.4].  
If only a single RAT is present, the simpler expression  

$$
\text{MaxDLDataRate}\!\times\!\text{RLC RTT} \;+\; \text{MaxULDataRate}\!\times\!\text{RLC RTT}
$$

is used [TS 38.306 §4.1.4].

The **RLC round‑trip time (RTT)** depends on the smallest sub‑carrier spacing (SCS) supported in the band combination (e.g., 50 ms for 15 kHz SCS) [TS 38.306 §4.1.4 Table 4.1.4‑1].

### UE categories – a clarification

Unlike earlier generations, **NR does not use UE categories** to signal fixed peak data rates. Categories exist only for marketing and are **not** transmitted to the network; the peak rate is derived from the actual capability parameters described above [TS 38.300 §14].

### Common pitfalls

1. **Ignoring the scaling factor** – many implementations default to $f=1$, but a UE may advertise 0.8, 0.75 or 0.4, which reduces the computed rate.  
2. **Applying the wrong overhead** – DL and UL have distinct values, and FR1 vs. FR2 must be distinguished; using 0.10 for FR1 DL will over‑estimate the rate.  
3. **Summing UL and SUL carriers** – the standard mandates counting only the carrier with the higher UL rate [TS 38.306 §4.1.2 NOTE 1].  
4. **Neglecting the RLC‑RTT dependence on SCS** – a larger SCS (e.g., 60 kHz) yields a shorter RTT, affecting the required buffer size.  
5. **Assuming UE categories are signalled** – they are not; relying on a category table will produce mismatches with the actual capability set [TS 38.300 §14].

Understanding and applying these formulas precisely ensures that network planning, SON algorithms, and terminal conformance testing are based on realistic UE limits.
