# 1.7.4 容量與負載平衡

所屬：[1.7 網路優化與終端](../1-7.md)

## 正文

In a mobile radio system the *capacity* of a cell is the amount of radio resources (e.g., Physical Resource Blocks – PRBs) that can be allocated to user equipment (UE) while meeting quality‑of‑service (QoS) requirements. *Load* is the fraction of those resources that are actually used at a given time. When a cell or a group of cells becomes congested, the user experience degrades (higher latency, lower throughput, increased handover failures). *Mobility load balancing* (MLB) is the set of mechanisms that redistribute traffic from overloaded cells to neighboring cells, or from one carrier/RAT to another, in order to keep the load evenly spread, improve overall system capacity, and even reduce energy consumption [TS 38.300 §15.5.1].

### Key Definitions

| Symbol | Meaning | Unit / Typical Range |
|--------|---------|----------------------|
| $L_{\text{DL}}$, $L_{\text{UL}}$ | Downlink / Uplink PRB usage (GBR, non‑GBR, total) | PRBs (0 … total PRBs per carrier) |
| $C_{\text{DL}}$, $C_{\text{UL}}$ | Offered/available TNL (Transport Network Layer) capacity | Mbps |
| $CC_{\text{UL}}$, $CC_{\text{DL}}$ | Cell Capacity Class value (relative capacity indicator) | Dimensionless (0 … 255) |
| $A_{\text{RRC}}$ | Available RRC connection capacity | Number of connections |
| $N_{\text{UE}}$ | Number of active UEs in the cell | Integer |
| $\Delta_{\text{HO}}$ | Change (delta) of a handover trigger parameter | dB or offset units |

The load reporting function supplies the above items over the Xn/X2/F1/E1 interfaces for *intra‑RAT* and *intra‑system inter‑RAT* balancing, and over NG‑AP/S1‑AP for *inter‑system* balancing [TS 38.300 §15.5.2‑§15.5.5].

### Load Reporting

A source gNB (or eNB) periodically or event‑triggeredly sends a **Resource Status Report** containing:

* per‑cell PRB usage (DL/UL GBR, non‑GBR, total)  
* TNL capacity indicators (offered and available)  
* Cell Capacity Class values  
* Available RRC connection capacity and current number of RRC connections  
* Number of active UEs  

These items enable the neighbor node to assess whether it can accept additional traffic [TS 38.300 §15.5.2].

### Load‑Balancing Action via Hand‑Over

When the source cell detects that its load exceeds a configured threshold, it may *initiate a hand‑over* of selected UEs to a less loaded target cell. The target cell applies **admission control** specifically for load‑balancing hand‑overs, distinguishing them from ordinary hand‑overs [TS 38.300 §15.5.3].

### Adapting Handover / Reselection Parameters

If a hand‑over alone cannot relieve congestion, the source cell can request the target cell to **adjust hand‑over trigger offsets** (e.g., increase the offset so that UEs hand‑over earlier). The request carries the *delta* $\Delta_{\text{HO}}$ between the current and desired trigger values. The target cell replies with the allowed delta range; the source cell must honour this range and any OAM‑imposed limits [TS 38.300 §15.5.4].

### Inter‑System Load Balancing

For load sharing between NR (NG‑RAN) and LTE (E‑UTRAN), the two systems exchange the same set of load metrics (Cell Capacity Class, available capacity, RRC connections, active UEs, PRB usage). Both **event‑triggered** (when a threshold is crossed) and **periodic** reports are supported. NGAP procedures (Uplink/Downlink RAN Configuration Transfer) and S1AP procedures (eNB/MME Configuration Transfer) carry the information [TS 38.300 §15.5.5].

### Worked Example

Consider two neighboring NR cells, **Cell A** and **Cell B**, each with 100 PRBs in downlink. At a certain instant the load reporting yields:

| Metric | Cell A | Cell B |
|--------|--------|--------|
| DL total PRB usage | 85 PRBs | 45 PRBs |
| UL total PRB usage | 70 PRBs | 40 PRBs |
| Active UEs | 120 | 55 |
| RRC connection capacity (available) | 30 | 70 |

Cell A’s downlink load = $85/100 = 85\%$, exceeding a hypothetical threshold of $80\%$. Cell B is under‑utilised (45 %). According to the MLB procedure, Cell A may:

1. **Report** its load to Cell B via Xn (Resource Status Reporting) [TS 38.300 §15.5.2].
2. **Initiate hand‑over** of a subset of UEs (e.g., 20 UEs) to Cell B. Cell B applies admission control for these *load‑balancing* hand‑overs [TS 38.300 §15.5.3].
3. **If needed**, Cell A requests Cell B to lower the hand‑over trigger offset by $\Delta_{\text{HO}} = -2$ dB, so that additional UEs will hand‑over earlier [TS 38.300 §15.5.4].

After hand‑over, assume Cell A’s DL usage drops to 70 PRBs (70 %) and Cell B’s rises to 60 PRBs (60 %). Both cells are now below the threshold, achieving a more balanced load.

### Common Mistakes & Practical Notes

* **Ignoring admission control** – Target cells must still enforce their own capacity limits; sending a hand‑over request does not guarantee acceptance [TS 38.300 §15.5.3].
* **Changing parameters beyond OAM limits** – Any automatic delta to hand‑over triggers must stay within the range configured by operations & maintenance; otherwise the request will be rejected [TS 38.300 §15.5.4].
* **Confusing intra‑RAT with inter‑system reports** – The same metric set is used, but the transport (Xn/X2/F1/E1 vs NGAP/S1AP) differs; using the wrong interface can cause the neighbor to ignore the report [TS 38.300 §§15.5.2, 15.5.5].
* **Neglecting slice‑specific load** – When network slicing is active, PRB usage and capacity values must be reported per slice; overlooking this can lead to overload in a particular slice even if the aggregate load looks acceptable [TS 38.300 §15.5.2].
* **Over‑relying on hand‑over alone** – In highly congested scenarios, parameter adaptation (e.g., increasing cell‑edge coverage, adjusting reselection) together with hand‑overs yields better balancing [TS 38.300 §15.5.1].

Proper implementation of MLB thus requires accurate load measurement, timely reporting, coordinated hand‑over initiation, and careful configuration of mobility parameters within OAM‑defined limits. When applied correctly, MLB improves user experience, maximises spectral efficiency, and can contribute to energy savings by allowing under‑utilised cells to enter low‑power states [TS 38.300 §15.5.1].

## 練習題

**1.** 下列哪一項 **不是** 15.5.1.2 中列出的「負載相關資訊」之一？

- A. Radio resource usage (PRB usage)
- B. TNL capacity indicator
- C. Cell temperature
- D. HW capacity indicator

<details><summary>看答案</summary>

正解：C。參考文件只列出 Radio resource usage、TNL capacity indicator、HW capacity indicator 等項目，未提到 Cell temperature。

</details>

**2.** 當來源小區偵測到負載不均時，可採取的動作是什麼？

- A. 提升傳輸功率
- B. 因負載而發起切換 (handover)
- C. 減少可用頻寬
- D. 要求 UE 回傳測量報告

<details><summary>看答案</summary>

正解：B。規格明確指出來源小區可以因負載而發起切換程序。

</details>

**3.** 在「調整切換與/或重新選擇設定」的程序中，來源小區如何向目標小區表達欲變更的切換門檻？

- A. 直接給出新的絕對值
- B. 以目前值與新值之差 (delta) 表示
- C. 以二進位旗標方式傳送
- D. 以 QoS 類別識別碼傳遞

<details><summary>看答案</summary>

正解：B。變更以「差值 (delta)」方式傳送，讓目標小區知道調整幅度。

</details>

**4.** 在 NG‑RAN 與 E‑UTRAN 之間的「跨系統負載平衡」中，使用哪個 NGAP 程序來傳送負載資訊？

- A. Uplink RAN Configuration Transfer
- B. Downlink RAN Configuration Transfer
- C. Xn Interface Load Reporting
- D. X2 Interface Load Reporting

<details><summary>看答案</summary>

正解：A。規格列出 Uplink RAN Configuration Transfer 為跨系統負載平衡所使用的 NGAP 程序之一。

</details>

**5.** 若收到鄰近 NG‑RAN 節點的通知指出某個小區已變為「inactive」狀態，接收端 NG‑RAN 應如何處理？

- A. 主動觸發向該小區的切換
- B. 避免向該小區觸發切換
- C. 增加對該小區的測量報告頻率
- D. 降低該小區的發射功率

<details><summary>看答案</summary>

正解：B。接收端應避免對已標示為不活躍的小區發起切換，以減少連線失敗。

</details>
