# 1.2.4 路由協定：OSPF、BGP

所屬：[1.2 通訊協定](1-2.md)

## 內文

OSPF 和 BGP 分別處理不同範圍的路由控制。OSPF 可在同一自治系統內散布鏈路狀態，讓路由器計算通往目的地的路徑。BGP 在自治系統之間交換前綴可達性和路徑屬性，也可在一個自治系統內分發 BGP 路由。遇到網路邊界失去可達性時，確認哪種協定負責產生或傳遞該路由，有助於把問題定位在內部基礎路徑或外部政策。 [IETF RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html)

以 OSPFv2 為例，路由器與鄰居建立適用的鄰接關係，散布鏈路狀態通告，並為所屬區域維護鏈路狀態資料庫。收到更新後，可重新計算最短路徑並更新路由。BGP 路由器透過對等工作階段接收前綴，依屬性與本地政策決定哪些路由被選用、保存或向鄰居公告。路徑屬性包括 AS_PATH 與 NEXT_HOP。若下一跳的內部可達性改變，BGP 即使仍收到外部公告，對應路徑的可用狀態也可能改變。實際轉送的最長前綴比對見 1.2.2。 [IETF RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html) [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html)

假設在同一 OSPF 區域內有兩條候選路徑，第一條連續使用成本為 10 和 5 的鏈路，第二條只經成本為 20 的鏈路。若其他條件相同，兩條總成本分別為 15 與 20，計算會偏好第一條。成本是路由度量。若現場還要解釋延遲或容量，須另外測量，而不能把成本數值直接當成毫秒或位元每秒。 [IETF RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html)

常見混淆包括把 OSPF 最低成本當成 BGP 通用選路法、把 BGP 對端已建立當成前綴已接收，以及把路由控制紀錄當作流量已通過。BGP 選擇受路徑屬性與本地政策影響。前綴經過策略處理後，還要查路由是否安裝及下一跳是否可用。 [IETF RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html)

維運先記錄目的前綴、路由器、鄰居、時間點及路由變化。內網團隊比對 OSPF 鄰接、區域與鏈路狀態，互連團隊對照 BGP 收送政策、路徑屬性及公告歷史。若控制面紀錄與轉送結果不同，查該前綴實際採用的下一跳與方向，必要時請對端共同驗證。 [IETF RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html) [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html)
