# 1.1.4 傳輸網：光纖、微波，前傳／中傳／回傳

所屬：[1.1 網路架構](1-1.md)

## 內文

行動傳輸網承載基地台各功能節點之間，以及接取網通往核心的資料和信令。前傳、中傳與回傳按所連接的功能位置辨識，可用來描述同一行動服務跨越哪些網段。完成拓樸辨識後，才能針對各段選擇介面量測和責任窗口，並在鏈路故障時估算哪些小區或服務共用受影響的路徑。 [ITU-T G.8300](https://www.itu.int/rec/T-REC-G.8300/en) [3GPP TS 38.401 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138401/18.01.00_60/ts_138401v180100p.pdf)

在常見的分離部署中，前傳自無線單元到分布單元，中傳自分布單元到集中單元，回傳再連向核心網方向。若功能共置，部分邏輯接口可能留在機房內，現場路由也可能經過交換、匯聚及保護鏈路。光纖與微波是可用的承載媒介，實際設計取決於現地條件和服務要求。除了承載用戶流量，部分部署還會由傳輸網分發頻率、相位或時間基準。維運要把承載路徑和授時路徑分開畫在心中，即使資料仍可通過，無線側也可能因參考時鐘品質出現告警。 [ITU-T G.8300](https://www.itu.int/rec/T-REC-G.8300/en) [3GPP TS 38.401 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138401/18.01.00_60/ts_138401v180100p.pdf) [ITU-T G.8275.1](https://www.itu.int/rec/T-REC-G.8275.1/en)

觀察傳輸路徑時，帶寬以位元每秒表示，延遲以時間單位表示，授時則要依適用同步方案檢查時間或相位誤差。單條鏈路的標稱容量只能用於理解個別路段，端到端轉送還受沿途瓶頸、流量整形及排隊影響。前傳延遲預算要由採用的切分和部署條件確認，勿沿用其他接口的工程門檻。 [ITU-T G.8300](https://www.itu.int/rec/T-REC-G.8300/en) [ITU-T G.8275.1](https://www.itu.int/rec/T-REC-G.8275.1/en)

前傳容易與回傳混用，原因是現場口語常按機房或光纖走向命名。辨識時要先看功能端點，再看媒介。另一個常見混淆是把介面「連線正常」視同服務符合要求。鏈路已上線時，封包丟失、時延變化或時鐘未鎖定仍可能影響無線業務。同步是否正常應從同步源、選擇狀態和實際量測確認。 [ITU-T G.8300](https://www.itu.int/rec/T-REC-G.8300/en) [ITU-T G.8275.1](https://www.itu.int/rec/T-REC-G.8275.1/en)

告警交接至少列清兩端設備、實際路由、失效方向、異常開始時間和受影響小區。傳輸團隊核對光功率或微波設備狀態、介面錯誤、容量和路由切換紀錄。無線團隊回報成功率或同步告警，必要時與核心用戶面計數對照。在排查長距離或多段匯聚路徑時，逐段查同一時窗的流量和丟包，便於區分接取端、匯聚端與核心方向。 [ITU-T G.8300](https://www.itu.int/rec/T-REC-G.8300/en) [ITU-T G.8275.1](https://www.itu.int/rec/T-REC-G.8275.1/en) [3GPP TS 38.401 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138401/18.01.00_60/ts_138401v180100p.pdf)
