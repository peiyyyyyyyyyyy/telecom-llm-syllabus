# 1.6.5 資源使用率：PRB、處理器、傳輸

所屬：[1.6 指標與名詞](../1-6.md)

## 正文

In a 5G radio access network (RAN) the term *resource utilisation* quantifies how much of the finite physical or logical capacities are actually consumed by traffic. Operators monitor these indicators to avoid over‑loading the radio layer, to dimension compute nodes in the core, and to detect abnormal data‑plane behaviour on transport links. Excessive utilisation can lead to dropped calls, increased latency, or even service outage, while under‑utilisation signals wasted capital expenditure.

### PRB (Physical Resource Block) Utilisation

A Physical Resource Block (PRB) is the smallest allocatable unit in the time‑frequency grid of an NR cell. The 3GPP TS 28.552 specification defines two basic measurements:

* **DL Total PRB Usage** – percentage of downlink PRBs that are occupied for any purpose.  
* **UL Total PRB Usage** – percentage of uplink PRBs that are occupied for any purpose.  

Both measurements are obtained with the same formula  

$$
\text{PRB\_Usage}_{\text{DL/UL}} = 
\frac{N_{\text{used}}}{N_{\text{total}}}\times 100\;[\%]
$$

where  

* $N_{\text{used}}$ – count of full physical resource blocks and all PRBs used for traffic transmission during the measurement period (see ![](media/image6.wmf) in the specification).  
* $N_{\text{total}}$ – total number of PRBs available for transmission during the same period (see ![](media/image7.wmf)).  
* The result is an **integer** in the range 0–100 % [TS 28.552 §5.1.1.2.1].

The measurement name is **RRU.PrbDl** for downlink and **RRU.PrbUl** for uplink. Optional suffixes allow the metric to be broken down per PLMN ID, per S‑NSSAI, or per QoS resource type (Non‑GBR, GBR, Delay‑critical GBR) [TS 28.552 §5.1.1.2.1‑2].

### Distribution of PRB Usage

Beyond the average percentage, the specification also defines a histogram‑style measurement that records how many samples fall into predefined usage bins (e.g. 0‑10 %, 10‑20 %, …). This *Distribution of DL Total PRB Usage* is computed per sample $n$ as  

$$
M[n]=\Big\lfloor \frac{M_1[n]}{P[n]}\times100 \Big\rfloor
$$

where $M_1[n]$ is the count of used PRBs and $P[n]$ the total PRBs for that sample [TS 28.552 §5.1.1.2.3]. The distribution is generated **only in the time‑frequency domain**, with the reference point at the MAC–L1 Service Access Point [TS 28.552 §5.1.1.2.3].

### Processor (CPU) Utilisation

Core‑network functions are typically virtualised. TS 28.552 §5.7.1.1.1 defines **Mean virtual CPU usage** for a virtualised 3GPP Network Function (NF). The measurement is a single integer percentage representing the weighted average utilisation of the underlying virtual CPUs that host the NF [TS 28.552 §5.7.1.1.1].

The measurement name follows the pattern **VR.VCpuUsageMean** and is applicable to a long list of NF types (e.g. GNBCUCPFunction, AMFFunction, SMFFunction, etc.) [TS 28.552 §5.7.1.1.1].

### Transport (GTP‑U) Utilisation

On the user‑plane, traffic traverses the NG‑U interface between the UPF and the gNB/CU‑UP. TS 28.552 §5.1.1.36 defines the counter **GTP.InDataOctNgUgNB** which reports the **number of octets** of incoming GTP‑U data packets received on that interface [TS 28.552 §5.1.1.36]. The metric can be split per S‑NSSAI, but otherwise returns a single integer value.

### Worked Example

A gNB‑DU reports the following statistics for a 10‑second measurement window:

* Total downlink PRBs available per subframe: $N_{\text{total}} = 100$  
* Sum of used PRBs over the window (averaged per subframe): $N_{\text{used}} = 45$  

The DL PRB utilisation is  

$$
\text{PRB\_Usage}_{\text{DL}} = \frac{45}{100}\times100 = 45\%
$$

The corresponding measurement name is **RRU.PrbDl** and the reported integer is 45 % [TS 28.552 §5.1.1.2.1].

Assume the virtualised CU‑UP reports a mean CPU utilisation of **68 %**. The measurement name is **VR.VCpuUsageMean** and the value is an integer percentage [TS 28.552 §5.7.1.1.1].

Finally, the UPF sends 12 345 678 octets of GTP‑U payload to the gNB over NG‑U during the same period. The transport utilisation counter **GTP.InDataOctNgUgNB** records the value **12 345 678** [TS 28.552 §5.1.1.36].

### Common Mistakes & Practical Notes

| Pitfall | Why it Happens | Correct Approach |
|---------|----------------|------------------|
| **Ignoring optional splits** – treating RRU.PrbDl as a single cell‑wide value while the network is multi‑PLMN or multi‑S‑NSSAI. | The specification allows per‑PLMN/S‑NSSAI breakdowns. | Retrieve the appropriate suffixed metric (e.g. RRU.PrbDl.<PLMN>) when analysing slice‑level performance. |
| **Confusing average percentage with histogram bins** – interpreting a bin count as a utilisation percentage. | Distribution metrics (RRU.PrbTotDlDist.\*) are counts of samples, not percentages. | Remember that each bin holds the *number of samples* whose utilisation fell into the bin range [TS 28.552 §5.1.1.2.3]. |
| **Treating CPU utilisation as absolute core count** – assuming “68 %” means 0.68 cores. | The metric is a ratio of used CPU cycles to allocated virtual CPU capacity, expressed as a percent. | Use the percentage directly for capacity planning; convert to cores only if the underlying virtual CPU capacity (e.g. 4 vCPU) is known. |
| **Overlooking directionality on NG‑U** – using the same counter for both uplink and downlink GTP‑U traffic. | The defined counter **GTP.InDataOctNgUgNB** counts *incoming* packets *from UPF to RAN* only. | For traffic in the opposite direction, a different counter (not defined in the current references) would be required. |
| **Assuming PRB utilisation is always integer** – expecting fractional values. | The specification mandates the result be a *single integer* from 0 to 100 % [TS 28.552 §5.1.1.2.1]. | Round or floor the computed value to the nearest integer before reporting. |

By consistently applying the definitions and formulas above, engineers can accurately monitor radio, compute, and transport resource utilisation, enabling proactive network optimisation.

## 練習題

**1.** 哪一個測量名稱表示全部流量的下行 PRB 使用率？

- A. RRU.PrbUl
- B. RRU.PrbDl
- C. RRU.PrbTotDlDist
- D. VR.VCpuUsageMean

<details><summary>看答案</summary>

正解：B。RRU.PrbDl is defined as the measurement name for DL PRB usage for all traffic.

</details>

**2.** 虛擬化 CPU 使用率的測量值以什麼單位表示？

- A. 秒 (s)
- B. 百分比 (%)
- C. 核心數 (cores)
- D. 位元組 (bytes)

<details><summary>看答案</summary>

正解：B。The specification states the value is a single integer with unit %.

</details>

**3.** 下面哪個測量名稱用來統計 NgU 介面上接收的 GTP-U 資料封包的位元組數？

- A. GTP.InDataOctNgUgNB
- B. RRU.PrbDl
- C. VR.VCpuUsageMean
- D. PDUSesMeanNbr

<details><summary>看答案</summary>

正解：A。The measurement for incoming GTP data octets on NgU is named GTP.InDataOctNgUgNB.

</details>

**4.** 「VirtualResUtilizaiton」 KPI 的類型屬於哪一種？

- A. MEAN
- B. COUNTER
- C. RATIO
- D. GAUGE

<details><summary>看答案</summary>

正解：C。The KPI is described as a percentage and its type is Ratio.

</details>

**5.** 「Distribution of DL Total PRB Usage」的測量結果是一組整數，代表什麼？

- A. 每個 PRB 的使用時間（毫秒）
- B. 每個頻段的平均 PRB 使用率
- C. 每個使用率區間的樣本數量
- D. 每個 S‑NSSAI 的 PRB 使用比例

<details><summary>看答案</summary>

正解：C。The distribution provides the number of samples that fall into each usage bin.

</details>
