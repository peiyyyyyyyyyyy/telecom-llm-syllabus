# 1.2.2 IP 定址與子網路

所屬：[1.2 通訊協定](1-2.md)

## 內文

IP 位址用來識別網路中的通訊端，前綴表示可聚合的位址範圍。CIDR 用斜線和前綴長度表達共用的高位元，有利於子網切分、路由公告及轉送。規劃或修改子網時，先核對位址族、前綴、分配範圍及預期的上游路由，便能減少因遮罩或下一跳配置不符造成的連線問題。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html)

IPv4 位址由四個十進位數值表示，IPv6 常以十六進位欄位表示，並有對連續零欄位的壓縮方式。斜線後的數字指定共同位元數。當路由器找目的位址時，可同時找到個別子網、彙總路由和預設路由，最後採用符合的最長前綴。主機是否把目的端當成本鏈路的一員，還受該介面上的位址及前綴資訊影響。跨網段時應檢查去程和回程都能找到對應網段，尤其是在重疊網段或多路由來源的情境。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html) [IETF RFC 1122](https://www.rfc-editor.org/rfc/rfc1122.html)

IPv4 位址為 32 位元（[RFC 791](https://www.rfc-editor.org/rfc/rfc791.html)），IPv6 位址為 128 位元。假設使用文件範例 192.0.2.0/26，有 32 − 26 = 6 個剩餘位元，因此前綴涵蓋 2^6 = 64 個位址值。該數字是整個集合大小，能配給一般終端的數量還要依位址用途及該網段規則判定。IPv6 的 /64 表示前 64 位元為前綴，同樣可用位元界線說明包含關係。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html) [IETF RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html) [IETF RFC 5737](https://www.rfc-editor.org/rfc/rfc5737.html)

常見問題包括把斜線後的值當成主機位元數、把位址集合大小直接當可分配用戶數，以及把預設路由當作所有目的地的第一優先。判讀時先算前綴的界線，再查管理平台分配和保留的位址。遇到精確前綴與預設路由並存時，依轉送表確認具體目的位址採用哪個下一跳。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html)

維運遇到同網段能通，外網不通，先蒐集來源及目的位址、兩端前綴、閘道、實際轉送路由及是否涉及多介面。網路團隊比對路由來源與路由安裝結果，主機端團隊檢查位址及介面綁定。變更驗收應同時選子網內、子網外與反向流量，並對照變更前後前綴與轉送結果。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 1122](https://www.rfc-editor.org/rfc/rfc1122.html) [IETF RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html)
