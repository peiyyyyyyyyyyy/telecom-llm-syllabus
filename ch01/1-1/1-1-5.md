# 1.1.5 4G 核心網（EPC）

## 正文

The Evolved Packet Core (EPC) is the backbone of a 4G LTE network. It interconnects the Radio Access Network (RAN) with external packet data networks (PDNs) such as the Internet, corporate LANs, or private clouds. EPC’s primary purpose is to provide a **flat, all‑IP transport** for user plane traffic while handling control‑plane signaling for mobility, session management, authentication, and quality‑of‑service (QoS) enforcement. Because all user traffic traverses the EPC, its design directly impacts latency, throughput, scalability, and the ability to support emerging services (e.g., VoLTE, IoT).

---

### 1. Core EPC Functional Entities  

| Entity | Acronym | Main Functions | Typical Interfaces |
|--------|---------|----------------|--------------------|
| **Mobility Management Entity** | **MME** | NAS signaling, UE authentication, bearer setup, hand‑over control, idle‑mode tracking | S1‑MME (to eNodeB), S11 (to SGW), S6a (to HSS) |
| **Serving Gateway** | **SGW** | User‑plane anchor for intra‑eNodeB handovers, tunnels to eNodeB (S1‑U) and PGW (S5‑C), packet buffering | S1‑U (to eNodeB), S5‑C (to PGW), S11 (to MME) |
| **Packet Data Network Gateway** | **PGW** | IP address allocation, PDN connectivity (Internet, corporate), policy enforcement, charging | S5‑U (to SGW), Gx (to PCRF), Gy (to OCS), Sxa (to other PGWs) |
| **Home Subscriber Server** | **HSS** | Centralized subscriber database (authentication vectors, subscription data, QoS profiles) | S6a (to MME), S6d (to PCRF) |
| **Policy and Charging Rules Function** | **PCRF** | Dynamic QoS policy, charging rules, bandwidth allocation | Gx (to PGW), Rx (to AF), Sy (to charging system) |

These entities are defined in **3GPP TS 23.401** (Evolved Packet System (EPS) architecture). The EPC is deliberately modular: each function can be instantiated multiple times and placed in different geographic locations for load balancing and redundancy.

---

### 2. EPS Bearer Model  

An **EPS bearer** is a logical tunnel that carries user data with a specific QoS. Two types exist:

* **Default bearer** – created during the initial Attach procedure; carries best‑effort traffic; identified by the APN (Access Point Name) requested by the UE.
* **Dedicated bearer** – established on‑demand for services requiring guaranteed QoS (e.g., VoLTE).  

Each bearer is described by a **QoS Class Identifier (QCI)**, an **Allocation and Retention Priority (ARP)**, and a **Maximum Bit Rate (MBR)** / **Guaranteed Bit Rate (GBR)**.

The aggregate user‑plane capacity of an EPC node can be approximated by  

$$
C_{\text{node}} = \sum_{i=1}^{N_{\text{bearer}}} R_i
$$

where  

* $N_{\text{bearer}}$ = number of active EPS bearers on the node,  
* $R_i$ = allocated bitrate for bearer $i$ (Mbps).  

---

### 3. Control‑Plane Signaling Flow (Attach Example)  

1. **UE → eNodeB → MME**: NAS *Attach Request* (contains SUPI).  
2. **MME ↔ HSS (S6a)**: Authentication and subscription retrieval.  
3. **MME → SGW (S11)**: Create Session Request → SGW allocates a TEID (Tunnel Endpoint Identifier).  
4. **SGW → PGW (S5‑C)**: Create Session Request → PGW selects an IP address from the PDN and applies APN policy.  
5. **PGW → SGW → MME**: Responses travel back, establishing the default bearer.  

All signaling messages are transported over **S1‑MME**, **S11**, **S5‑C**, and **S6a** interfaces, each using the **SCTP** transport protocol with stream‑oriented reliability.

### 4. Worked Example – Dimensioning the MME  

**Problem:** A city‑wide LTE deployment expects a peak **attach rate** of 250 UE/s. Each MME instance can process 4,000 Attach requests per second (including authentication and bearer setup). Determine the minimum number of MME instances required to keep the CPU utilization below 80 %.

**Solution:**  

1. Compute the **required processing capacity** to meet the peak load with the desired headroom:  

$$
C_{\text{required}} = \frac{\text{Peak attach rate}}{0.8} = \frac{250\ \text{UE/s}}{0.8} = 312.5\ \text{UE/s}
$$

2. Determine the number of MME instances ($N_{\text{MME}}$) needed, given each instance handles $C_{\text{instance}} = 4{,}000\ \text{UE/s}$:  

$$
N_{\text{MME}} = \left\lceil \frac{C_{\text{required}}}{C_{\text{instance}}} \right\rceil = \left\lceil \frac{312.5}{4{,}000} \right\rceil = \left\lceil 0.0781 \right\rceil = 1
$$

Although a single MME can theoretically satisfy the load, best practice recommends **at least two instances** for redundancy and fault tolerance.  

**Result:** Deploy **2 MME nodes** (active‑active or active‑standby) to satisfy the attach demand while providing resilience.

### 5. Common Mistakes & Practical Notes  

| Mistake | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| **Confusing SGW and PGW roles** – treating SGW as the Internet gateway. | Both are gateways and share “G” in their names. | Remember: **SGW = user‑plane anchor for mobility**, **PGW = PDN gateway & policy enforcer**. |
| **Omitting APN validation in the PGW** – leading to traffic leakage. | Focus on bearer establishment, neglecting policy checks. | PGW must consult the **PCRF** (via Gx) to verify the UE’s subscribed APN and enforce charging rules. |
| **Under‑estimating MME signaling load** – only counting data plane traffic. | Data plane appears dominant; control plane is invisible. | Use real‑world attach, hand‑over, and paging statistics; dimension MME by **signaling messages per second**, not just UE count. |
| **Deploying SGW/PGW with mismatched interface versions** – causing SCTP association failures. | Vendor documentation may hide version numbers. | Verify that all EPC nodes support the same **3GPP release** (e.g., Release 15) for S1, S5, and S11 interfaces. |
| **Hard‑coding static IP pools in PGW** – exhausting address space. | Simpler to configure static ranges. | Use **Dynamic IP address allocation** (IPv4 DHCP or IPv6 prefix delegation) and monitor pool utilization. |

**Practical tip:** EPC nodes are typically virtualized (NFV) and scaled horizontally. When planning capacity, consider **per‑bearer processing cost**, **average session length**, and **peak concurrent bearers** in addition to raw attach rates.

---

**In summary**, the EPC provides the logical and physical framework that turns the LTE radio link into an end‑to‑end IP service. Mastery of its entities, interfaces, and QoS model is essential for designing reliable, high‑performance 4G networks and for transitioning smoothly to the service‑oriented 5G Core (5GC).
