# 1.1.7 IP 網與網際網路互連

所屬：[1.1 網路架構](../1-1.md)

## 正文

In a 5G system the **Data Network (DN)** – which may be a private intranet or the public Internet – is reached through the **User Plane Function (UPF)**. From the DN’s point of view the UPF appears as a conventional IP router, and the logical interface that connects them is called **N6**. This inter‑working is essential because all user‑plane traffic (e.g., web browsing, video streaming, enterprise VPN) must traverse the 5G core before it can be delivered to external IP networks. Consequently, understanding how the 5G core presents itself to the DN, and how IP addresses and authentication are handled, is a prerequisite for designing and operating end‑to‑end services [TS 29.561 §8.1].

---

### Key Definitions

| Symbol / Term | Meaning (as defined in the reference) |
|---------------|----------------------------------------|
| **DN** | “Data Network” that may be an intranet or the Internet [TS 29.561 §8.1]. |
| **UPF** | “5GS access point” that performs user‑plane forwarding and terminates the N6 interface [TS 29.561 §8.2.1]. |
| **N6** | Reference point **between the UPF and the external IP network**; from the external side the UPF looks like a normal IP router [TS 29.561 §8.2.1]. |
| **Transparent access** | UE receives an IP address from the operator’s pool and the 5GS does not participate in user authentication [TS 29.561 §8.2.2.1]. |
| **Non‑transparent access** | UE receives an IP address from the ISP/intranet pool and the 5GS may request authentication from an external DN‑AAA server (e.g., RADIUS, Diameter) [TS 29.561 §8.2.2.2]. |
| **Static address** | Assigned at subscription time and does not change [TS 29.561 §8.2.2.1]. |
| **Dynamic address** | Assigned during PDU session establishment [TS 29.561 §8.2.2.1]. |
| **Intranet Protocol** | Any protocol that provides end‑to‑end security between UE and the intranet; an example is IPsec [TS 29.561 §8.2.2.1]. |
| **DN‑AAA** | Authentication, Authorization, Accounting server used by the DN (e.g., RADIUS, Diameter) [TS 29.561 §8.2.2.2]. |
| **DHCPv4** | Address allocation server that may be used in non‑transparent IPv4 scenarios [TS 29.561 §8.2.2.2]. |

No specific formulas are required for the inter‑working model; the process is governed by the allocation of IP addresses (IPv4 or IPv6) and optional authentication exchanges.

---

### Inter‑working Models

#### 1. Transparent Access (Figure 8.2.2.1‑1)

* The UE is given an IPv4 address and/or an IPv6 prefix **belonging to the operator addressing space**. The address can be **static** (provisioned at subscription) or **dynamic** (assigned at PDU session establishment) [TS 29.561 §8.2.2.1].
* No authentication request is sent by the UE during PDU session establishment, and the SMF/UPF does **not** participate in user authentication [TS 29.561 §8.2.2.1].
* The UPF forwards packets to the DN over N6 as a regular IP router [TS 29.561 §8.2.1].

#### 2. Non‑transparent IPv4 Access (Figure 8.2.2.2‑1)

* An IPv4 address **belonging to the Intranet/ISP address space** is allocated to the UE at PDU session establishment. Allocation may be performed from a **local address pool** or via external servers such as **DHCPv4** or **DN‑AAA** [TS 29.561 §8.2.2.2].
* The SMF (or SMF + PGW‑C) **may request user authentication** from an external DN‑AAA server (RADIUS, Diameter) [TS 29.561 §8.2.2.2].
* If the transport between the UPF (or UPF + PGW‑U) and the Intranet/ISP traverses an insecure network (e.g., the public Internet), a **security protocol** (mutually agreed) can be inserted [TS 29.561 §8.2.2.2].

---

### Worked Example (Transparent IPv4)

A mobile broadband operator wants to give a UE transparent Internet access.

| Step | Action | Relevant Detail |
|------|--------|-----------------|
| 1 | UE initiates a PDU session. | No authentication request is sent [TS 29.561 §8.2.2.1]. |
| 2 | SMF instructs the UPF to allocate a **dynamic IPv4 address** from the operator pool, e.g., **198.51.100.23**. | Address belongs to the operator addressing space and is used for forwarding [TS 29.561 §8.2.2.1]. |
| 3 | UPF advertises the address to the UE and starts forwarding packets on N6. | From the external network’s view, the UPF behaves like a normal IP router [TS 29.561 §8.2.1]. |
| 4 | UE sends a TCP SYN to a web server (93.184.216.34). | The packet is encapsulated in the user‑plane tunnel, reaches the UPF, and is routed over N6 to the Internet. |
| 5 | Response packets follow the reverse path and are delivered to the UE. | No additional authentication or security protocol is required at N6 [TS 29.561 §8.2.2.1]. |

The entire flow demonstrates that the 5G core can be **transparent** to the Internet service, merely providing IP forwarding.

### Practical Notes & Common Mistakes

| Mistake | Why it is wrong (according to the reference) | Correct practice |
|---------|---------------------------------------------|------------------|
| Assuming the UPF authenticates the UE in transparent mode. | “the UE need not send any authentication request … and the SMF/UPF need not take any part in the user authentication/authorization process” [TS 29.561 §8.2.2.1]. | Rely on the fact that authentication is optional; only external DN‑AAA is involved in non‑transparent cases. |
| Using the operator’s IP address space for a private intranet without explicit agreement. | Interworking with “user defined ISPs and private/public IP networks is subject to interconnect agreements” [TS 29.561 §8.2.1]. | Ensure interconnect agreements are in place before allocating ISP‑owned addresses. |
| Believing that N6 must implement a specific routing protocol. | “It is out of the scope of the present document to standardise the router functions and the used protocols in the N6 reference point.” [TS 29.561 §8.2.1]. | Treat N6 as a generic IP interface; the operator may choose any routing protocol. |
| Forgetting to configure a security protocol when the UPF‑to‑Intranet link traverses the public Internet. | “There may be a specific security protocol in between… defined by mutual agreement between PLMN operator and Intranet/ISP administrator.” [TS 29.561 §8.2.2.2]. | Deploy IPsec or another mutually agreed security mechanism for insecure paths. |
| Assuming IPv6 address allocation always uses DHCPv6. | For IPv6 transparent access the reference states “Stateless Address Autoconfiguration shall be used” [TS 29.561 §8.2.2.1]. | Use SLAAC for IPv6 in transparent mode; DHCPv6 is not mandated. |

Understanding these nuances helps engineers design robust inter‑working configurations that respect both 3GPP specifications and the operational policies of external IP networks.

## 練習題

**1.** Which logical reference point connects the User Plane Function (UPF) to an external IP network?

- A. N4
- B. N6
- C. N9
- D. N3

<details><summary>看答案</summary>

正解：B。The specification defines the interface between the UPF and external IP networks as N6.

</details>

**2.** In the transparent access model, what is the role of the UE regarding authentication?

- A. The UE must authenticate with an external DN‑AAA server.
- B. The UE sends an authentication request that the SMF forwards to the DN.
- C. The UE need not send any authentication request and the SMF/UPF do not participate.
- D. The UE authenticates using a pre‑shared key with the UPF.

<details><summary>看答案</summary>

正解：C。Transparent access explicitly states that no authentication request is sent by the UE and the core functions do not take part.

</details>

**3.** When a UE receives an IP address in transparent access, that address must belong to which address space?

- A. The ISP’s public address pool.
- B. The operator’s addressing space.
- C. A private address range reserved for intranets.
- D. Any address space negotiated with the DN.

<details><summary>看答案</summary>

正解：B。Transparent access requires the UE to be assigned an address from the operator’s own IP space.

</details>

**4.** In non‑transparent IPv4 access, which type of server can the SMF request user authentication from?

- A. DNS server
- B. DHCPv6 server
- C. DN‑AAA server (e.g., RADIUS, Diameter)
- D. NTP server

<details><summary>看答案</summary>

正解：C。The specification allows the SMF (or SMF+PGW‑C) to query an external DN‑AAA server for authentication.

</details>

**5.** If the connection between the UPF (or UPF+PGW‑U) and an external intranet traverses an insecure network such as the public Internet, what must be done according to the reference?

- A. No action is needed; the UPF always encrypts traffic.
- B. The UPF must terminate the tunnel and forward plain IP.
- C. A security protocol, mutually agreed upon, may be inserted.
- D. The UE must switch to a different PDU session.

<details><summary>看答案</summary>

正解：C。The standard states that a security protocol can be used on insecure links, defined by agreement between the operators.

</details>
