## 正文

In a modern mobile system the radio access network (RAN) and the core network (EPC for 4G, 5GC for 5G) are ultimately attached to an **IP network** that provides transport for user‑plane (U‑plane) and control‑plane (C‑plane) packets. The IP network is also the gateway to the public Internet, enabling services such as web browsing, video streaming, and over‑the‑air (OTA) software updates. Proper design of the IP‑Internet interconnection therefore influences **throughput, latency, scalability, and security** of the whole mobile system.

---

### 1.1.7.1 Key Concepts and Definitions  

| Symbol | Meaning | Unit / Format |
|--------|---------|---------------|
| $IP_{v4}$ | IPv4 address (32‑bit) | dotted decimal, e.g. 192.0.2.10 |
| $IP_{v6}$ | IPv6 address (128‑bit) | colon‑hex, e.g. 2001:db8::1 |
| $N$ | Prefix length (number of leading 1 bits) | integer $0\!-\!32$ for IPv4, $0\!-\!128$ for IPv6 |
| $H$ | Number of usable host addresses in a subnet | count |
| $BGP$ | Border Gateway Protocol, the inter‑AS routing protocol used on the Internet |
| $PE$ | Provider Edge router (connects the mobile operator’s MPLS backbone to external IP networks) |
| $VRF$ | Virtual Routing and Forwarding instance – isolates routing tables per service or tenant |
| $NAT$ | Network Address Translation – maps private to public addresses |
| $QoS$ | Quality‑of‑Service – per‑flow priority, policing, shaping |
| $RTT$ | Round‑Trip Time – sum of forward and reverse propagation + processing delays, measured in ms |

#### Subnet size
For an IPv4 prefix of length $N$ the number of **usable** host addresses is  

$$
H = 2^{32-N} - 2
$$

The subtraction of 2 removes the network identifier (all‑zero host part) and the broadcast address (all‑one host part). For IPv6 the address space is so large that the “‑2” term is normally ignored.

#### BGP path selection (simplified)
When multiple external routes to the same destination exist, a BGP speaker selects the best path according to the following ordered criteria (high‑level view):

1. Highest **local preference** (default 100) – $LP$
2. Shortest **AS‑PATH length** – $L_{AS}$
3. Lowest **origin type** (IGP < EGP < INCOMPLETE) – $O$
4. Lowest **MED** (Multi‑Exit Discriminator) – $MED$

The effective metric can be expressed as a tuple  

$$
\text{Metric} = (LP,\; -L_{AS},\; -O,\; -MED)
$$

where larger $LP$ and smaller negative values are preferred.

#### Latency budget
A typical 5G user‑plane latency budget is 10 ms (one‑way). If the IP backbone contributes $t_{IP}$ ms and the radio link $t_{RAN}$ ms, the constraint is  

$$
t_{IP} + t_{RAN} \le 10\ \text{ms}
$$

---

### 1.1.7.2 Typical Interconnection Architecture  

```
[UE] ←→ [gNB] ←→ [UPF] ←→ [PE‑Router] ←→ [Internet]
                │                │
                └─[SMF]          └─[BGP]←→[External ASes]
```

* **UPF (User Plane Function)** forwards user data to the PE router using Ethernet or MPLS over a fiber or microwave link.
* The **PE router** hosts one or more **VRFs** (e.g., one for subscriber traffic, one for operator management). Each VRF runs a separate BGP session with the corresponding external Autonomous System (AS).
* **NAT** is optional. In 5G the preferred approach is **dual‑stack** (IPv4 + IPv6) with **public addressing** for subscriber sessions, reducing the need for NAT and preserving end‑to‑end reachability.

---

### 1.1.7.3 Worked Example  

**Scenario:** A mobile operator allocates a /28 IPv4 prefix to its PE router for subscriber traffic. The operator also runs BGP with a Tier‑1 ISP, advertising the prefix with a local preference of 150. Compute the number of usable subscriber IPs, determine the maximum number of simultaneous sessions if each subscriber requires a unique public IP, and verify whether the latency budget of 10 ms can be met when the IP backbone adds 4 ms of delay.

1. **Usable hosts**  

$$
H = 2^{32-28} - 2 = 2^{4} - 2 = 16 - 2 = 14
$$

Thus the operator can assign **14 public IPv4 addresses** to subscribers (e.g., for fixed‑wireless access points or dedicated IoT devices).  

2. **Maximum simultaneous sessions**  

If each subscriber uses exactly one public IP, the ceiling is 14 concurrent sessions. In practice, **NAT** or **IPv6** would be employed to serve many more users; otherwise the operator would need to request a larger prefix (e.g., /24 provides 254 usable addresses).  

3. **Latency check**  

Given $t_{IP}=4$ ms and a target one‑way latency of 10 ms, the allowable radio‑link budget is  

$$
t_{RAN} \le 10\ \text{ms} - 4\ \text{ms} = 6\ \text{ms}
$$

If the RAN contributes 5 ms (typical for a dense 5G small‑cell deployment), the total one‑way latency is 9 ms, satisfying the requirement.  

**Take‑away:** A /28 allocation is sufficient only for a very small cell or private network; larger prefixes or IPv6 are mandatory for commercial 5G deployments.

### 1.1.7.4 Common Pitfalls and Practical Notes  

| Pitfall | Why it happens | Correct practice |
|---------|----------------|------------------|
| **Under‑provisioning public IPv4 space** | Assuming NAT will hide scarcity, but many services (e.g., SIP, IPsec) need end‑to‑end reachability. | Deploy IPv6, or request larger IPv4 blocks; use Carrier‑Grade NAT only as a last resort. |
| **Mis‑configuring BGP local preference** | Setting a low $LP$ on the preferred upstream can cause traffic to flow through a higher‑cost ISP, increasing latency and cost. | Verify $LP$ values on all eBGP sessions; use route‑maps to enforce the intended preference. |
| **Ignoring MTU mismatch** | Ethernet (1500 B) vs. MPLS (1492 B) vs. PPPoE (1492 B) can cause fragmentation or packet loss. | Align MTU across the IP backbone; enable Path MTU Discovery (PMTUD) on UPF and PE. |
| **Overlooking QoS mapping** | Mapping 5G QoS Identifiers (5QI) to IP DSCP incorrectly can degrade latency‑sensitive services. | Follow the 3GPP TS 23.501 mapping tables; configure DSCP policing on the PE router. |
| **Assuming symmetric routing** | Asymmetric paths (different inbound/outbound routes) break stateful firewalls and some UDP‑based applications. | Deploy symmetric BGP policies or enable NAT state synchronization across routers. |

**Standard reference:** The interworking of the mobile core with IP networks is defined in *3GPP TS 23.501* (System Architecture for the 5G System) and the use of BGP for inter‑AS routing follows *IETF RFC 4271*.
