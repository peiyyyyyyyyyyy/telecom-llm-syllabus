# 1.1.9 網路與用戶識別碼：SUPI、GUTI、DNN、gNB／Cell ID

## 正文

In a mobile system the control plane must be able to uniquely address both **users** (UEs) and **network elements** (cells, gNBs, data networks).  Accurate identification is essential for authentication, session management, mobility handling, and for routing user‑plane traffic across the converged IP backbone.  The 5G system introduces a set of identifiers that replace or augment legacy ones (e.g., IMSI, TMSI) and that are designed to be privacy‑preserving, scalable, and interoperable with the IP world.

---

### 1.1.9.1 Subscription Permanent Identifier (SUPI)

The **SUPI** is the permanent, globally unique identifier of a subscription.  It is stored in the Home Subscriber Server (HSS/UDM) and is never exposed on the radio interface; instead it is transformed into a **SUCI** (encrypted SUPI) before transmission.

A SUPI follows the **IMSI‑like** format:

$$
\text{SUPI}= \underbrace{\text{MCC}}_{\text{3‑digit Mobile Country Code}}
               \; \underbrace{\text{MNC}}_{\text{2‑ or 3‑digit Mobile Network Code}}
               \; \underbrace{\text{MSIN}}_{\text{Mobile Subscription Identification Number}}
$$

* **MCC** – 3 decimal digits, e.g. “310” (USA).  
* **MNC** – 2 or 3 decimal digits, e.g. “260”.  
* **MSIN** – up to 10 decimal digits, uniquely assigned by the operator.

The SUPI is therefore a decimal string of 15–16 digits.  In binary, the IMSI encoding (as defined in 3GPP TS 23.003) packs each digit into 4 bits (BCD) with a filler “1111” for odd‑length numbers.

---

### 1.1.9.2 Globally Unique Temporary Identifier (GUTI)

To protect subscriber privacy during radio access, the network assigns a **temporary** identifier called the **GUTI**.  The GUTI is unique **globally** (i.e., across all PLMNs) for the lifetime of the UE’s registration with a particular AMF, and it is refreshed on handover or periodic re‑allocation.

The GUTI is composed of:

$$
\text{GUTI}= \bigl(\text{MCC},\ \text{MNC},\ \text{AMF\_Set\_ID},\ \text{AMF\_Pointer},\ \text{GUTI\_ID}\bigr)
$$

| Field | Size (bits) | Description |
|-------|------------|-------------|
| MCC   | 12 (3 × 4)  | Mobile Country Code (same as SUPI) |
| MNC   | 12 (2 × 4 + 4) | Mobile Network Code (2‑digit or 3‑digit) |
| AMF Set ID | 10 | Identifier of the AMF set within the PLMN |
| AMF Pointer | 6 | Pointer to the specific AMF instance |
| GUTI ID | 32 | Randomly allocated by the AMF, unique per UE |

The binary layout is defined in **3GPP TS 23.003 § 2.2.1**.  The total length is 64 bits (8 bytes) after the PLMN part.

---

### 1.1.9.3 Data Network Name (DNN)

A **DNN** identifies a specific data network (e.g., an internet service, a corporate LAN, or a private LTE network) that a UE may attach to.  In the 5G core, the DNN is carried in the **Session Management (SM) context** and is used by the **UPF** to select the appropriate routing and QoS policies.

The DNN is a **UTF‑8 string** up to 100 octets, typically expressed as a Fully Qualified Domain Name (FQDN) such as:

```
internet
enterprise.example.com
iot.mnc260.mcc310.3gppnetwork.org
```

When a UE requests a PDU session, it includes the DNN in the **PDU Session Establishment Request**; the SMF then maps the DNN to a **Data Network (DN) instance** and to the corresponding **UPF**.

---

### 1.1.9.4 gNB Identifier and Cell Identifier

The **gNB** (next‑generation NodeB) is the 5G radio access node.  Its identifier is needed for:

* RAN‑level signaling (NG‑interface, Xn‑interface)  
* Mobility management (handover, tracking area updates)  
* Radio resource allocation (scheduling, beamforming)

A **gNB ID** is defined as a 24‑bit value that, together with the PLMN ID, forms a **global gNB identifier**:

$$
\text{Global\_gNB\_ID}= \bigl(\text{MCC},\ \text{MNC},\ \text{gNB\_ID}\bigr),\qquad
\text{gNB\_ID}\in[0,2^{24}-1]
$$

The **Cell ID** (also called **NR‑Cell‑Identity**) is a further subdivision of the gNB’s coverage.  It is encoded as a 36‑bit value (the first 24 bits are the gNB ID, the remaining 12 bits identify the cell within the gNB).  Formally:

$$
\text{Cell\_ID}= \bigl(\text{gNB\_ID},\ \text{Cell\_Local\_ID}\bigr),\qquad
\text{Cell\_Local\_ID}\in[0,2^{12}-1]
$$

Both identifiers are carried on the **NG‑AP** and **RRC** messages.  The mapping to physical resources (carrier frequency, beam, sector) is defined locally by the gNB.

### 1.1.9.5 Worked Example

A UE belonging to **PLMN** with MCC = 310, MNC = 260 wishes to establish a PDU session to the public internet.

| Parameter | Value |
|-----------|-------|
| MCC | 310 |
| MNC | 260 |
| MSIN | 1234567890 |
| AMF Set ID | 0x1A3 (decimal 419) |
| AMF Pointer | 0x2D (decimal 45) |
| GUTI ID | 0x5F3C9A1B (decimal 1 595 099 099) |
| gNB ID | 0x00A1B2 (decimal 66 002) |
| Cell Local ID | 0x0F3 (decimal 243) |
| DNN | “internet” |

1. **SUPI** (decimal string)  

$$
\text{SUPI}= 310\;260\;1234567890 = \text{“3102601234567890”}
$$

2. **GUTI** (binary fields)  

$$
\begin{aligned}
\text{MCC} &= 310 = 0x13E \\
\text{MNC} &= 260 = 0x104 \\
\text{AMF\_Set\_ID} &= 0x1A3 \\
\text{AMF\_Pointer} &= 0x2D \\
\text{GUTI\_ID} &= 0x5F3C9A1B
\end{aligned}
$$

Packed into 64 bits (hex representation):  

`0x13E1041A32D5F3C9A1B`

3. **Global gNB ID**  

$$
\text{Global\_gNB\_ID}= (310,\ 260,\ 0x00A1B2)
$$

4. **Cell ID**  

$$
\text{Cell\_ID}= (0x00A1B2,\ 0x0F3) \;\Rightarrow\; 0x00A1B20F3
$$

5. **DNN**  

The UE includes the UTF‑8 string “internet” (7 octets) in the **PDU Session Establishment Request**.

The SMF receives the DNN, selects the default public internet data network, and creates a PDU session with the UPF.  The GUTI is stored in the UE’s **NAS context**, and the gNB/Cell ID are used to allocate radio resources for the session.

### 1.1.9.6 Practical Notes & Common Mistakes

| Pitfall | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| **Confusing SUPI with IMSI** | Both share the MCC‑MNC‑MSIN format, but SUPI is the logical name in 5G while IMSI is the legacy 2G/3G identifier. | Treat SUPI as the subscription’s permanent identifier; use **SUCI** (encrypted SUPI) on the air interface. |
| **Re‑using a GUTI after handover** | GUTI is meant to be refreshed when the UE moves to a new AMF or after a defined timer expires. | Implement the **GUTI Reallocation Procedure** (3GPP TS 23.502) and verify that the UE receives the new GUTI before completing handover. |
| **Assuming DNN is globally unique** | DNN strings are scoped per operator; the same name can exist in different PLMNs. | Combine DNN with PLMN ID when building routing tables in the SMF/UPF. |
| **Using only the 24‑bit gNB ID for cell discrimination** | Within a gNB, multiple cells share the same gNB ID; the Cell ID adds the local identifier. | Always use the full 36‑bit Cell ID when addressing a specific NR cell (e.g., in Xn handover). |
| **Neglecting the length limits of DNN** | Oversized DNN strings cause NAS message rejections. | Enforce the 100‑octet limit and validate UTF‑8 encoding before sending. |

Finally, remember that these identifiers are **layer‑specific**: SUPI/GUTI belong to the **NAS/SDAP** domain, DNN to the **Session Management** domain, and gNB/Cell ID to the **RAN** domain.  Proper translation between layers is performed by the AMF and SMF, ensuring that each identifier is used only where it is defined.
