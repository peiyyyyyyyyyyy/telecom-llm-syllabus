# 1.1.1 行動網路整體架構（終端、接取網、核心網、數據網）

所屬：[1.1 網路架構](../1-1.md)

## 正文

### Why an overall view matters
A mobile system is not a single monolithic device; it is a set of logically distinct domains that cooperate to deliver voice, data, and emerging services. Understanding the four‑tier view – **User Equipment (UE)**, **Access Network (RAN)**, **Core Network (5GC)**, and **Data Network (DN)** – is essential for any telecom engineer because each tier has its own set of network functions (NFs), interfaces, and performance constraints. Design, troubleshooting, and optimization decisions are made at the boundary of these tiers, therefore a clear picture of how they interconnect is a prerequisite for any further study (e.g., RAN functional splits or core‑network service‑based architecture).

### Reference architecture (non‑roaming)
The 3GPP TS 23.501 specification depicts the **non‑roaming 5G system architecture** in two complementary diagrams:

* **Figure 4.2.3‑1** shows the logical block diagram of the system, where service‑based interfaces (SBIs) are used inside the control plane.  
* **Figure 4.2.3‑2** presents the same architecture as a set of point‑to‑point reference points, making explicit the interactions among the NFs.

Both figures contain the same set of functional blocks:

| Domain | Representative NFs (examples) | Role |
|--------|-------------------------------|------|
| **UE** | – | Generates user traffic and signalling. |
| **Access Network (RAN)** | gNB (or gNB‑CU / gNB‑DU) | Provides radio connectivity to the UE. |
| **Core Network (5GC)** | AMF, SMF, UPF, PCF, UDM, NRF (and optionally NEF, UDR, etc.) | Handles control‑plane procedures, session management, user‑plane forwarding, policy, and subscriber data. |
| **Data Network (DN)** | Public Internet, private enterprise networks, edge clouds | Destination of user packets (PDN). |

The reference points (e.g., N1, N2, N3, N4, N6, N11, N12, N13, N15, N16) connect these NFs, but the specification deliberately omits some auxiliary NFs (UDSF, NEF, NRF, UDR, etc.) for clarity while noting that they can be present and interact as needed [TS 23.501 §4.2.3].

### Control‑plane service‑based interfaces
Within the core, **service‑based interfaces** replace the legacy point‑to‑point protocols. For instance, the AMF, SMF, PCF, and UDM expose services that other NFs discover and invoke via the **Network Repository Function (NRF)**. The NRF therefore “provides proper network function instance information during network function discovery and selection” [TS 23.501 §4.2.3].

### User‑plane forwarding (UPF)
User‑plane packets travel from the UE through the RAN (N3) to the **User Plane Function (UPF)**, which may be collocated with the SMF or placed in the transport network. The specification notes that “direct interaction between UPF and NFs can be supported via the Nupf interface” [TS 23.501 §4.2.3].

### Multiple PDU Sessions and data‑network selection
A UE can simultaneously attach to **two data networks** (e.g., a local enterprise network and a central Internet) using **multiple PDU Sessions**. Figure 4.2.3‑3 illustrates a scenario where two distinct SMFs are selected – one for each PDU Session – and each SMF may control its own UPF. Conversely, Figure 4.2.3‑4 shows that a single PDU Session can also carry traffic for two data networks, with the same SMF governing both a local and a central UPF [TS 23.501 §4.2.3].

### Subscriber and policy data sources
The **Unified Data Management (UDM)** supplies *subscription data* and *authentication data* to the AMF and SMF, while the **Policy Control Function (PCF)** provides *policy data* that may be stored in the **Unified Data Repository (UDR)** [TS 23.501 §4.2.3].

### Worked example: Dual‑PDU‑Session setup

A UE wishes to connect simultaneously to:

1. **Local corporate network** (requiring low latency) – *PDU Session 1*  
2. **Public Internet** (high bandwidth) – *PDU Session 2*

Assume the following simplified mapping, consistent with Figures 4.2.3‑3 and 4.2.3‑4:

| Element | Assigned NF | Reason |
|---------|-------------|--------|
| UE → RAN | gNB (CU‑DU split) | Radio access |
| PDU 1 Control | SMF‑A | Selected for local network |
| PDU 1 User‑plane | UPF‑A (edge‑located) | Low‑latency forwarding |
| PDU 2 Control | SMF‑B | Selected for Internet |
| PDU 2 User‑plane | UPF‑B (central) | High‑capacity core |

Steps (high‑level):

1. UE sends **PDU Session Establishment** request (N1) to the AMF.  
2. AMF contacts the **NRF** to discover suitable SMFs.  
3. For *PDU 1*, the NRF returns **SMF‑A**; for *PDU 2*, **SMF‑B**.  
4. Each SMF selects an appropriate **UPF** (A or B) and creates the corresponding **user‑plane tunnel** (N3).  
5. The AMF informs the UE of the two **PDU Session IDs** and the associated QoS parameters.

Result: traffic for the corporate application traverses **UPF‑A → local DN**, while bulk Internet traffic uses **UPF‑B → public DN**. This example directly follows the architecture described in Figures 4.2.3‑3 and 4.2.3‑4, where “two SMFs are selected for the two different PDU Sessions” and “each SMF may also have the capability to control both a local and a central UPF within a PDU Session” [TS 23.501 §4.2.3].

### Common mistakes and practical notes

| Mistake | Why it is wrong (reference) | Practical tip |
|---------|----------------------------|---------------|
| Treating the **core** as a monolithic block rather than a collection of service‑based NFs. | The specification stresses “service‑based interfaces are used within the Control Plane” and that each NF provides discoverable services [TS 23.501 §4.2.3]. | View each NF (AMF, SMF, PCF, etc.) as an independent micro‑service that can be scaled and placed flexibly. |
| Assuming a **single SMF** must serve all PDU Sessions of a UE. | Figure 4.2.3‑3 shows “two SMFs are selected for the two different PDU Sessions” [TS 23.501 §4.2.3]. | Deploy multiple SMFs when different sessions have distinct QoS or data‑network requirements. |
| Ignoring the **NRF** role in NF discovery. | “The NRF … provides proper network function instance information during network function discovery and selection” [TS 23.501 §4.2.3]. | Ensure the NRF is reachable and correctly populated; otherwise NFs cannot locate each other. |
| Overlooking the optional **direct UPF‑NF interaction** (Nupf). | “Direct interaction between UPF and NFs can be supported via the Nupf interface” [TS 23.501 §4.2.3]. | When low‑latency policy enforcement is needed, configure the Nupf path. |
| Forgetting that auxiliary NFs (UDSF, NEF, UDR, etc.) exist even if omitted from the diagrams. | The notes explicitly state that “UDSF, NEF and NRF have not been depicted… however, all depicted Network Functions can interact with the UDSF, UDR, NEF and NRF as necessary” [TS 23.501 §4.2.3]. | Include these functions in design documents; they are required for subscription management, exposure of services, and data storage. |

By keeping these points in mind, engineers can correctly interpret the logical blocks of the 5G system, design robust deployments, and avoid configuration pitfalls that stem from an incomplete architectural understanding.

## 練習題

**1.** What is the role of an SCP in the non‑roaming 5G system architecture?

- A. It provides direct exposure of network services to external applications.
- B. It can be used for indirect communication between NFs and NF services, but does not expose services itself.
- C. It replaces the NRF for network function discovery.
- D. It functions as a user plane function for data forwarding.

<details><summary>看答案</summary>

正解：B。The SCP is only a mediator for indirect NF communication and does not expose services.

</details>

**2.** Which reference points are noted as not being shown in all other figures, though they may be applicable?

- A. N1 and N2
- B. N3 and N4
- C. N9 and N14
- D. N11 and N12

<details><summary>看答案</summary>

正解：C。The text explicitly mentions that N9 and N14 are omitted from many diagrams.

</details>

**3.** Which network function uses subscription data and authentication data according to the reference text?

- A. PCF
- B. UDR
- C. UDM
- D. NEF

<details><summary>看答案</summary>

正解：C。The UDM is responsible for handling subscription and authentication information.

</details>

**4.** Which figure illustrates the non‑roaming architecture for concurrent access to two data networks within a single PDU Session?

- A. Figure 4.2.3‑2
- B. Figure 4.2.3‑3
- C. Figure 4.2.3‑4
- D. Figure 4.2.3‑5

<details><summary>看答案</summary>

正解：C。Figure 4.2.3‑4 is described as showing the single‑PDU‑Session option for dual data‑network access.

</details>

**5.** According to the reference, the trust domain for NEF is the same as that for which other function?

- A. SMF
- B. SCEF
- C. PCF
- D. UDM

<details><summary>看答案</summary>

正解：B。The NEF shares the same trust domain as the SCEF.

</details>
