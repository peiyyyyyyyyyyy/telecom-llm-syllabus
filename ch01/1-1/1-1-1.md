## 正文

A modern mobile‑communication system is a hierarchy of functional domains that together deliver end‑to‑end (E2E) services to a user equipment (UE). Understanding the four logical layers—**UE, Access Network (AN), Core Network (CN), and Data Network (DN)**—is essential for any telecom engineer because performance, scalability, and service differentiation are all derived from how these layers interact.

---

### 1.1.1.1 Definitions  

| Symbol | Meaning | Unit |
|--------|---------|------|
| **UE** (User Equipment) | Mobile terminal (smartphone, IoT module, vehicle‑mounted modem) that hosts the protocol stack up to the application layer. | – |
| **AN** (Access Network) | Radio Access Network (RAN) that provides the air‑interface between UE and the transport network. In 4G it consists of eNodeB (eNB); in 5G it is split into gNB‑CU, gNB‑DU, and optionally gNB‑RU. | – |
| **CN** (Core Network) | Packet‑core that performs control‑plane (signalling) and user‑plane (data) functions. 4G EPC includes MME, SGW, PGW; 5G 5GC includes AMF, SMF, UPF, etc. | – |
| **DN** (Data Network) | Any IP network that terminates user traffic: public Internet, private enterprise LAN, cloud edge, or IoT platform. | – |
| **DNN** (Data Network Name) | Identifier of a DN in 5G (similar to APN in 4G). | – |
| **T\_UE** | Processing delay inside the UE (layer‑2/3 stack, application). | ms |
| **T\_RAN** | One‑way air‑interface latency (including scheduling, HARQ, propagation). | ms |
| **T\_TRAN** | Transport (back‑haul/ fronthaul) one‑way latency between AN and CN. | ms |
| **T\_CN** | One‑way processing delay inside the CN (signalling, forwarding). | ms |
| **T\_DN** | One‑way latency from the CN’s user‑plane function to the final DN (e.g., Internet round‑trip). | ms |

The **end‑to‑end (E2E) latency** for a single direction is the sum of the above components:

$$
T_{\text{E2E}} = T_{\text{UE}} + T_{\text{RAN}} + T_{\text{TRAN}} + T_{\text{CN}} + T_{\text{DN}} \tag{1}
$$

For a round‑trip measurement (e.g., ping) the latency is doubled, assuming symmetric paths.

---

### 1.1.1.2 Functional Overview  

1. **UE Layer** – Implements the radio protocol stack (PDCP, RLC, MAC, PHY) and the IP stack. It also hosts the application that generates traffic.  
2. **Access Network** – Provides radio resources, performs scheduling, and forwards user‑plane packets to the transport network. In 5G the split architecture (CU/DU/RU) enables functional disaggregation and edge computing.  
3. **Core Network** – Hosts control‑plane entities (e.g., AMF, SMF) that manage session establishment, mobility, and authentication, and user‑plane entities (e.g., UPF) that route IP packets to the appropriate DNN.  
4. **Data Network** – The ultimate destination of user traffic. The CN maps the UE’s DNN (or APN) to a DN route, possibly inserting policy enforcement (QoS, charging).

The **control plane (C‑plane)** traverses UE → AN → CN, while the **user plane (U‑plane)** continues UE → AN → CN → DN. The separation is explicit in 5G, allowing the U‑plane to be steered independently of signalling.

---

### 1.1.1.3 Worked Example  

A 5G‑NR UE streams a 108 Mbps video packet to a cloud server on the public Internet. Typical component delays (one‑way) are:

| Component | Typical value |
|-----------|---------------|
| $T_{\text{UE}}$ | 2 ms (MAC processing + IP stack) |
| $T_{\text{RAN}}$ | 5 ms (scheduling + propagation at 3.5 GHz) |
| $T_{\text{TRAN}}$ | 2 ms (fiber fronthaul + backhaul) |
| $T_{\text{CN}}$ | 3 ms (UPF processing, QoS enforcement) |
| $T_{\text{DN}}$ | 10 ms (Internet router hops to cloud) |

Using (1):

$$
\begin{aligned}
T_{\text{E2E}} &= 2 + 5 + 2 + 3 + 10 \\
               &= 22\ \text{ms (one‑way)} .
\end{aligned}
$$

For a round‑trip (RTT) measurement the latency is approximately $2 \times 22 = 44$ ms, which is well within the 50 ms latency budget for ultra‑reliable low‑latency communications (URLLC) but would be too high for tactile‑internet applications requiring <10 ms RTT.

### 1.1.1.4 Practical Notes & Common Mistakes  

| Mistake | Why it Happens | Correct Approach |
|---------|---------------|------------------|
| **Ignoring transport latency** | Engineers sometimes treat the AN–CN link as “instantaneous” because fiber is fast. | Always add $T_{\text{TRAN}}$; even a 1 km fiber adds ~5 µs per km plus queuing, which can become significant in dense deployments. |
| **Confusing DNN with IP prefix** | DNN is a logical name; it is not the same as the actual IP subnet announced by the DN. | Map DNN → DNN‑Profile → IP routing table in the UPF; keep the two layers distinct. |
| **Assuming control‑plane latency is negligible** | Control signalling (e.g., handover) traverses the same path but often incurs extra processing. | Include an extra $T_{\text{CN}}^{\text{C‑plane}}$ (typically 5–10 ms) when evaluating handover interruption time. |
| **Mismatching 4G and 5G terminology** | Using “PGW” in a 5G diagram creates confusion. | Use EPC terms for 4G (MME, SGW, PGW) and 5GC terms for 5G (AMF, SMF, UPF). |
| **Overlooking edge‑computing placement** | Edge servers are sometimes placed in the AN or CN without adjusting latency budgets. | When a DN resides at the edge (e.g., MEC), set $T_{\text{DN}}$ ≈ 1–2 ms, and recalculate $T_{\text{E2E}}$ accordingly. |

**Key takeaway:** The overall performance of a mobile network is the linear sum of delays across its four logical layers. Accurate dimensioning requires realistic values for each component and an awareness of where functional splits (CU/DU/RU) or edge services reside.

*Reference:* 3GPP TS 23.501 “System Architecture for the 5G System (5GS)”; 3GPP TS 23.401 for LTE EPC.
