# 1.1.4 傳輸網：光纖、微波，前傳／中傳／回傳

所屬：[1.1 網路架構](../1-1.md)

## 正文

In a mobile radio access network (RAN) the *transport network* is the set of links that carry digitised radio‑frequency (RF) samples, control and user‑plane data between the functional blocks of the base station (gNB) and the rest of the system.  The transport segment is usually divided into three logical layers:

* **Fronthaul** – between the radio unit (RU) and the distributed unit (DU) (or directly between base‑band and RF in a split‑1 architecture).  
* **Midhaul** – between the DU and the central unit (CU) (or between DU and the core network when a split‑2 or split‑3 is used).  
* **Backhaul** – between the CU (or the aggregation node) and the 4G/5G core network.

These layers can be realised with **optical fiber** (e.g., wavelength‑division‑multiplexed (WDM) links) or **microwave point‑to‑point** radio links.  The 3GPP specifications do not prescribe a particular medium; the choice is a deployment decision that must meet the bitrate requirements derived in the transport‑network analysis of the RAN functional split [TS 38.801 §11.1.4]​.

---

### 1.1.4.1 Bit‑rate Requirement Model

The transport network must sustain the *peak* bitrate generated by the conversion of base‑band samples to a digital stream.  For the PHY/RF split considered in the reference architecture, the peak bitrate on a transmission link is given by  

$$
R_{\text{peak}} = N_{\text{ant}} \times f_{\text{s}} \times B_{\text{w}} + R_{\text{overhead}},
$$

where  

* $N_{\text{ant}}$ – number of antenna ports (or antenna elements) $$unit: dimensionless$$  
* $f_{\text{s}}$ – sampling frequency $$unit: samples s$^{-1}$], defined as **30.72 MS/s per 20 MHz** of system bandwidth (the reference uses 30.72 MS/s for each 20 MHz) [TS 38.801 §11.1.4]​  
* $B_{\text{w}}$ – bit width per sample \[unit: bits/sample], taken as **30 bits** in the reference [TS 38.801 §11.1.4]​  
* $R_{\text{overhead}}$ – protocol overhead (e.g., Ethernet, FEC).  The reference treats this term generically and does not give a numeric value, so it is retained as a placeholder.

Because $f_{\text{s}}$ scales linearly with the **system bandwidth**, the overall bitrate grows linearly with both the bandwidth and the number of antenna ports [TS 38.801 §11.1.4]​.

---

### 1.1.4.2 Example Calculation

Assume a deployment with the following parameters:

* System bandwidth = **20 MHz** (thus $f_{\text{s}} = 30.72\;\text{MS/s}$)  
* Number of antenna ports = **8**  
* Bit width = **30 bits** (as specified)  

The peak bitrate per antenna port is  

\[
R_{\text{per\;ant}} = f_{\text{s}} \times B_{\text{w}} = 30.72 \times 10^{6}\;\text{samples/s} \times 30\;\text{bits/sample}
                 = 921.6 \times 10^{6}\;\text{bit/s}
                 = 0.9216\;\text{Gbps}.
$$

Multiplying by the number of antenna ports:

$$
R_{\text{peak}} = 8 \times 0.9216\;\text{Gbps} = 7.3728\;\text{Gbps}.
$$

Rounded to the nearest integer, the required transport capacity is **8 Gbps**, which matches the value shown in Table 11.1.4.2‑1 of the specification for 8 antenna ports and 20 MHz bandwidth [TS 38.801 §11.1.4]​.

If the same 8‑port radio were to operate on a **200 MHz** system bandwidth, the sampling frequency would increase ten‑fold (because 200 MHz / 20 MHz = 10).  Consequently, the required bitrate would also increase ten‑fold, yielding **80 Gbps**—again consistent with the table.

---

### 1.1.4.3 Implications for Fronthaul / Midhaul / Backhaul Design

* **Fronthaul** links, which sit closest to the RU, must support the highest bitrate because they carry the raw digitised RF samples.  For massive‑MIMO configurations (e.g., 64 or 256 antenna ports) and wide system bandwidths (up to 1 GHz as allowed by NR), the required fronthaul capacity can reach **3.2 Tbps** (256 ports × 1 GHz) [TS 38.801 §11.1.4]​.
* **Midhaul** links, connecting DU to CU, can often use a *higher‑level functional split* (e.g., split‑2 or split‑3) that reduces the transported data volume.  The reference does not give explicit numbers for these splits; therefore, any quantitative statement would be outside the scope of the cited material.
* **Backhaul** links aggregate traffic from many cells and must be dimensioned for the *user‑plane* load rather than the raw RF sample rate.  The specification does not provide backhaul‑specific bitrate figures, so a detailed backhaul design is also outside the scope of this subsection.

---

### 1.1.4.4 Common Mistakes and Practical Notes

| Mistake | Why it occurs | Correct approach |
|--------|---------------|-----------------|
| **Assuming a fixed bitrate regardless of antenna count** | Engineers sometimes use a single “1 Gbps fronthaul” rule of thumb. | Use the linear formula $R_{\text{peak}} = N_{\text{ant}} \times f_{\text{s}} \times B_{\text{w}}$ and update $f_{\text{s}}$ when the system bandwidth changes [TS 38.801 §11.1.4]​. |
| **Neglecting overhead** | Overhead is easy to overlook because the table shows rounded values. | Include $R_{\text{overhead}}$ when dimensioning the physical link (e.g., Ethernet framing, FEC). The specification notes “+ overhead” in the peak bitrate expression. |
| **Confusing functional split with physical medium** | Some designers equate “fronthaul = fiber” and “midhaul = microwave”. | The 3GPP documents do not bind a split to a specific transport technology; both fiber and microwave can be used for any logical layer as long as the bitrate requirement is satisfied [TS 38.801 §11.1.4]​. |
| **Treating the table values as exact limits** | The table presents *maximised* requirements; real deployments may need less due to compression or lower antenna counts. | Use the table as an upper bound; apply the exact formula for the specific deployment to obtain a precise figure. |

Finally, remember that the **system bandwidth** in NR is defined per carrier component; aggregating multiple carriers (carrier aggregation) will further increase the required transport capacity proportionally.  Any design must therefore consider both the per‑carrier bitrate and the number of aggregated carriers.

--- 

*All statements above are directly supported by 3GPP TS 38.801 §11.1.4.*

## 練習題

**1.** According to the 3GPP reference, what is the sampling frequency used for each 20 MHz of NR system bandwidth?

- A. 15.36 MS/s
- B. 30.72 MS/s
- C. 61.44 MS/s
- D. 122.88 MS/s

<details><summary>看答案</summary>

正解：B。The specification explicitly states a sampling frequency of 30.72 Mega Samples per second for each 20 MHz bandwidth.

</details>

**2.** How does the required transport bitrate scale when both the number of antenna ports and the system bandwidth are increased?

- A. It scales quadratically with the number of antenna ports.
- B. It scales linearly with the number of antenna ports and linearly with the system bandwidth.
- C. It scales exponentially with the system bandwidth only.
- D. It remains constant regardless of bandwidth or antenna count.

<details><summary>看答案</summary>

正解：B。The reference notes that the required bitrate is linearly increasing with both parameters.

</details>

**3.** Which of the following statements about the transport medium (fiber vs. microwave) is supported by the reference text?

- A. The specification mandates the use of optical fiber for fronthaul.
- B. Microwave links are prohibited for backhaul in NR.
- C. The choice of fiber or microwave is a deployment decision outside the scope of the specification.
- D. Both fiber and microwave are required in every NR deployment.

<details><summary>看答案</summary>

正解：C。The reference does not prescribe any specific transport medium; it only defines bitrate requirements.

</details>

**4.** What is the bit width per sample assumed in the peak bitrate calculation of the reference?

- A. 8 bits
- B. 16 bits
- C. 24 bits
- D. 30 bits

<details><summary>看答案</summary>

正解：D。The reference explicitly uses a bit width of 30 bits per sample.

</details>
