# 1.2.9 控制面與用戶面協定堆疊

所屬：[1.2 通訊協定](1-2.md)

## 內文

控制面負責建立並維護服務與資源，用戶面運送服務資料。兩者即使共用實體傳輸網，也有各自的協定、邏輯端點和狀態。在 gNB 與 5G 核心之間，N2 讓接取網和控制功能交換訊息，N3 讓接取網與 UPF 之間送收用戶資料。這個區分有助於解釋控制程序完成後，資料仍可能只在某個方向中斷。 [3GPP TS 23.501 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/18.11.00_60/ts_123501v181100p.pdf) [3GPP TS 38.300 Release 19](https://www.etsi.org/deliver/etsi_ts/138300_138399/138300/19.02.00_60/ts_138300v190200p.pdf)

以 N2 為例，接取網控制訊息由 NGAP 表達，經 SCTP 及 IP 抵達對端。N3 上的用戶資料則依 GTP-U 規則封裝，再以 UDP 和外層 IP 送往另一個隧道端點。外層 IP 指明目前傳輸路段的對端，內層則是原用戶資料所保留的內容。接收端依隧道資訊定位對應資料流，並在適當位置解封裝或再轉送。閱讀封包時先核對觀測位置和封裝的內外界線，再辨識哪一層的欄位可用來關聯事件。N2 和 N3 兩端的功能角色見 1.2.10。 [3GPP TS 38.412 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138412/18.01.00_60/ts_138412v180100p.pdf) [3GPP TS 38.413 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138413/18.09.00_60/ts_138413v180900p.pdf) [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf) [3GPP TS 23.501 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/18.11.00_60/ts_123501v181100p.pdf)

假設 N3 的外層採用 IPv6，且沒有 IPv6 擴充標頭，GTP-U 也只採基本標頭，則外層標頭的開銷是 40 + 8 + 8 = 56 位元組，依序來自 IPv6、UDP 與 GTP-U。這個算例不含鏈路層與其他可選封裝。實際承載有擴充欄位時，要從線上封包或組態查其額外長度。 [IETF RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html) [IETF RFC 768](https://www.rfc-editor.org/rfc/rfc768.html) [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf)

常見混淆包括把外層 IP 當成使用者位址、把可見的控制成功訊息當作用戶資料已通，以及忽略隧道方向。外層端點與內層資料要分欄讀。控制面證據用來確認資源與上下文是否建立，資料是否到達仍要靠適用方向的封包紀錄及計數驗證。 [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf) [3GPP TS 38.413 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138413/18.09.00_60/ts_138413v180900p.pdf) [3GPP TS 23.501 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/18.11.00_60/ts_123501v181100p.pdf)

工單應保留對應程序、邏輯介面、方向、兩端節點及測點。控制團隊核對 NGAP 與 SCTP，用戶面團隊比對外層端點、隧道資訊及內層資料，傳輸團隊再確認兩個網路端點間的實際可達性。若只有一個方向受影響，保留同一會話的雙向基準，便於對照第一個流量落差。 [3GPP TS 38.412 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138412/18.01.00_60/ts_138412v180100p.pdf) [3GPP TS 38.413 Release 18](https://www.etsi.org/deliver/etsi_ts/138400_138499/138413/18.09.00_60/ts_138413v180900p.pdf) [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf) [3GPP TS 23.501 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/18.11.00_60/ts_123501v181100p.pdf)
