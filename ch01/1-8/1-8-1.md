# 1.8.1 網管中心的角色與分工

所屬：[1.8 維運組織](../1-8.md)

## 正文

In a Public Land Mobile Network (PLMN) the *Network Management Center* (NMC) is the logical hub where the day‑to‑day control, monitoring, and optimisation of the radio and core infrastructure are performed. Its importance stems from the need to keep the network **operational, meet quality‑of‑service (QoS) commitments, and generate accurate billing** for every subscriber. If any of these functions fail, customers experience dropped calls, reduced data rates, or incorrect invoices, which directly impacts revenue and brand reputation.

### Core concepts defined in the PLMN management architecture

| Term | Definition (as per TS 32.101 §4.1.4) |
|------|--------------------------------------|
| **Management infrastructure** | “Every PLMN Organisation has its own management infrastructure.” It aggregates the hardware, software, and procedural assets required to deliver the four functional pillars of a mobile operator. |
| **Functional pillars** | “Every PLMN Organisation: provides services to its customers; needs an infrastructure …; assures them …; bills them ….” These are **Service Provision**, **Infrastructure Management**, **Assurance**, and **Billing**. |
| **Operations System (OS)** | Part of the ITU‑TMN architecture: “OS (Operations Systems) …”. An OS hosts management applications (e.g., fault management, performance management). |
| **Network Element (NE)** | “NE (Network Elements) …”. Physical or logical devices such as base stations, routers, or core nodes that are managed. |
| **Q‑interface** | “Q, within one Operator Domain …”. The interface used for management communication *inside* the same operator’s domain. |
| **X‑interface** | “X, between different Operators …”. The interface used to reach processes that are not locally implemented, i.e., to invoke functions in another PLMN entity. |
| **Telecom Operations Map (TOM)** | An alternative, top‑down, customer‑oriented view that builds on the TMN model. |

These definitions are the building blocks for the NMC’s internal organisation.

### Division of labor inside the NMC

Because the PLMN management architecture is *core‑similar* across operators, most NMCs adopt a **functional split** that mirrors the four pillars:

1. **Service Provision Team** – Handles order intake, service activation, and provisioning of subscriber profiles.  
2. **Infrastructure Team** – Manages inventory, configuration, and software upgrades of NEs and OSs.  
3. **Assurance Team** – Performs fault detection, QoS monitoring, and trouble‑ticket handling.  
4. **Billing Team** – Generates usage records, applies rating and discount rules, and produces invoices.

Each team owns a subset of the **management functions** defined by ITU‑TMN (fault, performance, configuration, accounting). The *division of labor* is not dictated by a single standard but follows directly from the statement that “Each management infrastructure contains different functionality depending on the role‑played and the equipment used by that PLMN Entity” [TS 32.101 §4.1.4].

### Interaction model – Q and X interfaces

Within a single operator, the NMC’s functional teams communicate over the **Q‑interface**. For example, when the Assurance Team detects a fault on a base station (NE), it raises a trouble ticket that the Infrastructure Team receives via the Q‑link to trigger a corrective work order.

If a particular PLMN entity does **not** implement a required process (e.g., a small MVNO that outsources fault management), the missing function is reached through an **X‑interface** to a partner organisation that does implement it. The reference text explicitly states: “Processes not implemented by a particular organisation are accessed via interconnections to other organisations … (called X‑interfaces in the ITU‑TM TMN architecture)” [TS 32.101 §4.1.4].

### Simple quantitative illustration

Assume an NMC operates with the following staffing allocation (persons) for a medium‑size operator:

| Function | Staff (persons) | % of total staff |
|----------|----------------|------------------|
| Service Provision | 12 | 30 % |
| Infrastructure | 10 | 25 % |
| Assurance | 14 | 35 % |
| Billing | 4 | 10 % |
| **Total** | **40** | **100 %** |

The **staffing ratio** can be expressed as  

$$
\text{Ratio}_{\text{Assurance}} = \frac{N_{\text{Assurance}}}{N_{\text{Total}}}= \frac{14}{40}=0.35\;(35\%)
$$

This simple calculation highlights that, in practice, the **Assurance** function typically consumes the largest share of resources because fault detection and QoS monitoring are continuous activities, whereas **Billing** can be more automated.

### Common pitfalls and practical notes

| Pitfall | Why it occurs | Mitigation |
|---------|---------------|------------|
| **Treating Q and X as identical** | The reference does not differentiate external vs. internal interfaces, leading to the false belief that any interface can be used interchangeably. | Remember: *Q* is intra‑operator; *X* is inter‑operator. Use X only when a function is absent locally. |
| **Over‑centralising all functions** | “Each management infrastructure contains different functionality depending on the role‑played” – a one‑size‑fits‑all NMC ignores role‑specific equipment and processes. | Align team responsibilities with the actual equipment (e.g., RAN vs. core) and with the functions each PLMN entity actually provides. |
| **Assuming every PLMN implements the full architecture** | The text notes that “Not every PLMN Organisation will implement the complete management architecture”. | Conduct a gap analysis early and document which functions are outsourced or accessed via X‑interfaces. |
| **Neglecting the Telecom Operations Map** | The TOM provides a top‑down, customer‑oriented view that complements TMN but is often omitted. | Use TOM to verify that the NMC’s functional split still satisfies end‑to‑end customer processes (order → activation → assurance → billing). |

By adhering to the principles above, the NMC can reliably fulfil the PLMN’s four essential management pillars while remaining flexible enough to interoperate with external partners when needed.

## 練習題

**1.** 哪一項不是每個 PLMN 組織的核心功能之一？

- A. 提供服務給客戶
- B. 需要具備廣告、訂購、建置、佈建等基礎設施
- C. 確保服務運作與品質
- D. 為客戶計費

<details><summary>看答案</summary>

正解：B。核心功能包括提供服務、確保運作與品質以及計費，基礎設施的需求屬於支援性需求而非核心功能。

</details>

**2.** 若某個 PLMN 組織未實作特定流程，應透過何種介面取得該流程？

- A. Q‑介面
- B. X‑介面
- C. Z‑介面
- D. 手動程序

<details><summary>看答案</summary>

正解：B。未實作的流程會透過與其他已實作該流程的組織之間的 X‑介面連接取得。

</details>

**3.** 在 ITU‑TMN 架構中，哪一種介面用於不同營運商之間的連接？

- A. Q 介面
- B. X 介面
- C. Y 介面
- D. Z 介面

<details><summary>看答案</summary>

正解：B。X 介面專門用來連接不同營運商的管理系統。

</details>

**4.** 管理架構對外部與內部介面的區別是什麼？

- A. 明確區分兩者
- B. 不作區分
- C. 僅支援外部介面
- D. 僅支援內部介面

<details><summary>看答案</summary>

正解：B。管理架構將外部與內部介面視為相同，沒有特別的區分。

</details>

**5.** 哪一種管理方法以 TMN 為基礎，提供自上而下、以客戶為導向的視角？

- A. ITU‑TMN
- B. Telecom Operations Map
- C. LLA（Logical Layered Architecture）
- D. OS/NE 架構

<details><summary>看答案</summary>

正解：B。Telecom Operations Map 以 TMN 為基礎，從客戶導向的角度進行管理。

</details>
