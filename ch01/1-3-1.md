# 1.3.1 語音：電路交換、CSFB、VoLTE／VoNR（IMS）與 SRVCC

所屬：[1.3 服務與多媒體](1-3.md)

## 內文

行動語音可由傳統電路交換服務提供，也可由封包網上的 IMS 提供。電路交換語音為通話安排相應的電路資源。VoLTE 和 VoNR 則分別利用 LTE 與 NR 接取提供 IMS 語音。在設備與網路世代共存時，還有呼叫建立前的回落及通話中的延續程序。理解當時採用的語音方式，能把撥不通、通話中斷與通話後沒有聲音分開查。 [3GPP TS 23.272 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123272/18.00.00_60/ts_123272v180000p.pdf) [3GPP TS 23.216 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123216/18.00.00_60/ts_123216v180000p.pdf) [3GPP TS 24.229 Release 18](https://www.etsi.org/deliver/etsi_ts/124200_124299/124229/18.06.00_60/ts_124229v180600p.pdf) [ETSI TS 103 905](https://www.etsi.org/deliver/etsi_ts/103900_103999/103905/01.01.01_60/ts_103905v010101p.pdf)

CSFB 適用於 EPS 與相應電路交換系統協作的情境。當終端在 LTE 要發起或接收電路交換呼叫時，依程序移到可提供該語音服務的接取，接著在電路交換側處理呼叫。SRVCC 則用於適用部署中，讓進行中的 IMS 語音通話轉到電路交換接取。走 IMS 語音時，可用 SIP 信令確認呼叫建立和會話協商，以 RTP 等媒體線索查看語音承載。即使通話雙方已接通，媒體流仍可能受路由或單向傳送問題影響。 [3GPP TS 23.272 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123272/18.00.00_60/ts_123272v180000p.pdf) [3GPP TS 23.216 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123216/18.00.00_60/ts_123216v180000p.pdf) [3GPP TS 24.229 Release 18](https://www.etsi.org/deliver/etsi_ts/124200_124299/124229/18.06.00_60/ts_124229v180600p.pdf) [IETF RFC 3550](https://www.rfc-editor.org/rfc/rfc3550.html) [ETSI TS 103 905](https://www.etsi.org/deliver/etsi_ts/103900_103999/103905/01.01.01_60/ts_103905v010101p.pdf)

常見混淆包括將 CSFB 與 SRVCC 合稱回落、不區分 5GS 的 EPS fallback 與回到電路交換，以及用信令成功推論媒體正常。CSFB 主要處理在 LTE 開始的電路交換呼叫，SRVCC 著重維持已進行中的 IMS 呼叫。EPS fallback 讓適用的語音需求改用 EPS，後續可採 IMS 語音。即使會話建立成功，實際收送的媒體仍要另外確認。 [3GPP TS 23.272 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123272/18.00.00_60/ts_123272v180000p.pdf) [3GPP TS 23.216 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123216/18.00.00_60/ts_123216v180000p.pdf) [3GPP TS 23.502 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123502/18.11.00_60/ts_123502v181100p.pdf) [3GPP TS 24.229 Release 18](https://www.etsi.org/deliver/etsi_ts/124200_124299/124229/18.06.00_60/ts_124229v180600p.pdf) [IETF RFC 3550](https://www.rfc-editor.org/rfc/rfc3550.html)

工單應記接取類型、呼叫方向、異常發生於建立前還是通話中，以及是否出現接取變更。無線團隊查小區及回落或切換結果，核心和語音平台團隊查註冊、呼叫信令、會話協商及媒體路徑。若只單向無聲，保留雙向的媒體端點、流量與時間供傳輸及語音團隊對照。若在跨小區時重現，將失效時刻和無線、核心及 IMS 訊息排在同一時序，以確認當時有沒有執行語音延續。 [3GPP TS 23.216 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123216/18.00.00_60/ts_123216v180000p.pdf) [3GPP TS 23.502 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123502/18.11.00_60/ts_123502v181100p.pdf) [3GPP TS 24.229 Release 18](https://www.etsi.org/deliver/etsi_ts/124200_124299/124229/18.06.00_60/ts_124229v180600p.pdf) [IETF RFC 3550](https://www.rfc-editor.org/rfc/rfc3550.html) [ETSI TS 103 905](https://www.etsi.org/deliver/etsi_ts/103900_103999/103905/01.01.01_60/ts_103905v010101p.pdf)
