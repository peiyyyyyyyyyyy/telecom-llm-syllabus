# 1.3.2 簡訊與訊息服務

所屬：[1.3 服務與多媒體](1-3.md)

## 內文

SMS 為終端提供短訊息的提交與交付，並可依部署使用不同接取和信令承載。終端發出、網路接受、接收端取得和回報結果，是可以分開觀察的事件。如果使用者說訊息送不出去或接收延遲，應先確認服務確為業者簡訊，並辨認所採用的承載與交付階段。 [3GPP TS 24.011 Release 18](https://www.etsi.org/deliver/etsi_ts/124000_124099/124011/18.00.00_60/ts_124011v180000p.pdf) [3GPP TS 23.040 Release 18](https://www.etsi.org/deliver/etsi_ts/123000_123099/123040/18.00.00_60/ts_123040v180000p.pdf) [3GPP TS 23.204 Release 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123204/19.01.00_60/ts_123204v190100p.pdf)

在 LTE 的相容部署中，SMS 可以經 SGs 與對應的核心交換。在 5GS 的 SMS over NAS 情境，終端可透過 NAS 交付簡訊訊息，核心的 AMF 與 SMSF 協作，後續依部署與簡訊傳送網路交接。支援 IMS 的終端和網路則可透過 IMS 送收 SMS，並由對應的閘道銜接簡訊服務。一次送出可跨越終端、接取、服務核心和目的端，故回報應標出是提交、核心接手、目的端交付，或狀態通知，並查明前一階段是否已回覆成功。 [3GPP TS 23.272 Release 18](https://www.etsi.org/deliver/etsi_ts/123200_123299/123272/18.00.00_60/ts_123272v180000p.pdf) [3GPP TS 24.501 Release 18](https://www.etsi.org/deliver/etsi_ts/124500_124599/124501/18.11.01_60/ts_124501v181101p.pdf) [3GPP TS 23.502 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123502/18.11.00_60/ts_123502v181100p.pdf) [3GPP TS 23.540 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123540/18.03.00_60/ts_123540v180300p.pdf) [3GPP TS 23.204 Release 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123204/19.01.00_60/ts_123204v190100p.pdf)

容易混淆的是 SMS over NAS 與 SMS over IMS、上送確認與收件確認，以及業者簡訊與應用程式訊息。前兩種 SMS 會在不同介面留下信令紀錄。上送有回覆時，接收端的到達結果仍要依後續紀錄辨識。若使用者實際使用的是資料網上的應用程式，應轉查其資料連通及應用服務。遇到只有一部分目的號碼異常時，也需再查訊息送達路徑。 [3GPP TS 24.501 Release 18](https://www.etsi.org/deliver/etsi_ts/124500_124599/124501/18.11.01_60/ts_124501v181101p.pdf) [3GPP TS 23.540 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123540/18.03.00_60/ts_123540v180300p.pdf) [3GPP TS 23.204 Release 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123204/19.01.00_60/ts_123204v190100p.pdf) [3GPP TS 24.011 Release 18](https://www.etsi.org/deliver/etsi_ts/124000_124099/124011/18.00.00_60/ts_124011v180000p.pdf)

維運須保留發送與接收方向、共同時間、實際接取、相關原因與狀態回報，號碼等資料以允許的方式遮罩。核心團隊核對 NAS 及短訊息功能，IMS 團隊核對相應信令，簡訊平台團隊確認後續路由及交付。若「可送不可收」或只有異網失敗，分別重測正反向和網內外目的端，再按前後事件判定應請哪個交接窗口加入。記錄每次測試的提交、接收及回報時間，並保留終端當時的接取狀態。若目的端一度離線，接收狀態與所見通知的時間也應分開保存。 [3GPP TS 23.502 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123502/18.11.00_60/ts_123502v181100p.pdf) [3GPP TS 23.540 Release 18](https://www.etsi.org/deliver/etsi_ts/123500_123599/123540/18.03.00_60/ts_123540v180300p.pdf) [3GPP TS 23.204 Release 19](https://www.etsi.org/deliver/etsi_ts/123200_123299/123204/19.01.00_60/ts_123204v190100p.pdf) [3GPP TS 24.011 Release 18](https://www.etsi.org/deliver/etsi_ts/124000_124099/124011/18.00.00_60/ts_124011v180000p.pdf)
