### 1.2.10 Network Interfaces: NG, Xn, F1, E1 and N4 (PFCP)

#### Why these interfaces matter
In a 5G Core (5GC) the separation of control‑plane (CP) and user‑plane (UP) functions is a cornerstone of scalability and flexibility. The logical reference points **NG**, **Xn**, **F1**, **E1** and **N4** are the “glue” that bind the distributed RAN and Core elements together:

* **NG** connects the NG‑RAN (gNB‑Central Unit, gNB‑Distributed Unit) to the Access and Mobility Management Function (AMF) and to the User Plane Function (UPF).  
* **Xn** links neighbouring NG‑RAN nodes, enabling hand‑over, dual‑connectivity and data forwarding without involving the Core.  
* **F1** and **E1** are the intra‑RAN split interfaces (F1 between CU‑CP and DU, E1 between CU‑CP and CU‑UP). No detailed specifications are provided in the current reference set, therefore they are mentioned here only for completeness.  
* **N4** is the PFCP (Packet Forwarding Control Protocol) reference point over which the SMF (Session Management Function) programs the UPF.

Understanding the protocol stacks and the guaranteed vs. non‑guaranteed delivery semantics of each interface is essential for network planning, performance engineering, and troubleshooting.

---

#### 1. NG Interface (NG‑U and NG‑C)

| Direction | Interface | Transport | Protocol stack | Delivery guarantee | Main functions |
|-----------|-----------|-----------|----------------|--------------------|----------------|
| User‑plane | **NG‑U** | IP / UDP | GTP‑U on top of UDP/IP | non‑guaranteed | Carry user‑plane PDUs between NG‑RAN node and UPF |
| Control‑plane | **NG‑C** | IP / SCTP | SCTP on top of IP, application layer NGAP | guaranteed (SCTP) | Interface management, UE context, mobility, NAS transport, paging, PDU Session Management, configuration transfer, warning messages |

* The NG‑U transport network layer is built on IP transport and GTP‑U is used on top of UDP/IP to carry the user plane PDUs between the NG‑RAN node and the UPF. **NG‑U provides non‑guaranteed delivery** of user plane PDUs.  
* The NG‑C transport network layer is built on IP transport. **SCTP is added on top of IP** for reliable transport of signalling messages. The SCTP layer provides **guaranteed delivery** of application‑layer messages.  

These two logical links together realise the split between the Central Unit (CU‑CP) and the UPF, allowing independent scaling of CP and UP resources.

---

#### 2. Xn Interface (Xn‑U and Xn‑C)

| Direction | Interface | Transport | Protocol stack | Delivery guarantee | Main functions |
|-----------|-----------|-----------|----------------|--------------------|----------------|
| User‑plane | **Xn‑U** | IP / UDP | GTP‑U on top of UDP/IP | non‑guaranteed | Data forwarding, flow control |
| Control‑plane | **Xn‑C** | IP / SCTP | SCTP on top of IP, application layer XnAP | guaranteed (SCTP) | Interface management, UE mobility (context transfer, RAN paging), dual connectivity |

* The Xn‑U interface uses **GTP‑U on top of UDP/IP** and **provides non‑guaranteed delivery** of user plane PDUs. It supports data forwarding and flow control between two NG‑RAN nodes.  
* The Xn‑C interface uses **SCTP on top of IP** and the **XnAP** signalling protocol. SCTP guarantees delivery of the signalling messages. Xn‑C supports UE mobility management, including context transfer and RAN paging, as well as dual connectivity.

---

#### 3. PFCP over N4

PFCP is the protocol that the SMF uses to program the UPF. The reference point is called **N4** (or **N4mb** for multi‑broadcast sessions). PFCP messages carry instructions such as creation, modification or deletion of **PDRs** (Packet Detection Rules), **FARs** (Forwarding Action Rules), **QERs** (QoS Enforcement Rules) and **URRs** (Usage Reporting Rules).

Key operational principle (excerpted from the specification):

> “The CP function controls the packet processing in the UP function by establishing, modifying or deleting **PFCP Session contexts** and by provisioning (i.e. adding, modifying or deleting) **PDRs, FARs, QERs, URRs, BAR and/or MAR** …”  [TS 29.244 §5.2.1]

A PFCP session context may correspond to a single PDU session, a standalone session, or an MBS (multicast‑broadcast) session. Each **PDR** contains a **PDI** (Packet Detection Information) that defines the match fields (e.g., UE IP address, F‑TEID). The **FAR** tells the UPF what to do with matched packets (forward, drop, duplicate, buffer). The **QER** enforces QoS parameters such as maximum bitrate, while **URR** collects traffic statistics.

---

#### 4. Worked Example: Provisioning an UL PDR over N4

A UE establishes a single non‑GBR uplink (UL) bearer. The SMF must instruct the UPF to forward all UL packets to the Data Network (DN) via the SGW‑U (in a 5GC this is the UPF itself). The steps are:

1. **Create PFCP Session** (N4) → SMF sends a **PFCP Session Establishment Request** to the UPF.  
2. **Provision a PDR**:
   * **PDI**: match on UE IPv4 address = 10.0.0.5, UE F‑TEID = 12345.  
   * **FAR**: Apply Action = **FORWARD**, Forwarding Parameters = Destination UPF (IP = 192.168.10.10, GTP‑U port = 2152).  
3. **Provision a QER** (optional) to enforce a maximum uplink bitrate of 10 Mbps.  
4. **Provision a URR** to report total UL bytes every 5 seconds.

Assume the UE sends a 1500‑byte IP packet. The UPF matches the packet against the PDR (using the UE IP address). Because the FAR’s Apply Action is *FORWARD*, the UPF encapsulates the packet in GTP‑U and sends it to the destination IP 192.168.10.10. The QER ensures the aggregate UL rate does not exceed 10 Mbps; if it does, the UPF will drop excess packets. Every 5 seconds the UPF sends a **Usage Report** to the SMF containing the byte count.

This example shows how **N4 (PFCP)** translates high‑level session concepts into concrete forwarding rules that the UPF enforces in real time.

---

#### 5. Practical notes and common pitfalls

| Pitfall | Why it occurs | Remedy |
|---------|---------------|--------|
| Assuming **NG‑U** guarantees delivery | NG‑U uses UDP/GTP‑U, which is connection‑less and does not retransmit lost packets. | Design applications (e.g., video streaming) to tolerate packet loss or use higher‑layer retransmission (RTP/RTCP). |
| Mixing up **SCTP** and **UDP** transport for control planes | Both NG‑C and Xn‑C rely on SCTP for reliability; confusing them with the user‑plane UDP can lead to mis‑configuration. | Verify the transport mapping in the network element configuration: control‑plane = SCTP, user‑plane = UDP. |
| Forgetting to include **PDI** fields that uniquely identify a PFCP session | The specification requires each PDR to contain information that identifies the PFCP session (e.g., UE IP, F‑TEID). | When creating PDRs, always include at least one unique identifier in the PDI. |
| Over‑provisioning identical PDR match fields in the same PFCP session | The CP must not provision more than one PDR with the same set of match fields, otherwise the UPF cannot deterministically select a rule. | Use distinct match criteria (e.g., differentiate by VLAN ID or QoS Flow Identifier). |
| Ignoring **dual connectivity** functions on Xn‑C | Xn‑C also carries signalling for dual connectivity; omitting it can break hand‑over between master and secondary gNBs. | Ensure Xn‑C is enabled and correctly configured on all neighbouring NG‑RAN nodes. |

---

#### 6. Scope note on F1 and E1

The **F1** (CU‑CP ↔ DU) and **E1** (CU‑CP ↔ CU‑UP) split interfaces are defined in other 3GPP specifications (e.g., TS 38.401, TS 38.473). They are not covered by the reference material provided for this subsection and therefore are mentioned only for completeness.

## 練習題

**1.** Which transport protocol provides guaranteed delivery for the NG‑C control plane?

- A. UDP
- B. TCP
- C. SCTP
- D. GTP‑U

<details><summary>看答案</summary>

正解：C。NG‑C uses SCTP on top of IP, which guarantees delivery of signalling messages.

</details>

**2.** What is the primary function of the Xn‑U interface?

- A. Transfer of NAS messages
- B. Data forwarding and flow control between NG‑RAN nodes
- C. UE context management
- D. Provisioning PFCP rules

<details><summary>看答案</summary>

正解：B。Xn‑U carries user‑plane PDUs and supports data forwarding and flow control.

</details>

**3.** In PFCP, which information element identifies the packets that a PDR should match?

- A. FAR
- B. QER
- C. PDI
- D. BAR

<details><summary>看答案</summary>

正解：C。The Packet Detection Rule (PDR) contains a Packet Detection Information (PDI) element that defines the match fields.

</details>

**4.** Which statement correctly describes the delivery guarantee of the Xn‑C interface?

- A. It provides non‑guaranteed delivery because it uses UDP.
- B. It provides guaranteed delivery because it uses SCTP.
- C. It provides guaranteed delivery because it uses GTP‑U.
- D. It provides non‑guaranteed delivery because it uses TCP.

<details><summary>看答案</summary>

正解：B。Xn‑C uses SCTP on top of IP, which guarantees delivery of signalling messages.

</details>
