# 1.2.9 控制面與用戶面協定堆疊

所屬：[1.2 通訊協定](../1-2.md)

## 正文

**Control‑Plane and User‑Plane Protocol Stacks**  

In a 5G system the *control plane* (signalling) and the *user plane* (user‑data transport) are defined by separate protocol stacks.  The separation allows the network to scale independently: control‑plane functions such as registration, mobility management and session set‑up are handled by lightweight signalling protocols, while the user plane can be optimized for high‑throughput tunnelling.  Understanding the exact protocol layers and their reference points (N1, N2, N3, N4, N9, etc.) is essential for designing, troubleshooting, and extending 5G radio access networks (RAN) and core networks (5GC).

---

### 1. Control‑Plane Stacks  

#### 1.1 N2 – 5G‑AN ↔ AMF  
The N2 interface connects any type of 5G access node (3GPP NG‑RAN, N3IWF for un‑trusted non‑3GPP access, etc.) to the Access and Mobility Management Function (AMF) using **NG Application Protocol (NG‑AP)** over **Stream Control Transmission Protocol (SCTP)**.  

*Key properties*  

* A **single NG‑AP protocol** is used for both 3GPP and non‑3GPP accesses.  
* The AMF hosts **one unique N2 termination point per access for a given UE**, independent of how many PDU Sessions the UE has.  
* NG‑AP can carry *N2 SM information* that the AMF simply forwards between the 5G‑AN and the Session Management Function (SMF).  

> “The connection of multiple different kinds of 5G‑AN … to the 5GC via a unique Control Plane protocol: A single NGAP protocol is used for both the 3GPP access and non‑3GPP access”[TS 23.501 §8.2.1.1]  
> “There is a unique N2 termination point in AMF per access for a given UE regardless of the number (possibly zero) of PDU Sessions of the UE”[TS 23.501 §8.2.1.1]  
> “NOTE 2: The N2 SM information is exchanged between the SMF and the 5G‑AN transparently to the AMF.”[TS 23.501 §8.2.1.1]  

#### 1.2 N1 – UE ↔ AMF  
Every UE establishes **one N1 NAS signalling connection** to the AMF, regardless of the number of accesses it uses.  The N1 stack contains two sub‑protocols:

* **NAS‑MM** (Mobility Management) – handles registration, connection‑management state machines, integrity protection and ciphering.  
* **NAS‑SM** (Session Management) – carries session‑related messages that are later forwarded to the SMF.  

> “A single N1 NAS signalling connection is used for each access to which the UE is connected. The single N1 termination point is located in AMF.”[TS 23.501 §8.2.2]  
> “The NAS protocol on N1 comprises a NAS‑MM and a NAS‑SM components.”[TS 23.501 §8.2.2]  
> “Provide a secure NAS signalling connection (integrity protection, ciphering) between the UE and the AMF, including for the transport of payload;”[TS 23.501 §8.2.2]  

The N1 protocol is *access‑agnostic*: the same NAS messages are used over both 3GPP and non‑3GPP accesses.

---

### 2. User‑Plane Stacks  

#### 2.1 PDU Session User Plane (N3, N9, N4)  
When a UE activates a PDU Session, the user‑plane data are carried over **GPRS Tunnelling Protocol – User plane (GTP‑U)**.  GTP‑U creates an IP tunnel between the 5G‑AN and the User‑Plane Function (UPF) on the **N3** interface, and between UPFs on the **N9** interface.  The same protocol is reused on **N4** for control of the tunnel (see TS 29.244, not reproduced here).  

*Important attributes*  

* **Encapsulation** – GTP‑U encapsulates **all end‑user PDUs** (IPv4, IPv6, Ethernet, etc.) on a per‑PDU‑Session basis.  
* **QoS marking** – The tunnel carries QoS Flow identifiers defined in the session.  
* **Flexibility of the data path** – 3GPP does not constrain the number of UPFs; a path may contain zero, one, or many UPFs, and a UPF may optionally act as a *non‑PDU‑Session‑Anchor*.

> “GPRS Tunnelling Protocol for the user plane (GTP‑U): This protocol supports tunnelling user data over N3 … and N9 … GTP shall encapsulate all end user PDUs.”[TS 23.501 §8.3.1]  
> “The number of UPF in the data path is not constrained by 3GPP specifications: there may be … 0, 1 or multiple UPF …”[TS 23.501 §8.3.1]  

#### 2.2 Transport Layers  
Below the GTP‑U header the stack uses **UDP/IP** (or optionally UDP over IPsec for NAT traversal).  For un‑trusted non‑3GPP accesses (e.g., N3IWF) the UDP layer may be placed **below the IPsec layer** to enable NAT traversal.  

> “The UDP protocol may be used below the IPsec layer to enable NAT traversal.”[TS 23.501 §8.3.2]  

---

### 3. Worked Example  

A UE establishes **two PDU Sessions**:  

| Session | Type | QoS Flow ID | Required UPFs |
|--------|------|------------|---------------|
| 1      | IPv4 | 10         | UPF‑A (anchor) |
| 2      | Ethernet | 20    | UPF‑A (anchor) → UPF‑B (branch) |

**Control‑plane view**  

* **N1**: One NAS signalling connection to the AMF.  
* **N2**: One NG‑AP termination in the AMF for the UE (independent of the two sessions).  

**User‑plane view**  

* Both sessions use **GTP‑U** tunnels on **N3** between the gNodeB and **UPF‑A**.  
* Session 2 additionally traverses **N9** from **UPF‑A** to **UPF‑B** (branching point).  

Because the specification permits **zero, one, or multiple UPFs**, this layout is valid. The GTP‑U header in each tunnel carries the appropriate QoS Flow ID (10 or 20) and the PDU type (IPv4 or Ethernet).  

---

### 4. Common Mistakes & Practical Notes  

| Mistake | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| Assuming one UPF per PDU Session | The spec explicitly states the number of UPFs is not constrained. | Design the data path with the required number of UPFs; a session may traverse none, one, or several UPFs. |
| Treating N2 as a per‑session interface | N2 termination is per‑UE per‑access, not per‑session. | Use a single NG‑AP association for all sessions of a UE on a given access. |
| Using TCP for N2 signalling | SCTP, not TCP, guarantees delivery of NG‑AP messages. | Deploy SCTP as the transport for N2. |
| Confusing N1 with user‑plane traffic | N1 carries only NAS signalling, never user data. | Keep user‑plane traffic on N3/N9/N4 with GTP‑U. |
| Ignoring the need for IPsec on un‑trusted accesses | NAT traversal requires UDP under IPsec. | Insert an IPsec layer between the UE and the N3IWF, with UDP below it. |

By keeping the control‑plane and user‑plane stacks distinct and by respecting the reference points defined in 3GPP TS 23.501, engineers can build interoperable, scalable 5G deployments.
