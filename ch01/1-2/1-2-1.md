# 1.2.1 OSI 與 TCP/IP 分層

所屬：[1.2 通訊協定](../1-2.md)

## 正文

### 1.2.1 OSI and TCP/IP Layering  

**Why layering matters** – Modern telecommunication networks are built from heterogeneous hardware, operating systems, and application software. A layered architecture isolates concerns: each layer offers services to the layer above and hides its internal mechanisms from the layer below. This modularity enables independent evolution, simplifies troubleshooting, and provides a common vocabulary for engineers and protocol designers.

---

#### 1.2.1.1 The OSI Reference Model  

The Open Systems Interconnection (OSI) model, defined by ISO 8473‑1, specifies **seven logical layers**:

| Layer | Name                | Primary Function |
|-------|---------------------|-------------------|
| 7     | Application         | Network‑level services for end‑user processes (e.g., HTTP, SMTP). |
| 6     | Presentation        | Data representation, encryption, compression. |
| 5     | Session             | Dialog control, synchronization, checkpointing. |
| 4     | Transport           | End‑to‑end reliability, flow control, multiplexing (TCP, UDP, SCTP). |
| 3     | Network             | Path selection, logical addressing, routing (IP). |
| 2     | Data Link           | Framing, MAC addressing, error detection (Ethernet, 802.11). |
| 1     | Physical            | Bit‐level transmission, signaling, media characteristics. |

Each layer communicates with its immediate neighbours via **service primitives** (request, indicate, confirm, response). The model is *conceptual*; real protocols often collapse adjacent layers.

---

#### 1.2.1.2 The TCP/IP Model  

The Internet Engineering Task Force (IETF) standardized a **four‑layer** model that directly maps to the protocols used on the public Internet:

| Layer (TCP/IP) | Approximate OSI counterpart | Core protocols |
|----------------|-----------------------------|----------------|
| Application    | OSI 5‑7                     | HTTP, DNS, SIP, TLS |
| Transport      | OSI 4                       | TCP, UDP, SCTP |
| Internet       | OSI 3                       | IPv4, IPv6, ICMP |
| Link (Network Interface) | OSI 2‑1            | Ethernet, Wi‑Fi (802.11), PPP |

The TCP/IP model is **implementation‑oriented**: the four layers are defined by the protocols that actually exist, not by abstract service definitions. Consequently, the *Link* layer subsumes both OSI Data Link and Physical functions.

---

#### 1.2.1.3 Mapping Between the Two Models  

| OSI Layer | TCP/IP Layer(s) | Example mapping |
|-----------|----------------|-----------------|
| Application, Presentation, Session | Application | An HTTP request traverses OSI 7‑5 but is treated as a single Application‑layer payload in TCP/IP. |
| Transport | Transport | TCP segment → OSI Transport PDU. |
| Network | Internet | IPv4 packet → OSI Network PDU. |
| Data Link + Physical | Link | Ethernet frame (MAC + PHY) → OSI Data Link + Physical. |

Understanding this mapping is essential when configuring devices that expose OSI‑style terminology (e.g., “layer 2 switch”) but must interoperate with TCP/IP stacks.

---

#### 1.2.1.4 Key Quantitative Relationships  

1. **Maximum Transmission Unit (MTU)** – the largest payload size a layer can forward without fragmentation.  
   $$\text{MTU}_{\text{L}} = \text{MTU}_{\text{L+1}} - H_{\text{L+1}}$$  
   where $H_{\text{L+1}}$ is the header size added by the upper layer $L\!+\!1$.  

2. **End‑to‑end latency** across $n$ layers (ignoring queuing) can be approximated as:  
   $$T_{\text{e2e}} = \sum_{i=1}^{n} \left( \frac{L_i}{R_i} + t_{p,i} \right)$$  
   - $L_i$ = length of the header+payload at layer $i$ (bits)  
   - $R_i$ = transmission rate of the medium at layer $i$ (bits/s)  
   - $t_{p,i}$ = processing delay introduced by layer $i$ (s)  

These formulas are useful for capacity planning and for estimating the impact of adding or removing encapsulation layers (e.g., VPN tunnels).

---

#### 1.2.1.5 Worked Example  

**Scenario**: A 1500‑byte Ethernet frame carries an IPv4 packet that encapsulates a TCP segment containing a 1200‑byte application payload (e.g., a file chunk). Ethernet’s MTU is 1500 bytes, IPv4 header = 20 bytes, TCP header = 20 bytes.

1. **Calculate the IPv4 payload size**:  
   $$L_{\text{IPv4 payload}} = \text{MTU}_{\text{Ethernet}} - H_{\text{Ethernet}} = 1500\ \text{B} - 14\ \text{B} = 1486\ \text{B}$$  
   (Ethernet header = 14 B, ignoring FCS).

2. **Check if the IPv4 packet fits**:  
   $$H_{\text{IPv4}} + H_{\text{TCP}} + \text{App payload} = 20\ \text{B} + 20\ \text{B} + 1200\ \text{B} = 1240\ \text{B} < 1486\ \text{B}$$  
   Hence no IP fragmentation is required.

3. **Compute total bits transmitted on the wire** (including preamble 8 B, SFD 1 B, IFG 12 B):  
   $$\text{Total bytes} = 8\ (\text{preamble}) + 1\ (\text{SFD}) + 1500\ (\text{frame}) + 12\ (\text{IFG}) = 1521\ \text{B}$$  
   $$\text{Total bits} = 1521\ \text{B} \times 8\ \frac{\text{bits}}{\text{B}} = 12{,}168\ \text{bits}$$  

If the link runs at $R = 1\ \text{Gb/s}$, the transmission time is:  
   $$t_{\text{tx}} = \frac{12{,}168\ \text{bits}}{1 \times 10^{9}\ \text{bits/s}} = 12.168\ \mu\text{s}$$  

This example illustrates how each layer’s header contributes to the overall wire‑level size and latency.

---

#### 1.2.1.6 Common Mistakes & Practical Notes  

| Mistake | Why it’s wrong | Remedy |
|---------|----------------|--------|
| Treating the OSI Presentation layer as a separate protocol in IP networks. | Most modern stacks fold presentation functions (e.g., TLS) into the Application layer. | Map any “encoding” protocol to the Application layer when drawing TCP/IP diagrams. |
| Assuming the MTU is always 1500 bytes. | Different media (e.g., jumbo‑frame Ethernet, PPPoE, VPN tunnels) have distinct MTUs. | Query the interface (`ifconfig`, `ip link`) and consider Path MTU Discovery (PMTUD). |
| Adding processing delay $t_{p,i}$ only for the Transport layer. | Every layer incurs CPU or ASIC processing; neglecting lower‑layer delays underestimates latency, especially on low‑speed links. | Use measured $t_{p,i}$ values or vendor‑specified per‑layer latency specs. |
| Confusing “layer 2 switch” with “layer 3 router”. | A layer‑2 device forwards based on MAC addresses only; a layer‑3 device performs IP routing. | Verify the device’s control plane capabilities before designing L2/L3 topologies. |
| Ignoring the impact of encapsulation overhead in VPNs or MPLS. | Each extra header reduces the effective payload, possibly causing fragmentation. | Re‑calculate MTU after each encapsulation step and enable fragmentation avoidance mechanisms. |

By keeping these pitfalls in mind, engineers can design more robust, scalable networks and avoid costly performance surprises.

## 練習題

**1.** In the TCP/IP model, which layer is responsible for logical addressing and routing of packets?

- A. Physical layer
- B. Link layer
- C. Internet layer
- D. Transport layer

<details><summary>看答案</summary>

正解：C。The Internet layer (Layer 3) handles IP addressing and routing; it corresponds to the OSI Network layer.

</details>

**2.** An Ethernet frame carries a 1200‑byte TCP payload, a 20‑byte TCP header, and a 20‑byte IPv4 header. Which of the following statements is true regarding fragmentation?

- A. The packet will be fragmented because Ethernet MTU is 1500 bytes.
- B. No fragmentation occurs because the total size (1240 bytes) is less than Ethernet’s payload limit.
- C. Fragmentation depends on the Physical layer’s symbol rate, not the MTU.
- D. IPv6 would always fragment this packet regardless of MTU.

<details><summary>看答案</summary>

正解：B。Ethernet’s payload limit is 1500 bytes; 1240 bytes (headers + payload) fits, so no IP fragmentation is needed.

</details>

**3.** Which OSI layers are combined into the “Link” layer of the TCP/IP model?

- A. Only the OSI Physical layer.
- B. OSI Data Link and Physical layers.
- C. OSI Transport and Network layers.
- D. OSI Application, Presentation, and Session layers.

<details><summary>看答案</summary>

正解：B。The TCP/IP Link layer encompasses both the Data Link (framing, MAC) and Physical (signaling) functions of OSI.

</details>

**4.** The formula MTU\_L = MTU\_{L+1} – H\_{L+1} is used to compute:

- A. The maximum number of devices on a LAN.
- B. The payload size a layer can forward without fragmentation.
- C. The round‑trip time of a TCP connection.
- D. The number of hops a packet will traverse.

<details><summary>看答案</summary>

正解：B。The formula derives the MTU of a lower layer by subtracting the header size added by the upper layer.

</details>

**5.** Which of the following is a common source of error when mapping OSI layers to TCP/IP layers?

- A. Assuming the OSI Presentation layer maps to the TCP/IP Transport layer.
- B. Treating the OSI Session layer as part of the TCP/IP Application layer.
- C. Mapping the OSI Physical layer to the TCP/IP Internet layer.
- D. Ignoring the OSI Data Link layer entirely.

<details><summary>看答案</summary>

正解：B。In practice, OSI Session (and Presentation) functions are incorporated into the TCP/IP Application layer, not kept separate.

</details>
