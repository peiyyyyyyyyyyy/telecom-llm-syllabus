## 正文

An IP address is the fundamental identifier for a host or interface on an IP‑based packet network. It enables end‑to‑end routing, determines the scope of a device (global, private, link‑local), and drives many operational functions such as access control lists, routing protocols, and network management. In modern telecom environments—whether a carrier‑grade core, a data‑center fabric, or a 5G RAN back‑haul—the size, allocation, and aggregation of IP prefixes directly affect scalability, latency, and address‑plan hygiene.

---

### 1.2.2.1 Key definitions

| Symbol | Meaning | Unit / Format |
|--------|---------|---------------|
| **IPv4 address** | 32‑bit identifier, usually written as four decimal octets `a.b.c.d` | 0 – 255 per octet |
| **IPv6 address** | 128‑bit identifier, written as eight groups of four hexadecimal digits `x:x:x:x:x:x:x:x` | 0 – FFFF per group |
| **Network prefix length** | Number of high‑order bits that define the network portion | `n` where 0 ≤ `n` ≤ 32 (IPv4) or ≤ 128 (IPv6) |
| **Subnet mask** | Binary mask with `n` leading 1‑bits followed by zeros; in IPv4 often expressed in dotted decimal | e.g. `255.255.255.0` for /24 |
| **Host bits** | Remaining bits after the network prefix; determine the number of assignable host addresses | `h = 32‑n` (IPv4) |
| **Usable hosts** | Number of distinct host addresses that can be assigned in a subnet (excluding network and broadcast addresses for IPv4) | $$U = \begin{cases}2^{h} - 2 & h \ge 2 \\ 0 & h < 2\end{cases}$$ |
| **CIDR block** | Classless Inter‑Domain Routing notation `a.b.c.d/n` (IPv4) or `x:x::/n` (IPv6) | Combines address and prefix length |
| **Supernet** | Aggregation of contiguous subnets into a larger prefix (shorter mask) | Prefix length `m < n` |

---

### 1.2.2.2 IPv4 subnet calculations

Given a prefix length `n`, the subnet mask `M` is:

$$
M = \underbrace{11111111\ldots111}_{n\text{ bits}} \underbrace{00000000\ldots000}_{(32-n)\text{ bits}}
$$

The mask can be expressed in dotted decimal by converting each 8‑bit octet to decimal.

The **network address** (`N`) of a host IP `I` is obtained by a bitwise AND with the mask:

$$
N = I \,\&\, M
$$

The **broadcast address** (`B`) for the subnet is:

$$
B = N \,\lor\, \overline{M}
$$

where `\overline{M}` is the bitwise NOT of the mask (all host bits set to 1) and `\lor` denotes bitwise OR.

---

### 1.2.2.3 Worked example (IPv4)

**Problem:** An enterprise receives the block `203.0.113.0/22`. The network engineer must create subnets that support at most 50 hosts each, while preserving address efficiency.

1. **Determine host bits needed:**  
   For 50 hosts we need the smallest `h` such that `2^{h} - 2 ≥ 50`.  
   $$2^{5} - 2 = 30 < 50$$  
   $$2^{6} - 2 = 62 ≥ 50$$  
   Hence `h = 6` host bits → subnet mask length `n = 32 - 6 = 26`.  

2. **Subnet mask:**  
   `/26` → binary `11111111.11111111.11111111.11000000` → dotted decimal `255.255.255.192`.

3. **Number of subnets:**  
   Original block is `/22`. New subnets are `/26`. Difference `Δ = 26 - 22 = 4`.  
   Number of subnets = $2^{Δ} = 2^{4} = 16$.

4. **First two subnets:**  
   - Subnet 0: Network `203.0.112.0/26` (note that `/22` spans `203.0.112.0`‑`203.0.115.255`).  
     - Network address: `203.0.112.0`  
     - First usable host: `203.0.112.1`  
     - Last usable host: `203.0.112.62`  
     - Broadcast: `203.0.112.63`  
   - Subnet 1: Network `203.0.112.64/26`  
     - First usable: `203.0.112.65`  
     - Last usable: `203.0.112.126`  
     - Broadcast: `203.0.112.127`

All 16 subnets together cover the original `/22` without overlap.

### 1.2.2.4 IPv6 prefix planning

IPv6 eliminates the need for wasteful broadcast addresses; every address in a /64 subnet is usable. Consequently, the **usable host count** for IPv6 is simply:

$$
U_{IPv6} = 2^{(128-n)}
$$

Because a /64 is the de‑facto standard for a LAN segment, most carrier networks allocate larger aggregates (e.g., /48 for a customer, /56 for a site) and rely on **stateless address autoconfiguration (SLAAC)** or DHCPv6 for host address assignment.

---

### 1.2.2.5 Practical notes and common pitfalls

| Pitfall | Why it happens | Remedy |
|---------|----------------|--------|
| **Using /31 or /32 for point‑to‑point links in IPv4** | Older textbooks state that at least two host bits are required; modern RFC 3021 permits /31 on point‑to‑point links, saving address space. | Verify that equipment (routers, firewalls) supports RFC 3021 before deployment. |
| **Assuming classful boundaries** | Legacy class A/B/C masks (`255.0.0.0`, `255.255.0.0`, `255.255.255.0`) lead to inefficient allocations. | Adopt CIDR exclusively; calculate masks from required host count. |
| **Overlapping subnets** | Overlaps cause routing ambiguities and ARP conflicts. | Use a centralized IP address management (IPAM) system and validate subnets with tools (`ipcalc`, `cidrmerge`). |
| **Neglecting IPv6 address aggregation** | Assigning many /64s individually to customers prevents route‑aggregation, inflating global routing tables. | Allocate per‑customer prefixes that are power‑of‑two aggregates (e.g., /48) and let the customer subnet internally. |
| **Forgetting reserved addresses** | In IPv4, the first address is the network identifier and the last is the broadcast. In IPv6, the all‑zeros address is the subnet‑router anycast. | Document the reserved addresses in the address plan and configure routers accordingly. |

Proper subnetting reduces the size of routing tables, improves security zoning, and eases capacity planning—critical considerations for any carrier or enterprise network.
