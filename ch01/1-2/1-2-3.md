## 正文

The transport layer (Layer 4) is the bridge between the network‑level routing of IP packets and the application‑level data streams that end‑users see. It provides end‑to‑end services such as multiplexing, reliability, flow control, and congestion management. In modern telecom networks these services are essential for everything from voice‑over‑IP (VoIP) and video streaming to signalling between core network functions. Understanding the three dominant transport protocols—**TCP**, **UDP**, and **SCTP**—allows engineers to select the right trade‑off between latency, reliability and resource utilisation.

---

### 1.2.3.1 Fundamental Concepts

| Symbol | Meaning | Unit |
|--------|---------|------|
| $MSS$ | Maximum Segment Size (TCP) or Maximum Datagram Size (UDP) | bytes |
| $RTT$ | Round‑Trip Time – time for a packet to travel from sender to receiver and back | s |
| $p$ | Packet loss probability (fraction) | – |
| $cwnd$ | Congestion window (TCP) | bytes |
| $rwnd$ | Receiver advertised window (TCP) | bytes |
| $ssthresh$ | Slow‑start threshold (TCP) | bytes |
| $L$ | Length of a UDP datagram payload | bytes |
| $TSN$ | Transmission Sequence Number (SCTP) | – |
| $SID$ | Stream Identifier (SCTP) | – |

Transport protocols use **ports** (16‑bit numbers, $0\!-\!65535$) to multiplex many application sockets over a single IP address. A *socket* is the 4‑tuple $(\text{srcIP},\text{srcPort},\text{dstIP},\text{dstPort})$.

---

### 1.2.3.2 Transmission Control Protocol (TCP)

TCP is a **connection‑oriented**, reliable byte‑stream protocol. Its core mechanisms are:

1. **Three‑way handshake** – establishes a virtual circuit:
   - SYN → $(seq = x)$
   - SYN‑ACK → $(ack = x+1,\; seq = y)$
   - ACK → $(ack = y+1)$

2. **Reliability** – each byte is acknowledged (ACK). Retransmission timer $RTO$ is computed with Jacobson/Karels algorithm:
   $$ RTO = \max(G,\; SRTT + 4 \cdot RTTVAR) $$
   where $G$ is the clock granularity, $SRTT$ is the smoothed RTT, and $RTTVAR$ is the RTT variance.

3. **Flow control** – the receiver advertises $rwnd$; the sender must keep $cwnd \le rwnd$.

4. **Congestion control** – classic *TCP Reno* algorithm:
   - **Slow start**: $cwnd \leftarrow cwnd + MSS$ for each ACK (exponential growth).
   - **Congestion avoidance**: when $cwnd \ge ssthresh$, increase linearly: $cwnd \leftarrow cwnd + \frac{MSS^2}{cwnd}$ per RTT.
   - **Loss detection**: triple duplicate ACK → $ssthresh = \frac{cwnd}{2}$, $cwnd = ssthresh$ (fast retransmit); timeout → $ssthresh = \frac{cwnd}{2}$, $cwnd = MSS$ (enter slow start).

A convenient closed‑form estimate of steady‑state TCP throughput (Mathis et al., 1997) is:
$$
\boxed{T_{\text{TCP}} \approx \frac{MSS}{RTT \sqrt{p}}}
$$
where $p$ is the packet loss probability (assumed small) and $T_{\text{TCP}}$ is in bytes / s.

---

### 1.2.3.3 User Datagram Protocol (UDP)

UDP is a **connection‑less**, best‑effort transport. Its packet (datagram) format consists of:

| Field | Size |
|-------|------|
| Source Port | 16 bits |
| Destination Port | 16 bits |
| Length | 16 bits (header + data) |
| Checksum | 16 bits (optional in IPv4) |
| Data | 0–65507 bytes |

Key properties:

* No sequencing, no acknowledgements, no retransmission.
* Fixed header of 8 bytes ⇒ low per‑packet overhead.
* Suitable for latency‑sensitive traffic (e.g., RTP for voice, DNS, SNMP) where occasional loss is tolerable.

The UDP checksum covers a pseudo‑header (source/destination IP, protocol, length) plus the UDP header and data. It is computed as the 16‑bit one's‑complement sum; the result is stored in the checksum field. If the computed sum equals $0xFFFF$, the transmitted checksum field is set to zero.

---

### 1.2.3.4 Stream Control Transmission Protocol (SCTP)

SCTP is a **message‑oriented**, reliable transport designed for telecommunication signalling (e.g., SS7 over IP) and for applications requiring multihoming and multi‑streaming.

* **Four‑way handshake** (COOKIE‑ECHO) prevents SYN‑flood attacks:
  1. INIT → $(\text{init\_tag}=I)$
  2. INIT‑ACK → $(\text{init\_tag}=R,\; \text{cookie}=C)$
  3. COOKIE‑ECHO → $(C)$
  4. COOKIE‑ACK → $(\text{ack}=C)$

* **Multihoming** – an endpoint can list several IP addresses; if the primary path fails, SCTP seamlessly switches to a backup without breaking the association.

* **Multi‑streaming** – an association contains up to $2^{16}$ streams, each identified by a $SID$. Streams are independent; loss in one stream does not block delivery in others, eliminating head‑of‑line blocking.

* **Reliability** – each DATA chunk carries a Transmission Sequence Number ($TSN$). The receiver acknowledges cumulatively the highest contiguous $TSN$ received; selective acknowledgements (SACK) allow fast retransmission of missing chunks.

* **Congestion control** – SCTP adopts TCP‑like congestion avoidance, but it also implements *Partial Reliability* (PR‑SCTP) where the sender may abandon retransmission after a configurable $\text{max\_retrans\_time}$.

### 1.2.3.5 Worked Example – Estimating TCP Throughput

A video streaming server uses TCP over a 10 Gbps backbone to a client located 1500 km away. Measured parameters:

* $MSS = 1460$ bytes (standard Ethernet MTU 1500 bytes minus IP/TCP headers)
* $RTT = 20$ ms (propagation + queuing)
* Observed packet loss $p = 10^{-4}$ (0.01 %)

Compute the approximate steady‑state TCP throughput.

$$
\begin{aligned}
T_{\text{TCP}} &\approx \frac{MSS}{RTT \sqrt{p}} \\
               &= \frac{1460\ \text{bytes}}{0.020\ \text{s} \times \sqrt{10^{-4}}} \\
               &= \frac{1460}{0.020 \times 0.01} \\
               &= \frac{1460}{2 \times 10^{-4}} \\
               &= 7.3 \times 10^{6}\ \text{bytes/s} \\
               &= 58.4\ \text{Mbit/s}.
\end{aligned}
$$

Even though the physical link can carry 10 Gbps, the loss‑induced congestion limit reduces usable throughput to ≈ 58 Mbit/s. This demonstrates why loss‑free paths (or loss‑resilient protocols such as QUIC) are critical for high‑throughput services.

### 1.2.3.6 Common Pitfalls & Practical Notes

| Pitfall | Why it Happens | Remedy |
|---------|----------------|--------|
| **Assuming UDP guarantees delivery** | UDP has no ACK or retransmission. | Add application‑level reliability (e.g., RTP with RTCP NACK) when loss is unacceptable. |
| **Neglecting Path MTU** | Sending $MSS$ larger than the smallest link causes IP fragmentation, which degrades performance and may be blocked. | Use Path MTU Discovery (PMTUD) or set $MSS$ ≤ 1400 bytes for heterogeneous networks. |
| **Forgetting TCP window scaling** | On high‑delay links, the default 64 KB window caps throughput. | Enable the Window Scale option (RFC 7323) and set an appropriate scale factor. |
| **Misconfiguring SCTP multihoming** | Listing backup IPs without proper routing leads to “black‑hole” failover. | Verify each address is reachable and that the underlying routing protocol advertises the alternate paths. |
| **Treating streams as independent of congestion** | Each SCTP stream shares the same $cwnd$; a burst on one stream can starve others. | Use pacing or separate SCTP associations if strict per‑stream isolation is required. |

Finally, remember that transport‑layer decisions interact with higher‑layer mechanisms (e.g., HTTP/2 multiplexing over TCP, QUIC over UDP) and with lower‑layer QoS (e.g., DiffServ PHB markings). A holistic view ensures that the chosen protocol aligns with latency, reliability, and bandwidth requirements of the service.
