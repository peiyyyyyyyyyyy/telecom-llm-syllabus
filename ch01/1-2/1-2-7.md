# 1.2.7 核心網信令：NAS、NGAP、GTP、Diameter、SBI

## 正文

In a mobile packet‑core, the *control plane* (signaling) is the glue that creates and tears down sessions, authenticates subscribers, and coordinates radio and transport resources. While the user‑plane carries user data (IP packets), the signaling protocols – **NAS (Non‑Access Stratum)**, **NGAP (NG Application Protocol)**, **GTP (GPRS Tunneling Protocol)**, **Diameter**, and the **SBI (Service‑Based Interface)** – operate across distinct layers and interfaces to deliver end‑to‑end connectivity. Understanding their roles, message flows, and performance parameters is essential for designing, troubleshooting, and optimizing 4G LTE and 5G NR networks.

---

### 1.2.1 Non‑Access Stratum (NAS)

NAS resides **above** the radio access network (RAN) and **below** the core network. It carries subscriber‑level procedures such as registration, authentication, security mode command, and session management. NAS messages are encapsulated in the **RRC** (Radio Resource Control) layer on the control plane.

Key fields:
- **Message Type (MT)** – 1 byte identifier.
- **Security Header Type (SHT)** – indicates whether the payload is plain, integrity‑protected, or ciphered.
- **MAC** – 4 bytes Message Authentication Code for integrity.

Typical NAS procedure: *5G Registration* (NAS Registration Request → NAS Registration Accept). The NAS security context is derived from the **5G‑AKA** algorithm; the key derivation function (KDF) uses the subscriber’s SUPI and network challenge.

---

### 1.2.2 NG Application Protocol (NGAP)

NGAP runs on the **NG interface** between the gNB (next‑generation NodeB) and the **AMF** (Access and Mobility Management Function). It transports RAN‑level control information such as UE context setup, handover, and paging.

Important NGAP Information Elements (IEs):
- **AMF UE NGAP ID** – 32 bits, unique per UE at the AMF.
- **RAN UE NGAP ID** – 24 bits, unique per UE at the gNB.
- **UE Aggregate Maximum Bit Rate (UE‑AMBR)** – expressed in bits per second (bps).

NGAP uses **ASN.1 PER** (Packed Encoding Rules) for compact binary encoding, and the transport protocol is **SCTP** (Stream Control Transmission Protocol). The SCTP association must satisfy the **SCTP‑INIT** handshake with a **heartbeat interval** $T_{hb}$ (commonly 30 s) to detect path failure.

---

### 1.2.3 GPRS Tunneling Protocol (GTP)

GTP provides the **user‑plane** (GTP‑U) and **control‑plane** (GTP‑C) tunnels that forward IP packets between the **UPF** (User Plane Function) and the **SGW/PGW** (LTE) or between **UPFs** (5G). A tunnel is identified by a **TEID** (Tunnel Endpoint Identifier), a 32‑bit opaque value.

**GTP‑U Header (8 bytes)**  
| Byte | Field | Description |
|------|-------|-------------|
| 0    | Flags | Version (3), PT, E, S, PN |
| 1    | Message Type | e.g., 255 = *G-PDU* |
| 2‑3  | Length | Payload length (excluding header) |
| 4‑7  | TEID | Tunnel Endpoint Identifier |

When transporting Ethernet frames, the **GTP‑U overhead** is:
$$
O_{\text{GTP}} = H_{\text{IP}} + H_{\text{UDP}} + H_{\text{GTP-U}} = 20\ \text{B} + 8\ \text{B} + 8\ \text{B} = 36\ \text{B}
$$
where $H_{\text{IP}}$, $H_{\text{UDP}}$, and $H_{\text{GTP-U}}$ are header sizes in bytes.

**Throughput reduction** due to overhead for an MTU of 1500 B:
$$
\eta = \frac{1500 - O_{\text{GTP}}}{1500} = \frac{1464}{1500} \approx 0.976
$$
Thus, effective user‑plane throughput is ≈97.6 % of the raw link rate.

---

### 1.2.4 Diameter

Diameter is the **authentication, authorization, and accounting (AAA)** protocol used between the **AMF**, **SMF**, **PCF**, and external **HSS/UDM**. It replaces RADIUS in 4G/5G and operates over **TCP** (or SCTP) on port 3868.

Key Diameter AVPs (Attribute‑Value Pairs):
- **Session‑Id** – globally unique string.
- **Auth‑Application‑Id** – identifies the application (e.g., 16777251 for 3GPP AA‑S).
- **Result‑Code** – 32‑bit integer (e.g., 2001 = *DIAMETER_SUCCESS*).

Diameter uses a **re‑transmission timer** $T_R$ (default 3 s) and a **maximum retransmission count** $N_{\max}=5$. The **average response time** $T_{avg}$ can be approximated by:
$$
T_{avg} = \frac{1}{N}\sum_{i=1}^{N} (RTT_i + R_i \cdot T_R)
$$
where $RTT_i$ is the measured round‑trip time for the $i$‑th successful exchange, and $R_i$ is the number of retransmissions.

---

### 1.2.5 Service‑Based Interface (SBI)

In 5G, core functions expose **RESTful APIs** over **HTTP/2** and **JSON** payloads, forming the SBI. For example, the **SMF** queries the **PCF** for policy decisions via the **`/policy-data`** resource.

Important SBI concepts:
- **NF Service Name** – e.g., `nsmf-pdu-session`.
- **Discovery** – functions register with the **NRF** (Network Repository Function) using the **`/nf-instances`** resource.
- **Security** – mutual TLS (mTLS) with certificates; the **Authorization Token** is a JWT (JSON Web Token) signed with the network’s private key.

The **SBI latency budget** $L_{\text{SBI}}$ is often set to ≤ 10 ms for session establishment, calculated as:
$$
L_{\text{SBI}} = T_{\text{TLS\_handshake}} + T_{\text{HTTP/2\_frame}} + T_{\text{processing}}
$$

---

### Worked Example: Calculating GTP‑U Effective Throughput

A 5G NR user equipment (UE) receives a 100 Mbps downlink over an S1‑U interface that uses GTP‑U tunneling. The underlying Ethernet MTU is 1500 B.

1. **Determine overhead**: $O_{\text{GTP}} = 36$ B (IP+UDP+GTP‑U).  
2. **Effective payload per packet**: $P = 1500 - 36 = 1464$ B.  
3. **Payload efficiency**: $\eta = 1464 / 1500 = 0.976$.  
4. **Effective throughput**: $T_{\text{eff}} = 100\ \text{Mbps} \times 0.976 = 97.6\ \text{Mbps}$.

Thus, the UE experiences roughly **2.4 Mbps** of overhead loss due to tunneling headers.

### Common Mistakes & Practical Notes

| Pitfall | Why it Happens | Remedy |
|---------|----------------|--------|
| **Confusing NAS with RRC** | Both reside in the control plane; NAS is access‑network independent, RRC is radio‑specific. | Keep a clear mental boundary: NAS = subscriber procedures, RRC = radio resource procedures. |
| **Re‑using TEID across tunnels** | TEID must be unique per UPF pair; duplication leads to mis‑routed packets. | Implement a TEID allocation table with per‑pair uniqueness checks. |
| **Ignoring SCTP stream ordering** | NGAP messages may be sent on different SCTP streams; assuming in‑order delivery can cause deadlocks. | Use separate streams for independent procedures and enable unordered delivery where appropriate. |
| **Diameter retransmission loops** | Over‑aggressive timers cause unnecessary traffic and may saturate the back‑haul. | Tune $T_R$ based on measured RTT; apply exponential back‑off. |
| **SBI certificate expiration** | mTLS connections fail silently if certificates are stale, leading to service disruptions. | Deploy automated certificate rotation (e.g., using ACME) and monitor expiry dates. |

Finally, remember that **signaling load scales with the number of active UEs**, not just the data rate. Proper dimensioning of AMF, SMF, and UPF control‑plane resources (CPU, memory, SCTP associations) is as critical as provisioning user‑plane bandwidth.
