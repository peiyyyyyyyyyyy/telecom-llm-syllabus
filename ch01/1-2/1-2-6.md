## 正文

Modern cellular systems (e.g., 5G NR) separate the radio access network (RAN) into a **control plane** and a **user plane**. The user‑plane data that traverses the air interface is processed by a strict stack of six protocols:

```
RRC → SDAP → PDCP → RLC → MAC → PHY
```

Each layer adds specific functions—such as radio resource control, security, segmentation, error correction, and physical transmission—while exposing a well‑defined Service Data Unit (SDU) to the layer above. Understanding this stack is essential for engineers who design, optimise, or troubleshoot radio links, because performance bottlenecks (throughput, latency, reliability) are often traceable to a single protocol’s parameters.

---

### 1. Radio Resource Control (RRC)

RRC resides in the **control plane** (NAS‑to‑RAN signalling). It establishes and re‑configures radio bearers, handles mobility (handover, cell reselection), and conveys security keys. The most relevant RRC concepts for the user‑plane stack are:

| Symbol | Meaning | Unit |
|--------|---------|------|
| $T_{\text{RRC}}$ | RRC re‑configuration latency | ms |
| $N_{\text{RB}}$ | Number of allocated Resource Blocks (RB) per subframe | – |
| $M_{\text{UE}}$ | Maximum number of simultaneous RRC connections per UE | – |

A typical RRC re‑configuration message may request a new **Data Radio Bearer (DRB)** with a specific QoS Flow Identifier (QFI) and allocate $N_{\text{RB}} = 20$ RBs (each 180 kHz) for a 5 ms duration.

---

### 2. Service Data Adaptation Protocol (SDAP)

SDAP maps **QoS Flows** (identified by QFI) to **Data Radio Bearers (DRBs)**. It is the only layer that is aware of the 5G QoS model (GBR, non‑GBR, latency, packet error rate). SDAP adds a **QoS Flow Identifier** field (1 byte) to each SDU.

*Key formula – effective data rate per QoS flow*  

$$
R_{\text{eff}} = \frac{L_{\text{SDU}} \times (1 - P_{\text{loss}})}{T_{\text{TTI}}}
$$

where  

- $L_{\text{SDU}}$ = payload length after SDAP header (bits)  
- $P_{\text{loss}}$ = target packet loss rate (dimensionless)  
- $T_{\text{TTI}}$ = Transmission Time Interval (e.g., 1 ms for 5G NR).

---

### 3. Packet Data Convergence Protocol (PDCP)

PDCP provides **header compression**, **ciphering/deciphering**, and **in‑order delivery** for both user‑plane and control‑plane data. For user data, PDCP adds a **sequence number** (12 bits for NR) and optionally encrypts the payload.

*Key formula – PDCP overhead*  

$$
\eta_{\text{PDCP}} = \frac{L_{\text{payload}}}{L_{\text{payload}} + H_{\text{PDCP}}}
$$

where  

- $L_{\text{payload}}$ = original payload size (bits)  
- $H_{\text{PDCP}}$ = PDCP header size (bits), typically 12 bits (SN) + optional 4 bits (ciphering).

---

### 4. Radio Link Control (RLC)

RLC works in three modes:

| Mode | Use case | Retransmission |
|------|----------|----------------|
| Transparent Mode (TM) | Broadcast, low‑latency | No |
| Unacknowledged Mode (UM) | Real‑time video, VoIP | No |
| Acknowledged Mode (AM) | File transfer, TCP | Yes (ARQ) |

RLC segments SDUs into **PDUs**, adds a **Header (7–12 bits)** containing a **Sequence Number (SN)**, and, in AM, a **Poll Bit** for HARQ feedback.

*Key formula – RLC throughput in AM*  

$$
R_{\text{RLC}} = \frac{L_{\text{SDU}}}{T_{\text{TTI}}} \times (1 - P_{\text{HARQ}})
$$

where $P_{\text{HARQ}}$ is the probability of a HARQ retransmission.

---

### 5. Medium Access Control (MAC)

MAC multiplexes RLC PDUs from multiple logical channels onto the physical channel, performs **scheduling**, **Hybrid ARQ (HARQ) soft combining**, and **priority handling**. It works on a **slot** basis (0.125 ms for NR) and allocates **Transport Blocks (TBs)**.

*Key formula – MAC scheduling efficiency*  

$$
\epsilon_{\text{MAC}} = \frac{\sum_{i=1}^{K} L_{\text{TB},i}}{N_{\text{RB}} \times N_{\text{SC}} \times N_{\text{sym}}}
$$

where  

- $K$ = number of scheduled TBs in the subframe  
- $L_{\text{TB},i}$ = bits carried by TB $i$  
- $N_{\text{RB}}$ = number of RBs allocated  
- $N_{\text{SC}}$ = subcarriers per RB (12)  
- $N_{\text{sym}}$ = OFDM symbols per slot.

---

### 6. Physical Layer (PHY)

PHY converts MAC PDUs into **waveforms** using OFDM, SC‑FDMA, or DFT‑S‑OFDM. It handles **channel coding (LDPC for data, Polar for control)**, **modulation (QPSK, 16QAM, 64QAM, 256QAM)**, **layer mapping**, and **beamforming**.

*Key formula – Spectral efficiency*  

$$
\eta_{\text{spec}} = \log_2(M) \times (1 - \text{BLER}) \times \frac{R_c}{1 + \text{OH}_{\text{PHY}}}
$$

where  

- $M$ = modulation order (e.g., 64 → $M=64$)  
- $\text{BLER}$ = block error rate (dimensionless)  
- $R_c$ = coding rate (e.g., 0.75)  
- $\text{OH}_{\text{PHY}}$ = PHY overhead fraction (e.g., reference signals, guard bands).

---

## Worked Example

A UE is allocated $N_{\text{RB}} = 10$ RBs for a downlink transmission in a 5 ms TTI. The scheduler chooses 64‑QAM ($M=64$) with a coding rate $R_c = 0.8$ and the target BLER is $10^{-2}$. PHY overhead (reference signals, DM‑RS) is $\text{OH}_{\text{PHY}} = 0.15$.

1. **Spectral efficiency**  

   $$
   \eta_{\text{spec}} = \log_2(64) \times (1 - 0.01) \times \frac{0.8}{1+0.15}
   = 6 \times 0.99 \times \frac{0.8}{1.15}
   \approx 4.13\ \text{bits/Hz}
   $$

2. **Available bandwidth**  

   Each RB is $180$ kHz, so total bandwidth $B = 10 \times 180\text{ kHz} = 1.8\text{ MHz}$.

3. **Maximum payload per TTI**  

   $$
   R_{\text{PHY}} = \eta_{\text{spec}} \times B = 4.13\ \frac{\text{bits}}{\text{Hz}} \times 1.8 \times 10^6\ \text{Hz}
   \approx 7.43\ \text{Mbit}
   $$

4. **Accounting for PDCP header (12 bits) and RLC header (12 bits) per packet**  

   Assume packets of $1,200$ bytes ($9,600$ bits). Overhead per packet = $24$ bits → negligible (<0.001 %). Effective user‑plane throughput ≈ $7.43$ Mbit per 5 ms, i.e., $1.49$ Gbit/s.

This simple calculation shows how the choice of modulation, coding, and RB allocation directly determines the achievable user‑plane rate.

---

## Common Mistakes & Practical Notes

1. **Ignoring PHY overhead** – Designers often compute spectral efficiency using only $\log_2(M)R_c$ and forget reference signals, guard bands, and control channels. This can over‑estimate throughput by 10–20 %.

2. **Mis‑matching RLC mode to traffic** – Using AM for latency‑critical voice traffic adds unnecessary HARQ delays; UM is preferred despite the lack of retransmission.

3. **Over‑provisioning RRC re‑configurations** – Frequent RRC re‑configurations increase $T_{\text{RRC}}$, leading to control‑plane congestion and higher handover failure rates.

4. **SDAP/QFI misuse** – Assigning a high‑priority QFI to bulk‑download traffic can starve mission‑critical URLLC flows. Proper QoS mapping must be enforced at SDAP.

5. **HARQ timing errors** – In TDD deployments, the HARQ feedback window must align with the UL/DL slot pattern; otherwise retransmissions are lost, causing a spike in $P_{\text{HARQ}}$.

By keeping these pitfalls in mind and carefully balancing parameters at each layer, engineers can achieve the targeted latency (e.g., sub‑1 ms for URLLC) and reliability (e.g., $10^{-5}$ BLER) required by modern services.
