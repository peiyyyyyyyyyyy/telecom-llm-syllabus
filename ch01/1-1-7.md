# 1.1.7 IP 網與網際網路互連

所屬：[1.1 網路架構](1-1.md)

## 內文

不同業者與組織的 IP 網路透過互連交換可達性並傳送封包。自治系統可視為由共同路由政策管理的一組網路。BGP 在自治系統間交換哪些位址範圍可經哪一方到達，以及協助路由選擇的路徑屬性。維運必須分別理解有沒有可用路由和封包能不能走通，才能在外部網站故障時找對交接點。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html)

當鄰接建立且政策允許時，BGP 路由器向對端公告前綴及路徑資訊。接收端依進站政策及路由選擇程序決定採用或再發布哪些路由。實際轉送時，路由器依目的位址找最長符合的前綴，並依轉送表指向適當下一跳。外部互連可由對等連接或其他提供可達性的路徑承載。相同目的地常有多個候選路徑，某條互連的公告撤回、政策變更或下一跳不可用，都可能改變來源網路的選路。BGP 屬性和選路程序見 1.2.4。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html)

假設互連路由器從甲、乙兩個自治系統收到同一文件用前綴 192.0.2.0/24。若目前採用甲的公告，當甲撤回時，仍需確認乙的公告通過政策、下一跳可達，而且替代路由確實安裝。此例可將互連撤回、控制面重新選路及資料實際恢復三個時點分開記錄。各觀測點記錄的時間差也有助於判斷回復在哪個階段停留。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html) [IETF RFC 5737](https://www.rfc-editor.org/rfc/rfc5737.html)

常見混淆有三項。BGP 工作階段已建立代表對端可交換訊息，各前綴仍要逐一檢查。位址能到達某網站的入口時，應用可以再受到伺服器、名稱解析或回程影響。封包轉送的最長前綴比對有別於 BGP 對同一前綴的候選路徑選擇，可各自從轉送表與 BGP 紀錄驗證。 [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html) [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html) [IETF RFC 1122](https://www.rfc-editor.org/rfc/rfc1122.html)

互連工單記下來源網段、目的前綴、測試方向、時間與受影響範圍。由 IP 互連團隊核對候選路徑、公告與撤回、進出政策及實際下一跳。採集正常及異常的對照案例，分開驗證不同來源與回程，並在交接對端時提供符合雙方約定的路由證據和時窗。 [IETF RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html) [IETF RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html)
