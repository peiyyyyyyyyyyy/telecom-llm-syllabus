# 1.4.3 計費架構：離線、線上與融合計費（CHF）

所屬：[1.4 網管、計費、安全與密碼學](1-4.md)

## 內文

電信計費先辨認誰使用了哪項服務，再採集可計量的用量，供授權或帳務處理使用。離線計費產生的資訊可供後續帳務處理，線上計費則可在服務進行期間透過許可與配額影響使用。融合計費支援在同一架構處理不同計費需求。掌握這些差別，可以分辨服務受到額度限制、用量紀錄漏接與帳單或費率錯誤。 [3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf)

在 5G 融合計費架構中，計費服務使用者向 Charging Function（CHF）請求相關處理。以支援配額的使用情境為例，會話初期可請求使用許可，服務端按已給額度控制可用量，並在相應事件時回報消耗和請求後續額度。結束時再處理剩餘用量及相關紀錄。離線類型的資料則可在指定事件產生並送往帳務流程。從請求、更新到結束，每階段都應檢查是否屬於同一計費關聯。 [3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf)

| 計費方式 | 與服務即時運作的關係及出處 |
| --- | --- |
| 離線 | 採集用量供後續計費及帳務處理。[3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) |
| 線上 | 支援服務進行期間的許可或配額控制。[3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf) |
| 融合 | 可依服務及部署支援有配額和不以配額控制的計費。[3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf) |

額度與用量須使用業務指定的單位，例如時間量或資料量。假設某服務取得 100 MB 額度，記錄同一口徑已使用 70 MB，在未追加、回收或調整前，尚餘 30 MB。額度描述允許使用的量，實際帳單涉及費率、折扣、計量規則及帳務程序。若查核的是資料量，應同時對照業務使用的單位與上下行範圍。 [3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf)

常見混淆包括把申請配額視為已經使用的量、把服務請求結果視為最終帳單，以及用收到紀錄的時間代替事件本身的發生時間。離線作業允許依服務設計在不同時點回報用量。線上作業則需追蹤對服務有影響的授權狀態。判讀重試或延遲時，還應對照同一計費會話及對應結果，避免重覆計量。 [3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf)

工單應附服務類型、受影響時段、可追蹤的計費關聯識別、配額及用量事件的處理結果。當服務被限制時，較適合由線上計費與服務承載團隊一起確認請求和回覆。帳單異常則由計費和帳務團隊對齊各階段用量與費率資料，區別事件未回報和費率套用問題。 [3GPP TS 32.240 V18.9.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132240/18.09.00_60/ts_132240v180900p.pdf) [3GPP TS 32.290 V19.5.0](https://www.etsi.org/deliver/etsi_ts/132200_132299/132290/19.05.00_60/ts_132290v190500p.pdf)
