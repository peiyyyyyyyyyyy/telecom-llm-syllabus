# 1.1.5 4G 核心網（EPC）

所屬：[1.1 網路架構](1-1.md)

## 內文

4G 的 EPC 把無線接取後的控制程序、訂戶資料與封包轉送接起來。它管理終端接入、移動性與承載的建立，使終端可透過 LTE 接取對應的封包資料網。學習這一架構時可先追一個已完成附著的終端，分別找出誰處理控制訊息、誰維持承載，以及資料要經過哪些閘道。 [3GPP TS 23.401 Release 18](https://www.etsi.org/deliver/etsi_TS/123400_123499/123401/18.08.00_60/ts_123401v180800p.pdf)

典型部署由 eNB 經 S1-MME 與 MME 交換控制訊息，MME 可經 S6a 向 HSS 取得訂戶及鑑權相關資料。MME 還需和 S-GW 協調承載及移動性程序。用戶資料經 S1-U 由 eNB 到 S-GW，再依所採架構沿 S5 或 S8 連往 P-GW，之後通往外部封包資料網。S-GW 與 P-GW 之間的接口選擇與部署及漫遊拓樸有關。終端的附著、預設承載建立和外部資料路徑各涉及不同節點，追查時應把程序時間、承載識別與兩端的流量資訊對在同一條事件鏈。 [3GPP TS 23.401 Release 18](https://www.etsi.org/deliver/etsi_TS/123400_123499/123401/18.08.00_60/ts_123401v180800p.pdf) [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf)

容易混淆的是 MME 與用戶面閘道、S1-MME 與 S1-U，以及預設承載與應用可達性。MME 的接取控制紀錄適合追訊息與原因值，S-GW 和 P-GW 的轉送紀錄用於查資料路徑。前兩種 S1 接口的分工不同，因此某一對端連線正常時還要確認另一側的狀態。預設承載建立完成後，若資料網方向的路由或服務異常，終端仍可能無法使用特定應用。 [3GPP TS 23.401 Release 18](https://www.etsi.org/deliver/etsi_TS/123400_123499/123401/18.08.00_60/ts_123401v180800p.pdf) [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf)

維運定位先看故障是無法附著、承載建立失敗，還是承載成功後缺少雙向資料。取終端所屬接取節點、出現異常的程序、原因值、對應 APN、承載與閘道路徑。區域性附著問題可先由無線與 EPC 控制面團隊核對，單一服務或方向的資料中斷可由用戶面閘道團隊追 S1-U 與外部路徑。漫遊場景還要記下服務與歸屬網路的交接界線，讓兩端團隊比對同一時窗及相同測試條件。 [3GPP TS 23.401 Release 18](https://www.etsi.org/deliver/etsi_TS/123400_123499/123401/18.08.00_60/ts_123401v180800p.pdf) [3GPP TS 29.281 Release 18](https://www.etsi.org/deliver/etsi_ts/129200_129299/129281/18.04.00_60/ts_129281v180400p.pdf)
