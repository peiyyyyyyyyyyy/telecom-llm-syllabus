# 1.3.1 語音：電路交換、CSFB、VoLTE／VoNR（IMS）與 SRVCC

所屬：[1.3 服務與多媒體](../1-3.md)

## 正文

Voice has been the first and most ubiquitous service in mobile networks. In legacy generations the call is carried over a *circuit‑switched (CS)* core, i.e. a dedicated end‑to‑end path that is set up for the whole duration of the call. With the advent of LTE and 5G the industry moved to *packet‑switched (PS)* transport, re‑using the IP data plane for voice. The transition is realised through three main mechanisms that coexist in modern operators:

| Mechanism | Where it is used | Main purpose |
|-----------|------------------|--------------|
| **Circuit‑Switched fallback (CSFB)** | LTE (E‑UTRAN) | Re‑use existing CS infrastructure when a UE is attached to LTE but the network cannot provide an IMS‑based call. |
| **IMS‑based voice over PS (VoLTE / VoNR)** | LTE (E‑UTRA) and 5G NR | Deliver voice (and video) as IP media streams using the IP Multimedia Subsystem (IMS). |
| **Single Radio Voice Call Continuity (SRVCC)** | Transition from LTE/5G to legacy 2G/3G RATs | Preserve an ongoing IMS call when the UE moves out of PS coverage, by handing the call over to the CS domain. |

The reference documents that underpin these mechanisms are **TS 23.272** (CS fallback) and **TS 23.228** / **TS 23.501** (IMS‑based multimedia telephony). The following sections summarise the functional elements, signalling principles and practical considerations that a telecom engineer must master.

---

### 1.3.1.1 CS fallback (CSFB)

In LTE the *CS fallback* function allows a UE that is camped on an E‑UTRAN cell to obtain voice services from the legacy CS domain. The fallback is possible only when the LTE coverage is overlapped by a GERAN or UTRAN cell, because the UE must be able to switch to one of those RATs to reach the Mobile Switching Centre (MSC) [TS 23.272 §4.1]. The SGs interface between the MME and the MSC server carries the mobility‑management and paging procedures that enable this inter‑working [TS 23.272 §4.2.1].

**Key steps (simplified):**

1. UE registers on LTE (EPS attach).  
2. UE requests a voice call (e.g. via `originate`).  
3. MME, detecting that IMS voice over PS is not available, triggers SGs signalling to the MSC.  
4. UE is instructed (via RRC) to perform a *fallback* to GERAN/UTRAN, where the call is set up as a traditional CS call.

A common mistake is to assume that CS fallback works without overlapping GERAN/UTRAN coverage; the specification explicitly requires such overlap [TS 23.272 §4.1].

---

### 1.3.1.2 IMS‑based Voice over PS (VoLTE / VoNR)

The *multimedia telephony* service is defined in TS 23.228 §4.16. It is delivered by a **Telephony Application Server (TAS)**, which is a SIP application server that provides the network support for the service [TS 23.228 §4.16.1]. The TAS may be collocated with the Media Resource Function Controller (MRFC) when media interaction is required.

When a UE capable of IMS voice registers, the **Access and Mobility Management Function (AMF)** informs the UE whether an IMS voice over PS session can be supported. This indication is sent during the **Registration procedure** over the access technology (3GPP or non‑3GPP) [TS 23.501 §5.16.3.2]. The indication is based on network policies, UE capabilities, QoS availability, and roaming agreements.

**Session establishment principles** (TS 23.228 §4.16.3):

* The UE should reserve IP‑CAN bearer(s) for voice (and video, if applicable) at the reception of the SDP answer, or earlier if it already knows the allowed media.  
* Resource reservation is marked as *required* only for voice and video.  
* The P‑CSCF may forward session information to the PCRF/PCF when the SDP offer is received, allowing the UE to attempt reservation before sending the SDP answer.  

**Attestation and security** – if configured by operator policy, the telephony AS (or any other AS) may perform attestation of the subscriber’s identity, of the RCD information, and of signatures for both originating and terminating requests [TS 23.228 §4.16.3].

---

### 1.3.1.3 SRVCC (Single Radio Voice Call Continuity)

SRVCC is the procedure that hands over an ongoing IMS voice call from a PS‑based RAT (LTE/NR) to the CS domain when the UE leaves the coverage of the 5G/4G core. The reference material provided does not contain the detailed SRVCC flow; therefore it is **outside the scope of this subsection** and readers should consult the dedicated 3GPP specifications (e.g., TS 23.216) for the exact signalling.

---

### 1.3.1.4 Worked Example – Reserving an IP‑CAN Bearer for a VoLTE Call

A UE registers on a 5G NR cell and receives the **IMS voice over PS supported** indication (the AMF confirmed support). The UE wants to start a voice‑only call.

| Parameter | Value |
|-----------|-------|
| Required voice bitrate (codec AMR‑WB) | 64 kbps |
| Minimum guaranteed QoS for voice (5G QoS Flow) | 64 kbps (as per clause 5.7) |
| SDP answer received from P‑CSCF | `m=audio 49170 RTP/AVP 97` (codec 97 = AMR‑WB) |

**Steps:**

1. UE receives SDP answer → decides that only voice is required.  
2. UE reserves an **IP‑CAN bearer** for the voice flow at the reception of the SDP answer, as recommended [TS 23.228 §4.16.3].  
3. The bearer is configured with a QoS Flow identifier (e.g., `5QI = 1`) guaranteeing at least 64 kbps.  
4. Call proceeds; if the UE later moves out of NR coverage, the network may trigger SRVCC (outside current scope).

The calculation of the required bandwidth is trivial: the codec’s bitrate (64 kbps) plus IP/UDP/RTP overhead (~12 kbps) yields a total of ~76 kbps, comfortably covered by the 5QI 1 flow.

---

### 1.3.1.5 Practical Notes & Common Pitfalls

| Pitfall | Why it happens | Correct practice |
|---------|----------------|------------------|
| **Late bearer reservation** – waiting until after the SDP offer is sent. | Misinterpretation of “reserve at SDP answer”. | Reserve the bearer as soon as the SDP answer is received (or earlier if policies allow) [TS 23.228 §4.16.3]. |
| **Assuming CS fallback works everywhere** | Ignoring the requirement for overlapping GERAN/UTRAN coverage. | Verify that the LTE cell is overlapped by a legacy RAT before relying on CS fallback [TS 23.272 §4.1]. |
| **Skipping attestation** | Believing it is optional. | If operator policy mandates, ensure the TAS performs subscriber identity and RCD attestation for both originating and terminating requests [TS 23.228 §4.16.3]. |
| **Neglecting the IMS voice over PS indication** | Assuming IMS is always available. | Respect the AMF‑sent indication during registration; only attempt IMS voice if the indication is “supported” [TS 23.501 §5.16.3.2]. |
| **Confusing CS fallback with SRVCC** | Treating them as the same handover. | Remember CS fallback is a *fallback* to CS before a call is set up, while SRVCC is a *continuity* procedure for an ongoing IMS call (outside current references). |

By mastering these concepts, engineers can design networks that seamlessly support voice across all generations, optimise resource utilisation, and ensure a consistent user experience.
