# 1.3.5 網路切片

所屬：[1.3 服務與多媒體](../1-3.md)

## 正文

Network slicing is a 5G system capability that allows a single Physical Layer Mobile Network (PLMN) – or a Stand‑alone Non‑Public Network (SNPN) – to host multiple logical networks, called *Network Slice instances*. Each instance contains its own Core Network (CN) control‑plane and user‑plane functions, and optionally one or more access‑network components such as the NG‑RAN, N3IWF/TNGF (for non‑3GPP access) or W‑AGF (for wireline access) [TS 23.501 §5.15.1].  

The main motivation is to provide differentiated behaviour (e.g., ultra‑reliable low‑latency, massive IoT, enhanced mobile broadband) over shared physical infrastructure while preserving isolation of resources, policies, and performance guarantees. Operators can therefore allocate a slice to a specific vertical industry, a premium‑service customer, or a public‑safety agency without affecting other traffic.

---

### 1.3.5.1 Key definitions  

| Symbol | Meaning | Unit / Type |
|--------|---------|-------------|
| **S‑NSSAI** | Single Network Slice Selection Assistance Information – identifier of a Network Slice | Composite (see below) |
| **SST** | Slice/Service Type – describes the expected behaviour of the slice (e.g., eMBB, URLLC, mMTC) | Integer (standardised values) |
| **SD** | Slice Differentiator – optional field that distinguishes multiple slices with the same SST | Octet string (optional) |
| **NSSAI** | Set of S‑NSSAIs that a UE is allowed or has requested | Set of identifiers |
| **AMF** | Access and Mobility Management Function – logical CN element that may belong to several slices simultaneously | – |
| **PDU Session** | Session that carries user data; belongs to exactly one slice instance per PLMN | – |

An **S‑NSSAI** is composed of an **SST** and optionally an **SD** [TS 23.501 §5.15.2.1].  
- If only a standardised SST is present, the S‑NSSAI is a *standard* value.  
- If an SD is present or the SST is non‑standard, the S‑NSSAI is *non‑standard* and uniquely identifies a slice within the PLMN [TS 23.501 §5.15.2.1].

A **Network Slice instance** includes the CN control‑plane and user‑plane functions and, in the serving PLMN, at least one of: NG‑RAN, N3IWF/TNGF, or W‑AGF [TS 23.501 §5.15.1].

A **PDU Session** is bound to a single slice instance; different slices may use the same Data Network Name (DNN) but never share the same PDU Session [TS 23.501 §5.15.1].

---

### 1.3.5.2 Slice selection process  

When a UE performs registration, the first contacted AMF interacts with the Network Slice Selection Function (NSSF) to determine the set of slice instances that the UE may use [TS 23.501 §5.15.1]. The result is the **Allowed NSSAI**, which contains the S‑NSSAIs that the UE may request. The number of simultaneous slice instances a UE can be attached to is limited by the number of S‑NSSAIs in the Requested/Allowed NSSAI [TS 23.501 §5.15.2].  

The AMF instance serving the UE is logically part of each slice instance that serves the UE; consequently a single AMF can be shared across multiple slices [TS 23.501 §5.15.1].

During handover, the source AMF selects a target AMF via the NRF, preserving the slice association of the UE [TS 23.501 §5.15.1].

---

### 1.3.5.3 Worked example  

Consider a UE that subscribes to two slices in its Home PLMN (HPLMN):

- Slice A: $SST = 1$ (eMBB), no SD (standard value).  
- Slice B: $SST = 1$, $SD = \text{0x01}$ (non‑standard, differentiates a premium eMBB slice).

The UE initiates registration. The AMF queries the NSSF and receives an **Allowed NSSAI** = $\{ \text{S‑NSSAI}_A, \text{S‑NSSAI}_B \}$.  

If the UE requests both slices, the network creates two **Network Slice instances**, each with its own CN functions. A single AMF instance is logically attached to both slices, satisfying the rule that “the AMF instance serving the UE logically belongs to each of the Network Slice instances serving the UE” [TS 23.501 §5.15.1].  

The UE then establishes two PDU Sessions, each bound to a different slice. Because “a PDU Session belongs to one and only one specific Network Slice instance per PLMN”, the two sessions are isolated even though they may use the same DNN [TS 23.501 §5.15.1].

---

### 1.3.5.4 Practical notes and common mistakes  

| Mistake | Why it is wrong (reference) |
|---------|-----------------------------|
| **Assuming a UE can attach to more slices than the number of S‑NSSAIs in its Allowed NSSAI** | The specification explicitly limits “the number of simultaneous connection of Network Slice instances per UE … by the number of S‑NSSAIs in the Requested/Allowed NSSAI” [TS 23.501 §5.15.2]. |
| **Using a non‑standard S‑NSSAI in a foreign PLMN** | “An S‑NSSAI with a non‑standard value shall not be used by the UE in access stratum procedures in any PLMN other than the one to which the S‑NSSAI is associated” [TS 23.501 §5.15.2.1]. |
| **Sharing a PDU Session across two slices** | “Different Network Slice instances do not share a PDU Session” [TS 23.501 §5.15.1]. |
| **Assuming each slice needs its own AMF** | The AMF can be common to several slice instances serving the same UE [TS 23.501 §5.15.1]. |

Other operational considerations (e.g., slice admission control, simultaneous registration groups, maximum bit‑rate per slice) are defined in later clauses of the specification but are outside the scope of this introductory subsection.

--- 

In summary, network slicing enables flexible, isolated service delivery by mapping UE‑requested S‑NSSAIs to distinct slice instances, each with dedicated CN functions and optionally distinct access‑network components. Correct identification (SST + optional SD) and adherence to the Allowed NSSAI limits are the backbone of a reliable slicing deployment.

## 練習題

**1.** Which component must be present in a Network Slice instance deployed in a PLMN, according to the specification?

- A. A dedicated Physical Layer (PHY) for each slice
- B. The Core Network Control Plane and User Plane functions
- C. An independent AMF per slice
- D. A separate Tracking Area per slice

<details><summary>看答案</summary>

正解：B。The definition of a Network Slice instance requires the CN control‑plane and user‑plane functions; other elements are optional.

</details>

**2.** An S‑NSSAI that contains both an SST and an SD is:

- A. A standard value that can be used in any PLMN
- B. A non‑standard value that uniquely identifies a slice within its PLMN
- C. Invalid according to the specification
- D. Only usable for non‑3GPP access

<details><summary>看答案</summary>

正解：B。Presence of an SD (or a non‑standard SST) makes the S‑NSSAI non‑standard and it uniquely identifies a slice in its PLMN.

</details>

**3.** How many Network Slice instances can a UE be simultaneously attached to?

- A. Unlimited, as long as the UE supports multiple radios
- B. At most one per PLMN
- C. Limited by the number of S‑NSSAIs in the Requested/Allowed NSSAI
- D. Equal to the number of AMF instances in the network

<details><summary>看答案</summary>

正解：C。The specification caps the simultaneous slice connections by the count of S‑NSSAIs in the NSSAI.

</details>

**4.** Which statement about the AMF's role across slices is correct?

- A. A separate AMF must be instantiated for each slice serving a UE
- B. The same AMF instance can belong logically to multiple slice instances serving the same UE
- C. AMF instances are never involved in slice selection
- D. An AMF can only serve slices that share the same SST

<details><summary>看答案</summary>

正解：B。The AMF serving a UE is common to all slice instances that serve that UE.

</details>

**5.** Which of the following is true about PDU Sessions and network slices?

- A. A single PDU Session may be shared by two different slice instances
- B. Each PDU Session belongs to exactly one slice instance per PLMN
- C. PDU Sessions are independent of slice selection
- D. A PDU Session can span multiple PLMNs within the same slice

<details><summary>看答案</summary>

正解：B。By definition, a PDU Session is bound to one slice instance only.

</details>
