# 1.3.8 邊緣運算

所屬：[1.3 服務與多媒體](../1-3.md)

## 正文

Edge computing in 5G refers to the placement of operator‑owned or third‑party application functions close to the UE’s point of attachment (i.e., the gNB). By hosting services at the network edge, the end‑to‑end latency is reduced and the load on the transport network is alleviated, which is essential for latency‑sensitive applications such as AR/VR, autonomous driving, and industrial control [TS 23.501 §5.13].

---

### Key Definitions  

| Symbol | Definition | Unit |
|--------|------------|------|
| UE | User Equipment (mobile device) | – |
| AN | Access Network (5G RAN) | – |
| UPF | User Plane Function – forwards user traffic | – |
| N6 | Interface between UPF and the Data Network (DN) | – |
| AF | Application Function – provides service logic | – |
| PCF | Policy Control Function – supplies QoS/charging rules | – |
| NEF | Network Exposure Function – mediates AF access to control‑plane NFs | – |
| EAS | Edge Access Server – logical entity exposing edge resources | – |
| DNAI | Data Network Access Identifier – identifies a specific DN or LADN | – |
| L6 delay | Measured round‑trip latency on the N6 interface | ms |
| QoS | Quality of Service – set of parameters governing latency, bandwidth, etc. | – |

**Latency requirement** – The maximum tolerable one‑way delay for a given service, denoted $L_{\text{req}}$ (ms).  

**Measured latency** – The observed N6 delay, $L_{\text{meas}}$ (ms).  

A UPF is considered “edge” if $L_{\text{meas}} \le L_{\text{req}}$ and the UPF is geographically close to the UE, as determined by the 5GC steering rules [TS 23.501 §5.13].

---

### How the 5G Core Selects an Edge UPF  

The 5G Core (5GC) selects a UPF close to the UE and forwards traffic to the local part of the Data Network (DN) via the N6 interface according to traffic‑steering rules [TS 23.501 §5.13]. The selection may be based on:

* UE subscription data and location,
* Information supplied by the AF,
* EAS information reported from the EAS Discovery Function (EASDF),
* Policy rules from the PCF,
* Measured user‑plane latency between the AN and candidate UPF(s),
* N6 delay measurement results, and
* Other traffic rules defined by the operator [TS 23.501 §5.13].

If the UE or the AF moves, session and service continuity mechanisms ensure that the traffic continues to be steered to an appropriate edge UPF [TS 23.501 §5.13].

---

### Enablers for Edge Computing  

Edge support can be realised by one or more of the following mechanisms [TS 23.501 §5.13]:

1. **User‑plane (re)selection** – 5GC (re)selects a UPF that routes traffic to the local DN.  
2. **Local Routing and Traffic Steering** – traffic is directed to applications residing in the local DN; this includes using a single PDU Session with multiple anchors (UL CL / IPv6 multihoming) or a Distributed Anchor Point with SSC mode 2/3.  
3. **Session and Service Continuity** – maintains UE‑application connectivity when either moves.  
4. **AF influence** – an AF may affect UPF selection and routing via PCF or NEF.  
5. **Network Capability Exposure** – 5GC and AF exchange capability information through NEF or directly.  
6. **QoS and Charging** – PCF provides QoS control and charging rules for edge‑routed traffic.  
7. **Local Area Data Network (LADN) support** – connects to a LADN where edge applications are hosted.  
8. **Discovery & Re‑discovery of Edge Application Servers** – performed by EASDF.  
9. **Edge Relocation** – triggered by 5GC when the UE moves, possibly involving AF change.  
10. **(I‑)SMF selection based on DNAI** – selects SMF/ISM​F that serve the required DN.  
11. **N6 delay measurement and reporting** – enables latency‑aware UPF selection and edge relocation [TS 23.501 §5.13].

---

### Worked Example  

A mobile operator offers an augmented‑reality (AR) service that requires $L_{\text{req}} = 15\,$ms one‑way latency. The UE is attached to gNB‑A. The 5GC measures N6 delays to two candidate UPFs:

| UPF | Measured N6 delay $L_{\text{meas}}$ (ms) |
|-----|------------------------------------------|
| UPF‑X (edge) | 8 |
| UPF‑Y (core) | 22 |

The steering logic evaluates $L_{\text{meas}} \le L_{\text{req}}$; only UPF‑X satisfies the condition. Consequently, the 5GC selects UPF‑X, routes the AR traffic over N6 to the local DN, and the AF receives a QoS rule from the PCF that enforces the required latency [TS 23.501 §5.13].

If the UE later moves to a region served by gNB‑B, the 5GC may re‑measure N6 delays, discover that UPF‑Z now offers $L_{\text{meas}} = 9\,$ms, and perform an **edge relocation** to maintain the latency guarantee [TS 23.501 §5.13].

---

### Practical Notes & Common Mistakes  

| Mistake | Why it Happens | Correct Approach |
|---------|----------------|------------------|
| Assuming edge computing works for all roaming cases | The reference limits edge support to non‑roaming and LBO roaming; HR‑SBO roaming is the only HR scenario allowed [TS 23.501 §5.13]. | Verify the roaming mode before expecting edge services; for HR‑SBO, follow the specific clause in TS 23.548. |
| Ignoring N6 delay measurements | Latency‑aware UPF selection relies on measured N6 delays [TS 23.501 §5.13]. | Configure N6 delay measurement and feed results to the steering logic. |
| Letting every AF directly access control‑plane NFs | Only some AFs may interact directly; others must use the NEF exposure framework [TS 23.501 §5.13]. | Classify AFs according to operator policy and route their requests accordingly. |
| Forgetting to update QoS rules after edge relocation | QoS and charging rules are tied to the selected UPF; relocation may require new rules [TS 23.501 §5.13]. | Trigger PCF re‑evaluation whenever the UPF changes. |
| Overlooking LADN support | Applications may be deployed in a Local Area Data Network; failure to connect to it defeats the edge benefit [TS 23.501 §5.13]. | Use the LADN support enabler to bind the edge UPF to the appropriate DNAI. |

By adhering to the selection criteria and enablers defined in TS 23.501 §5.13, operators can reliably deliver low‑latency edge services while preserving session continuity and proper QoS enforcement.

## 練習題

**1.** Which roaming scenario is explicitly mentioned as supporting edge computing?

- A. Home Routed with Session Breakout in VPLMN (HR‑SBO)
- B. Full International Roaming
- C. Local Break‑Out (LBO) roaming
- D. Visitor Local Break‑Out (VLBO)

<details><summary>看答案</summary>

正解：A。The reference notes that edge computing applies to non‑roaming, LBO roaming, and only HR‑SBO for HR roaming.

</details>

**2.** Which component can directly influence UPF selection and traffic routing via the PCF or NEF?

- A. User Equipment (UE)
- B. Application Function (AF)
- C. Access Network (AN)
- D. Charging Function (CHF)

<details><summary>看答案</summary>

正解：B。The AF may affect UPF selection and routing through PCF or NEF as stated in the reference.

</details>

**3.** What measurement is used by the 5GC to decide whether a UPF qualifies as an “edge” UPF?

- A. RRC connection setup time
- B. N6 delay measurement results
- C. Number of active bearers
- D. UE battery level

<details><summary>看答案</summary>

正解：B。The reference explicitly mentions N6 delay measurement results as a factor in UPF selection.

</details>

**4.** Which enabler involves using a single PDU Session with multiple anchors to support edge computing?

- A. User‑plane (re)selection
- B. Local Routing and Traffic Steering
- C. Session and Service Continuity
- D. QoS and Charging

<details><summary>看答案</summary>

正解：B。The reference lists this technique under Local Routing and Traffic Steering.

</details>
