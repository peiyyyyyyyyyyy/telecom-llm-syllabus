# 1.3.7 多媒體廣播（MBMS／MBS）與串流

## 正文

Multimedia Broadcast/Multicast Service (MBMS) – known in the 5G era as *Multimedia Broadcast and Multicast Service* (MBS) – is a network‑level mechanism that delivers the same content (e.g., live TV, software updates, or large‑scale video streaming) to many user equipments (UEs) simultaneously using a single radio resource allocation. Unlike unicast, where each UE consumes an independent data pipe, MBMS re‑uses the same transport channel for all receivers, thereby conserving spectrum and reducing latency for massive delivery scenarios. In real mobile networks, MBMS/MBS is the cornerstone for services such as mobile TV, emergency alerts, over‑the‑air (OTA) firmware upgrades, and large‑scale live event streaming.

---

### Key Definitions

| Symbol | Definition | Unit |
|--------|------------|------|
| $R_{\text{svc}}$ | Service bit‑rate (e.g., video codec rate) | bit s$^{-1}$ (bps) |
| $B_{\text{alloc}}$ | Bandwidth allocated to the MBMS bearer (including control) | Hz |
| $\eta_{\text{link}}$ | Link‑level spectral efficiency of the MBMS Transport Channel (MCH) | bit s$^{-1}$ Hz$^{-1}$ |
| $N_{\text{UE}}$ | Number of UEs subscribed to the MBMS session | – |
| $P_{\text{tx}}$ | Transmit power dedicated to the MBMS carrier | Watt (W) |
| $T_{\text{lat}}$ | End‑to‑end latency from source to UE (including encoding, scheduling, and propagation) | seconds (s) |
| $C_{\text{MCH}}$ | Capacity of the MBMS Control Channel (used for session signalling) | bit s$^{-1}$ |
| $R_{\text{eff}}$ | Effective data‑rate perceived by each UE | bit s$^{-1}$ |

MBMS creates a *Multicast Channel* (MCH) in LTE/5G NR that is mapped onto a set of physical resource blocks (PRBs) or slots. The same MCH is broadcast over the cell (or a group of cells) and can be further *scalable* (e.g., layered video) so that UEs with poorer radio conditions can receive a lower‑quality layer.

---

### Fundamental Relationships

1. **Bandwidth requirement**  
   The minimum bandwidth that must be allocated to carry the service is
   $$
   B_{\text{alloc}} \ge \frac{R_{\text{svc}}}{\eta_{\text{link}}}
   $$
   where $\eta_{\text{link}}$ is determined by the modulation and coding scheme (MCS) selected for the MCH. Because the same data is sent once, $B_{\text{alloc}}$ does **not** depend on $N_{\text{UE}}$.

2. **Spectral efficiency of the broadcast**  
   The *effective* spectral efficiency perceived by the audience is
   $$
   \eta_{\text{eff}} = \frac{R_{\text{svc}}}{B_{\text{alloc}}}
   $$
   which, in an ideal allocation, equals $\eta_{\text{link}}$.

3. **Latency budget**  
   For a live streaming service, the total latency must satisfy
   $$
   T_{\text{lat}} = T_{\text{enc}} + T_{\text{sched}} + T_{\text{prop}} + T_{\text{dec}} \le T_{\text{max}}
   $$
   where $T_{\text{enc}}$ and $T_{\text{dec}}$ are encoder/decoder processing times, $T_{\text{sched}}$ is the scheduler delay (often a few ms in LTE/NR), and $T_{\text{prop}}$ is the radio propagation delay (≈ µs). $T_{\text{max}}$ is service‑specific (e.g., ≤ 150 ms for ultra‑low‑latency video).

4. **Power per bit** (useful for network planning)  
   $$
   \frac{P_{\text{tx}}}{R_{\text{svc}}} \quad \text{[W/(bit s}^{-1}\text{)]}
   $$

### Worked Example

A mobile operator wants to broadcast a 1080p video stream at **8 Mbps** to a stadium of **20 000** spectators using LTE‑Advanced. The network can allocate a 5 MHz carrier for the MBMS session. The operator selects an MCS that yields a link‑level spectral efficiency $\eta_{\text{link}} = 2.5$ bit s$^{-1}$ Hz$^{-1}$.

1. **Check bandwidth sufficiency**  
   Required bandwidth:
   $$
   B_{\text{req}} = \frac{R_{\text{svc}}}{\eta_{\text{link}}}
   = \frac{8 \times 10^{6}\ \text{bit s}^{-1}}{2.5\ \text{bit s}^{-1}\,\text{Hz}^{-1}}
   = 3.2\ \text{MHz}
   $$
   Since 3.2 MHz < 5 MHz, the allocation is adequate.

2. **Determine number of PRBs** (LTE 15 kHz sub‑carrier spacing)  
   One PRB occupies 180 kHz.  
   $$
   N_{\text{PRB}} = \frac{B_{\text{alloc}}}{180\ \text{kHz}} = \frac{5\ \text{MHz}}{0.18\ \text{MHz}} \approx 28\ \text{PRBs}
   $$
   The scheduler will reserve 28 PRBs per subframe for the MCH.

3. **Effective spectral efficiency**  
   $$
   \eta_{\text{eff}} = \frac{R_{\text{svc}}}{B_{\text{alloc}}}
   = \frac{8\ \text{Mbps}}{5\ \text{MHz}} = 1.6\ \text{bit s}^{-1}\,\text{Hz}^{-1}
   $$
   The gap between $\eta_{\text{eff}}$ (1.6) and $\eta_{\text{link}}$ (2.5) reflects overhead (control signalling, coding margin).

4. **Power per bit** (assuming the MBMS carrier uses 5 W)  
   $$
   \frac{P_{\text{tx}}}{R_{\text{svc}}} = \frac{5\ \text{W}}{8 \times 10^{6}\ \text{bit s}^{-1}} = 6.25 \times 10^{-7}\ \text{W bit}^{-1}
   $$

Result: The operator can reliably deliver the stream to all 20 000 UEs using only 5 MHz of spectrum, and the per‑UE data rate is exactly the service rate because the broadcast is *one‑to‑many*.

### Common Mistakes & Practical Notes

| Mistake | Why it Happens | Correct Practice |
|---------|----------------|------------------|
| **Treating MBMS like unicast** – allocating a separate bearer per UE. | Engineers accustomed to LTE‑PC5 or normal LTE data may forget that MBMS uses a *single* MCH per session. | Always dimension the MCH based on the service bitrate **only**, not on the number of receivers. |
| **Ignoring link‑adaptation limits** – selecting the highest MCS irrespective of cell‑edge SINR. | Higher MCS improves $\eta_{\text{link}}$ but reduces robustness. | Choose the MCS that satisfies the worst‑case UE SINR (or use *layered* multicast with a base layer for edge users). |
| **Overlooking control‑channel overhead** – assuming $B_{\text{alloc}} = R_{\text{svc}}/\eta_{\text{link}}$ is sufficient. | MBMS session signalling (MCH, MCCH) consumes a non‑trivial fraction of the allocated PRBs. | Add a 10‑15 % margin to $B_{\text{alloc}}$ to accommodate MCCH and paging. |
| **Assuming all UEs receive simultaneously** – forgetting that some devices may be in *inactive* state and need to be paged. | MBMS paging is optional; if omitted, UE may miss the start of a session. | Deploy MBMS paging (as defined in 3GPP TS 23.246) for latency‑critical services. |
| **Neglecting inter‑cell coordination** – broadcasting independently in each cell. | Without coordination, the same content may be transmitted on different frequencies, wasting spectrum. | Use *Single Frequency Network* (SFN) mode where multiple cells transmit the same MCH synchronously, improving coverage and spectral efficiency. |

**Practical tip:** When planning a large‑scale broadcast, run a *coverage‑efficiency* simulation that jointly evaluates SINR maps, required MCS, and the number of SFN cells needed to meet the target $T_{\text{lat}}$ and $R_{\text{svc}}$. The 3GPP specification *TS 23.246* (Release 15) details the MBMS architecture, bearer setup, and SFN operation; adherence to its guidelines ensures interoperability across vendors.
