# 1.3.7 多媒體廣播（MBMS／MBS）與串流

所屬：[1.3 服務與多媒體](../1-3.md)

## 正文

**Multimedia Broadcast (MBS) and Streaming in 5G**

Multimedia Broadcast Service (MBS) is the 5G evolution of the legacy MBMS concept. It enables a *point‑to‑multipoint* distribution of user‑plane data from a single source (e.g., a video‑on‑demand server) to many User Equipments (UEs) simultaneously. In commercial networks MBS is used for live TV, emergency alerts, or large‑scale video streaming, where delivering the same content individually to each UE would waste radio and core‑network resources. The 5G System (5GS) therefore defines specific *delivery methods* that preserve the efficiency of the radio interface while still providing the QoS guarantees required for multimedia services [TS 23.247 §4.1].

### Key Definitions

| Symbol | Definition | Unit / Note |
|--------|------------|-------------|
| **MBS** | Multicast/Broadcast Service – a point‑to‑multipoint service defined in 5GS. | – |
| **Broadcast MBS session** | A session addressed to *all* UEs in a broadcast service area. | – |
| **Multicast MBS session** | A session addressed to a *multicast group* as defined in TS 22.146. | – |
| **5GC Shared MBS traffic delivery** | The Core Network receives a *single copy* of the data and forwards **one** copy to the NG‑RAN node, which then distributes it to one or more UEs. | – |
| **5GC Individual MBS traffic delivery** | The Core Network receives a single copy but creates *separate* per‑UE copies on distinct PDU sessions. Required only for multicast when some UEs are attached to NG‑RAN nodes that do **not** support MBS. | – |
| **PTP (Point‑to‑Point) delivery** | NG‑RAN sends an individual copy of the packet to each UE over the radio interface. | – |
| **PTM (Point‑to‑Multipoint) delivery** | NG‑RAN sends *one* copy over the radio interface that is received by multiple UEs simultaneously. | – |

The reference architecture (Fig. 5.1‑1) places the MBS Function (MBSF) and the MBS Traffic Function (MBSTF) as optional network functions that interact with the existing 5G service‑based interfaces (e.g., Nsmf, Nudm) [TS 23.247 §5.1].

### Delivery Method Hierarchy

The 5GS separates delivery into two logical hops:

1. **Core‑to‑RAN (5GC ↔ NG‑RAN)**  
   - *Shared* method is mandatory for *all* MBS deployments.  
   - *Individual* method is optional and used only for multicast when a UE is attached to a node that lacks MBS support [TS 23.247 §4.1].

2. **RAN‑to‑UE (NG‑RAN ↔ UE)**  
   - *PTM* can be used for both broadcast and multicast sessions.  
   - *PTP* may be used for multicast when the NG‑RAN decides that PTM is not feasible (e.g., heterogeneous UE capabilities) [TS 23.247 §4.1].

A typical broadcast flow therefore follows **Shared + PTM** only; a multicast flow may combine **Shared + PTM**, **Shared + PTP**, or **Individual + PTP** depending on UE mobility and NG‑RAN capabilities [TS 23.247 §4.1].

### Worked Example – Radio Resource Saving

Assume a live video stream of **2 Mbps** is to be delivered to **1 000** UEs in a single cell.

| Delivery mode | Number of copies over the radio interface | Total radio bandwidth required |
|---------------|-------------------------------------------|--------------------------------|
| Unicast (baseline) | 1 000 copies (one per UE) | $2\ \text{Mbps} \times 1\,000 = 2\,000\ \text{Mbps}$ |
| MBS PTM (broadcast) | 1 copy (PTM) | $2\ \text{Mbps}$ |
| MBS Shared + PTP (multicast) | 1 000 copies (PTP) | $2\,000\ \text{Mbps}$ (same as unicast) |
| MBS Shared + PTM (multicast) | 1 copy (PTM) | $2\ \text{Mbps}$ |

The example shows that **PTM** reduces the required radio bandwidth by a factor of **1 000**, because only a single packet needs to be transmitted regardless of the number of receivers. This efficiency is the primary reason operators deploy MBS for mass‑media streaming [TS 23.247 §4.1].

### Mobility and Roaming Considerations

When a UE moves from an MBS‑enabled NG‑RAN node to one that does **not** support MBS, the Core Network temporarily switches from the *Shared* to the *Individual* delivery method for that UE. This coexistence allows seamless handover without service interruption [TS 23.247 §4.1].  

Conversely, **multicast/broadcast roaming is not supported** in the current release; a UE roaming into a foreign PLMN cannot receive an MBS session originating from the home network [TS 23.247 §4.1].

### Charging and Service Differentiation

Charging for MBS follows two TS 32 series specifications: **PDU‑session charging** (TS 32.255) and **MBS‑session charging** (TS 32.279). The network can also apply **QoS differentiation** and **local or location‑dependent MBS services**, enabling, for example, a city‑wide emergency alert that is only delivered to UEs inside the affected area [TS 23.247 §4.1].

### Common Pitfalls and Practical Notes

| Pitfall | Why it occurs | Correct practice |
|---------|---------------|------------------|
| Confusing *unicast delivery* with *5GC Individual MBS traffic delivery*. | The reference explicitly separates the two concepts; the former uses standard IP routing, the latter is a special MBS mechanism. | Remember that *Individual* delivery is only for multicast and involves per‑UE PDU sessions inside the 5GC. |
| Assuming PTM is always possible for multicast. | NG‑RAN may lack PTM capability for certain UEs or frequency bands. | Verify NG‑RAN support; fall back to PTP if required. |
| Ignoring the need for the *Shared* method in broadcast sessions. | The specification mandates Shared + PTM for broadcast. | Design the core‑to‑RAN interface to deliver a single copy to the NG‑RAN node. |
| Overlooking the temporary coexistence of Shared and Individual methods during handover. | Mobility handling is described only for the case where the target NG‑RAN node does not support MBS. | Implement the handover logic defined in clause 6.3 (referenced in the spec) to switch methods seamlessly. |
| Expecting MBS to work while roaming. | Roaming support is explicitly *not* included in this release. | Deploy separate broadcast solutions for visited PLMNs or wait for future releases. |

By adhering to the delivery hierarchy and respecting the limitations (no roaming, optional local services), engineers can reliably integrate MBS into 5G networks and achieve the massive efficiency gains required for modern multimedia streaming. [TS 23.247 §4.1][TS 23.247 §5.1]

## 練習題

**1.** MBS（Multicast and Broadcast Service）的核心概念是什麼？

- A. 從單一來源傳送資料給單一使用者
- B. 點對多點服務，將資料從單一來源傳送給多個接收者
- C. 僅支援點對點的資料傳輸
- D. 只支援單向單播流媒體

<details><summary>看答案</summary>

正解：B。MBS 被定義為點對多點服務，資料從單一來源傳送給多個使用者。

</details>

**2.** 依據規範，MBS 會提供哪兩種會話類型？

- A. 單播會話與多播會話
- B. 廣播會話與單播會話
- C. 廣播 MBS 會話與多播 MBS 會話
- D. 多播 MBS 會話與點對點會話

<details><summary>看答案</summary>

正解：C。規格列出「Broadcast MBS session」與「Multicast MBS session」兩種會話。

</details>

**3.** 在所有 MBS 部署中，哪一種 5GC 交付方法是必須的？

- A. 5GC Individual MBS traffic delivery method
- B. 5GC Shared MBS traffic delivery method
- C. 兩者皆可選擇
- D. 皆非必須

<details><summary>看答案</summary>

正解：B。規範明確指出，Shared 交付方法在所有 MBS 部署中都是必需的。

</details>

**4.** 對於 MBS 廣播通信，哪一種交付組合是唯一適用的？

- A. 5GC Individual delivery with PTM
- B. 5GC Shared delivery with PTM
- C. 5GC Shared delivery with PTP
- D. 5GC Individual delivery with PTP

<details><summary>看答案</summary>

正解：B。廣播時只能使用 Shared 交付方式，且必須以 PTM 方式在無線介面傳送。

</details>

**5.** 在本版規範中，MBS 的漫遊支援情況為何？

- A. 完全支援
- B. 不支援
- C. 只支援廣播服務的漫遊
- D. 只支援多播服務的漫遊

<details><summary>看答案</summary>

正解：B。規範明確指出，MBS 的漫遊功能在此版本中未被支援。

</details>
