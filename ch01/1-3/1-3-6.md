## 正文

In modern industry, factories, campuses, logistics hubs and large‑scale venues demand a communications fabric that is *dedicated*, *secure* and *optimised* for their specific traffic patterns. An **Enterprise Private Network (EPN)** satisfies these needs by providing a logical or physical separation from the public mobile network while still leveraging the 5G radio access technology (RAN). The two principal deployment models defined by 3GPP are:

* **Standalone Non‑Public Network (SNPN)** – a completely independent 5G Core (5GC) and radio access network (RAN) that does **not** inter‑operate with the public network. It is identified by its own PLMN‑ID and can be operated by the enterprise, a system integrator, or a mobile operator under a “private‑by‑operator” contract.  
* **Public Network Integrated Non‑Public Network (PNI‑NPN)** – the private traffic is carried over the same RAN as the public network but is isolated in the core by a dedicated **Network Slice** (often called a *private slice*). The PLMN‑ID may be shared, yet the control‑plane and user‑plane traffic are kept distinct.

A third, more specialised, concept is the **5G LAN** (Local Area Network). Here the 5G base stations (gNBs) are deployed within a confined area (e.g., a factory floor) and the core functions are either fully localised (edge‑deployed 5GC) or bypassed entirely, turning the radio link into a high‑speed, low‑latency LAN that can inter‑connect sensors, robots and edge‑computing nodes without ever touching the public internet.

### Key Definitions

| Symbol | Definition | Unit |
|--------|------------|------|
| $B_{\text{req}}$ | Required user‑plane throughput per device | bit s$^{-1}$ (bps) |
| $N_{\text{UE}}$ | Number of simultaneous user equipments (UEs) | – |
| $\eta$ | Spectral efficiency (bits per second per Hertz) | bit s$^{-1}$ Hz$^{-1}$ |
| $\Delta f$ | Subcarrier spacing (typically 15 kHz for FR1) | Hz |
| $N_{\text{PRB}}$ | Number of Physical Resource Blocks needed | – |
| $T_{\text{lat}}$ | End‑to‑end latency (including RAN, transport and core) | ms |
| $S_{\text{slice}}$ | Slice identifier (S‑ST) that isolates traffic | – |
| $P_{\text{tx}}$ | Transmit power per gNB sector | dBm |
| $L_{\text{link}}$ | Path loss (including shadowing) | dB |

**Throughput Allocation Formula**

The number of PRBs that must be scheduled for a group of UEs is approximated by  

$$
N_{\text{PRB}} = \frac{N_{\text{UE}} \times B_{\text{req}}}{\Delta f \times \eta}
\tag{1}
$$

where $\Delta f$ is the subcarrier spacing (15 kHz for the most common 5G‑NR numerology). The product $\Delta f \times \eta$ gives the *effective* bit rate per PRB.

**Latency Budget**

For many industrial control loops, the total latency must stay below a target $T_{\text{max}}$ (e.g., 1 ms for motion control). The latency budget is split among the RAN, transport network, and core:

$$
T_{\text{lat}} = T_{\text{RAN}} + T_{\text{transport}} + T_{\text{core}} \le T_{\text{max}}
\tag{2}
$$

Typical values: $T_{\text{RAN}} \approx 0.3$ ms, $T_{\text{transport}} \approx 0.2$ ms (with fiber backhaul), $T_{\text{core}} \approx 0.4$ ms for an edge‑deployed 5GC.

### Worked Example

**Scenario:** A smart‑factory floor requires 50 autonomous guided vehicles (AGVs). Each AGV streams sensor data at $B_{\text{req}} = 2$ Mbps and the network must guarantee $T_{\text{max}} = 1$ ms latency. The chosen numerology uses $\Delta f = 15$ kHz and the channel conditions allow $\eta = 4$ bit s$^{-1}$ Hz$^{-1}$ (e.g., 64‑QAM with a suitable MCS).

1. **Compute PRBs needed** using (1):

$$
N_{\text{PRB}} = \frac{50 \times 2 \times 10^{6}}{15 \times 10^{3} \times 4}
= \frac{100 \times 10^{6}}{60 \times 10^{3}}
\approx 1667 \text{ PRBs}
$$

2. **Check available bandwidth:** One 100 MHz carrier in FR1 provides  

$$
\frac{100 \text{ MHz}}{\Delta f} = \frac{100 \times 10^{6}}{15 \times 10^{3}} \approx 6667 \text{ PRBs}
$$

Thus, the required 1667 PRBs represent **25 %** of the total resources, leaving ample headroom for control traffic and future expansion.

3. **Latency budgeting:** Assume the deployment uses an edge‑located 5GC (core latency 0.4 ms) and fiber backhaul (transport latency 0.2 ms). The RAN latency for a scheduled transmission in TDD with a 0.5 ms slot is roughly 0.3 ms. Summing gives  

$$
T_{\text{lat}} = 0.3 + 0.2 + 0.4 = 0.9 \text{ ms} \le 1 \text{ ms}
$$

The design meets the latency requirement.

### Practical Notes & Common Mistakes

| Pitfall | Why it Happens | Remedy |
|---------|----------------|--------|
| **Treating SNPN as “just another PLMN”** | Engineers sometimes configure the same PLMN‑ID for private and public traffic, causing the core to route private UE data onto the public slice. | Assign a *unique* PLMN‑ID for the SNPN and enforce it in the SIM/USIM provisioning. |
| **Under‑estimating interference from the public RAN** (in PNI‑NPN) | Private slice shares the same radio spectrum; neighboring public cells can raise the noise floor. | Deploy dedicated carrier frequencies (or use higher‑frequency mmWave) and apply strict inter‑slice interference coordination (ICIC). |
| **Neglecting the transport latency budget** | Assuming fiber backhaul is “instantaneous” leads to missed latency targets. | Measure actual round‑trip time on the transport network; if $T_{\text{transport}} > 0.2$ ms, consider Ethernet‑based fronthaul with TSN (Time‑Sensitive Networking). |
| **Using generic QoS Class Identifier (QCI) values** | Public QCI tables may not reflect the deterministic needs of factory automation. | Define custom 5G QoS Flow identifiers (5GF) with guaranteed bit rate (GBR) and latency bound, mapped to the private slice. |
| **Over‑provisioning PRBs without checking UE capability** | The formula assumes all UEs can achieve the target $\eta$, which may not hold for legacy devices. | Verify the minimum supported MCS per UE, or allocate a lower $\eta$ (e.g., 2 bit s$^{-1}$ Hz$^{-1}$) and recompute resources. |

**Security tip:** SNPNs typically use a separate Authentication Server Function (AUSF) and Unified Data Management (UDM). Do not reuse public‑network subscriber keys; generate dedicated keys to avoid cross‑domain credential leakage.

**Regulatory note:** In many jurisdictions the spectrum for private networks is either *licensed shared access* (e.g., 3.5 GHz CBRS) or *unlicensed* (e.g., 60 GHz). Ensure the chosen band complies with national spectrum policy; otherwise the deployment may be illegal.

By carefully separating the PLMN identity, allocating dedicated resources through network slicing, and respecting the latency budget, enterprises can harness the full potential of 5G—ultra‑reliable low‑latency communication (URLLC), massive machine‑type communication (mMTC), and high‑throughput enhanced mobile broadband (eMBB)—within a private, controllable environment.
