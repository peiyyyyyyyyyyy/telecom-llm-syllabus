# 8.1.4 服務目標與安全餘量

所屬：[8.1 設定問題](8-1.md)

## 內文

服務目標寫的是忙時仍要提供的服務品質，例如電路型業務的最大阻塞機率、封包業務的使用者速率分位數，或工程運轉中的最大使用率。安全餘量是在模型誤差、短期波動或恢復條件下保留的資源。規劃人員在編列擴容門檻、設計活動保障或核定節能策略時，先定出可檢驗的服務條件，再決定哪一層要留多少餘量，以及過了何種門檻就啟動處置。

訂目標時應寫清楚對象、統計時窗、達標方向和處理例外的方式。若為無等候、遭阻塞即清除的電路群，可在符合模型假設時使用 Erlang B。先估提供話務 A，再從 B₀＝1 起逐一算 Bₘ＝A × Bₘ₋₁ ÷ (m＋A × Bₘ₋₁)。增加電路，直到阻塞機率第一次小於或等於目標，整數電路數便是模型給出的最小配置。等待通話、回撥與溢流會改變模型條件，應先核對規劃對象。驗算時可一併列出較少一條電路的阻塞機率，確認已達到門檻所需的最小值。[ITU-T E.520 無溢流電路群配置](https://www.itu.int/rec/T-REC-E.520/en)

封包業務要把工程門檻和體驗門檻各自訂出來。以小區使用率為例，可先設定業者自己的上限，再用同口徑的忙時樣本校驗上限是否能保護低分位使用者速率。要判定比率，必須知道分母是當時全部可用資源、名目設備能力，還是扣除保留量的能力。以體驗速率為例，若目標用第十百分位數判斷，應寫明統計樣本、速率計量層和低流量測試樣本的處理方式。若餘量已體現在較低的使用率上限，把同一風險再用同一比例扣一次會放大擴容量。不同用途有不同餘量時，可以分別保留，但須寫出各自保護的事件與作用對象。也可分別設定正常和故障條件的服務目標，並註明故障模式容許維持多久。

以虛構的北浦匯聚區為例，假設其中一段下行現有名目能力 300 Mbps，正常忙時需求預估為 216 Mbps，規劃要求以需求的 10% 保留成長餘量，且正常忙時使用率不得高於 80%。先把需求增加 21.6 Mbps，得設計需求 237.6 Mbps。再用 0.80 反推最低名目容量，237.6 ÷ 0.80 等於 297 Mbps。既有能力 300 Mbps，名目容量超出最低配置 3 Mbps。也可以從容量端檢查，300 × 0.80 等於 240 Mbps，減去設計需求後的可用吞吐餘量為 2.4 Mbps。兩種表示方式各有自己的分母。如果另外假設故障時只剩 240 Mbps 名目容量，依同一使用率目標可承接 192 Mbps，距設計需求少 45.6 Mbps。這樣的算例可用來決定故障情況是否要獨立設服務目標。

| 北浦匯聚區假設輸入 | 數值 |
| --- | ---: |
| 正常忙時需求 | 216 Mbps |
| 需求成長餘量 | 10% |
| 工程使用率上限 | 80% |
| 正常名目容量 | 300 Mbps |
| 故障剩餘名目容量 | 240 Mbps |

容易混淆的有需求增加百分比和容量保留百分比。加 10% 需求等於乘 1.10，保留 10% 名目容量則使可用部分剩 90%，反推容量時需除以 0.90。另一個問題是平均體驗達標但低分位用戶仍低於門檻，這兩個判定可同時成立。各業者所選門檻依服務和回復能力而定，應記錄選定依據及觸發動作，才方便後續回頭驗證。

服務目標在 8.2.1 可成為計算與模擬的判定條件，在 8.3.1 可把單純的名目缺口改成達標缺口。8.4.3 比較節能時，也要在休眠前後套用同一套目標與樣本定義。
