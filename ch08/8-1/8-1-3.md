# 8.1.3 現有容量

所屬：[8.1 設定問題](../8-1.md)

## 正文

When a mobile operator designs a new network slice, the first step is to inventory the **existing capacity** that is already provisioned in the infrastructure. Existing capacity is the amount of **virtualised resources** (processor, memory, disk) that have been allocated to a particular network slice instance. Knowing this baseline is essential because all subsequent dimensioning—peak demand, concurrency ratios, safety margins—are expressed relative to what is already available. If the operator over‑estimates the usable capacity, the slice will suffer congestion; if the estimate is too conservative, valuable resources remain idle, reducing overall network efficiency.

The 3GPP Technical Specification **TS 28.554 §6.4** defines a set of Utilization Key Performance Indicators (KPIs) that quantify how much of the allocated capacity is currently being used. These KPIs provide the only normative way to translate raw resource numbers into a single, comparable metric that can be used in planning calculations.  

### Key KPI definitions

| KPI (as defined in TS 28.554 §6.4) | Description | KPI type | Unit / expression |
|-----------------------------------|-------------|----------|-------------------|
| **VirtualResUtilizaiton** | Utilization of virtualised resource (e.g. processor, memory, disk) that are allocated to a network slice. It is obtained by the usage of virtualised resource divided by the system capacity allocated to the slice. | Ratio | Percentage (%) |
| **PDUSesMeanNbr** | Mean number of PDU sessions successfully established in a network slice. | MEAN | Integer (count) |
| **PDUSesMaxNbr** | Maximum number of PDU sessions successfully established in a network slice. | MEAN | Integer (count) |
| **MaPDUSesMeanNbr** | Mean number of MA PDU sessions successfully established in a network slice. | MEAN | Integer (count) |
| **MaPDUSesMaxNbr** | Maximum number of MA PDU sessions successfully established in a network slice. | MEAN | Integer (count) |

Only the **VirtualResUtilizaiton** KPI directly expresses *existing capacity* as a proportion of allocated resources. The other KPIs (mean and maximum numbers of PDU sessions) are indirect indicators of how much session‑handling capacity is being exercised, but they do not convey the absolute size of the underlying compute or storage pool.

### Formula for virtualised resource utilization

The specification states that utilization is “the usage of virtualised resource … divided by the system capacity that allocated to the network slice.” Formally:

$$
\text{VirtualResUtilizaiton} \; (\%) = 
\frac{\text{Resource\_Used}}{\text{Resource\_Allocated}} \times 100
$$

* **Resource\_Used** – measured amount of processor cycles, memory bytes, or disk space actually consumed by the slice during the observation interval.  
* **Resource\_Allocated** – total amount of the same resource that has been reserved for the slice (the “existing capacity”).  

Because the KPI type is **Ratio**, the result is expressed as a percentage.  

### Mean and maximum PDU‑session counts

The mean number of PDU sessions, **PDUSesMeanNbr**, is defined as “the mean number of PDU sessions that are successfully established in a network slice” and its KPI type is **MEAN**【TS 28.554 §6.4】. Likewise, **PDUSesMaxNbr** gives the peak number of concurrent sessions observed and is also of type **MEAN** (the spec treats the maximum as a mean of a set of maximum observations). These counts are useful when capacity is measured in terms of session handling rather than raw CPU or memory, e.g., when the slice hosts a core network function that is session‑bound.  

### Worked example

Assume an operator has allocated to Slice A the following virtualised resources:

* CPU capacity: 200 GHz of processing power  
* Memory capacity: 256 GB  

During a one‑hour monitoring window the slice reports:

* CPU usage: 120 GHz  
* Memory usage: 128 GB  

Compute the utilization for each resource:

$$
\text{CPU Utilization} = \frac{120\;\text{GHz}}{200\;\text{GHz}} \times 100 = 60\%
$$

$$
\text{Memory Utilization} = \frac{128\;\text{GB}}{256\;\text{GB}} \times 100 = 50\%
$$

If the operator aggregates these two dimensions into a single **VirtualResUtilizaiton** KPI (as allowed by the specification when a composite metric is defined), the overall utilisation could be reported as the higher of the two percentages (60 %) to respect the most constrained resource.  

In the same interval the slice records a mean of 1 200 PDU sessions (**PDUSesMeanNbr**) and a maximum of 1 800 sessions (**PDUSesMaxNbr**). These figures indicate that, while CPU is only 60 % busy, the session handling capacity is approaching its limit, suggesting that the next planning step should focus on scaling the session‑oriented function rather than adding raw CPU.  

All KPI values above are derived directly from the definitions in **TS 28.554 §6.4**【TS 28.554 §6.4】.  

### Practical notes and common pitfalls

* **Do not confuse utilisation with absolute capacity.** A 70 % VirtualResUtilizaiton does *not* tell you the total CPU or memory that the slice possesses; you must still reference the underlying allocation (e.g., 200 GHz) to understand the absolute headroom.  
* **Scope of the VirtualResUtilizaiton KPI.** The specification explicitly notes that this KPI applies “when NF is not shared between different network slice”【TS 28.554 §6.4】. If network functions are shared, the KPI may double‑count usage and give misleadingly high utilisation values.  
* **Integer nature of session‑based KPIs.** Both **PDUSesMeanNbr** and **PDUSesMaxNbr** are defined as integers. Rounding errors in reporting (e.g., reporting 1 200.5 sessions) are therefore non‑conformant.  
* **Time granularity matters.** The mean values are computed over the observation period defined by the measurement system. Short‑term spikes can be hidden if the averaging window is too large; conversely, a too‑short window may over‑emphasise transient bursts.  
* **Safety margins must be applied after utilisation is known.** Existing capacity alone is insufficient for planning; operators typically add a safety margin (e.g., 20 % extra) on top of the observed utilisation to accommodate traffic growth and unexpected events.  

By grounding capacity assessments in the normative KPIs of **TS 28.554 §6.4**, engineers obtain a reproducible, standards‑based view of how much of the allocated resources are in use, which directly informs the sizing of additional capacity, the selection of appropriate slice templates, and the verification that service‑level objectives can be met.

**1.** What does the KPI **PDUSesMeanNbr** describe?

- A. The maximum number of PDU sessions that can be established in a network slice.
- B. The mean number of PDU sessions that are successfully established in a network slice.
- C. The utilization percentage of virtualised resources in a network slice.
- D. The time taken to establish a PDU session.

<details><summary>看答案</summary>

正解：B。PDUSesMeanNbr measures the average count of successfully established PDU sessions per slice.

</details>

**2.** In what unit is the **PDUEstTime** KPI expressed?

- A. Seconds
- B. Milliseconds
- C. Minutes
- D. Bytes

正解：B。PDUEstTime is defined as a time interval measured in milliseconds.

</details>

**3.** The KPI **RegUpdMeanNbr** is measured at which network function?

- A. SMF
- B. AMF
- C. UPF
- D. NRF

<details><summary>看答案</summary>

正解：B。RegUpdMeanNbr counts successful periodic registration updates at the AMF.

</details>

**4.** What does **ConnectedModeMeasRelaxationUsage** quantify?

- A. The average latency of connected mode measurements.

- C. The total number of connected mode RRM relaxation sessions.

</details>
