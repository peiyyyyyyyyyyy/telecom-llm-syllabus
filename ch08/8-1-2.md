# 8.1.2 同時上線比例

所屬：[8.1 設定問題](8-1.md)

## 內文

同時上線比例用來把一群用戶的規模換成同一時間需要連線的裝置數。裝置連線後也可能在等候資料、保留連線或執行背景作業，真正同時傳輸的裝置通常還要再估一次。這個區分適用於新設場館、住宅社區、企業園區與活動時段的規劃。估連線處理能力時，關心的是同時維持的連線數，估空中介面及傳輸流量時，則關心正在傳輸的數量、每台傳輸速率與方向。工程文件應先寫清楚「上線」指哪一種狀態。

第一步是選適當分母。住宅需求可從小區服務範圍內的訂戶或裝置估起，活動需求則常先估到場人數，再乘適用的使用者占比。若每人可能攜帶多台裝置，用人數當分母時還須換算成裝置數。第二步是訂出連線的分子與採樣條件，例如單一小區同時處於連線模式的裝置，並記錄是採樣平均、採樣最大，還是特定分鐘的快照。第三步是在這些連線裝置中估出同時下行或同時上行傳輸的比例。若第二層是「已連線裝置中的傳輸比例」，兩層可相乘。若第三項本身就以全體裝置為分母，應直接乘全體裝置數。比率要附時間、地點和樣本來源，方便重算。

可先從相似日期蒐集成對樣本。在相同小區、方向與短窗，取得可比較的裝置母體、連線數以及清楚定義的活躍傳輸數。有多個小區時，量測總量可作為資源負荷觀察，但若要推回去重的現場裝置數，仍要確認雙連線、跨區移動與資料合併的口徑。以 3GPP TS 28.552 Release 18 為例，RRC.ConnMean 是 NR 小區在統計粒度期間依採樣取得的連線模式用戶數均值。RRC.ConnMax 是採樣最大值，另有針對 inactive 狀態的量測。規劃時可用這些資料校核連線層估計，傳輸層比例則應使用另行定義、同時段的量測或明確的暫定假設。[3GPP TS 28.552 V18.11.0 §5.1.1.4](https://www.etsi.org/deliver/etsi_ts/128500_128599/128552/18.11.00_60/ts_128552v181100p.pdf)

以虛構的石溪展館為例，假設同一場次有 4,800 人，每人平均對應一台符合規劃範圍的裝置，再假設這些裝置中有 25% 在繁忙時段同時連線。連線數估為 4,800 × 0.25，等於 1,200 台。若這批連線裝置中有 35% 同時下行傳輸，則有 1,200 × 0.35，等於 420 台活躍裝置。在每台持續需要 1.8 Mbps 應用層下行的假設下，合計是 756 Mbps。若實地樣本顯示連線比例可能升到 30%，而其他條件維持，重新計算得到 1,440 台連線、504 台傳輸與 907.2 Mbps，比基準多 151.2 Mbps。這些都是場景估計，還要按小區分配並與現場樣本比對。

| 石溪展館假設輸入 | 基準 | 連線比例提高 |
| --- | ---: | ---: |
| 規劃裝置母體 | 4,800 台 | 4,800 台 |
| 同時連線比例 | 25% | 30% |
| 已連線裝置同時傳輸比例 | 35% | 35% |
| 每台活躍裝置下行需求 | 1.8 Mbps | 1.8 Mbps |

需要分辨的是，在整個時段至少上線一次的獨立用戶數，與同一時刻上線的用戶數屬於不同統計量。平均連線數配上不同時窗取得的峰值傳輸比例，也會把兩個狀態混在一起。若不同用戶群的連線習慣差異很大，可先分群計算再加總。觀眾共同收到通知或在活動結束後同時上傳時，平日估得的比例也應重新校準。

把這裡的同時傳輸數與每台需求速率相乘，可和 8.1.1 的忙時流量做交叉檢查。8.3.2 會進一步拆開連線比例、傳輸比例和每台速率，逐項評估哪個假設最值得補量測。
