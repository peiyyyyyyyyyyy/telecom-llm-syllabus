```cpp
bool pdu_rx_handler::handle_rx_pdu(slot_point sl_rx, du_cell_index_t cell_index, mac_rx_pdu pdu)
{
  trace_point rx_tp = up_tracer.now();
  // > Store PCAP
  write_pcap_rx_pdu(sl_rx, pdu);

  // > Fetch UE index based on PDU RNTI.
  du_ue_index_t ue_index = rnti_table[pdu.rnti];

  // > Decode MAC UL PDU.
  decoded_mac_rx_pdu      ctx{sl_rx, cell_index, std::move(pdu), ue_index};
  error_type<std::string> ret = ctx.decoded_subpdus.unpack(ctx.pdu_rx.pdu);
  if (not ret.has_value()) {
    logger.info("{}: Failed to decode MAC UL PDU. Cause: {}", create_prefix(ctx), ret.error());
    return false;
  }

  // > Log MAC UL PDU.
  if (logger.info.enabled()) {
    // Note: Since subPDUs are just views, they should not be passed by value to the logging backend.
    fmt::memory_buffer fmtbuf;
    fmt::format_to(std::back_inserter(fmtbuf), "{}", ctx.decoded_subpdus);
    logger.info("{} subPDUs: [{}]", create_prefix(ctx), to_c_str(fmtbuf));
  }
```

這段 MAC 程式在進入 `handle_rx_pdu` 後先保留追蹤時間點，並寫入封包擷取介面，再依上行資料所帶 RNTI 讀取 UE 索引。這些步驟發生在解包前。建立 `decoded_mac_rx_pdu` 時，接收時槽、小區、原始資料與查出的索引被保存在同一份上下文。`unpack` 回傳錯誤時，資訊通道記錄格式將 `create_prefix(ctx)` 及 `ret.error()` 放在兩個不同的替代位置。搜尋時可保留 `Failed to decode MAC UL PDU. Cause:` 這段固定文字，再把實際原因對回解包器的回傳。`return false` 會結束這次呼叫，使後面的子 PDU 格式化及分流都沒有執行。解包成功時仍先檢查資訊通道，才把借用資料所構成的視圖轉成可排入後端的文字。因此查到封包擷取紀錄不等於已成功解包，略過成功資訊訊息也可能只是通道未啟用。 [`lib/mac/mac_ul/pdu_rx_handler.cpp:91–126`](https://github.com/srsran/srsRAN_Project/blob/d2f4b70dda8e2c557d5b05a0ac5f92dbddda19bc/lib/mac/mac_ul/pdu_rx_handler.cpp#L91-L126)

另一種查法是先問「分支已完成了什麼」。`Dropping UL NAS transport. UE AMF ID not found` 出現在 NGAP 訊息已建立且放入 RAN 端識別碼之後。此時讀到的 AMF 端識別碼仍為無效值，函式回傳，未填寫該欄位或安排排程。如果日誌改成 AMF 通知器未設定，應翻到較後面的非同步傳送分支，因為訊息組合已經通過。比對前者時，先從 `msg.ue_index` 找該筆 UE 上下文何時取得 AMF 端識別碼。比對後者時，先檢查是哪個傳送通知介面回報失敗。這兩個原因對使用者而言都可能表現成尚未送達，但處理的第一步要由該字串所屬分支決定。 [`lib/ngap/ngap_impl.cpp:210–238`](https://github.com/srsran/srsRAN_Project/blob/d2f4b70dda8e2c557d5b05a0ac5f92dbddda19bc/lib/ngap/ngap_impl.cpp#L210-L238)

MAC 的程序背景可參照 TS 38.321 §5.1，解包後的欄位及組織則可回看 MAC PDU 格式。協定的程序與欄位提供閱讀方向。日誌等級、前綴、錯誤返回時機與動作排程需回到此版 C++。排查時也要留意兩種識別碼可能在不同階段生效，先核對字串中的欄位名稱，可以避免用 AMF 端識別碼到只接受 RAN 端索引的資料表搜尋。 [3GPP TS 38.321 V18.5.0 §5.1](https://www.etsi.org/deliver/etsi_ts/138300_138399/138321/18.05.00_60/ts_138321v180500p.pdf) [`lib/ngap/ngap_impl.cpp:214–234`](https://github.com/srsran/srsRAN_Project/blob/d2f4b70dda8e2c557d5b05a0ac5f92dbddda19bc/lib/ngap/ngap_impl.cpp#L214-L234)
