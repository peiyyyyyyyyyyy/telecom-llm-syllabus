```bash
main() {
    # Check number of args
    if [ $# -lt 1 ] || [ $# -gt 3 ]; then
        echo >&2 "Illegal number of parameters"
        echo >&2 "Run like this: \"./build_dpdk.sh <dpdk_version> [<arch> [<ncores>]]\" where arch is any gcc/clang compatible -march and ncores could be any number or empty for all"
        exit 1
    fi

    local dpdk_version=$1
    local arch="${2:-native}"
    local ncores="${3:-$(nproc)}"

    cd /tmp
    curl -L "https://fast.dpdk.org/rel/dpdk-${dpdk_version}.tar.xz" | tar xJf -
    cd dpdk*"${dpdk_version}"
    meson setup build --prefix "/opt/dpdk/${dpdk_version}" -Dcpu_instruction_set="${arch}"
    meson compile -j "${ncores}" -C build
    meson install -C build
}

main "$@"
```

先看最後一行，腳本用加引號的 `"$@"` 呼叫 `main`，各個位置參數仍維持原本的界線。進入函式後，第 26 行用 `$#` 比較參數總數，示範如何把不足與過多合在同一個條件。非法數量的分支以 `>&2` 將診斷與用法寫到標準錯誤，並以狀態 1 停止。接下來三個 `local` 為這次呼叫建立變數。第一項直接取得版本，第二項為空或未設定時用 `native`，第三項則只在需要預設值時呼叫 `nproc`。讀到 `:-` 時要同時考慮空字串與不存在這兩種輸入。

下載行以版本拼出來源網址，將資料交給解壓縮程序。下一行切換到解出的目錄，`meson setup` 設定安裝路徑與 CPU 指令集，`meson compile` 讀取平行工作數，最後的 `meson install` 才進入安裝。追查失敗時，應把腳本的階段和記錄中的命令對起來，因為下載失敗、解壓縮失敗與後續編譯錯誤屬於不同步驟。腳本在第 22 行設了 `set -e`。若希望分析一條管線如何回報，也要確認該檔案有沒有另外啟用 `pipefail`。 [Bash Reference Manual，Shell Parameters、Pipelines 與 The Set Builtin](https://www.gnu.org/software/bash/manual/bash.html)

此容器入口把 Telegraf 放到背景，緊接著用 `$!` 保存背景程序的識別碼，接著註冊結束訊號的處理函式。處理函式先進行健康檢查，立即以 `$?` 保存該命令的狀態，記錄檢查結果後通知背景程序停止。主流程以 `wait "$child"` 等待，最後返回保存的 `health_code`。預設值是 0，只有進到訊號處理函式才更新。閱讀這段時須把背景程序本身的退出狀態、健康檢查狀態，以及入口腳本最後交給容器的狀態分開。

這兩個例子的 Bash 語法、Meson 建置步驟與容器程序生命週期屬於實作和部署方式。即使產出的基地台會執行 3GPP 的協定程序，腳本的位置參數與重試策略也應以同一版原始碼及工具文件為準。4.2.5 進一步討論建置選項與 gNB 啟動，4.3.2 會從入口腳本呼叫的 Python 助手往下追，4.4.3 則可把本節的結束碼與各階段錯誤訊息接起來。
