## 練習題

**1.** According to the O‑RAN specification, how are M‑Plane data models organized?

- A. As a set of proprietary binary files
- B. As a collection of reusable YANG modules
- C. As free‑form text documents
- D. As a single monolithic XML schema

<details><summary>看答案</summary>

正解：B。The specification explicitly states that M‑Plane data models are organized as reusable YANG modules.

</details>

**2.** What is the intent of the O‑RAN specification regarding the use of YANG models?

- A. To develop only O‑RAN‑specific custom modules
- B. To reuse publicly available and generic YANG models whenever possible
- C. To replace YANG with proprietary formats
- D. To limit the number of modules to a maximum of three

<details><summary>看答案</summary>

正解：B。The specification encourages reuse of generic models instead of creating custom ones.

</details>

**3.** In the worked example, what reuse ratio is obtained when three out of four YANG modules are generic?

- A. 0.25
- B. 0.50
- C. 0.75
- D. 1.00

<details><summary>看答案</summary>

正解：C。The reuse ratio is calculated as generic modules divided by total modules: 3/4 = 0.75.

</details>

**4.** Which of the following actions best follows the specification’s guidance on module creation?

- A. Copying definitions from a generic module into a new custom module
- B. Importing the generic module directly into the O‑RAN node configuration
- C. Ignoring generic modules and writing all definitions from scratch
- D. Using only XML files without YANG

<details><summary>看答案</summary>

正解：B。Importing preserves reusability, aligning with the specification’s intent to reuse generic models.

</details>

**5.** Where can engineers find detailed information about each YANG module referenced in O‑RAN?

- A. In the O‑RAN hardware manual
- B. In clause D and the repository of YANG models
- C. In the source code of the network element
- D. In the user interface of the O‑RAN GUI

<details><summary>看答案</summary>

正解：B。The specification directs readers to clause D and the YANG model repository for details.

</details>
