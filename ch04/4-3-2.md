```python
def validate_yaml(filepath: str, schema: dict):
    """
    Validate a yaml file against a json schema
    """
    with open(filepath, "r", encoding="UTF-8") as file:
        data = yaml.safe_load(file)
    try:
        validate(instance=data, schema=schema)
        print(f"The config file {filepath} is valid.")
    except ValidationError as e:
        print(f"The config file {filepath} is NOT valid:")
        print(e.message)
        exit(1)


def main():
    current_directory = Path(__file__).parent
    yaml_files = get_yml_file_list(current_directory.absolute())

    schema_filepath = current_directory.joinpath("test_declaration_schema.json").absolute()
    with open(schema_filepath, "r", encoding="UTF-8") as schema_file:
        schema = json.load(schema_file)

    for yaml_file in yaml_files:
        validate_yaml(str(yaml_file), schema)
```

再看 `main`。程式用腳本所在目錄找候選檔案及 `test_declaration_schema.json`。前面的尋檔助手只挑符合 `test_declaration*.yml` 的路徑，並未遞迴搜尋子目錄。第 56 至 57 行讀入 JSON schema，後續迴圈對每個 YAML 檔重複使用同一份規則。這裡呼叫的是 Python 套件函式，沒有用子程序跑外部驗證器。對照 Docker 入口腳本時可以看到另一種邊界。入口以 `python3` 啟動助手，並根據其結束碼決定是否繼續。 [入口腳本的助手呼叫與狀態檢查](https://github.com/srsran/srsRAN_Project/blob/d2f4b70dda8e2c557d5b05a0ac5f92dbddda19bc/docker/open5gs/open5gs_entrypoint.sh#L35-L50)

此節所示結束碼、JSON Schema 與 Python 回呼都是專案工具的契約。對應到無線設定時才查其規格，例如以 3GPP TS 38.104 V18.5.0 §5.2 及 §5.3 核對工作頻段與通道頻寬的語意。測試宣告的型別規則應查看本版本的 schema。常見錯誤包括以為一切錯誤都會落到同一個例外處理、將測試檔名規則當成一般 gNB YAML 入口，或把某個工具的輸出當成已啟動服務的證據。 [3GPP TS 38.104 V18.5.0](https://www.etsi.org/deliver/etsi_ts/138100_138199/138104/18.05.00_60/ts_138104v180500p.pdf)

def _convert_extra_config_into_command(extra_config: dict) -> str:
    """
    Convert extra config into command
    """
    cmd_args = ""
    for key, value in sorted(extra_config.items(), key=lambda item: isinstance(item[1], dict)):
        if isinstance(value, dict):

        elif value is None:

        else:

    return cmd_args
