# 4.4.3 常見錯誤訊息

所屬：[4.4 日誌與錯誤訊息](../4-4.md)

## 正文

In a 5G Core‑NG interface, a node may receive a signalling message that is syntactically correct but contains information that cannot be processed (e.g., mismatched identifiers). Because such conditions cannot be expressed by the normal NGAP failure messages, the **Error Indication** procedure is used to report the problem to the peer node. This mechanism is essential for maintaining robust inter‑node coordination and for enabling operators to trace the root cause of failures from log files [TS 38.413 §8.7.5.1].

### Required Information Elements

An **ERROR INDICATION** message must contain at least one of the following Information Elements (IEs): the *Cause* IE or the *Criticality Diagnostics* IE [TS 38.413 §8.7.5.2]. When the error relates to **UE‑associated signalling**, the message must also carry the *AMF UE NGAP ID* IE and the *RAN UE NGAP ID* IE. These identifiers allow the receiving node to map the error back to the correct UE context [TS 38.413 §8.7.5.2].

If either the *AMF UE NGAP ID* or *RAN UE NGAP ID* is incorrect, the *Cause* IE shall be set to an appropriate value, for example **“Unknown local UE NGAP ID”** or **“Inconsistent remote UE NGAP ID”** [TS 38.413 §8.7.5.2].

### Typical Cause Values

The *Cause* IE enumerates the reason for the error. Although the full enumeration is extensive, the most frequently observed values in operational networks include:

| Cause value | Typical situation |
|-------------|-------------------|
| **Unknown local UE NGAP ID** | The receiving node cannot find the UE context identified by the *AMF UE NGAP ID*. |
| **Inconsistent remote UE NGAP ID** | The *RAN UE NGAP ID* does not match the one stored for the UE at the peer node. |
| **Unknown target ID** | A handover target cell identifier is not recognised. |
| **Cell not available** | The target cell is not reachable (e.g., out of service). |
| **No radio resources available in target cell** | The target cell has no free radio resources for the UE. |

These values are defined within the *Cause* IE and are used by network management systems to correlate log entries with specific failure modes [TS 38.413 §9.3.1.2].

### Worked Example

Consider a scenario where an NG‑RAN node receives an NGAP **Uplink NAS Transport** message that contains a *RAN UE NGAP ID* = **0x1234**. The node’s UE context table, however, stores **0x5678** for the same UE. The NG‑RAN node therefore cannot map the message to an existing UE and must trigger an Error Indication.

1. **Determine the signalling type** – the message is UE‑associated, so the Error Indication will use UE‑associated signalling.  
2. **Populate mandatory IEs** – include the *AMF UE NGAP ID* (as received) and the *RAN UE NGAP ID* (the erroneous **0x1234**).  
3. **Select the appropriate Cause** – because the *RAN UE NGAP ID* does not match the stored value, the cause is set to **“Inconsistent remote UE NGAP ID”** (per the example in the specification).  
4. **Construct the ERROR INDICATION** – the message now contains the two UE identifiers and the *Cause* IE.  
5. **Send the message** – the NG‑RAN node transmits the ERROR INDICATION to the AMF, which logs the event and may trigger corrective actions (e.g., UE context re‑establishment).

The key steps above illustrate how the mandatory IEs and the *Cause* value interact to provide a clear, actionable error report [TS 38.413 §8.7.5.2].

### Practical Tips & Common Mistakes

| Mistake | Why it matters | Remedy |
|---------|----------------|--------|
| **Omitting the *Cause* IE** when the message already contains *Criticality Diagnostics* only. | The specification requires **at least** one of the two IEs; missing both makes the message non‑compliant. | Verify that either *Cause* or *Criticality Diagnostics* is present before transmission. |
| **Using non‑UE‑associated signalling for a UE‑specific error**. | The peer node will be unable to map the error to a UE, leading to ambiguous logs. | Follow the rule: if the original message used UE‑associated signalling, the Error Indication must also use UE‑associated signalling. |
| **Setting an incorrect cause value** (e.g., “Cell not available” for an ID mismatch). | Misleading diagnostics hinder root‑cause analysis and may trigger unnecessary recovery procedures. | Choose the cause value that directly reflects the nature of the mismatch, as illustrated in the specification examples. |
| **Leaving out the UE identifiers when required**. | The receiving node cannot associate the error with a UE context, causing the error to be discarded. | Always include *AMF UE NGAP ID* and *RAN UE NGAP ID* for UE‑associated error indications. |

By consistently applying the IE requirements and selecting the correct *Cause* values, engineers can ensure that error logs are both standards‑compliant and useful for troubleshooting complex NG‑RAN/AMF interactions.

## 練習題

**1.** Who initiates the Error Indication procedure according to the specification?

- A. The UE
- B. The AMF only
- C. The NG‑RAN node only
- D. A node

<details><summary>看答案</summary>

正解：D。The procedure is started by any node that detects an error that cannot be reported by a failure message.

</details>

**2.** What must an ERROR INDICATION message contain at minimum?

- A. Both the *Cause* IE and the *Criticality Diagnostics* IE
- B. At least either the *Cause* IE or the *Criticality Diagnostics* IE
- C. Only the *AMF UE NGAP ID* IE
- D. Only the *RAN UE NGAP ID* IE

<details><summary>看答案</summary>

正解：B。The specification requires at least one of the two IEs to be present.

</details>

**3.** When one or both of the *AMF UE NGAP ID* IE and the *RAN UE NGAP ID* IE are not correct, what action should be taken?

- A. The message should be discarded silently.
- B. The cause shall be set to an appropriate value.
- C. The IDs must be omitted from the message.
- D. The procedure must be aborted.

<details><summary>看答案</summary>

正解：B。The specification directs that an appropriate cause value be assigned to indicate the ID problem.

</details>

**4.** Which of the following is listed as a possible Radio Network Layer cause in the *Cause* IE?

- A. Successful handover
- B. Unknown local UE NGAP ID
- C. Time critical handover
- D. Resource optimisation handover

<details><summary>看答案</summary>

正解：B。The *Cause* IE enumerates "Unknown local UE NGAP ID" as one of the Radio Network Layer causes.

</details>
