# 4.1.1 函式的用途、參數、回傳值（第 1／2 頁）

所屬：[4.1 讀懂程式](4-1.md)

## 內文

閱讀基地台程式時，先把函式視為呼叫端與實作之間的約定。呼叫端提供符合前提的輸入，函式依規則計算或轉換資料，再以回傳值、輸出參數或可觀察的狀態變化把結果交回去。追查設定未生效、排程結果與預期不符，或替某項行為補單元測試時，應先讀函式簽名和相關型別，再追到關鍵分支與第一個使用回傳結果的呼叫端。如此才能知道手上的數字是查表索引、實際資源數量，還是等待解碼的欄位。

```cpp
std::optional<srs_configuration> srsran::srs_configuration_get(uint8_t c_srs, uint8_t b_srs)
{
  span<const srs_configuration> table;

  switch (b_srs) {
    case 0:
      table = table0;
      break;
    case 1:
      table = table1;
      break;
    case 2:
      table = table2;
      break;
    case 3:
      table = table3;
      break;
  }
  if (c_srs < table.size()) {
    return table[c_srs];
  }

  return std::nullopt;
}
```

第一行宣告兩個無號整數輸入及可缺值的回傳型別。下一行建立只讀檢視，讓不同表共用同一段選列邏輯。`switch` 根據 `b_srs` 把檢視指向其中一張表，每一支的 `break` 都結束選表。接著 `if` 把 `c_srs` 當作從零開始的索引，只有小於表長度才會存取。索引剛好等於長度時會走到 `std::nullopt`。找不到符合的 `b_srs` 時也沒有選到表，空的檢視使索引檢查失敗。成功案例可從表一的開頭核對。假設 `b_srs = 1`、`c_srs = 2`，程式取得第三項 `{4, 3}`，對應 4 個實體資源區塊和 3 個跳頻位置。追到 `get_srs_information` 可看到呼叫端在讀取 `m_srs` 前先以斷言檢查結果，再依梳狀配置計算序列長度。查表回空與呼叫端如何處置空值是兩層行為，查錯時要各自定位。 [頻寬表一第 38～44 行](https://github.com/srsran/srsRAN_Project/blob/d2f4b70dda8e2c557d5b05a0ac5f92dbddda19bc/lib/ran/srs/srs_bandwidth_configuration.cpp#L38-L44)

[`include/srsran/ran/resource_allocation/sliv.h` 第 33～39 行](https://github.com/srsran/srsRAN_Project/blob/d2f4b70dda8e2c557d5b05a0ac5f92dbddda19bc/include/srsran/ran/resource_allocation/sliv.h#L33-L39)

```cpp
constexpr unsigned sliv_from_s_and_l(unsigned N, unsigned S, unsigned L)
{
  if ((L - 1) <= N / 2) {
    return N * (L - 1) + S;
  }
  return N * (N - L + 1) + (N - 1 - S);
}
```

簽名中的 `N` 是編碼使用的最大長度，`S` 是起點，`L` 是區間長度。函式開頭的條件比較 `L - 1` 和整數除法得到的 `N / 2`，等於邊界時仍使用第一式。以正常循環字首的 PDSCH 呼叫情境為例，假設 `N = 14`、`S = 2`、`L = 5`，結果為 `14 × (5 - 1) + 2 = 58`。呼叫端把它存入 `start_symbol_and_len`。反向函式以餘數與商恢復兩個輸出，測試可以檢查同一配置經編碼、解碼後能否恢復為起點 2 和長度 5。

SRS 頻寬欄位對照 TS 38.211 第 6.4.1.4.3 節與表 6.4.1.4.3-1。正常循環字首的 PDSCH 時域配置可對照 TS 38.214 第 5.1.2.1 節。標準定義參數及表示方式，C++ 使用可缺值型別、參考參數和檢視則是此版本原始碼的介面選擇。 [TS 38.211 V18.5.0](https://www.etsi.org/deliver/etsi_ts/138200_138299/138211/18.05.00_60/ts_138211v180500p.pdf) · [TS 38.214 V18.5.0](https://www.etsi.org/deliver/etsi_ts/138200_138299/138214/18.05.00_60/ts_138214v180500p.pdf)

常見錯誤包括把表索引當作以實體資源區塊表示的頻寬，把編碼整數當作開始符元，或只因參數型別是 `unsigned` 就認為所有非負輸入都符合規則。編碼函式本身沒有檢查長度是否為正，讀者要沿著呼叫位置追查有效區間的來源。遇到 `void` 也要檢查參考參數是否會被寫入，以免遺漏真正的輸出。

接著可用 4.1.2 理解查表結果與檢視各自承載哪些資料，用 4.1.3 追查上游設定及下游消費者。想更深入理解可缺值回傳和型別限制的寫法，可結合 4.1.4 閱讀。追到排程場景時，再用 4.2.6 把符元區間與資源格中的配置關係接起來。
