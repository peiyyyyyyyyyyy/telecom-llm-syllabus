# 4.2.4 程式對應的規格程序

所屬：[4.2 基地台軟體](../4-2.md)

## 正文

In a 5G‑NR base‑station the software that implements the RLC, MAC and HARQ layers is written as a sequence of functions that must follow the procedures defined in 3GPP TS 38.322 (RLC) and TS 38.321 (MAC).  Understanding which line of code corresponds to which specification step is essential for debugging, performance tuning and for ensuring conformance when the source is compiled for different hardware platforms.  

### Key Definitions

| Symbol | Meaning | Unit / Range |
|--------|---------|--------------|
| **TM** | Transparent Mode – RLC passes SDUs unchanged | – |
| **UM** | Unacknowledged Mode – segmentation/reassembly without retransmission | – |
| **AM** | Acknowledged Mode – segmentation with ARQ | – |
| **SN** | Sequence Number (modulo $2^{12}$ for UM, $2^{10}$ for AM) | – |
| **TX\_Next** | Next SN to assign for a newly created AMD/UMD PDU | – |
| **TX\_Next\_Ack** | Lower edge of the AM transmitting window | – |
| **RX\_Next\_Highest** | Highest SN received (inclusive) in UM | – |
| **RX\_Next\_Reassembly** | SN of the next UM SDU expected to be reassembled | – |
| **UM\_Window\_Size** | Size of the UM reassembly window (default 512) | – |
| **t‑Reassembly** | Timer that expires when a missing segment is not received | s |
| **HARQ entity** | MAC sub‑layer that stores PDUs for retransmission | – |
| **NDI** | New Data Indicator in HARQ feedback | – |
| **Grant** | UL resource allocation received on PDCCH or via RAR | – |

### Procedure Mapping

### Transparent Mode (TM)

*Transmit* – When the code calls `rlc_tm_submit_sdu(sdu)`, the implementation must **submit an RLC SDU without any modification to lower layer** [TS 38.322 §5.2.1.1].  

*Receive* – The function `rlc_tm_receive_pdu(pdu)` must **deliver the TMD PDU without any modification to upper layer** [TS 38.322 §5.2.1.2.1].  

### Unacknowledged Mode (UM)

*Transmit* – Before sending a UMD PDU the code must:  

1. **Set the SN to `TX_Next` if the PDU contains a segment of an SDU** [TS 38.322 §5.2.2.1.1].  
2. **Increment `TX_Next` by one if the segment maps to the last byte of the SDU** [TS 38.322 §5.2.2.1.1].  

*Receive* – The reception routine follows a three‑step decision tree (see Fig. 1 in the reference):  

1. **If the header lacks an SN, remove the RLC header and deliver the SDU** [TS 38.322 §5.2.2.2.2].  
2. **If the SN lies in the discard range**  
   $$ (RX\_Next\_Highest - \text{UM\_Window\_Size}) \le \text{SN} < RX\_Next\_Reassembly $$  
   the PDU is discarded. The range definition is taken from the standard **“a SN falls within the reassembly window if …”** [TS 38.322 §5.2.2.2.1].  
3. **Otherwise place the PDU in the reception buffer** and trigger the reassembly actions described in §5.2.2.2.3.  

When a PDU is placed in the buffer, the code must check whether **all byte segments with that SN have been received**; if so, it reassembles the SDU, strips the header and delivers it [TS 38.322 §5.2.2.2.3].  

If **t‑Reassembly expires**, the routine must **update `RX_Next_Reassembly` to the first SN ≥ `RX_Timer_Trigger` that has not been reassembled** and discard all older segments [TS 38.322 §5.2.2.2.4].  

### Acknowledged Mode (AM)

*Transmit priority* – The AM transmit function must first **prioritize RLC control PDUs over AMD PDUs**, and among AMD PDUs **prioritize those containing previously transmitted SDUs** [TS 38.322 §5.2.3.1.1].  

*Window management* – The code must enforce the transmitting window:  

$$ TX\_Next\_Ack \le \text{SN} < TX\_Next\_Ack + \text{AM\_Window\_Size} $$  

If a candidate SN falls outside, **the PDU must not be submitted to lower layer** [TS 38.322 §5.2.3.1.1].  

*SN assignment* – For each SDU received from the upper layer, the implementation **associates a SN equal to `TX_Next`, constructs an AMD PDU with that SN, and increments `TX\_Next`** [TS 38.322 §5.2.3.1.1].  

### UL Grant Reception (MAC)

When the MAC layer processes a PDCCH occasion, the code path that handles a newly received uplink grant must **deliver the grant and the associated HARQ information to the HARQ entity** [TS 38.321 §5.4.1].  This step is common for both dynamic and configured grants and is the point where the higher‑layer scheduler hands the resource to the lower‑layer HARQ logic.  

### Worked Example – UM Reassembly

Assume the following UM parameters:  

- `UM_Window_Size = 512`  
- Current `RX_Next_Highest = 3000` (mod $2^{12}$)  

A PDU arrives with SN = 2600 and a valid header.  

1. Compute the lower bound of the window:  

$$ 3000 - 512 = 2488 $$  

2. Since $2488 \le 2600 < 3000$, the SN is **inside** the reassembly window.  

3. The code places the PDU in the reception buffer.  

Later, the segment with SN = 2600 arrives complete, so the routine reassembles the SDU, strips the header and delivers it upward.  

If instead a PDU with SN = 2400 arrived, the condition $2400 < 2488$ would be false, placing the SN **outside** the window; the implementation must **update `RX_Next_Highest` to 2401**, discard out‑of‑window PDUs, and possibly restart `t‑Reassembly` according to §5.2.2.2.3.  

### Common Mistakes and Practical Notes

| Symptom | Typical Cause | Fix |
|---------|---------------|-----|
| UM PDU delivered without header removal | Missed check for “header does not contain SN” | Ensure code follows the first branch of §5.2.2.2.2 |
| AM PDU transmitted with SN outside window | Window limits not updated after ACKs | Update `TX_Next_Ack` on every STATUS PDU reception |
| t‑Reassembly never started | Incorrect calculation of `RX_Timer_Trigger` | Set `RX_Timer_Trigger` to `RX_Next_Highest` when starting the timer (see §5.2.2.2.3) |
| UL grant ignored by MAC | Forgetting to call the HARQ delivery function | Invoke the “deliver the uplink grant and the associated HARQ information to the HARQ entity” step for every received grant |
| Duplicate SDU delivery in TM | Copy‑on‑write of the SDU buffer before passing down | In TM transmit, **submit the SDU without any modification** – do not clone or alter it |

When reading open‑source base‑station code (e.g., the `rlc.c` and `mac.c` modules), locate the functions that implement the above bullets and verify they match the quoted specification steps.  Automated unit tests can be built around the exact conditions (window limits, timer expiry) to guarantee conformance across compiler versions.

## 練習題

**1.** In Transparent Mode, what must the transmitting RLC entity do with an SDU before sending it to the lower layer?

- A. Add an RLC header with a new SN
- B. Fragment the SDU into multiple PDUs
- C. Submit the SDU without any modification
- D. Encrypt the SDU payload

<details><summary>看答案</summary>

正解：C。TM transmits SDUs unchanged, as required by the specification.

</details>

**2.** Which condition determines that a received UM SN is inside the reassembly window?

- A. $(RX\_Next\_Highest - UM\_Window\_Size) \le \text{SN} < RX\_Next\_Highest$
- B. $\text{SN} = RX\_Next\_Reassembly$
- C. $\text{SN} > RX\_Next\_Highest$
- D. $\text{SN} < (RX\_Next\_Highest - UM\_Window\_Size)$

<details><summary>看答案</summary>

正解：A。The standard defines the reassembly window with that inequality.

</details>

**3.** When a UM PDU header does **not** contain an SN, the receiving entity must:

- A. Discard the PDU
- B. Place it in the reception buffer
- C. Remove the RLC header and deliver the SDU to the upper layer
- D. Trigger a status report to the transmitter

<details><summary>看答案</summary>

正解：C。Absence of SN leads to immediate delivery after header removal.

</details>

**4.** In AM, what must the transmitter do if an AMD PDU’s SN is outside the transmitting window?

- A. Send it anyway but set a flag
- B. Buffer it for later transmission
- C. Not submit it to the lower layer
- D. Change its SN to the next valid value

<details><summary>看答案</summary>

正解：C。The spec forbids sending PDUs with SNs outside the window.

</details>

**5.** After a UL grant is received on the PDCCH, what is the immediate action required by the MAC entity?

- A. Store the grant for future use only
- B. Forward the grant to the PDCP layer
- C. Deliver the grant and the associated HARQ information to the HARQ entity
- D. Ignore the grant if NDI = 0

<details><summary>看答案</summary>

正解：C。The MAC must pass the grant to HARQ for transmission.

</details>
