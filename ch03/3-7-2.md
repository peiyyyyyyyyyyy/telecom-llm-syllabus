# 3.7.2 信源編碼：霍夫曼、算術編碼

所屬：[3.7 資訊理論與編碼](3-7.md)

## 內文

#### 為什麼要學

信源編碼（source coding）的工作是把資料裡的冗餘拿掉，用比較少的位元表示同樣的內容。行動網路的空中介面資源昂貴，語音、影像編碼器，以及封包標頭壓縮，都要先把要送的位元數壓下來，再交給通道編碼加上保護用的冗餘。霍夫曼編碼（Huffman coding）與算術編碼（arithmetic coding）是兩種最基本的無失真熵編碼方法，許多影音壓縮標準的最後一級都採用這類技術。學這一節的目的，是能由符號機率算出平均碼長，並和熵比較，判斷一個編碼離理論極限還有多遠。

#### 定義與符號

| 符號 | 意思 | 單位 |
|---|---|---|
| $p_i$ | 第 $i$ 個符號出現的機率 | 無 |
| $l_i$ | 第 $i$ 個符號的碼字長度 | bit |
| $\bar{L}$ | 平均碼長，$\sum p_i l_i$ | bit／符號 |
| $H$ | 信源的熵 | bit／符號 |
| $\eta$ | 編碼效率，$H/\bar{L}$ | 無（或 %） |
| $[\text{low},\ \text{high})$ | 算術編碼目前的區間 | 無 |

#### 公式與推導

**前綴條件與 Kraft 不等式。** 可變長度碼要能不加分隔符號就唯一解出來，最常用的做法是讓任何一個碼字都不是另一個碼字的開頭，稱為前綴碼（prefix code）。二元前綴碼的碼長必須滿足 Kraft 不等式：

$$\sum_i 2^{-l_i}\le 1$$

反過來，只要一組碼長滿足這個不等式，就一定找得到對應的前綴碼。

**平均碼長的界限。** 對無記憶信源逐符號編碼時，任何唯一可解的碼都有 $\bar{L}\ge H$；而最佳前綴碼滿足

$$H\le \bar{L} < H+1$$

編碼效率定義為 $\eta = H/\bar{L}$，最大為 1。只有當每個機率都是 2 的負整數次方時，逐符號編碼才能做到 $\eta=1$。

**霍夫曼編碼。** 做法是：把機率最小的兩個符號合併成一個新節點，機率相加；重複這個動作直到只剩一個節點；再由根往下，每個分支標上 0 或 1，葉節點的路徑就是碼字。在「符號機率已知、逐符號、整數碼長」的條件下，霍夫曼碼的平均碼長最短。合併時若有機率相同的節點，選法不同會得到不同的樹，但平均碼長相同。

**算術編碼。** 算術編碼不替單一符號指定碼字，而是把整段訊息對應到 $[0,1)$ 裡的一個小區間。先依累積機率把 $[0,1)$ 切成每個符號的子區間；每讀進一個符號，就把目前區間依同樣比例再切一次，留下該符號對應的那一段：

$$\text{low}' = \text{low} + (\text{high}-\text{low})\,F_{\text{low}}(s),\qquad \text{high}' = \text{low} + (\text{high}-\text{low})\,F_{\text{high}}(s)$$

其中 $F_{\text{low}}(s)$、$F_{\text{high}}(s)$ 是符號 $s$ 的累積機率下界與上界。最後區間的寬度等於整段訊息的機率 $P$，輸出一個落在區間內的二進位小數即可；所需位元數不超過 $\lceil \log_2(1/P)\rceil + 1$。因為不必把每個符號的碼長取成整數，訊息夠長時每符號的平均位元數可以逼近熵。

#### 算例

**算例 1（霍夫曼編碼）** 已知五個符號的機率：A 0.35、B 0.25、C 0.20、D 0.12、E 0.08。

建樹：
1. 最小的兩個是 D（0.12）與 E（0.08），合併為 DE（0.20）。
2. 剩下 0.35、0.25、0.20、0.20，最小的兩個是 C 與 DE，合併為 CDE（0.40）。
3. 剩下 0.40、0.35、0.25，最小的兩個是 A 與 B，合併為 AB（0.60）。
4. AB（0.60）與 CDE（0.40）合併為根（1.00）。

指定位元（上分支 0、下分支 1）：AB 為 0、CDE 為 1；A＝00、B＝01；C＝10、DE＝11；D＝110、E＝111。

| 符號 | 機率 | 碼字 | 碼長 |
|---|---|---|---|
| A | 0.35 | 00 | 2 |
| B | 0.25 | 01 | 2 |
| C | 0.20 | 10 | 2 |
| D | 0.12 | 110 | 3 |
| E | 0.08 | 111 | 3 |

平均碼長：$\bar{L} = 2\times(0.35+0.25+0.20)+3\times(0.12+0.08) = 1.60+0.60 = 2.20$ bit／符號。

熵：$H = 0.5301+0.5000+0.4644+0.3671+0.2915 = 2.1531$ bit／符號。

效率：$\eta = 2.1531/2.20 = 0.9787$，約 97.9%。

檢查：沒有任何碼字是另一個碼字的開頭（00、01、10 都不是 110、111 的開頭），滿足前綴條件；Kraft 和為 $3\times 2^{-2}+2\times 2^{-3}=1$。$H\le\bar{L}<H+1$ 也成立。若用固定長度碼，五個符號需要 3 bit，霍夫曼碼省了約 27%。

**算例 2（算術編碼的區間）** 已知三個符號 A、B、C 的機率為 0.5、0.3、0.2，子區間依序為 A：$[0,\,0.5)$、B：$[0.5,\,0.8)$、C：$[0.8,\,1)$。對序列「B A C」編碼。

1. 讀 B：區間變成 $[0.5,\ 0.8)$，寬度 0.3。
2. 讀 A：取目前區間的前 50%，$[0.5,\ 0.5+0.3\times 0.5) = [0.5,\ 0.65)$，寬度 0.15。
3. 讀 C：取目前區間的 80%～100%，$[0.5+0.15\times 0.8,\ 0.65) = [0.62,\ 0.65)$，寬度 0.03。

檢查：最後寬度 $0.03 = 0.3\times 0.5\times 0.2$，正是這段訊息的機率。$\log_2(1/0.03)=5.06$，所以最多 $\lceil 5.06\rceil+1 = 7$ bit 就能表示這段訊息。二進位小數 $0.101_2 = 0.625$ 落在 $[0.62,\ 0.65)$ 內，是區間裡的一個點；解碼端依同樣的切法，由這個數值所在的子區間依序判出 B、A、C（解碼端還需要知道訊息長度或結束符號）。

#### 常見錯誤

- 把平均碼長算成碼長的算術平均（本例 $(2+2+2+3+3)/5=2.4$），沒有用機率加權。
- 霍夫曼建樹時沒有每次都重新排序，把剛合併出來的節點固定放在最後，結果合併到的不是最小的兩個。
- 效率寫成 $\bar{L}/H$，得到大於 1 的數字。效率是 $H/\bar{L}$，不會超過 1。
- 算術編碼更新區間時，用原始的 $[0,1)$ 比例直接取，而沒有乘上目前區間的寬度。

#### 和其他小節的關係

平均碼長的下限來自 3.7.1 的熵。信源編碼去掉冗餘之後，3.7.3 到 3.7.6 的通道編碼再加上有結構的冗餘來對抗錯誤，兩者的方向相反。壓縮後的位元率是 3.4 訊務量估算的輸入之一。
