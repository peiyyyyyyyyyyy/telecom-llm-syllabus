# 3.2.2 頻譜效率

所屬：[3.2 容量](3-2.md)

## 內文

#### 為什麼要學

頻譜是電信業者花大錢標來的資源，頻譜效率（spectral efficiency）就是衡量「每 1 Hz 頻寬每秒送出多少位元」的指標，單位 bit/s/Hz。它用在三個層次：比較不同調變與編碼的鏈路效率、比較不同世代或不同天線組態的小區效率、以及做容量規劃時把「頻寬 × 效率」換成每個小區與每平方公里能提供的吞吐量。看懂頻譜效率，才能判讀設備商宣稱的峰值數字與現網平均值為什麼差很多，也才能估算一個站台大約能服務多少使用者。

#### 定義與符號

| 符號 | 意思 | 單位 |
|---|---|---|
| $\eta$ | 鏈路頻譜效率，$\eta = R/B$ | bit/s/Hz |
| $R$ | 資訊速率（淨速率，扣掉編碼冗餘） | bit/s |
| $B$ | 占用頻寬 | Hz |
| $\eta_{\text{cell}}$ | 小區平均頻譜效率（一個小區內所有使用者吞吐量總和除以頻寬） | bit/s/Hz/cell |
| $T_{\text{cell}}$ | 小區吞吐量 | bit/s |
| $\alpha_{\text{DL}}$ | 分時雙工（TDD）中下行占用的時間比例 | 無單位（0～1） |
| $A$ | 一個站台的涵蓋面積 | km² |
| $\eta_{\text{area}}$ | 面積頻譜效率 | bit/s/Hz/km² |

#### 公式與推導

**鏈路頻譜效率**是速率除以頻寬：

$$\eta = \frac{R}{B}\quad[\text{bit/s/Hz}]$$

由 3.2.1，在 AWGN 通道、單一天線的條件下，它的上限是 $\eta \le \log_2(1+\text{SNR})$。反過來，要達到頻譜效率 $\eta$，SNR 至少要 $2^{\eta}-1$。實際的調變編碼組合，頻譜效率約為「每符號位元數 × 碼率」（見 3.2.4）；使用多層空間多工時再乘上層數（見 3.2.6），所以多天線系統的頻譜效率可以超過單天線的 Shannon 上限。

計算時要分清楚**毛值與淨值**：調變符號承載的是編碼後的位元，要乘上碼率才是資訊位元；再扣掉循環字首、參考訊號、控制通道與保護頻帶的開銷，才是使用者真正拿到的效率。

**系統（小區）頻譜效率**不看單一鏈路，而是把一個小區內所有使用者的吞吐量加總後除以頻寬。小區內有人在中心、有人在邊緣，所以平均值遠低於峰值。小區吞吐量為

$$T_{\text{cell}} = \eta_{\text{cell}}\times B\times\alpha_{\text{DL}}$$

其中 $\alpha_{\text{DL}}$ 只在 TDD 且 $\eta_{\text{cell}}$ 是以下行實際占用的時頻資源定義時才需要乘；分頻雙工（FDD）的下行載波取 $\alpha_{\text{DL}}=1$。若再除以涵蓋面積，就得到面積容量：

$$\text{面積容量} = \frac{N_{\text{sector}}\times T_{\text{cell}}}{A}\quad[\text{bit/s/km}^2]$$

要提高面積容量只有三條路：加頻寬、提高小區頻譜效率（高階調變、MIMO、干擾抑制）、把站台蓋密一點（縮小 $A$）。

國際電信聯盟對 IMT-2020（5G）訂的最低技術要求裡，峰值頻譜效率的目標是下行 30 bit/s/Hz、上行 15 bit/s/Hz；這是在多層 MIMO、最高階調變的理想條件下的數字，不是現網平均值。

#### 算例

**算例 1（鏈路效率與 Shannon 上限的差距）** TS 38.214 的 PDSCH MCS 表 1 中，最高的一階（索引 28）頻譜效率為 5.5547 bit/s/Hz（單層）。求理論上至少需要的 SNR；若實際在 SNR 20 dB 下使用這一階，它達到 Shannon 上限的幾成？

1. 最小 SNR：$2^{5.5547}-1 = 46.00$，即 $10\log_{10}(46.00) = 16.63$ dB。
2. SNR 20 dB 的上限：$\log_2(1+100) = 6.658$ bit/s/Hz。
3. 比值：$5.5547/6.658 = 0.834$，約 83%。
4. 合理性檢查：16.63 dB 是理論下限，實際接收機因為編碼長度有限、通道估計誤差等因素，需要比它更高的 SNR 才能穩定使用這一階；比值小於 1 也符合「實際效率不會超過上限」。

**算例 2（小區吞吐量與面積容量）** 假設某 TDD 載波頻寬 40 MHz，下行時間比例 0.7，下行小區平均頻譜效率 2.5 bit/s/Hz/cell（假設值）；每個站台 3 個扇區，站間距 500 m，站台涵蓋面積以六邊形近似 $A = \frac{\sqrt{3}}{2}d^2$。

1. 單一小區下行吞吐量：$2.5\times 40\times 0.7 = 70$ Mbps。
2. 一個站台：$3\times 70 = 210$ Mbps。
3. 面積：$A = 0.8660\times 0.5^2 = 0.2165$ km²。
4. 面積容量：$210/0.2165 = 970$ Mbps/km²（取整數）。
5. 若一個小區忙時同時有 35 個使用者在下載並平均分配，每人約 $70/35 = 2$ Mbps。
6. 合理性檢查：單一小區 70 Mbps 遠低於同頻寬的峰值速率，原因是平均效率 2.5 遠低於峰值效率；這正是規劃時要用平均值而不是峰值的理由。

#### 常見錯誤

- 把峰值頻譜效率當成小區平均值來做容量規劃，結果高估好幾倍。
- 忘了分毛值與淨值：把「調變位元數」直接當效率，沒有乘碼率、沒有扣開銷。
- TDD 系統忘了乘下行時間比例，或是重複乘了兩次。
- 單位寫成 bit/Hz 或 Mbps/MHz 時沒有注意兩者數值相同但量級不同：1 Mbps/MHz 等於 1 bit/s/Hz。

#### 和其他小節的關係

上限來自 3.2.1 的 Shannon 容量；鏈路效率由 3.2.4 的 MCS 決定；3.2.5 的峰值速率除以載波頻寬就是峰值頻譜效率；多層傳輸為何能倍增效率見 3.2.6；小區吞吐量會用在 3.4 細項的訊務與容量估算。
