# 3.7.9 離散通道容量：BSC、BEC

所屬：[3.7 資訊理論與編碼](3-7.md)

## 內文

#### 為什麼要學

通道容量（channel capacity）是「在這條通道上，錯誤率可以壓到任意低的最高碼率」。它替所有通道編碼畫了一條不能越過的線：碼率低於容量時，總有辦法靠夠長的碼把錯誤率壓下去；碼率高於容量時，再好的編碼也做不到。二元對稱通道（binary symmetric channel, BSC）與二元抹除通道（binary erasure channel, BEC）是兩個最基本的離散模型：BSC 對應「解調後做硬式判決、每個位元以固定機率出錯」的鏈路，BEC 對應「封包不是正確收到就是整個遺失」的情況。LDPC 碼、Polar 碼的效能通常就以「離容量還差多少」來衡量。

#### 定義與符號

| 符號 | 意思 | 單位 |
|---|---|---|
| $X,\ Y$ | 通道的輸入與輸出 | 無 |
| $p(y\mid x)$ | 通道轉移機率 | 無 |
| $I(X;Y)$ | 輸入與輸出的互資訊 | bit／次通道使用 |
| $C$ | 通道容量 | bit／次通道使用 |
| $p$ | BSC 的交叉（位元翻轉）機率 | 無 |
| $\varepsilon$ | BEC 的抹除機率 | 無 |
| $H_b(\cdot)$ | 二元熵函數 | bit |
| $R$ | 碼率 | bit／次通道使用 |

#### 公式與推導

**定義。** 離散無記憶通道（每次使用互相獨立、轉移機率固定）的容量是互資訊對輸入分布取最大值：

$$C=\max_{p(x)} I(X;Y)$$

Shannon 的通道編碼定理說：$R<C$ 時存在錯誤率任意小的編碼；$R>C$ 時不存在。

**BSC。** 輸入、輸出都是 0 或 1，每個位元以機率 $p$ 翻轉。不論輸入是什麼，輸出的不確定性都來自那一次翻轉，所以 $H(Y\mid X)=H_b(p)$：

$$I(X;Y)=H(Y)-H(Y\mid X)=H(Y)-H_b(p)\le 1-H_b(p)$$

輸入各佔一半時輸出也各佔一半，$H(Y)=1$，等號成立：

$$C_{BSC}=1-H_b(p),\qquad H_b(p)=-p\log_2p-(1-p)\log_2(1-p)$$

$p=0$ 時 $C=1$；$p=0.5$ 時輸出與輸入無關，$C=0$；容量對 $p=0.5$ 對稱，$p>0.5$ 時把輸出反相就等同 $1-p$ 的通道。

**BEC。** 輸入是 0 或 1，輸出是 0、1 或「抹除」；每個位元以機率 $\varepsilon$ 被抹除，沒被抹除的一定正確。收到抹除時對輸入一無所知，其餘時候完全知道，所以 $H(X\mid Y)=\varepsilon H(X)$：

$$I(X;Y)=H(X)-H(X\mid Y)=(1-\varepsilon)H(X)\le 1-\varepsilon$$

輸入各佔一半時 $H(X)=1$：

$$C_{BEC}=1-\varepsilon$$

直觀上，平均只有 $1-\varepsilon$ 的位元能通過；值得注意的是，即使傳送端事先不知道哪些位元會被抹除，仍然能達到這個速率。

**比較。** 同樣的機率值下 $1-\varepsilon>1-H_b(p)$（$0<p<0.5$ 時 $H_b(p)>p$）：知道哪裡壞了（抹除）比不知道哪裡錯了（翻轉）好處理得多。這也是軟式判決優於硬式判決的原因之一。

**適用條件。** 以上是無記憶通道、每次通道使用傳一個二元符號的結果，單位是 bit／次通道使用；乘上每秒的通道使用次數才是 bit/s。連續振幅、有頻寬限制的通道要用 3.2.1 的 Shannon 公式。

#### 算例

**算例 1（BSC 與 BEC 的容量）** 求 (a) $p=0.01$ 的 BSC、(b) $p=0.1$ 的 BSC、(c) $\varepsilon=0.1$ 的 BEC 的容量。

(a) $H_b(0.01)=-0.01\log_2 0.01-0.99\log_2 0.99=0.0664+0.0144=0.0808$；$C=1-0.0808=0.9192$ bit。

(b) $H_b(0.1)=0.3322+0.1368=0.4690$；$C=1-0.4690=0.5310$ bit。

(c) $C=1-0.1=0.9$ bit。

合理性檢查：位元錯誤率由 1% 升到 10%，容量由 0.92 掉到 0.53，不是只少 9%；翻轉 10% 的 BSC（0.531）遠不如抹除 10% 的 BEC（0.9）。(b) 的結果與 3.7.1 算例 2 的說明一致：輸入各半時互資訊為 0.5310 bit，輸入機率為 0.7／0.3 時只有 0.4558 bit，低於容量。若每秒使用通道 $10^6$ 次，(a) 最多可靠傳送約 $0.9192$ Mbit/s。

**算例 2（給定碼率能容忍多差的通道）** 一個碼率 $R=1/2$ 的碼，理論上最多能用在多差的 BSC 與 BEC 上？

BEC：需要 $1-\varepsilon\ge0.5$，即 $\varepsilon\le0.5$。

BSC：需要 $1-H_b(p)\ge0.5$，即 $H_b(p)\le0.5$。試算 $H_b(0.10)=0.4690$、$H_b(0.11)=0.4999$、$H_b(0.20)=0.7219$，所以門檻約為 $p\approx0.110$。

合理性檢查：碼率 1/2 的碼在 BEC 上最多容忍一半的位元被抹除，在 BSC 上只能容忍約 11% 的位元翻轉，再次顯示抹除比翻轉容易對付。實際的有限長度編碼達不到這個極限，例如 3.7.4 的 $(7,5)$ 迴旋碼碼率同為 1/2，可靠運作所需的 $p$ 遠低於 0.11。

#### 常見錯誤

- 把 BSC 容量寫成 $1-p$。$1-p$ 是「位元沒錯的機率」，不是容量；容量是 $1-H_b(p)$。$1-\varepsilon$ 的形式只適用於 BEC。
- 算 $H_b(p)$ 時用 $\log_{10}$ 或 $\ln$ 而沒有換底。
- 以為 $p=0.5$ 的 BSC 還能傳一半的資訊。這時輸出與輸入獨立，容量為 0；最差的是 0.5，不是 1。
- 把單位 bit／次通道使用直接當成 bit/s，忘了乘上符號率。
- 把容量當成某個特定編碼的效能。容量是上限，達到它需要夠長的碼與合適的解碼。

#### 和其他小節的關係

容量的定義建立在 3.7.1 的互資訊上。3.7.6 的 Polar 碼以 BEC 說明極化，$N$ 個子通道的容量總和就是 $N(1-\varepsilon)$。BSC 的 $p$ 可由 3.2.3 的位元錯誤率公式得到；連續通道的容量見 3.2.1。3.7.4 到 3.7.6 的碼率都要低於這裡的容量才可能可靠傳輸。
