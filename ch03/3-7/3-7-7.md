# 3.7.7 ARQ 與 HARQ：停等、Go-Back-N、選擇性重傳的效率

## 正文

Automatic Repeat reQuest (ARQ) mechanisms are the backbone of reliability in packet‑switched networks. When a forward error‑correcting (FEC) code cannot guarantee error‑free delivery, ARQ detects residual errors (usually with a CRC) and requests retransmission of the affected data units. In modern cellular systems (e.g., 3GPP TS 36.321) ARQ is combined with FEC in the form of Hybrid ARQ (HARQ), which can reuse partially decoded information to improve spectral efficiency.

---

### 1. Basic ARQ protocols

| Protocol | Working principle | Maximum outstanding frames |
|----------|-------------------|-----------------------------|
| **Stop‑and‑Wait (SW)** | Sender transmits one frame and waits for an ACK/NAK before sending the next. | 1 |
| **Go‑Back‑N (GBN)** | Sender can transmit up to *W* frames without waiting; on a NAK the sender discards the erroneous frame **and all later frames**, retransmitting them in order. | *W* (≤ $2^{k}-1$, where *k* is the sequence‑number field size) |
| **Selective Repeat (SR)** | Like GBN, but only the erroneous frames are retransmitted; correctly received frames are kept in a receiver buffer. | *W* (≤ $2^{k-1}$) |

All three rely on a **sequence number** to match ACKs/NAKs to transmitted frames and on a **timeout** to trigger retransmission when an ACK is lost.

---

### 2. Efficiency (throughput) metrics

Let  

* $P$ – payload size (bits)  
* $H$ – header + CRC size (bits)  
* $R$ – link data rate (bits s$^{-1}$)  
* $T_{\text{tx}} = \dfrac{P+H}{R}$ – transmission time of one frame  
* $T_{\text{prop}}$ – one‑way propagation delay  
* $a = \dfrac{T_{\text{prop}}}{T_{\text{tx}}}$ – normalized propagation delay (dimensionless)  
* $W$ – window size (frames)  
* $p_e$ – probability that a transmitted frame is received erroneous (after FEC).  

The **channel utilization** $\eta$ (fraction of time that carries useful payload) for each protocol is:

* **Stop‑and‑Wait**

$$
\boxed{\eta_{\text{SW}} = \frac{P}{P+H}\,\frac{1}{1+2a}}
\tag{1}
$$

The factor $\frac{1}{1+2a}$ reflects the idle time while waiting for the ACK.

* **Go‑Back‑N**

Assuming independent errors and that the sender never stalls because the window is full,

$$
\boxed{\eta_{\text{GBN}} = \frac{P}{P+H}\,\frac{W}{1+2a}}
\tag{2}
$$

The term $W$ multiplies the raw utilization because up to $W$ frames can be “in flight”. The expression is an upper bound; in practice the effective window shrinks after a loss.

* **Selective Repeat**

Selective Repeat attains the same theoretical bound as GBN but suffers less waste when errors are sparse. Its utilization is often approximated by

$$
\boxed{\eta_{\text{SR}} = \frac{P}{P+H}\,\frac{W}{1+2a}\,(1-p_e)}
\tag{3}
$$

The factor $(1-p_e)$ accounts for the fact that only erroneous frames are retransmitted, not the whole window.

---

### 3. Hybrid ARQ (HARQ)

HARQ merges ARQ with soft‑decision FEC. Two common types are:

| Type | Description |
|------|-------------|
| **Type I** | The same encoded packet is retransmitted on a NAK (equivalent to “ARQ on top of a strong code”). |
| **Type II (Incremental Redundancy, IR)** | The first transmission sends a high‑rate code (e.g., rate‑$1/2$). Each retransmission supplies additional parity bits, effectively lowering the code rate (e.g., to $1/3$, $1/4$, …). The receiver combines all received symbols before decoding. |

For Type I HARQ with a maximum of $N_{\max}$ retransmissions, the **expected number of transmissions** per packet is

$$
\boxed{E[N] = \sum_{n=1}^{N_{\max}} n\,p_e^{\,n-1}(1-p_e) + N_{\max}\,p_e^{\,N_{\max}}}
\tag{4}
$$

The **effective throughput** becomes

$$
\boxed{T_{\text{HARQ}} = \frac{P}{E[N]\,T_{\text{tx}} + 2a\,T_{\text{tx}}}}
\tag{5}
$$

For Type II HARQ the denominator of (5) is reduced because each retransmission carries *new* parity rather than a full duplicate; a common approximation is to replace $E[N]$ by the **average code‑rate factor** $r_{\text{avg}}$ (e.g., $r_{\text{avg}} = 0.6$ for a $1/2$ → $1/3$ → $1/4$ schedule).

---

### 4. Worked example

A wireless link operates at $R = 10\,$Mbps. One data frame carries a payload of $P = 1500\,$bytes and a header+CRC of $H = 40\,$bytes. The one‑way propagation delay is $T_{\text{prop}} = 5\,$ms.

1. **Compute $a$**  

   $$
   T_{\text{tx}} = \frac{(1500+40)\times 8}{10\times10^{6}} = \frac{12320}{10^{7}} = 1.232\text{ ms}
   $$
   $$
   a = \frac{5\text{ ms}}{1.232\text{ ms}} \approx 4.06
   $$

2. **Stop‑and‑Wait efficiency**  

   $$
   \eta_{\text{SW}} = \frac{1500\times8}{(1500+40)\times8}\,\frac{1}{1+2a}
   = \frac{12000}{12320}\,\frac{1}{1+8.12}
   \approx 0.974\,\times\,0.110 \approx 0.107\;(10.7\%)
   $$

3. **Go‑Back‑N with $W=7$**  

   $$
   \eta_{\text{GBN}} = \frac{12000}{12320}\,\frac{7}{1+8.12}
   \approx 0.974 \times 0.770 \approx 0.750\;(75.0\%)
   $$

4. **Selective Repeat with $W=7$ and $p_e=0.01$**  

   $$
   \eta_{\text{SR}} = \frac{12000}{12320}\,\frac{7}{1+8.12}\,(1-0.01)
   \approx 0.750 \times 0.99 \approx 0.743\;(74.3\%)
   $$

   The gain over GBN is modest because the error probability is already low.

5. **Type I HARQ, $p_e=0.10$, $N_{\max}=3$**  

   Compute $E[N]$ using (4):

   $$
   E[N] = 1\cdot0.9 + 2\cdot0.1\cdot0.9 + 3\cdot0.1^{2}\cdot0.9 + 3\cdot0.1^{3}
        = 0.9 + 0.18 + 0.027 + 0.003 = 1.110
   $$

   Effective throughput:

   $$
   T_{\text{HARQ}} = \frac{12000}{1.110\,(1.232\text{ ms}) + 2\cdot4.06\,(1.232\text{ ms})}
   = \frac{12000}{1.368\text{ ms} + 10.0\text{ ms}}
   \approx \frac{12000}{11.37\text{ ms}} \approx 1.055\text{ Mbps}
   $$

   Compared with pure Stop‑and‑Wait (≈ 1.07 Mbps) the HARQ loss is small, but note that the same link would achieve ≈ 7.5 Mbps with GBN ($W=7$) – illustrating that ARQ efficiency is dominated by the $W/(1+2a)$ term when propagation delay is large.

---

### 5. Common pitfalls and practical notes

| Pitfall | Why it hurts performance |
|---------|---------------------------|
| Ignoring ACK/NAK transmission time | The control packets add $H_{\text{ACK}}$ bits that reduce $\eta$; Eq. (1)‑(3) assume they are negligible only when $H_{\text{ACK}}\ll P$. |
| Using a window size $W>2^{k-1}$ for SR | Sequence‑number ambiguity leads to mis‑ordering and duplicate deliveries. |
| Assuming independent errors for GBN | In bursty channels a single loss can cause the whole window to be retransmitted, dramatically lowering $\eta$. |
| Forgetting timeout calibration | Too short a timeout triggers unnecessary retransmissions; too long wastes buffer space and increases latency. |
| Treating HARQ as “ARQ + stronger code” without accounting for incremental redundancy | Type II HARQ can achieve up to 30 % higher throughput than Type I in moderate‑SNR regimes, but only if the scheduler allows variable‑rate retransmissions. |

In practice, system designers select the smallest $W$ that satisfies the target latency, combine it with a powerful FEC (LDPC or Polar), and enable HARQ Type II to approach the Shannon limit while keeping the protocol overhead manageable.

## 練習題

**1.** Which ARQ protocol can achieve the highest throughput on a link with large propagation delay, assuming the same error probability and identical frame size?

- A. Stop‑and‑Wait
- B. Go‑Back‑N
- C. Selective Repeat
- D. Type I HARQ

<details><summary>看答案</summary>

正解：C。Selective Repeat retransmits only erroneous frames, preserving the $W/(1+2a)$ gain of windowed protocols while avoiding the waste of Go‑Back‑N; thus it yields the highest throughput under identical conditions.

</details>

**2.** In a Selective Repeat ARQ system with a $k$‑bit sequence number field, the maximum admissible window size $W_{\max}$ is:

- A. $2^{k}$
- B. $2^{k}-1$
- C. $2^{k-1}$
- D. $2^{k}+1$

<details><summary>看答案</summary>

正解：C。To avoid ambiguous acknowledgments, SR requires $W\le 2^{k-1}$, whereas Go‑Back‑N permits $W\le 2^{k}-1$.

</details>

**3.** For Type II HARQ (incremental redundancy), each retransmission:

- A. Sends the same coded packet again.
- B. Sends additional parity bits that were not transmitted previously.
- C. Sends only the payload without any coding.
- D. Sends a NACK to the transmitter.

<details><summary>看答案</summary>

正解：B。Incremental redundancy provides new parity bits on each retransmission, allowing the decoder to lower the effective code rate.

</details>

**4.** A link has data rate $R=5\,$Mbps, payload $P=1200\,$bytes, header $H=40\,$bytes, one‑way propagation delay $T_{\text{prop}}=2\,$ms. Compute the Stop‑and‑Wait efficiency $\eta_{\text{SW}}$ (as a percentage). Use Eq. (1).


<details><summary>看答案</summary>

詳解：

1. Convert payload and header to bits: $P_{\text{bits}}=1200\times8=9600$, $H_{\text{bits}}=40\times8=320$.  
2. Transmission time $T_{\text{tx}}=\dfrac{9600+320}{5\times10^{6}}= \dfrac{9920}{5\cdot10^{6}}=1.984\text{ ms}$.  
3. Normalized propagation delay $a = \dfrac{2}{1.984}\approx1.008$.  
4. Efficiency $\eta_{\text{SW}} = \frac{9600}{9920}\times\frac{1}{1+2a}=0.9677\times\frac{1}{1+2.016}=0.9677\times0.332 =0.3214$.  
5. Percentage $\eta_{\text{SW}}=0.3214\times100\approx32.14\%$.  
\boxed{32.14}

</details>

**5.** For a Type I HARQ system with packet error probability $p_e=0.08$ and a maximum of $N_{\max}=4$ retransmissions, compute the expected number of transmissions $E[N]$ using Eq. (4). Provide the result with three decimal places.


<details><summary>看答案</summary>

詳解：

$$
E[N]=\sum_{n=1}^{4} n\,p_e^{\,n-1}(1-p_e)+4\,p_e^{4}
$$
Compute each term:  
- $n=1$: $1\cdot p_e^{0}(1-p_e)=1\cdot0.92=0.92$  
- $n=2$: $2\cdot p_e^{1}(1-p_e)=2\cdot0.08\cdot0.92=0.1472$  
- $n=3$: $3\cdot p_e^{2}(1-p_e)=3\cdot0.08^{2}\cdot0.92=0.01766$  
- $n=4$: $4\cdot p_e^{3}(1-p_e)=4\cdot0.08^{3}\cdot0.92=0.00188$  
Add the tail term $4\,p_e^{4}=4\cdot0.08^{4}=0.00016384$.  
Sum: $0.92+0.1472+0.01766+0.00188+0.00016384=1.0869\,(rounded\ to\ 3\ decimals)$.  
\boxed{1.087}

</details>
