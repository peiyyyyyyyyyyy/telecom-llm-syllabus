# 3.7.2 信源編碼：霍夫曼、算術編碼

所屬：[3.7 資訊理論與編碼](../3-7.md)

## 正文

In a digital communication system the source generates a sequence of symbols (e.g., bytes, video macro‑blocks, or protocol fields).  Transmitting each symbol with a fixed‑length binary word is simple, but it is rarely efficient because the symbols usually have a non‑uniform probability distribution.  *Source coding* (also called *data compression*) transforms the original symbol stream into a binary bitstream whose average length approaches the theoretical lower bound given by the source entropy.  Reducing the number of transmitted bits directly lowers bandwidth consumption, energy usage, and latency—critical factors in cellular, satellite, and IoT networks.

### Entropy and the Coding Theorem

For a discrete memoryless source (DMS) that emits symbols $X\in\mathcal{X}$ with probabilities $p(x)=\Pr\{X=x\}$, the **entropy** is  

$$
H(X)= -\sum_{x\in\mathcal{X}} p(x)\log_2 p(x)\quad\text{[bits/symbol]} .
$$

Shannon’s source coding theorem states that any uniquely decodable code must satisfy  

$$
L_{\text{avg}} \ge H(X),
$$

where $L_{\text{avg}}=\sum_{x} p(x) \, \ell(x)$ is the **average codeword length** and $\ell(x)$ is the length (in bits) of the code assigned to symbol $x$.  Conversely, there exist coding schemes whose average length can be made arbitrarily close to $H(X)$.

### Huffman Coding – Optimal Prefix Codes

A **prefix code** is a set of binary codewords in which no codeword is a prefix of another; this guarantees instantaneous (symbol‑by‑symbol) decoding.  Huffman’s algorithm (1952) constructs a prefix code that minimizes $L_{\text{avg}}$ for a given set of symbol probabilities.  The steps are:

1. Initialise a list of leaf nodes, each containing a symbol $x$ and weight $p(x)$.
2. Repeatedly select the two nodes with the smallest weights, merge them into a parent node whose weight is the sum of the two, and assign binary digits (e.g., 0 to the left child, 1 to the right child).
3. Continue until a single root node remains; the codeword for each symbol is read from the root to its leaf.

The resulting code satisfies the **Kraft inequality** with equality:

$$
\sum_{x\in\mathcal{X}} 2^{-\ell(x)} = 1 .
$$

Because each merge adds one bit to the depth of the two combined symbols, the average length obeys  

$$
H(X) \le L_{\text{avg}} < H(X) + 1 .
$$

*Units*: $p(x)$ is dimensionless, $\log_2$ yields bits, $\ell(x)$ is in bits, $L_{\text{avg}}$ in bits per source symbol.

### Arithmetic Coding – Near‑Entropy Compression

Huffman coding is optimal among *symbol‑by‑symbol* prefix codes, but it cannot assign fractional bit lengths.  **Arithmetic coding** overcomes this limitation by representing an entire message as a sub‑interval of the real line $[0,1)$.  The procedure:

1. Build a cumulative distribution function (CDF) $F(x)=\sum_{y<x} p(y)$ for the ordered alphabet.
2. Start with interval $[L_0,U_0)=[0,1)$.
3. For each incoming symbol $x_i$, update  

$$
L_{i}=L_{i-1}+ (U_{i-1}-L_{i-1})\;F(x_i),
$$
$$
U_{i}=L_{i-1}+ (U_{i-1}-L_{i-1})\;(F(x_i)+p(x_i)).
$$

After processing $n$ symbols the final interval $[L_n,U_n)$ has length  

$$
|U_n-L_n| = \prod_{i=1}^{n} p(x_i),
$$

and any binary fraction lying inside uniquely identifies the message.  The **code length** (in bits) is  

$$
\ell_{\text{arith}} = \lceil -\log_2 (U_n-L_n) \rceil .
$$

Because the interval size equals the product of the symbol probabilities, the expected length satisfies  

$$
\mathbb{E}[\ell_{\text{arith}}] = H(X) + \epsilon,
$$

where $\epsilon < 2$ bits for practical implementations, and can be made arbitrarily small with high‑precision arithmetic.

### Worked Example

Consider a source with four symbols and the probabilities  

| Symbol | $p(x)$ |
|--------|--------|
| A      | 0.50   |
| B      | 0.20   |
| C      | 0.20   |
| D      | 0.10   |

**Entropy**

$$
\begin{aligned}
H(X) &= -\bigl[0.5\log_2 0.5 + 0.2\log_2 0.2 + 0.2\log_2 0.2 + 0.1\log_2 0.1 \bigr] \\
     &= -( -0.5 -0.4644 -0.4644 -0.3322 ) \approx 1.761\ \text{bits/symbol}.
\end{aligned}
$$

**Huffman Coding**

1. Merge the two smallest probabilities: $0.10$ (D) and $0.20$ (B) → node $0.30$.
2. Remaining list: $0.20$ (C), $0.30$ (B+D), $0.50$ (A).  
   Merge $0.20$ (C) and $0.30$ → node $0.50$.
3. Finally merge $0.50$ (A) and $0.50$ (C+B+D) → root.

Assigning 0 to left branches and 1 to right branches yields the codewords  

| Symbol | Codeword | $\ell(x)$ |
|--------|----------|-----------|
| A      | 0        | 1 |
| B      | 101      | 3 |
| C      | 100      | 3 |
| D      | 11       | 2 |

Average length  

$$
L_{\text{avg}} = 0.5\cdot1 + 0.2\cdot3 + 0.2\cdot3 + 0.1\cdot2 = 1.8\ \text{bits/symbol},
$$

which satisfies $H(X) \le L_{\text{avg}} < H(X)+1$.

**Arithmetic Coding of the message “A B D”**

CDF: $F(A)=0$, $F(B)=0.5$, $F(C)=0.7$, $F(D)=0.9$.

Start $[L_0,U_0)=[0,1)$.

| Step | Symbol | New $L$ | New $U$ |
|------|--------|---------|---------|
| 1 | A | $0 + 1\cdot0 = 0$ | $0 + 1\cdot0.5 = 0.5$ |
| 2 | B | $0 + 0.5\cdot0.5 = 0.25$ | $0 + 0.5\cdot0.7 = 0.35$ |
| 3 | D | $0.25 + 0.1\cdot0.9 = 0.34$ | $0.25 + 0.1\cdot1 = 0.35$ |

Final interval $[0.34,0.35)$.  Its width is $0.01$, so the arithmetic code length is  

$$
\ell_{\text{arith}} = \lceil -\log_2 0.01 \rceil = \lceil 6.6439 \rceil = 7\ \text{bits},
$$

only $0.239$ bits above the entropy of the three‑symbol sequence.

### Common Pitfalls & Practical Notes

| Pitfall | Reason & Remedy |
|---------|-----------------|
| **Assuming Huffman always reaches entropy** | Huffman codes are integer‑length; the redundancy can be up to $1$ bit/symbol.  Use arithmetic or range coding when fractional‑bit efficiency is required. |
| **Violating the Kraft inequality** | A set of code lengths that does not satisfy $\sum 2^{-\ell(x)} \le 1$ cannot correspond to a prefix code.  Check the inequality when designing custom codes. |
| **Using a static probability model for a non‑stationary source** | Probabilities change over time, causing mismatch and loss of compression.  Adaptive Huffman or adaptive arithmetic coding updates the model on‑the‑fly. |
| **Floating‑point underflow in arithmetic coding** | Multiplying many small probabilities shrinks the interval quickly.  Implement renormalisation (output the leading bits when the interval lies wholly in $[0,0.5)$ or $[0.5,1)$) to keep the mantissa in a safe range. |
| **Neglecting the “end‑of‑stream” marker** | Without an explicit terminator the decoder cannot know where the message ends, especially when the final interval does not align with a binary fraction.  Append a unique EOF symbol or transmit the length separately. |

By mastering Huffman and arithmetic coding, telecom engineers can design link‑layer compressors, protocol‑stack optimisers, and satellite‑uplink preprocessors that respect bandwidth budgets while preserving lossless data integrity.

## 練習題

**1.** Which of the following statements about the Kraft inequality is true for any binary prefix code?

- A. $\displaystyle\sum_{x\in\mathcal{X}} 2^{\ell(x)} = 1$
- B. $\displaystyle\sum_{x\in\mathcal{X}} 2^{-\ell(x)} \le 1$
- C. $\displaystyle\sum_{x\in\mathcal{X}} \ell(x) = |\mathcal{X}|$
- D. $\displaystyle\sum_{x\in\mathcal{X}} p(x)\,\ell(x) = H(X)$

<details><summary>看答案</summary>

正解：B。The Kraft inequality for binary prefix codes requires the sum of $2^{-\ell(x)}$ over all codewords to be at most one; equality holds for a complete code.

</details>

**2.** For a memoryless source with entropy $H(X)=2.3$ bits/symbol, which of the following guarantees that a Huffman code will have an average length $L_{\text{avg}} \le 3.3$ bits/symbol?

- A. The source must have at most $2^{2.3}$ symbols.
- B. The source probabilities must all be powers of $\tfrac12$.
- C. Huffman coding always satisfies $L_{\text{avg}} < H(X)+1$.
- D. The source must be binary.

<details><summary>看答案</summary>

正解：C。Huffman coding satisfies the bound $H(X) \le L_{\text{avg}} < H(X)+1$, so $L_{\text{avg}} < 3.3$ bits/symbol follows directly.

</details>

**3.** In arithmetic coding, after processing $n$ symbols the interval width equals the product of the symbol probabilities. What is the implication for the expected code length $\mathbb{E}[\ell]$?

- A. $\mathbb{E}[\ell]=n\,\log_2 n$
- B. $\mathbb{E}[\ell]=H(X)$ exactly
- C. $\mathbb{E}[\ell]\approx H(X)+\epsilon$, with $0<\epsilon<2$
- D. $\mathbb{E}[\ell]$ grows exponentially with $n$

<details><summary>看答案</summary>

正解：C。Because the interval width is $\prod p(x_i)$, the expected number of bits needed is $-\log_2$ of that product, which equals $nH(X)$ plus a small constant $\epsilon$ bounded by 2.

</details>

**4.** Using the probabilities $p(A)=0.5$, $p(B)=0.2$, $p(C)=0.2$, $p(D)=0.1$, compute the average Huffman code length for the codewords A:0, B:101, C:100, D:11.  Give the answer in bits per symbol.


<details><summary>看答案</summary>

詳解（式號指本頁正文的公式）：

1. List codeword lengths: $\ell(A)=1$, $\ell(B)=3$, $\ell(C)=3$, $\ell(D)=2$.  
2. Compute weighted sum: $L_{\text{avg}} = 0.5\cdot1 + 0.2\cdot3 + 0.2\cdot3 + 0.1\cdot2$.  
3. Evaluate: $0.5 + 0.6 + 0.6 + 0.2 = 1.9$.  
$\boxed{1.9}$

**5.** For the same source, encode the symbol sequence “A B D” with arithmetic coding. Provide the lower bound of the final interval $L_n$ (the left endpoint) in decimal.  Unit: none (dimensionless).


<details><summary>看答案</summary>

詳解（式號指本頁正文的公式）：

CDF: $F(A)=0$, $F(B)=0.5$, $F(C)=0.7$, $F(D)=0.9$.  
Start $[0,1)$.  
- After A: $L_1=0$, $U_1=0.5$.  
- After B: range $=0.5$, $L_2 = 0 + 0.5\times0.5 = 0.25$, $U_2 = 0 + 0.5\times0.7 = 0.35$.  
- After D: range $=0.35-0.25=0.1$, $L_3 = 0.25 + 0.1\times0.9 = 0.34$, $U_3 = 0.25 + 0.1\times1 = 0.35$.  
Thus the left endpoint $L_3 = 0.34$.  
$\boxed{0.34}$
