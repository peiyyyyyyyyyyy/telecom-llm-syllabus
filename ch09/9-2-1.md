# 9.2.1 允許範圍

所屬：[9.2 參數](9-2.md)

## 內文

參數的允許範圍包含它在管理介面上的型別、單位、可接受值及能否寫入。維運人員通常在把候選值填進變更單前做這項檢查，也會在設備拒絕設定時回頭比對。有效值要同時符合規格、部署的版本和本地核准條件。一個在規格中可以表示的值，仍可能因設備能力、頻率配置或目前物件狀態而不能在指定環境使用。

首先以物件類別和欄位名稱定位參數，再查該版本的資料模型。整數要檢查上下限是否包含端點、是否有步進。列舉要使用正式符號，布林要依介面支援的表示法送入。查到振幅或功率量時，要辨明欄位是實際物理量、偏移量還是抽象索引，並按原規格將其換成對應單位。RRC 規格的資訊元素是空中介面表示方式。它可以幫助辨認值域和語義，設定草案的欄位仍須從部署使用的管理模型取得。兩種文件的名稱和型別可能不同，不宜看到相似名稱便直接跨介面套用。[3GPP TS 38.331 V18.8.0 §6.3](https://www.etsi.org/deliver/etsi_ts/138300_138399/138331/18.08.00_60/ts_138331v180800p.pdf)

接著把預設值、現行值和新值分開。預設值只有在所述初始化或缺值條件成立時才適用。現行值應從正確物件讀回，並記錄觀察時間。若欄位標為唯讀，可以保存觀察值做診斷，不能列入更新負載。例如 NRCellDU 的 operationalState 和 cellState 在 3GPP 的屬性表中可讀但不可寫。遇到值域檢查失敗時，草案要指出錯在哪一層，例如型別不合、步進不符，或雖落在頻段表中但還缺合規設備能力資料。應保留原提案，另列需要向哪個資料來源確認，避免替請求人自行修成最近的值。[3GPP TS 28.541 V18.8.0 §4.3.5.2](https://www.etsi.org/deliver/etsi_ts/128500_128599/128541/18.08.00_60/ts_128541v180800p.pdf)

假設虛構的竹角小區要評估 n78 的候選頻道號 630001，且工程單已指定用 30 kHz 的通道格點列查核。先看 TS 38.104 表 5.4.2.3-1，該列上下行都列為 620000 至 653332，步進為 2。用候選號減去起點得到 10001。它落在上下界之內，但差值不能整除 2，故不符合這個格點列。若另有候選 630002，差值是 10002，可整除 2，就通過這一層。然而查格點成功後還要核對實際頻寬能否放進已分配的頻譜、設備支援的組合及同步信號相關限制。這個步驟審的是草案，現場是否接受仍取決於全部條件。[3GPP TS 38.104 V18.15.0 表 5.4.2.3-1](https://www.etsi.org/deliver/etsi_ts/138100_138199/138104/18.15.00_60/ts_138104v181500p.pdf)

| 竹角小區虛構草案 | 值 |
| --- | --- |
| 頻段與查核列 | n78，30 kHz 通道格點 |
| 第一候選 | 630001 |
| 第二候選 | 630002 |
| 後續檢查 | 頻寬、實際頻譜配置與設備能力 |

常見混淆包括把區間內任意整數當可用、把通道格點與同步格點混用，以及把預設值直接抄為舊值。也要注意表列頻道號不等於已取得的頻譜使用許可。這些檢查結果應在草案上各自留下文檔版本與判斷依據。若工具拒絕候選，要保存它回報的欄位路徑和錯誤類型，才容易區分是輸入表示錯誤、參數本身不可用，或是外層的部署限制。待請求人同意新的候選後，重新跑相同檢核再送審。

接下來的 9.2.2 檢查多個單獨合法的欄位是否能一起成立，9.2.3 核對版本。完成後再在 9.3.2 填入可追溯的舊值、新值與理由。
