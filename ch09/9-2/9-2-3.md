# 9.2.3 不同設備版本的差異

所屬：[9.2 參數](../9-2.md)

## 正文

When a mobile operator introduces a new release of equipment—whether a radio base station, a Radio Network Controller (RNC), or a core network node—the network undergoes a **system up‑grade**.  An up‑grade can bring new features, extend existing facilities, or remove obsolete ones, and it touches every functional area of the PLMN.  Understanding how different hardware or software versions interact is essential because a mismatch can cause service disruption, prevent the activation of new capabilities, or render rollback impossible.  The 3GPP specification therefore treats version differences as a controlled change that must follow strict **Configuration Management (CM)** rules【TS 32.600 §4.1.3.2】.

### Definitions
| Symbol | Meaning | Unit / Note |
|--------|---------|-------------|
| $NE$   | Network Element – a logical or physical entity such as a base station, RNC, or core node. | – |
| $NR$   | Network Resource – the set of functions or capacities offered by an $NE$ (e.g., a cell, a carrier). | – |
| $SW$   | Software version of an $NE$ or $NR$. | – |
| $HW$   | Hardware functionality (e.g., new radio front‑end, added processing board). | – |
| $S$    | Ordered set of upgrade steps, $S = \{HW, SW\}$, where $SW$ depends on $HW$ being available. | – |

The specification explicitly lists **creation**, **deletion**, and **modification** of $NE$s/$NR$s as the CM functions applied during an upgrade【TS 32.600 §4.1.3.2】.

### Upgrade sequence and dependencies
A required **upgrade sequence** must be respected: the new software can only be activated after the corresponding hardware functionality is present.  This dependency can be expressed as  

$$
SW \;\Longrightarrow\; HW
$$

meaning “new $SW$ depends upon the availability of new $HW$”.  Following this order minimizes the impact on ongoing traffic and guarantees that the network can continue to process user data while the upgrade proceeds【TS 32.600 §4.1.3.2】.

### Logical vs. physical $NE$/ $NR$ handling
The 3GPP CM model distinguishes **logical** resources (entries in the management database) from **physical** resources (installed hardware).  Two complementary capabilities are defined:

1. **Logical creation without physical equipment** – An operator may create a logical $NE$/$NR$ (e.g., a new cell in an RNC) even if the corresponding hardware is not yet installed.  The system must block any traffic to that logical entity until the hardware appears, thereby avoiding service to a non‑existent element【TS 32.600 §4.1.3.2】.

2. **Physical installation without logical creation** – Conversely, hardware can be added to the network without immediately creating the managing logical object.  This ensures that the existing functionality is not disturbed while the new equipment is physically integrated【TS 32.600 §4.1.3.2】.

Both capabilities support staged roll‑out strategies, where the physical roll‑out and the logical configuration are decoupled to reduce risk.

### Reversion and safety mechanisms
If an upgrade introduces a fault, the network must be able to **revert** to the pre‑upgrade configuration.  The specification calls this process *reversion* and mandates that the original state be restorable at any time【TS 32.600 §4.1.3.2】.  Additional safety rules include:

* An $NE$/$NR$ that is being **extended** (adding capacity or features) must be taken **out of service** until all required parameters and equipment are initialized.  Only then may it be placed back into service【TS 32.600 §4.1.3.2】.
* An $NE$/$NR$ that is being **reduced** (removing capacity) follows the same rule: it stays out of service until the re‑configuration completes【TS 32.600 §4.1.3.2】.
* Operators are provided with mechanisms to **inhibit traffic** before a traffic‑affecting CM action, and to **gracefully release calls** when a resource is about to be closed【TS 32.600 §4.2】.
* All modifications are **logged** to support later analysis or recovery from a second data source, thereby mitigating data‑inconsistency problems【TS 32.600 §4.2】.

### Worked example
Consider an operator upgrading a 3‑sector LTE cell (Cell‑ID 1001) from hardware version **v1** to **v2** and software from **SW‑A** to **SW‑B**.

| Step | Action | Reason (per spec) |
|------|--------|-------------------|
| 1 | Install new RF module (HW v2) in the base station. | Physical addition without logical change, “install an additional physical NE/NR without creation of the logical resource”【TS 32.600 §4.1.3.2】 |
| 2 | Create logical cell entry for Cell‑ID 1001 in the CM database (still marked *out of service*). | Logical creation before full hardware availability is allowed【TS 32.600 §4.1.3.2】 |
| 3 | Upload SW‑B to the base station. | Must follow the sequence “new SW depends upon the availability of the new equipment functionality”【TS 32.600 §4.1.3.2】 |
| 4 | Initialise all cell parameters (PCI, EARFCN, power). | Required before the cell can be taken into service; “An extended NE/NR cannot be placed into service until all needed parameters and equipment are initialised”【TS 32.600 §4.1.3.2】 |
| 5 | Bring Cell‑ID 1001 *into service*. | Traffic can now be routed; any earlier traffic inhibition is lifted. |
| 6 | If a fault is detected, execute **reversion** to the previous configuration (HW v1, SW‑A). | “This procedure is called ‘reversion’ … useful in maintaining service if any difficulty should arise”【TS 32.600 §4.1.3.2】 |

Assuming each step takes 5 minutes, the total upgrade time is 30 minutes, and at no point is user traffic blocked beyond the brief inhibition required in step 4.

### Common pitfalls and practical notes
* **Skipping the HW‑first rule** – Activating new software before the supporting hardware is present will violate the required sequence and can crash the node.  
* **Allowing traffic to a logical‑only entity** – Without the safeguard that blocks service to non‑existent hardware, users may experience call failures or dropped sessions.  
* **Forgetting to take the element out of service during modification** – An extended or reduced $NE$/$NR$ must be out of service until the logical part finishes; otherwise the network may route traffic to an incompletely configured element.  
* **Neglecting to log changes** – Without proper logging, the reversion process cannot be guaranteed, increasing recovery time after a faulty upgrade.  
* **Assuming immediate re‑use of a newly installed physical resource** – Physical installation does not automatically create the managing logical object; the operator must still perform the logical creation step to integrate the resource into the CM system.

By adhering to the CM requirements outlined in TS 32.600, engineers can safely manage version differences across equipment generations, ensuring that upgrades enhance the network without jeopardising ongoing services.

## 練習題

**1.** Which of the following CM functions is *not* listed as employed for a system up‑grade in the specification?

- A. Creation of NEs and/or NRs
- B. Deletion of NEs and/or NRs
- C. Modification of NEs and/or NRs
- D. Monitoring of traffic

<details><summary>看答案</summary>

正解：D。The spec lists creation, deletion, and modification, but does not list monitoring as a CM function for upgrades.

</details>

**2.** According to the specification, what must be true before new software can be activated on a network element?

- A. The corresponding hardware functionality must already be available.
- B. All ongoing traffic must be permanently blocked.
- C. The operator must obtain a regulatory licence.
- D. The configuration must be logged for audit.

<details><summary>看答案</summary>

正解：A。The upgrade sequence requires that new software depends on the availability of the new equipment functionality.

</details>

**3.** What term does the specification use for restoring the network to its pre‑upgrade state?

- A. Rollback
- B. Reversion
- C. Reset
- D. Reboot

<details><summary>看答案</summary>

正解：B。The process of returning to the previous configuration is explicitly called “reversion”.

</details>

**4.** Which capability allows an operator to create a logical NE/NR without the physical hardware being present?

- A. Logical provisioning
- B. Physical provisioning
- C. Software patching
- D. Traffic inhibition

<details><summary>看答案</summary>

正解：A。The spec permits creation of an additional logical NE/NR without installed physical resources.

</details>

**5.** When an NE/NR is extended, under what condition may it be placed back into service?

- A. Immediately after the extension command.
- B. After all needed parameters and equipment are initialised.
- C. After traffic has been inhibited for 10 seconds.
- D. After the operator logs the change.

<details><summary>看答案</summary>

正解：B。The specification states that an extended NE/NR cannot be placed into service until all required parameters and equipment are initialized.

</details>
